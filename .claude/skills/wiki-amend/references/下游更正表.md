# 下游更正表

規則、情境步驟、欄位、狀態任一有實質異動時，寫完 wiki 後讀本檔。11 層卡不跑本步。
wiki 是正本，下游從它派生。下游沒跟著改，矛盾就留在下游。本步直接查、列出、修改。

## 一、各載體怎麼找、怎麼改

| 下游載體 | 怎麼找受影響處 | 怎麼改 |
|---------|---------------|--------|
| Prototype 情境目錄與測試（`erp-prototype-tests/docs/scenario-catalog.md`） | 以情境卡名搜各 spec 的「**情境**:」標註，取出掛在被改步驟或分支下的條目；規則變動另搜「規則正本見 wiki 〈卡名〉」引用句；存量 spec 未標註，再以業務關鍵詞搜全文 | 驗收條目的 GIVEN、THEN 對齊新步驟與新判準；引用句的卡名、段名對齊。系統承諾本身要新增或改變時不在此改，走 OpenSpec change |
| Linear 已交付票 | 依規則主題搜對應 project 的 Feature 票規則段與驗收段 | 列出要更正的票與條目，先給 Miles 過目；再依 `linear-delivery` 留言規則寫更正留言 |
| 操作手冊 | 依情境卡名找取材該情境的頁；寫法見 `memory/erp/manual-writing-rules.md` | 列出要改的頁與段，先給 Miles 過目，再改 |
| Prototype | 依欄位、狀態、流程節點對映 erp repo `(prototype)/` 頁面 | 只列不改；改走 change 與 erp repo 的 `prototype-from-prompt` |

- 找不到對應處時寫「無下游」，不略過本步。
- 結果寫在對話回報與提交訊息，不寫 wiki/log.md。log 只記 wiki 事件。

## 二、受影響清單格式

```markdown
下游更正（本次 wiki 異動：[[卡A]]、[[卡B]]）

| 載體 | 位置 | 現在寫什麼 | 要改成什麼 | 處置 |
|------|------|-----------|-----------|------|
| 情境目錄 | <情境目錄節號> 的測試條目 | <原句> | <新句> | 已改 |
| Linear | <票號> 規則段 | <原句> | <新句> | 待 Miles 過目 |
| 操作手冊 | <頁名> § <段名> | <原句> | <新句> | 待 Miles 過目 |
| Prototype | <頁面路徑> | <現況> | <應為> | 只列不改 |

無下游的載體：<載體名>
```

處置欄只填下列值：已改、待 Miles 過目、只列不改、無下游。
