## Prototype 為介面標準的精簡版（2026-10-04）

Miles 拍板：開發對著 Prototype 實作，欄位、值域、版面、操作動線、單欄必填都以 Prototype 為準，票不重述。Feature 票收斂為權限、實體關係、驗證規則、算式、具名驗收。以需求單模組試寫五版定型。

- Project：刪「測試決策」區塊；Scope 每條改寫「做完後使用者能做到什麼」。
- Feature 票：票頭加權限表（權限名稱、動作、範圍三欄，範圍四詞彙，不寫角色、代碼、狀態條件、反面）；功能節固定為使用者故事、實體關係、驗證規則、算式（有才放）、驗收；節名受詞加動詞；驗證規則只寫流程面受理條件，不寫單欄必填與值域；驗收改編號條列、前提用 Prototype 具名案例；段內各自編號。
- 刪規則短名制，Task 票改括註功能節名。刪流程表。刪「權限反面要寫」。
- 取材：wiki → Prototype → 後端現況；迭代差異改依 wiki/log.md 與 Prototype 提交紀錄；交付前先補該模組 Prototype 逆流程。
- 範本、範例同步改寫；範例改為需求單建立票（三節）與一張後端 Task 票。
- 評分維度 D1 到 D5 的檢查項與 0 分情形依上述調整；門檻值刪「受測介面數量」。
- 被取代的寫法進反例：節名「印件項目與金額」、權限表寫誰可以或代碼、驗證寫單欄必填、驗收泛稱、功能節放步驟表。

## 分層重整（2026-09-23）

原 `rubric.md` 與 `delivery-template.md` 合併拆為規範、範本、範例三檔；規則集中於規範檔並加短名，評分維度併入規範檔，門檻值集中於規範檔一處。Linear 評分停止條件改為前 3 輪換人不判停、第 4 輪起同一評分者、總分連 2 輪沒上升即停、10 輪安全上限。

重整後同日補充（盲測三輪驗證）：
- 範例縮小為 project 描述、一張 Feature 票（有流程表與純規則各一節）、一張 Task 票，五輪重評達合格分數。
- 規範新增：沒有角色接力或時序先後時不放流程表；沒有拆節條件時不拆節；每條驗收在同節規則段有對應規則。
- 評分維度的 1 分改為「有違規但未達 0 分所列情形」；Feature 另案段、概述可加狀態流轉引用句。
- 盲測結果（同一題目、各 3 份初稿、同一評分者隱名評分）：現況版三輪皆為 8、8、8；重整後版三輪為 10／9／8、9／10／9、9／10／10。

2026-09-24 補充（Miles grill 拍板）：
- 驗收只驗本功能規則，沿用規則交給正本票；權限規則的反面屬本功能規則。
- Task 規則每條括註 Feature 規則短名；無括註者限通用實作契約（值域外不受理、拒絕時回覆原因）；Task 規則不新增使用者看得到的新東西。
- Task 驗收前提取自父票具名案例，期望結果可加本票規則行為。
- 流程表「行為」欄只寫業務動作，不寫畫面位置與操作方式；範例同步修改。
