調整處：

| 項目 | Linear 上的原文 | 本範例 |

## Project 描述

```markdown
## 概述

需求單讓客戶還在談、尚未成交的印刷需求有一張獨立的單據承載。談成時業務一鍵轉出訂單。談不成時業務留下結構化的流失原因。

現行報價靠業務與印務主管在即時通訊上討論。客戶提供的參考檔散在對話紀錄裡。印務主管估價時常漏看參考檔，或要回頭問業務。談不成的需求沒有收尾出口，管理層看不出輸單輸在哪。

---

## 使用情境

### Use Case

1. 業務接到客戶詢價，建立需求單。
   1. 業務逐筆登記印件項目的規格、數量與難易度。
   2. 業務把客戶提供的參考檔掛到對應的印件項目下。
2. 業務指定一位印務主管，送出成本評估。
3. 印務主管照參考檔填妥各筆成本，完成評估。
4. 業務拿到成本後，與客戶逐件談單價。
5. 客戶接受報價時，業務標記成交並轉出草稿訂單。
6. 客戶不成交時，業務標記流失並選擇流失原因。
7. 客戶回頭時，業務重新啟動已流失的需求單。

### Scope（功能票清單）

1. **需求單建立與印件項目**：業務用它把客戶要印的東西逐筆登記成一張需求單。　PM-1207
2. **成本評估、報價與結案**：業務與印務主管用它接力估成本、談價錢，最後以成交或流失收尾。　PM-1215
3. **需求單複製、紀錄與分享**：業務用它從過往需求單起手，或把單子交給同事代做。　PM-1216

**Out of Scope**

* 成交轉訂單時各欄位帶入訂單與印件的行為：歸 <project id="4927231b-7fe3-407e-8d1f-94eddc3f0a84" href="https://linear.app/sensationdeveloper/project/%E4%B8%AD%E5%8F%B0-%E8%A8%82%E5%96%AE%E7%AE%A1%E7%90%86-414a81747028/overview">中台 - 訂單管理</project>。
* 審稿人員分派與稿件審查：歸 <project id="6cdc708c-7619-4ade-abbc-6d89977d1a11" href="https://linear.app/sensationdeveloper/project/%E4%B8%AD%E5%8F%B0-%E5%AF%A9%E7%A8%BF%E7%AE%A1%E7%90%86-1d734eb71219/overview">中台 - 審稿管理</project>。
* 電商規格品的定價：歸 EC 平台。價格在商品建立時已設定，不走需求單報價。

## 測試決策

* 受測介面（測試觀察點）：需求單建立與編輯表單（看得到可填什麼、填錯擋不擋）、需求單詳情（看得到這張單存了什麼值、哪些還能改）
* 測試基準：只驗可觀測行為（狀態轉移結果、欄位值、可否修改），不驗內部實作
* 開發依測試先行處理：每條驗收先落地為失敗測試，再實作至通過；期望值取自各 Feature 票的驗收條件，不由實作重算

>>> ## 印件項目參考附件

身為業務，我要把客戶給的參考檔掛在對應的印件項目下，以讓印務主管照著實際稿件估價，不必回頭找我。

**上傳與取用**

| 步驟 | 角色 | 行為 | 系統結果 |
| -- | -- | -- | -- |
| 1 | 業務 | 把客戶提供的參考檔上傳到該筆印件項目 | 該筆印件項目的參考附件清單出現這份檔案 |
| 2 | 業務 | 客戶提供修改版後，在同一筆印件項目再上傳新版 | 新版與舊版並存於清單 |
| 3 | 印務主管 | 開啟參考檔評估成本 | 印務主管取得客戶實際稿件作為估價依據 |

**規則**

1. **參考附件掛載層級**：參考附件掛在印件項目下，不掛在需求單層。
2. **參考附件多檔並存**：同一筆印件項目可掛多個檔案。
3. **參考附件新版不覆蓋**：再上傳新版時，舊版保留在清單。
4. **參考附件不動狀態**：上傳參考附件不更動需求單的狀態。
5. **參考附件可改期間**：報價階段可增刪；需求單進入成交或流失後鎖定。

**驗收條件**

* 假設業務在某筆印件項目上傳一個檔案，當上傳完成，則該筆的參考附件清單出現這份檔案。
* 假設同一筆印件項目已有一個檔案，當業務再上傳一版，則清單同時列出兩版。
* 假設需求單停在「需求確認中」，當業務上傳參考附件，則需求單仍停在「需求確認中」。
* 假設需求單已標記成交，當業務要刪除參考附件，則系統不接受。

>>>

>>> ## 印件項目免審稿

身為業務，我要在報價階段就標出哪些印刷品不必送審稿，以讓這些件成交後直接進生產，省掉審稿往返的交期與人力。

**規則**

1. **免審稿值域**：業務逐筆選是或否。
2. **免審稿可改期間**：報價階段可改；需求單進入成交或流失後鎖定。

**驗收條件**

* 假設業務在某筆印件項目標記免審稿為是，當儲存後重新開啟該需求單，則該筆的免審稿為是。
* 假設需求單停在「議價中」，當業務修改某筆印件項目的免審稿，則修改成立。
* 假設需求單已標記流失，當業務開啟印件項目，則免審稿不可修改。

>>>

* 參考附件的檔案數量上限、單檔大小與儲存配額：本票不設門檻。

## Task 票

```markdown
標題：[ Task ] - 印件項目參考附件與免審稿的資料存取
Label：ERP、Backend、Task
Parent：PM-1207

## 背景

身為業務，我要讓印件項目的參考附件與免審稿存得住、取得回，以讓印務主管照參考附件估價，成交後的生產照免審稿判定走。

## 規則

1. 參考附件以印件項目為單位存放（依「參考附件掛載層級」）。
2. 新上傳的參考附件與既有檔案並存，既有檔案不被覆寫（依「參考附件多檔並存」「參考附件新版不覆蓋」）。
3. 上傳參考附件不變更需求單狀態（依「參考附件不動狀態」）。
4. 參考附件的增刪請求依可改期間受理或拒絕（依「參考附件可改期間」）。
5. 是否免審稿只受理值域內的值（依「免審稿值域」）。
6. 是否免審稿的修改請求依可改期間受理或拒絕（依「免審稿可改期間」）。
7. 拒絕時回覆業務讀得懂的原因。

## 驗收

* 假設同一筆印件項目已有一個檔案，當業務再上傳一版，則取回的清單同時含兩版（受測介面：需求單詳情）。
* 假設需求單停在「需求確認中」，當業務上傳參考附件，則需求單仍停在「需求確認中」（受測介面：需求單詳情）。
* 假設需求單已標記成交，當業務要刪除參考附件，則不接受（受測介面：需求單詳情）。
* 假設需求單已標記流失，當業務修改免審稿，則不接受（受測介面：需求單建立與編輯表單）。

## 範圍

* 需求單狀態與印件項目的當前值：只取用、不自行實作。
* 不做：成交轉單時參考附件與免審稿帶入訂單的行為。原因：轉單帶入歸 <project id="4927231b-7fe3-407e-8d1f-94eddc3f0a84" href="https://linear.app/sensationdeveloper/project/%E4%B8%AD%E5%8F%B0-%E8%A8%82%E5%96%AE%E7%AE%A1%E7%90%86-414a81747028/overview">中台 - 訂單管理</project>。
* 不做：參考附件的數量上限與儲存配額。原因：來源尚未定案。
```
