## Project 描述

```markdown
## 概述

需求單讓客戶還在談、尚未成交的印刷需求有一張獨立的單據承載。談成時業務一鍵轉出訂單，談不成時留下流失原因。

現行報價靠業務與印務主管在 Slack 討論，客戶的參考檔散在對話裡，印務主管估價常漏看或回頭問。談不成的需求沒有收尾出口，管理層看不出輸單輸在哪。

---

## 使用情境

### Use Case

1. 業務接到詢價，建立需求單，逐筆登記印件項目與難易度，掛上參考檔。
2. 業務指定印務主管送出成本評估。
3. 印務主管填妥各筆成本。
4. 業務按評估完成，與客戶逐件談單價。
5. 客戶接受時業務標記成交並轉出草稿訂單；不接受時標記流失並選原因。
6. 客戶回頭時業務重新啟動已流失的需求單。

### Scope（功能票清單）

1. **需求單建立**：業務把客戶要印的東西登記成一張需求單並送出成本評估。　PM-1207
2. **成本評估與報價**：印務主管填成本、業務拿到報價依據並與客戶談定單價。　PM-1215
3. **需求單結案與轉單**：業務把談成的需求單轉成訂單、談不成的收掉或重啟。　PM-1216

**Out of Scope**

* 成交轉訂單後各欄位在訂單上的行為：歸 <project id="4927231b-7fe3-407e-8d1f-94eddc3f0a84" href="https://linear.app/sensationdeveloper/project/%E4%B8%AD%E5%8F%B0-%E8%A8%82%E5%96%AE%E7%AE%A1%E7%90%86-414a81747028/overview">中台 - 訂單管理</project>。
* 需求單的分享與職務代理：沿用單據分享規則，不在本 project 另寫。
* 電商規格品的定價：歸 EC 平台。

>>> ## 需求單建立

身為業務，我要把客戶的詢價開成一張需求單，以讓後續的估價、報價都掛在同一個對象上。

**實體關係**

1. 一張需求單屬於一個客戶，窗口聯絡人從該客戶底下的聯絡人選。
2. 從諮詢轉來的需求單記來源諮詢單，一對一，諮詢人員成為接單業務。

**驗證規則**

1. 建立需求單時驗證必填欄位是否填寫，未填齊則無法建立。

**驗收**

1. 假設業務填齊必填欄位、客戶為喜互惠量販股份有限公司、窗口許雅琪，當儲存，則需求單狀態為需求確認中、接單業務與建立者皆為該業務。
2. 假設業務有必填欄位未填，當儲存，則無法建立。

>>>

>>> ## 印件項目建立

身為業務，我要逐筆登記客戶要印的東西與數量，以讓印務主管有規格可估、客戶有金額可談。

**實體關係**

1. 一張需求單有多筆印件項目。每筆可掛多個參考附件、可選多條預計產線。
2. 印件項目是需求紀錄，不是印件。印件在成交轉訂單時才由系統建立。

**驗證規則**

1. 新增或修改印件項目時驗證必填欄位是否填寫，未填齊則無法儲存。
2. 需求單在成交或流失時，印件項目不可新增、修改、刪除。

**算式**

​```
小計 ＝ 數量 × 單價，四捨五入至整數元
未稅金額 ＝ 全部印件項目小計加總
稅額 ＝ 未稅金額 × 5%，四捨五入至整數元
含稅總額 ＝ 未稅金額 ＋ 稅額
​```

1. 單價為未稅，可到小數點後兩位。
2. 小計算出即定案，之後訂單、收款、發票都用這個整數，不再用單價回算。
3. 數量改動時用既有單價重算小計，單價不動。
4. 需求單不含運費與折扣，成交轉訂單後在訂單上填。

**驗收**

1. 假設 Q-20260601-01 的會員卡（客製燙金）數量 5,000、單價 9.8，當儲存，則小計 49,000、未稅金額 49,000、稅額 2,450、含稅總額 51,450。
2. 假設 Q-20260905-01 的福利禮盒外包裝數量 800、單價 18.75，當儲存，則小計 15,000。
3. 假設上一條數量改為 801，當儲存，則小計 15,019、單價仍為 18.75。
4. 假設 Q-20260601-01 已成交，當業務修改印件項目，則系統拒絕。

>>>

>>> ## 送印務評估

身為業務，我要指定印務主管協助估成本，以在報價前拿到可靠的成本。

**實體關係**

1. 一張需求單可指定多位評估印務主管。
2. 被指定的印務主管自動取得這張需求單的編輯分享，移出名單即撤銷。這份分享不含刪除需求單。
3. 送出後接單業務仍可增減評估印務主管。

**驗證規則**

1. 需求單在需求確認中才可送印務評估。
2. 任一印件項目難易度未填時不可送評估，系統列出缺漏的印件項目。

**驗收**

1. 假設一張新建需求單有兩筆印件項目、其中一筆難易度未填，當業務送印務評估，則系統拒絕並列出該筆，狀態仍為需求確認中。
2. 假設兩筆難易度皆已填，當業務送印務評估，則狀態轉待評估成本。
3. 假設 Q-20260905-01 的評估印務主管為吳國豪，當吳國豪開啟該需求單，則可改成本估算與預計產線，無送評估、新增印件、刪除。

## Task 票

```markdown
標題：[ Task ] - 需求單與印件項目的資料存取
Label：ERP、Backend、Task
Parent：PM-1207

## 背景

身為業務，我要讓需求單與印件項目存得住、金額算得對、送評估時擋得住缺漏，以讓印務主管拿到完整的估價依據。

## 規則

1. 建立需求單時檢查必填欄位，未填齊拒絕建立（依「需求單建立」）。
2. 來源諮詢單帶入時，接單業務記為該諮詢人員（依「需求單建立」）。
3. 印件項目以需求單為單位存放，附件與預計產線以印件項目為單位存放（依「印件項目建立」）。
4. 小計、未稅金額、稅額、含稅總額在印件項目新增、修改、刪除時重算並回傳（依「印件項目建立」）。
5. 需求單在成交或流失時拒絕印件項目的新增、修改、刪除（依「印件項目建立」）。
6. 送印務評估時檢查全部印件項目的難易度，有缺漏時拒絕並回傳缺漏清單（依「送印務評估」）。
7. 評估印務主管名單變動時同步該需求單的編輯分享，移出者撤銷（依「送印務評估」）。
8. 拒絕時回覆業務讀得懂的原因。

## 驗收

1. 假設 Q-20260601-01 的會員卡（客製燙金）數量 5,000、單價 9.8，當儲存，則取回小計 49,000、稅額 2,450、含稅總額 51,450（需求單詳情）。
2. 假設 Q-20260905-01 的福利禮盒外包裝數量改為 801，當儲存，則取回小計 15,019、單價 18.75（需求單詳情印件側板）。
3. 假設一張新建需求單有一筆印件項目難易度未填，當業務送印務評估，則拒絕並回傳該筆印件項目，狀態仍為需求確認中（需求單詳情）。
4. 假設 Q-20260905-01 的評估印務主管移除吳國豪，當儲存，則吳國豪開啟該需求單時成本估算不可修改（需求單詳情印件側板）。
