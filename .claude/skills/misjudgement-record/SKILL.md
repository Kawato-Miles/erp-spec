# 稽核誤判記錄

管理 `plan-audit` 稽核者的誤判案例。**正本單一卡**：[稽核誤判記錄](../../../memory/Sens_wiki/wiki/erp/11-review-knowledge/稽核誤判記錄.md)（Vault 內 [[稽核誤判記錄]]）——§ 一為禁用推論模式（原則）、§ 二為案例庫（append-only）。

## 三種操作模式

| 模式 | 觸發時機 | 做法 |
|------|---------|------|
| A：查詢 | 稽核前重溫案例／Miles 想看既有案例 | Read 正本卡；關鍵字用 grep |
| B：新增（含去重）| 識別到誤判／Miles 說「記下來」 | 見下方流程 |
| C：更新 | 既有案例補充細節／同類誤判重演 | Edit 追加至既有條目（同類重演在原條目加「歷史案例」行，不新增條目）|

## 模式 B 流程（禁止跳步）

1. **提取四要素**：日期與發生場景（哪個設計的稽核、哪個檢核項）／誤判內容（稽核者判了什麼）／Miles 反饋（**原話保留**，不轉述）／教訓（萃取可重用判準）。
   - 教訓 **MUST** 用具體場景描述，**MUST NOT** 用學術理由（「資料模型語義學」這類詞 Miles 看不懂，套不回下次稽核——此規則本身來自 2026-05-08「期次待收金額」案例）。
2. **去重**：讀正本卡 § 一與 § 二，判相似度——同類重演 → 擴充既有條目；相關不同面向 → 新條目＋標關聯；全新 → 新條目。回報分類與建議動作，**等 Miles 確認**再寫。
3. **寫入**：Edit 追加至 § 二（**禁 Write 覆蓋整檔**），格式照卡內四要素模板；若教訓可通則化，同步在 § 一加一條禁用模式，並評估是否需修 [[規劃品質評分準則]] 對應檢核項。
4. **更新 frontmatter** `last-reviewed` 為今日。
5. **回報**：分類／案例標題／教訓一句話／是否連動修準則卡。

## 不適用情境

- 一般 spec 修訂建議（不是誤判）
- 稽核者建議合理但 Miles 不採（設計選擇）
- 未確認的「可能誤判」（先確認再記）
- 純口語措辭調整

## Anti-Pattern

- **口頭說「以後注意」不建檔** → 下次 session 失憶重犯。識別到誤判必走 mode B。
- **不去重直接新增** → 案例庫膨脹、教訓重複。先 grep 再寫。
- **四要素缺漏**（只寫「以後別這樣」）→ 下次稽核套不上。四要素齊才算建檔。
