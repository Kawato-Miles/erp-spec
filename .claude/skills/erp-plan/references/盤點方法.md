# 盤點方法

本檔寫 precheck.md 各段怎麼判、怎麼寫。順序見 `../SKILL.md`；必含段與檢核陳述見 [[規劃品質評分準則]]，本檔不複寫。

## 一、卡類型矩陣

每個涉及領域一列，每種卡類型一欄。逐格回答下列問句。

| 卡類型 | 位置 | 問句 |
|--------|------|------|
| 角色 | `03-roles/`、活動清單卡 | 本議題的每個動作，活動清單有沒有對應活動與擁有角色？角色卡職責與現況一致嗎？ |
| 實體 | `05-entities/`、`06-state-machines/`、該領域資料結構總覽卡 | 本議題碰到的欄位、算式、狀態、關聯，實體卡、狀態機卡、總覽卡都寫了嗎？ |
| 流程 | `04-business-logic/服務藍圖/` | 本議題所屬的端到端業務鏈有藍圖嗎？角色交接與決策點清楚嗎？ |
| 業務情境 | `07-scenarios/` | 本議題的目標完成過程有情境卡嗎？變體判對了嗎？步驟判準是可觀測的業務結果嗎？已知例外有延伸岔路嗎？ |
| 業務邏輯 | `04-business-logic/` | 本議題的規則、計算、跨實體連帶寫了嗎？ |
| 法規 | `04-business-logic/` 法規類卡 | 本議題碰到的外部硬約束（如電子發票規格）獨立成卡了嗎？ |

每格寫三個整數：已涵蓋 N 張、待修補 M 處、待確認 OQ K 張。矩陣下加一行：資料結構總覽「有（卡名）」或「無」。
禁「大致完整」「再看看」這類沒有數字的結論。

## 二、缺口分類

判缺口前，讀完該卡全文。卡內已寫明延後或範圍外的，不算缺口。

| 類 | 判準 | 去處 |
|----|------|------|
| 現況缺漏 | 正本該寫、沒寫的已知事實 | 列目標卡；Miles 確認後轉 `wiki-amend` |
| 現況錯誤 | 正本與現行實作或其他正本矛盾 | 依 [[卡片撰寫共用規範]] § 三 矛盾呈報固定格式呈報，不調和 |
| 未決 | 要 Miles 決定的事 | `oq-manage` mode B 開卡 |
| 定案後要改 | 本次設計拍板後會改寫的卡 | 「寫 specs 前須更新的卡」段；盤點時不修 |
| 已宣告延後 | 卡內寫明延後或範圍外 | 列卡名與宣告句，不算缺口 |

## 三、precheck.md 各段

| 段 | 寫法 |
|----|------|
| 涉及領域與載入卡 | 領域名取 taxonomy 現行中文名；卡名清單附張數；總覽卡有或無 |
| 卡類型矩陣 | 照 § 一 |
| 現況缺口 | 一列一缺口：卡名、缺什麼、分類、去處 |
| 待確認 OQ | 依涉及領域查 `08-open-questions/` 平層（`oq-manage` mode A）；列編號與一句議題；不預設任何編號前綴 |
| 連帶影響 | 該領域有連帶矩陣卡（如 [[帳務規劃連帶矩陣]]）就照矩陣逐實體列；沒有就寫「本領域無連帶矩陣」，改列總覽卡上與本議題相連的實體 |
| 寫 specs 前須更新的卡 | 04～07 內提及本議題的卡，含狀態機卡、活動清單卡、流程群組卡等下游；一列一卡附改寫要點；新規則寫「新增，落點由 wiki-amend 判」 |
| 調研建議 | 照 `調研判斷.md` § 二 |
| 衝突筆記 | 只在探索有產出時寫；照 `衝突檢查.md` § 二 |

## 四、log 一筆

```markdown
## [YYYY-MM-DD HH:MM] 健檢(pre-check) | <領域>盤點（議題：<議題名稱>）
- 變更：矩陣合計 已涵蓋 N／待修補 M／OQ K；新開 OQ <編號或無>；調研建議 <要或不要>
- 動機：免（健檢類）
- 衝突：無
```

逐格矩陣與缺口明細寫在 precheck.md，不進 log。
