# 衝突檢查

用在探索新需求、還沒建立 `.scratch/<主題>/` 時。
目的：方向定下前，先知道這個方向會不會撞到既有商業規則。

## 一、讀什麼

| 讀 | 範圍 |
|----|------|
| 對應領域的 `04-business-logic/` 規則卡 | 依 [[business-domain-taxonomy]] § 檢索規約先列卡名，攤給 Miles 後載入 |
| 相關的未決 OQ | `oq-manage` mode A；只查 `08-open-questions/` 平層 |

## 二、衝突筆記

一條衝突一列。

| 欄 | 寫法 |
|----|------|
| 方向 | Miles 提的做法，一句 |
| 撞到的規則 | 卡名與行號，或 OQ 編號 |
| 衝突點 | 兩者哪裡不能同時成立 |
| 處置選項 | A 繞過：用既有機制；B 推翻：改既有規則；C 待釐清：開 OQ |

- 處置選項列給 Miles。決策權在 Miles，不替 Miles 決定方向。
- 沒有衝突時寫「未見衝突」，附讀過的卡名。
- 筆記交後續 grill 與設計承接。建立 `.scratch/<主題>/` 後併入 precheck.md 衝突筆記段；盤點不重掃已列的衝突。

## 三、訪談紀律

- 決策類問題一次只問一題。
- 每題附建議答案，讓 Miles 可以一字拍板。
- 該題有結論，才問下一題。
- 能從環境查到的事實（wiki、spec、Notion、git）自己查，不拿來問 Miles。只有決策才問人。
