# plan-audit

正本量尺：[規劃品質評分準則](../../memory/Sens_wiki/wiki/erp/11-review-knowledge/規劃品質評分準則.md)。本 skill 只管流程，檢核項內容、評分規則、稽核者紀律一律以準則卡為準，本檔不複寫。

## 流程

### 步驟 1：收件檢查（主對話執行，機械性）

驗五必含段是否齊備（準則卡 § 二）。缺任一段 → **直接退件**，不派稽核 agent、不進 rubric。這是 grill 對齊與自證責任的硬閘門。

### 步驟 2：分級判定（主對話執行，先亮給 Miles）

| 分級 | 判準 | 稽核形態 |
|------|------|---------|
| 局部變動 | 單模組欄位、單流程節點，不動跨模組 | 單一稽核者跑完整 rubric |
| 結構性變更 | 新增實體、跨模組關聯、狀態機層級變動、新增角色 | 單一稽核者跑 rubric ＋ 對抗式情境推演並行找漏 |

輸出「判定＝X（一句話理由）」給 Miles 過目後才開跑；**判不準 MUST 直接問 Miles，不自行猜**。判錯案例由 `misjudgement-record` 累積，回頭修判準。

### 步驟 3：派稽核 sub-agent（模型用 Opus 5）

dispatch prompt 必含：
- 設計方案全文（含四必含段），不摘要、不刪減。
- 準則卡全文或路徑（稽核者 MUST 先讀）。
- 領域背景：依 [[business-domain-taxonomy]] 檢索規約載入的相關正本卡清單、wiki `07-scenarios/` 相關情境卡。
- 稽核者紀律重述（準則卡 § 六）。

結構性變更另派對抗推演者（**雙盲**，依準則卡 § 五）：2-4 個並行、互不知對方結果（第一盲）；各給**去論證版**設計——只含規則、流程、數字，抽掉設計理由與說帖（第二盲）。取向分配：技術取向（中途變更／跨模組連動失敗／時序錯位／極端值）＋兩個立場鏡頭（資源流出把關視角、現場操作成本視角）。回收後去重彙整，並把判定與原論證對照：獨立撞上既有理由＝理由經得起盲測；撞不上＝真缺口。

### 步驟 4：評分表（稽核產出的唯一格式)

| 欄位 | 標準 |
|------|------|
| 檢核項 | 準則卡 § 四編號（1-1 至 5-2）逐項列，不可跳項 |
| 判定 | 三值：通過／部分通過／未通過 |
| 證據 | 強制。卡名／情境名／欄位名／「推演至第 N 步斷掉：缺 Y」；無證據的判定退回稽核者重出 |
| 處置 | 部分通過必填（開 OQ／修正時補／可接受理由） |

### 步驟 5：裁決與循環（主對話執行）

- 任一「未通過」→ 退回主對話修正 → 回步驟 3 復審（復審可只重驗未通過項＋受修正牽動項）。
- 全過 → 評分表原樣呈 Miles 拍板，**不由協調者改寫或美化**。
- 拍板後接 `wiki-amend` 落卡（推演打出漏洞的有效對抗情境一併回寫 `07-scenarios/`）→ `/opsx:propose`。

## 誤判回饋

Miles 指出稽核誤判（假缺漏、分級判錯、規則套錯）時，MUST 觸發 `misjudgement-record` 建檔（對象：稽核者），並評估是否修準則卡對應檢核項。
