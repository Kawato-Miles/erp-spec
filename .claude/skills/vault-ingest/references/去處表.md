# 去處表

## 一、素材進來時的分流（mode A）

| 判斷 | 去處 |
|------|------|
| 能直接回答 What／Why 的已確認知識 | 直接寫既有 wiki 卡，不經 raw；03～07 走 `wiki-amend` |
| 明確未解問題（問句、「是否要」） | OQ（`oq-manage` mode B） |
| 還沒消化的已驗證觀察、反饋、研究筆記、外部檔案 | raw（mode A） |
| LLM 自編、沒有外部來源 | 拒絕（防線 2） |
| 介面規範細節 | Prototype 的 DESIGN.md，不進 vault |

## 二、精練去處（mode B）

對照 `memory/Sens_wiki/wiki/erp/00-meta/scope-boundary.md` 判。

| 素材內容 | 去處 | 寫入入口 |
|---------|------|---------|
| 公司商業規則 | `04-business-logic/` | `wiki-amend` |
| 業務可見欄位、算式 | `05-entities/` | `wiki-amend` |
| 狀態與轉換條件 | `06-state-machines/` | `wiki-amend` |
| 公司業務流程的步驟與分支 | `07-scenarios/` | `wiki-amend` |
| 業界做法、守恆量 | `11-review-knowledge/參考模型/<領域>.md` | [[審查知識路由]] § 四 |
| 審查方法、代理協作協議 | `11-review-knowledge/` 其他卡 | [[審查知識路由]] § 四 |
| 未解問題 | OQ | `oq-manage` mode B |
| 不進 vault | raw 卡 status=cancelled，附理由 | 本 skill |

- 業界做法不寫進 03～07。業務正本卡只寫公司現行做法。
- 參考模型卡每條附 raw 卡出處；只收的段落見 [[審查知識路由]] § 四。
- 同主題累積達門檻時，一併判這批合起來該寫進哪張卡。門檻見 `掃描報告格式.md` § 一。
