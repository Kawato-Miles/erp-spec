## Problem Statement

公司 2026/09 在需求單到審稿階段試用系統，同事留下標「優先 L1」的回饋。介面與命名類（甲乙類）已做進 Prototype（sensationsprint/erp#267）。剩下的是商業規則類，業務與會計在日常作業會卡住：

- 業務在 Caac（漸強 CRM 的服務）跟客戶對話，需求單上沒地方記對話在哪，回頭查要翻 Caac。
- [[需求單]] 的難易度原本必填，送印務評估前會擋。業務在需求單階段多半不知道審稿難度，填出來是佔位值（[[QR-011-印件難易度是否改為非必填並取消送印務評估把關]]）。
- 同一規格常報不同數量（500 本、1000 本各一筆）。需求單只能複製整張單，業務要重打一次規格。
- 客戶給的參考檔有時只是顏色參考，不是稿件。參考附件沒有說明欄，審稿與印務容易誤用。
- 線上單客戶已在官網表態是否同意公司公開成品，訂單上的授權分享仍要業務再問一次。
- 正式前端已做好訂單備註的固定條款清單（27 條，取自業務的報價單備註產生器），Prototype 沒有，Prototype 落後開發。
- 業務主管核准收款計畫後，業務改金額、改日期、取消期次都不送審也不擋（[[付款發票邏輯]]），但會計與主管看不到哪些訂單的收款計畫被改過。現行「變更次數」只計日期，改金額不留次數。

## Solution

| 項 | 使用者看到的變化 |
|----|----------------|
| 1a | 需求單基本資訊多「Caac 訊息連結」「Caac 名稱」兩欄，選填，只在需求單 |
| 1b | 難易度在需求單、送印務評估、成交轉訂單、訂單上新增或編輯印件、分派審稿都可以空著；線上單自動分派遇到空值時所有審稿人員都是候選 |
| 1c | 需求單印件項目列上多「複製」鈕，複製出一筆新項目：成本估算與單價清空，其餘欄位帶入原值 |
| 1d | 需求單每個參考附件可以填「參考附件說明」（200 字內），不印在報價單上；轉訂單時帶進訂單其他附件的用途說明（空著就寫「需求單參考附件」），之後可以改 |
| 8 | 線上單建立訂單時，授權分享與授權備註帶入客戶在官網填的內容；線下單不變 |
| 10 | 編輯訂單備註抽屜的訂單須知、交貨備註、付款備註各有「選擇範本」鈕，從固定條款清單帶入文字，接在既有內容後，可再改 |
| 13 | 以「收款計畫核定時點」為界（線下單＝訂單審核通過；諮詢訂單＝訂單建立）：原始預計收款日與原始預計開發票日在核定時點凍結；收款項目表的「異動次數」改計核定後的改金額、改兩個預計日期與取消，每改一欄計一次；核定後改這三欄要填異動原因；核定前可刪除收款項目、之後只能取消並寫原因；款項管理多一張跨訂單「收款項目異動清單」，一列一張訂單，展開看每筆異動 |

## Implementation Decisions

### 本體

| 項目 | 內容 | 正本卡 |
|------|------|-------|
| Caac 訊息連結、Caac 名稱 | 新增，需求單基本資料兩欄，選填；OP-QR-001 建立需求單、OP-QR-003 編輯需求單填；成交轉訂單不帶入。OP-QR-002 複製需求單帶不帶這兩欄屬 QR-021 待解答，拍板前此行為不寫進規劃單 | [[需求單]] |
| 難易度選填 | 需求單印件項目、印件的難易度改選填；送印務評估的轉換條件拿掉難易度 | [[需求單]]、[[印件]]、[[需求單狀態]] |
| 線上單候選條件 | 難易度空值時不比對能力等級 | [[線上單候選條件]] |
| 複製印件項目 | 歸 OP-QR-003 編輯需求單，不另立操作（執行者相同）；帶入範圍：成本估算與單價清空，其餘欄位帶入原值，小計與利潤率依規則重算；可用時機同新增印件項目 | [[需求單]]、[[複製需求單帶入範圍]] |
| 參考附件說明 | 新增，參考附件每個檔案一則說明，選填，200 字內，不印在報價單 | [[需求單]] |
| 其他附件用途說明 | 需求單轉入時取參考附件說明，空值寫「需求單參考附件」；訂單未取消時可改 | [[訂單]] |
| 授權分享、授權備註 | 線上單由系統於接收 EC 訂單時帶入 | [[訂單]] |
| 客戶條款組 | 三格可從系統固定條款清單帶入文字，追加於既有內容後、可再改 | [[訂單]]、[[訂單客戶條款組維護]] |
| 收款計畫核定時點 | 新增名詞：線下單＝訂單進入 [[訂單狀態]] 審核通過；諮詢訂單＝訂單建立；線上單見 BI-031 | [[帳務]] 稽核事件說明 |
| 原始預計收款日、原始預計開發票日 | 改在核定時點凍結；核定後新增的期次取新增當下的值；線上單維持首次儲存 | [[帳務]] |
| 異動次數 | 欄名由「變更次數」改「異動次數」；核定時點之後計改預計金額、改預計收款日、改預計開發票日、取消；新增從 0 起；一次儲存改多欄，每欄各計一次 | [[帳務]] |
| 異動原因 | 核定時點之後以 OP-BIL-001 改上述三欄須填，記在該筆事件 | [[帳務]] OP-BIL-001 |
| 刪除收款項目 | OP-BIL-003 限核定時點之前：線下單為草稿或待業務主管審核；諮詢訂單不可刪除 | [[帳務]]、[[付款發票邏輯]]、[[帳務流程群組]]、[[收款項目規劃活動清單]] |
| 取消原因 | 改必填 | [[帳務]] |
| 收款項目事件 | 記在訂單活動紀錄：新增、改預計金額、改預計收款日、改預計開發票日、取消（另記核銷覆寫）；每筆記類型、改前值、改後值、操作者、時間、原因（取消原因或異動原因；新增不記原因）；拆期記改金額加新增兩筆；不設拆期與刪除事件 | [[帳務]] |
| 收款項目異動清單 | 新增具名清單，列核定時點之後有收款項目事件的線下單與諮詢訂單；不移出；只供查閱 | [[訂單]]、[[帳務]] OP-BIL-018、[[跨訂單作業清單]] |

### 流程與活動

| 步 | 執行角色 | 活動 | 完成判準 |

| 刪除收款項目 | 業務、諮詢；被分享（編輯）；協助角色 | [[收款項目規劃活動清單]] ACT-BPL-010～012 | 核定時點之前，收款項目消失，不留事件 |
| 取消收款項目 | 同上 | ACT-BPL-007～009 | 收款項目標記取消、原因必填；核定時點之後異動次數加 1、清單多一筆 |
| 改金額或預計日期 | 同上 | ACT-BPL-004～006 | 核定時點之前：欄位為新值，不計次、不進清單。核定時點之後：須填異動原因，每改一欄異動次數加 1、清單多一筆 |
| 核定後新增收款項目 | 同上 | ACT-BPL-001～003（[[訂單]] OP-ORD-005 新增收款項目） | 新一期異動次數 0、原始預計日期為新增當下的值；清單多一筆「新增」 |
| 查閱異動清單 | 業務、諮詢（全公司）；被分享（檢視、編輯）；業務主管；會計；Supervisor | [[訂單與帳務檢視活動清單]] ACT-VORD-043～048 | 清單列出訂單、展開見事件 |

- 線上單授權帶入沒有人員活動，由系統於接收 EC 訂單時寫入（[[訂單狀態]] 建立轉換）。
- 諮詢完成時，收款項目由系統於諮詢收尾時自動建立（[[收尾自動建收款項目]]），沒有人員活動；這筆就是核定的計畫本身，不算核定後新增。
- 諮詢取消時系統不建收款項目（[[取消不自動建收款項目]]），業務以 ACT-BPL-001～003 自建一期開留存收入的發票；這一期發生在核定時點之後，照常記新增、列入異動清單。

### 守恆

| 量 | 等式 | 說明 |
|----|------|------|
| 收款項目預計金額合計與應收總額 | 不變：本案不改金額計算，只記改金額事件 | 三方對帳口徑見 [[帳務]]，不受影響 |
| 需求單印件項目小計 | 小計＝數量 × 單價；複製項目單價為空，小計為空 | 既有規則，見 [[需求單]] |
| 異動次數與清單筆數 | 同一收款項目，核定時點之後的改金額、改兩個日期、取消事件筆數＝該期異動次數 | 新增事件不計次數，但列入清單 |

### 管理指標

本案不新增指標。異動次數在後端欄位註解標為 KPI 資料來源，wiki 目前沒有指標卡引用它。本案改了它的計入口徑（加計改金額與取消、改為逐欄計次、改從核定時點起算），日後若有指標引用，口徑以 [[帳務]] 異動次數欄為準。

### 總覽差異

本案沒有增、改、刪實體間關聯。收款項目事件沿用既有「訂單與活動紀錄」關聯（[[ERP 資料結構總覽]]）；需求單與印件項目、印件項目與參考附件兩條關聯只補建立時機與屬性說明，基數不變。

### 關鍵決策與否決方案

| 決策 | 否決方案 | 否決理由 |
|------|---------|---------|
| 難易度全系統不擋 | 成交前補擋 | 轉訂單後分派者仍可補填，擋在成交只增加業務負擔（QR-011 決議） |
| 複製印件項目歸編輯需求單 | 另立「複製印件項目」操作 | [[規範 - 實體]] § 三：執行者相同不另立操作 |
| 複製時清空成本與單價 | 帶入原值當預設 | 複製多半是換數量，舊成本與單價幾乎一定不對，帶入會讓利潤率與報價出錯 |
| 參考附件說明另設欄 | 沿用稿件備註 | 稿件備註寫給審稿人員、說稿件；參考附件說明說參考檔的用途，對象與內容不同 |
| 異動清單沿用訂單活動紀錄 | 另立異動紀錄子表 | 後端已把收款項目事件存在訂單活動紀錄，沿用不新增實體（Miles 拍板） |
| 不設拆期事件 | 記一筆拆期 | 拆期就是改原期金額加新增一期，兩筆事件已能還原；多一種類型反而要定義跟另兩種的重疊 |
| 核定時點之前可刪、之後只取消 | 任何時點都能刪；拿掉刪除 | 主管核准過的收款計畫要留原貌與取消原因；草稿期間建錯直接刪，不留雜訊 |
| 以核定時點為界起算異動、凍結原始日 | 從訂單建立起算；原始日維持首次儲存凍結 | 草稿期間的反覆試算不是計畫改變，會塞滿清單；原始日要等於主管核准的日期，會計對照才有意義（Miles 拍板，取代 BI-1） |
| 一次儲存改多欄每欄各計一次 | 一次儲存計一次 | 清單一筆對一個欄位的改前改後，次數與清單筆數對得上；後端日期欄已逐欄記事件（Miles 拍板，取代 BI-1） |
| Caac 兩欄只在需求單 | 帶入訂單 | Caac 對話是接單前的溝通，訂單階段有自己的討論串；Miles 拍板只在需求單 |
| 核定後改動必填異動原因 | 只有取消有原因；選填 | 會計看清單時要知道為什麼改，空白原因要回頭問業務（Miles 拍板） |
| 諮詢訂單比照線下單、建立即核定 | 併入線上單待裁決 | 諮詢訂單的收款項目由系統依諮詢費建立，建立當下就是定案金額（Miles 拍板） |
| 條款用系統固定清單 | 主檔由業務主管維護 | 條款改動不頻繁；與封存 OQ XM-006 決議一致 |
