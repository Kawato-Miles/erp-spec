# grill 拍板紀錄：需求單多版本報價

- 分級：結構性（Miles 2026-11-05 確認）。調研：要（Miles 2026-11-05 同意）。
- 設計方向：需求單對應 Salesforce 商機，報價版本對應報價單；報價版本內容以公司規則為主，不照搬 Salesforce 的報價單欄位（Miles 2026-11-05，Q8）。

## 一、前一工作階段已拍板（交接，不重問）

| 編號 | 拍板 |
|------|------|
| P1 | 需求單對應商機；報價版本對應報價單，版本有自己的印件項目列 |
| P2 | 版本有系統編號，另有業務自填名稱 |
| P3 | 同一時間只有一個同步版本，雙向同步；切換同步版本時，以該版本的項目列取代需求單印件項目 |
| P4 | 需求單金額＝需求單印件項目加總 |
| P5 | 方案報價單只在「議價中」可下載，且所有價格要填齊 |
| P6 | 成交時開對話框，預選同步版本；只有該版本的項目轉入訂單；維持 1 張需求單對 1 張訂單 |
| P7 | 刪除版本時一併刪除該版本的項目列與方案報價單檔案 |
| P8 | 印務評估成本涵蓋所有版本的項目列，依版本分組；新建版本時帶入成本與報價 |
| P9 | 報價紀錄的輪次機制不變，快照包含版本 |
| P10 | 預測（成交機率、預計成交日）延後不做 |

## 二、本次 grill 拍板（Miles 2026-11-05）

| 編號 | 題目 | 拍板 |
|------|------|------|
| Q1 | 報價版本的承載 | 開獨立實體卡；版本操作登記在需求單卡，不另設單據代碼 |
| Q2 | 可動版本的需求單狀態 | 需求確認中、待評估成本、已評估成本、議價中皆可新增、編輯、刪除版本與切換同步；成交、流失後連同版本鎖定 |
| Q3-1 | 版本是否選用 | 改為每張需求單至少一版：建立需求單時系統自動建第 1 版並設為同步版本（取代交接時「版本是選用」） |
| Q3-2 | 成交選非同步版本 | 系統先把選定版本切為同步版本、需求單印件項目與金額跟著換，再成交鎖定；不另設主要版本 |
| Q4 | 方案報價單與報價單 | 兩種文件分名：方案報價單是需求單階段文件、金額取版本、不經業務主管核可；報價單維持訂單階段、核可後外發供回簽 |
| Q5 | 停止同步 | 拿掉停止同步（取代交接時「業務可停止同步」與「刪除同步版本會停止同步」）：永遠有一版同步；同步版本不能刪，要刪先切到別版；只剩一版時不能刪 |
| Q6 | 評估範圍 | 送印務評估的難易度檢查、評估完成的成本檢查涵蓋全部版本；議價中出現沒有成本的印件項目，走重新評估報價回待評估成本；議價中改成本仍走重新評估 |
| Q7 | 標案比價 | 改走版本：在需求單開多版、各下載方案報價單；刪除訂單成立確認的訂單層比價副流程 |
| Q8 | 版本金額 | 版本只有印件金額：未稅、稅額、含稅由項目加總；不設折扣與運費；報價截止日留在需求單 |
| Q9-1 | 版本項目列欄位 | 與需求單印件項目完全相同；切換同步時整列取代；參考附件跟著項目走 |
| Q9-2 | 複製需求單 | 只帶同步版本的印件項目，成為新單第 1 版；其他版本不帶 |
| Q9-3 | 重新啟動 | 版本與同步版本全部保留 |
| Q9-4 | 成交後未選中版本 | 保留唯讀 |
| Q9-5 | 成交版本 | 就是成交當下的同步版本；訂單不加來源版本欄 |
| Q9-6 | 報價紀錄快照 | 含全部版本，依版本分組 |
| Q9-7 | 方案報價單檔案 | 每次下載產出一份，存在該版本下保留歷次；內容照公司報價單格式，不含運費、折扣與訂單才有的客戶條款 |
| Q9-8 | 執行者 | 版本操作比照編輯需求單；下載方案報價單限編輯層級 |
| Q9-9 | 版本名稱 | 選填 |
| Q9-10 | Slack | 開新版不發通知 |
| Q9-11 | 利潤率 | 版本上不另顯示 |
| Q9-12 | 活動紀錄 | 哪些版本動作要記，併入既有 QR-023 裁決 |
| Q10 | 矛盾呈報：收款項目規劃 L60 對 訂單成立確認 L48 | 訂單成立確認對；收款項目規劃範圍外句改指訂單成立確認的追加回簽副流程 |
| Q12 | 編輯報價版本、切換同步版本的操作粒度（落卡後矛盾呈報） | 依 [[規範 - 實體]] § 三併入 OP-QR-003 編輯需求單，活動列另列；建立報價版本、刪除報價版本、下載方案報價單維持獨立操作；不改規範 |
| Q13 | 新建報價版本從哪一版帶入成本與報價 | 業務選來源版本，預設同步版本 |
| Q14 | 矛盾呈報：[[付款發票邏輯]]、[[收款項目開立發票]] 範圍外寫重開、重簽報價單屬需求單議價中 | 照 Q10 改：重開、重簽報價單改指 [[訂單成立確認]] 追加回簽；重新評估報價留在需求單 |
| Q15 | 稽核第 1 輪：評估完成後新開版本出現無成本項目，進入議價、下載方案報價單、成交要不要擋 | 不擋，業務自己注意；系統只在送印務評估與評估完成檢查全部版本 |
| Q16 | 稽核第 1 輪：自來源版本帶入成本後改數量或規格，成本仍是舊值 | 全由業務判斷，系統不清空、不提醒 |
| Q17 | 稽核第 1 輪：刪除已給客戶的版本後查不到方案報價單 | 刪除報價版本改為軟刪除：版本連同印件項目與方案報價單保留可查，不再出現在版本清單；版次不重用（取代 P7 的硬刪語意） |
| Q18 | 稽核第 1 輪：版本最少筆數 | 不設最少筆數；有的訂單不會有印件，報價版本與需求單印件項目都可為零筆 |
| Q19 | 開新版本時參考附件 | 一併自來源版本帶入 |
| Q20 | 方案報價單版式 | 沿用公司報價單格式，不開 OQ |
| Q21 | 待評估成本期間開新版本或切換同步 | 系統不發通知，業務到 Slack 討論串手動提及評估印務主管（比照換評估印務主管） |
| Q22 | 稽核第 2 輪：已刪除報價版本能否還原 | 不還原；可當來源版本開新報價版本（用新版次）；已刪除版本不計入需求單的報價版本（評估檢查、報價紀錄、改選同步都不含） |
| Q23 | rebase 後矛盾：Q6 送印務評估檢查全部版本難易度，對上 QR-011 難易度選填全系統不擋 | 照 QR-011 不擋；Q6 只保留評估完成檢查全部版本成本 |
| Q11 | 售前無資料結構總覽卡 | 依 [[規範 - 資料結構總覽]]，結構性變更須先建；落卡時新建售前領域資料結構總覽（規範強制，非拍板題） |
