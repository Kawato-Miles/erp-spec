# 19：追蹤與交接的既有 skill 與外掛

Type: research
Status: resolved

## Question

跨需求的工作追蹤、工作階段之間的交接，有哪些現成的 skill、外掛或內建功能可用？
每一個的運作方式要讀完原始檔後寫清楚：存什麼檔、怎麼接續、怎麼避免同一件事記兩處、成熟度。
哪些適合「一位產品經理加 AI 代理、工作記在 repo 的 Markdown、Linear 只給開發」這個條件？

## Answer

全文在 `research/19-tracking-handoff-skills.md`，檔頭有主對話的抽查。

- 沒有任何現成方案同時滿足跨需求追蹤、工作階段交接與四項條件（記在 repo 的 Markdown、不用 Linear 管自己的工作、代理自行判斷、一人使用）。
- 最接近且已在用的是 matt `wayfinder` 的本機慣例（地圖加票、狀態行、阻擋行）。缺口：一個主題一張地圖，沒有跨主題總覽；沒有「等 Miles 看原型」「待驗收」等階段；啟動靠使用者下指令。
- matt `handoff` 把交接檔存在系統暫存目錄，重開機會清空，與「從 repo 檔案接續」衝突。可借用的是「只指向既有檔、不複製內容」的原則。
- 公開方案中較接近的：CCPM（以指令稿回答下一步，但預設終點是 GitHub 議題）、Backlog.md（一任務一檔，欄位偏工程任務）。主對話未對照原始檔。
- 資料庫型或需外部服務的方案（beads、Task Master 等）不符合條件。
- Claude Code 內建：壓縮後會從磁碟重新注入專案指令檔與自動記憶；任務清單工具的狀態不在 repo。
- 未查證 16 項。
