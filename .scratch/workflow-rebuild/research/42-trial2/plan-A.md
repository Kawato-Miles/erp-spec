### 需求：諮詢單（清單、明細、編輯、出口操作）

用完即丟的驗證草稿：資料放模組內的記憶體，不寫測試，不接側欄選單，直接用網址開頁。只在 `(prototype)/consultations/` 內新增檔案。

#### 1. 頁型

| 畫面 | 頁型 | 參照配方 | 網址 |
|------|------|---------|------|
| 諮詢單清單 | 資源列表頁（篩選、統計卡、表格），不放「新增」 | `docs/recipes/resource-page.recipe.md` | `/consultations` |
| 諮詢單明細 | 獨立詳情頁，從清單點單號進入 | `docs/recipes/detail-page.recipe.md` | `/consultations/detail?id=<諮詢單編號>` |
| 編輯諮詢單 | 明細頁右側抽屜 | 由製作者依元件目錄決定 | 同明細頁 |
| 取消諮詢、代派、改派 | 明細頁置中對話框 | 由製作者依元件目錄決定 | 同明細頁 |
| 完成諮詢、轉需求單 | 明細頁確認框 | 由製作者依元件目錄決定 | 同明細頁 |

辦公角色只支援桌機瀏覽器，不做手機寬度。

#### 2. 角色、可見範圍與操作

權限一律呼叫既有的 `(prototype)/_lib/access-control.js` 的 `canDo`，單據事實鍵為「諮詢單 諮詢人員」。

| 角色 | 看得到哪些諮詢單 | 可做的操作 |
|------|----------------|-----------|
| 諮詢 | 全公司（認領用） | 認領諮詢單（全公司未認領的單）、編輯諮詢單（全公司）、撰寫諮詢人員筆記、轉需求單、完成諮詢、取消諮詢（後四項限自己是諮詢人員的單） |
| 業務主管 | 全公司 | 代派諮詢人員、改派諮詢人員、撰寫諮詢人員筆記、取消諮詢（全公司） |
| Supervisor | 全公司 | 改派諮詢人員 |
| 其他角色 | 看不到 | 清單頁顯示「目前角色沒有檢視諮詢單的權限」，明細頁導回該角色預設頁 |

- 按鈕依角色與狀態判斷，不符合的直接隱藏，不做停用。
- 業務主管不能編輯諮詢單（需求原文寫可以，wiki 活動清單只列諮詢，見第三節第 1 項）。

#### 3. 操作與狀態條件

狀態名照 [[諮詢單狀態]]：待諮詢、完成諮詢、已轉需求單、已取消。後三者合稱終態。

| 操作 | 何時出現 | 執行後 |
|------|---------|-------|
| 認領諮詢單 | 待諮詢且沒有諮詢人員 | 諮詢人員寫入自己，狀態不變，留一筆活動紀錄 |
| 代派諮詢人員 | 待諮詢且沒有諮詢人員 | 對話框選一位諮詢人員，狀態不變，留活動紀錄（記操作者與被指派者） |
| 改派諮詢人員 | 待諮詢且已有諮詢人員 | 對話框選另一位諮詢人員，狀態不變，留活動紀錄 |
| 編輯諮詢單 | 待諮詢 | 抽屜修改外部表單欄位；每次儲存留一筆活動紀錄，列出改了哪些欄位 |
| 撰寫諮詢人員筆記 | 待諮詢且已有諮詢人員 | 筆記區就地切成輸入框，上限 2000 字；每次儲存留一筆活動紀錄 |
| 轉需求單 | 待諮詢且已有諮詢人員 | 確認框；狀態改為已轉需求單，關聯需求單寫入一個新編號 |
| 完成諮詢 | 待諮詢且已有諮詢人員 | 確認框，寫明「系統建立諮詢訂單，諮詢費 2,000 元轉入該訂單結算」；狀態改為完成諮詢，關聯諮詢訂單寫入新編號 |
| 取消諮詢 | 待諮詢 | 對話框必選取消理由分類，未選不可確認；寫明「系統建立已取消的諮詢訂單並辦理半額退費，退還 1,000 元」與「離開待諮詢後不可再取消」；狀態改為已取消，關聯諮詢訂單寫入新編號 |
| 檢視諮詢單 | 有檢視權的角色 | — |

終態後只剩檢視：上表除檢視外的操作全部隱藏，筆記鎖定。

#### 4. 諮詢單清單（`/consultations`）

使用者第一眼要看到：下一位預約客戶是誰、哪些單還沒人接。

| 項目 | 內容 |
|------|------|
| 列單位 | 一張諮詢單 |
| 欄位 | 諮詢單編號（連到明細）、狀態、預約時段（日期加星期加時間）、客戶（公司戶顯示公司抬頭，一般顯示聯絡人）、聯絡人、來訪人數、預計製作數量級距、諮詢人員（沒有時顯示「未認領」標籤）、操作 |
| 操作欄 | 諮詢角色在未認領的列顯示「認領」 |
| 統計卡 | 四個狀態各一張，顯示張數（wiki：按狀態分組即諮詢成效分布） |
| 篩選 | 一個搜尋框（諮詢單編號、客戶、聯絡人）；狀態下拉；諮詢人員下拉（含「未認領」選項） |
| 預設排序 | 待諮詢依預約時段由近到遠排在前，終態依預約時段由新到舊排在後 |
| 空狀態 | 有篩選條件而沒結果時顯示「沒有符合條件的諮詢單」；完全沒資料時顯示「目前沒有諮詢單」 |

#### 5. 諮詢單明細（`/consultations/detail?id=`）

使用者第一眼要看到：這張單停在哪個狀態、下一步能選哪個出口。

| 區塊 | 內容 |
|------|------|
| 標頭 | 返回鈕、標題「諮詢單 {編號}」、狀態標籤；右側操作鈕（認領諮詢單、編輯諮詢單、取消諮詢、轉需求單、完成諮詢）。主色鈕同時只有一顆：未認領時是「認領諮詢單」，已認領時是「完成諮詢」 |
| 終態結果提示 | 終態才出現。完成諮詢：寫關聯諮詢訂單；已轉需求單：寫關聯需求單（有收尾諮詢訂單時一併寫）；已取消：寫取消理由分類與關聯諮詢訂單 |
| 預約與客戶資料 | 客戶類型、公司統編、公司抬頭、聯絡人、市話與分機、手機、Email、預約日期、預約時間、來訪人數、預計製作數量級距、諮詢費發票意向 |
| 客戶原話與諮詢人員筆記 | 左右兩欄等寬。左欄客戶原話，標示唯讀；右欄諮詢人員筆記，右上「撰寫筆記」 |
| 受理與結果 | 諮詢單編號、狀態、諮詢人員（沒有時顯示「未認領」標籤；旁邊放「代派」「改派」文字鈕，依第三節條件，比照需求單詳情「接單業務」旁的改派鈕）、諮詢費、取消理由分類、關聯需求單、關聯諮詢訂單 |
| 活動紀錄 | 新到舊排列，一列為操作者、事件、時間 |

#### 6. 編輯諮詢單（抽屜）

| 欄位 | 形態 | 必填 |
|------|------|------|
| 客戶類型 | 單選：一般、公司戶 | 是 |
| 公司統編、公司抬頭 | 文字 | 公司戶時必填 |
| 聯絡人 | 文字 | 是 |
| 市話、分機 | 文字 | 否 |
| 手機 | 文字 | 是 |
| Email | 文字，檢查格式 | 是 |
| 預約日期 | 日期 | 是 |
| 預約時間 | 單選：10:30 至 18:30，每半小時一格 | 是 |
| 來訪人數 | 單選：1 至 4 | 是 |
| 預計製作數量級距 | 單選：1-100、101-300、301-500、501-1000、1000 以上 | 是 |

抽屜頂端提示：「修改會寫入活動紀錄。客戶原話、諮詢費發票意向建立後不可修改。」並唯讀列出這兩欄。

#### 7. mock 資料

- 四個狀態都要有資料；待諮詢至少三張（一張未認領、兩張分屬兩位諮詢人員）。
- 一張已轉需求單的單同時有關聯諮詢訂單（需求單流失後收尾，wiki 情境例子 CR-2026-0604）。
- 諮詢單編號照實體卡範例格式 `CR-2026-0604`；需求單 `QR-2026-0188`；訂單 `ORD-2026-0530`。
- 諮詢人員用 Prototype 名冊的諮詢角色：張惠雯、蘇怡君。

## 四、interface-design 與 erp 規範的不相容清單

衝突時一律照 erp 規範。

| 編號 | interface-design 的要求 | erp 規範 | 結果 |
|------|-----------------------|---------|------|
| 1 | 字型要有個性，不用系統或常見字型（Avoid：Default typography） | Designs.md §4 字族固定 Noto Sans TC | 照 erp；替換測試必然不通過 |
| 2 | 字級用比例階（1.25：11、14、16、18、22、28、44） | 字級固定 12、14、16、20、24，禁止自訂 font-size | 照 erp |
| 3 | 色票取自產品世界（紙樣米白、牛皮紙褐、印章紅） | 禁止手寫 hex、禁止暖米色；主色只有藍 | 照 erp；色彩世界只留在探索紀錄 |
| 4 | token 名稱要能聯想到產品（`--ink`、`--parchment`） | token 由 Figma 匯出，名稱固定（`neutral`、`accent`） | 照 erp；token 測試必然不通過 |
| 5 | 邊框用低透明度 rgba，或用多層陰影取代邊框 | 容器用 `neutral[200]` 實線 1px 邊框（TableBlock、BorderBlock） | 照 erp |
| 6 | 表面層級自建數字階（每階差幾個百分點亮度） | 版面底與容器底兩層固定 | 照 erp |
| 7 | 輸入框比周圍略深 | AntD 輸入框白底加邊框，由主題統一注入 | 照 erp |
| 8 | 點擊區至少 44×44（最低 40） | 共用 Button 預設 small 尺寸，AntD 預設控制項高 32 | 照 erp |
| 9 | 自訂動畫曲線、按下時縮放 0.97 | 動態由 AntD 內建，改要動共用樣式 | 照 erp |
| 10 | 巢狀圓角同心（外圓角＝內圓角加內距） | 圓角固定 6 與 12 | 照 erp |
| 11 | 根層加字體平滑、標題加 `text-wrap: balance` | 根層 layout 屬 app 層檔，本任務不准動 | 未做 |
| 12 | 識別元素要「只屬於這個產品」，避免同尺寸同間距的卡片排列 | 核心原則「套既有配方加真元件，不自由發揮、不自創 UI」；分區一律 PanelBlock | 識別元素收斂為版面結構（排序、並排），不做新元件 |
| 13 | 提議方向後詢問使用者確認 | prototype-from-prompt 第 1 步也要求一次問完 | 子代理受測無法詢問；兩邊都未問，假設列在第三節 |
| 14 | 交付前在瀏覽器或截圖實看（桌機與手機寬度） | 本任務不准啟動伺服器；辦公角色只做桌機 | 未實看 |
| 15 | 決定存進專案 `.interface-design/system.md` | 本任務只准在 `consultations/` 新增檔案 | 改存 `plan-A-files/system.md` |

相容、不衝突的項目：文字四階（erp 有 colorText 四階）、間距用 8 的倍數、一個主色、狀態色只表示狀態、先用既有元件與原生元件（方法的 Use What Exists 與 erp §6.1 一致）。
