## 步驟 2：意圖優先（Intent First）

| 問題 | 回答 |
|------|------|
| 這個人是誰 | 諮詢人員張惠雯。坐在辦公桌前，兩場視訊諮詢之間。五分鐘前剛收到客戶付款通知或剛結束一場諮詢；五分鐘後要接下一位預約客戶。另一位是業務主管林雅婷，每天早上掃一遍哪些單還沒人接、哪些單談完卻沒收尾 |
| 要完成什麼（動詞） | 諮詢人員：認領今天的預約、記下談話重點、談完當下選出口收尾。業務主管：找出沒人接的單並代派、處理客戶反悔的取消 |
| 該有什麼感覺 | 像印刷門市櫃台的預約簿：依時段排、一眼看出下一位是誰、哪一格還空著。冷靜、有秩序、不催促。資訊密度中等，介於報表與表單之間 |

意圖要貫徹到全系統（Intent must be systemic）：清單依預約時段排序、明細頁把「客戶說了什麼」與「我們記了什麼」並排，都是「預約簿」意圖的結構表現。顏色與字型無法表現意圖，原因見不相容清單。

## 步驟 3：產品領域探索（Product Domain Exploration）

### 領域（Domain，至少 5 項）

1. 預約時段：10:30 至 18:30，半小時一格
2. 來訪人數：1 至 4 人，決定要排哪間會議室
3. 客戶原話：客戶自己寫的需求，唯讀，可追溯（ISO 9001）
4. 諮詢費預收：先付 2,000 元才進系統，錢要掛在一張單上
5. 三個出口：轉需求單做大貨、完成諮詢結案、諮詢前取消半額退費
6. 認領：諮詢人員依專長自己挑單
7. 紙樣冊與打樣：諮詢桌上真正被翻閱的東西
8. 製作數量級距：客戶預估的量級，決定後續報價方向

### 色彩世界（Color world，至少 5 項）

1. 紙樣冊的白與米白
2. 雪銅紙的冷白光澤
3. 牛皮紙信封的褐色
4. 印刷四色（青、洋紅、黃、黑）的色票
5. 收據上的紅色印章
6. 會議室木桌

### 識別元素（Signature）

「兩種聲音並排」：明細頁中段把「客戶原話」（鎖頭、唯讀）與「諮詢人員筆記」（可撰寫）左右並排。這只會出現在諮詢單：客戶指示要可追溯、內部紀錄另起一欄，是這張單據獨有的商業規則（[[諮詢單]] 欄位表客戶原話列）。

輔助識別：清單依預約時段排序，未認領的單在諮詢人員欄顯示「未認領」標籤，主管掃一眼就找得到空格。

### 預設做法（Defaults，3 項以上，視覺與結構都列）

| 預設做法 | 改成 | 理由 |
|---------|------|------|
| 清單依建立時間由新到舊排 | 待諮詢的單依預約時段由近到遠排在前面，終態的單排在後面 | 諮詢人員關心的是下一位客戶何時到，不是單據何時建立 |
| 明細頁把所有欄位平鋪成一張欄位表 | 分「預約與客戶資料」「客戶原話與筆記對照」「受理與結果」「活動紀錄」四區 | 客戶原話與筆記是兩種聲音，平鋪會讓唯讀與可寫的欄位混在一起 |
| 編輯抽屜開放全部欄位 | 只開放可修改的欄位；客戶原話、諮詢費、發票意向、編號只顯示不給改 | wiki 欄位表明定這些欄位建立後不可修改 |
| 取消用刪除的紅色二次確認 | 取消開對話框，必選取消理由分類，並寫明半額退費的後果 | 取消不是刪除：單據仍留存、會建諮詢訂單並退費 |

### 去除產品名測試（The test）

把「諮詢單」三字拿掉，看到「預約時段排序、客戶原話鎖頭、三個出口按鈕、諮詢費 2,000 元」，仍可判斷這是預約制付費諮詢的受理單。通過。

## 步驟 4：提議方向並詢問（Suggest + Ask）

```
Domain:     預約時段、來訪人數、客戶原話、諮詢費預收、三個出口、認領、紙樣冊、數量級距
Color world:紙樣冊米白、雪銅冷白、牛皮紙褐、印刷四色色票、收據紅章、會議室木桌
Signature:  客戶原話（唯讀）與諮詢人員筆記左右並排的對照區
Rejecting:  依建立時間排序 → 依預約時段排序；欄位平鋪 → 四區分段；全欄位可編輯 → 只開放可修改欄位；紅色刪除確認 → 必選理由的取消對話框
Direction:  預約簿式的受理畫面。結構表現時段與出口，顏色與字型沿用 erp 規範
```

方法要求此時問「這個方向對嗎」。本次是子代理受測，無法詢問 PM。方向依上表定案，未經確認，列入 plan-A.md 未定事項。

## 步驟 7：每個元件動手前的檢查點（Before Writing Each Component）

### 清單頁

```
Intent:     諮詢人員找下一位預約客戶並認領；主管找沒人接的單
Hierarchy:  焦點是「待諮詢」的列。贏的方式：排在最前、狀態標籤用主色系、未認領顯示標籤。統計卡只當摘要，不當焦點
Palette:    erp 中性灰加單一藍主色；狀態色只用在狀態標籤（待諮詢藍、完成諮詢綠、已轉需求單紫點綴、已取消灰）
Depth:      erp 既有的實線邊框容器（TableBlock、BorderBlock），不另加陰影
Surfaces:   erp 版面底灰、容器白，兩層
Typography: Noto Sans TC；用 AntD 預設 14 字級，層次靠字重與文字四階灰
Spacing:    erp 間距 8、12、16、24
```

### 明細頁

```
Intent:     諮詢人員談完當下選出口；主管處理取消與改派
Hierarchy:  焦點是標頭右側的主色鈕，同時只有一顆：已認領時是「完成諮詢」，未認領時是「認領諮詢單」。次要出口用次要樣式，取消用危險樣式
Palette:    同清單；終態結果提示依狀態用提示框的 success／info／warning 型別
Depth:      同清單
Surfaces:   同清單
Typography: 同清單；區塊標題沿用 PanelBlock 內建樣式
Spacing:    區塊間 16，區塊內 24（沿用 PanelBlock）
```

### 編輯抽屜、取消對話框、完成確認框

```
Intent:     修正客戶填錯的資料；取消時留下理由；完成時看清楚錢的去處
Hierarchy:  抽屜焦點是可修改的欄位；對話框焦點是必選的取消理由與後果說明
Palette:    提示框用 info（說明）與 warning（不可逆）
Depth:      AntD 抽屜與對話框內建
Surfaces:   同上
Typography: 同上
Spacing:    表單垂直排列，沿用 AntD Form 預設
```

## 步驟 8：交付前的檢查（The checks）

| 檢查 | 結果 |
|------|------|
| 替換測試（Swap test） | 字型換成常見字型沒有差別：字型由 erp 規範固定，這一項必然不通過，屬不相容項。版型換成通用範本：清單的預約時段排序與未認領標籤、明細的對照區會消失，這兩處是做過決定的地方 |
| 瞇眼測試（Squint test） | 未在瀏覽器實看（不准啟動伺服器）。依程式結構推估：標頭一顆主色鈕最突出，其餘為白底灰框，不會有刺眼元素 |
| 識別元素測試（Signature test，指出五處） | 1 清單「預約時段」欄排第二、為預設排序依據；2 清單諮詢人員欄的「未認領」標籤；3 明細對照區左欄的鎖頭與唯讀說明；4 明細對照區右欄的「撰寫筆記」與字數上限；5 取消對話框的半額退費說明與必選理由 |
| token 測試（Token test） | token 名稱是 `theme.colors.neutral[500]` 這類通用名，聽不出產品。erp 規範禁止自訂 token，必然不通過，屬不相容項 |
