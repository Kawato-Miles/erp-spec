# 急件新定義 grill 拍板紀錄（2026-10-27）

起因：
- 現行 wiki：線下單由業務填「未扣急件內部完成日」，系統扣急件凍結天數得出印件內部完成日；線上單沒有起算規則；訂單層沒有急件標注。
- Miles 在 2026-10-27 的對話中逐題拍板新定義：線上與線下拆開、線下急件不影響日期、線上才扣天數，並新增一個從訂單貫穿到生產任務的急件標注。
- 同案裁決 [[ORD-059-業務輸入端改填未扣急件預計交期]]：選方案 B，但不扣急件。

本檔只記拍板結果，供 proposal、design、plan-audit、wiki-amend 承接。
本檔整理自起案 session 的任務書；Miles 已逐題拍板，本次不重新 grill。拍板當時未列出具名對照選項的題目，「對照選項」欄寫「拍板時未列」，不補寫事後推測的選項。
變動性質：結構性變更。理由：急件標注跨訂單、印件、工單、生產任務四個實體；線上與線下日期起算分流；ORD-059 改變日期輸入端。稽核走 rubric 加雙盲對抗式情境推演。

## 五、已知事實（不需拍板）

- 現行 [[印件]] 的「印件預計交期」是系統建議值（印件內部完成日的下一個工作天）；新定義反轉為業務輸入值，印件內部完成日由它往前減 1 個工作天。兩者互為反算，工作天算法不變。
- 北極星「印件準時完工率」比對完工日與印件內部完成日，口徑不變；內部完成日的來源改變。
