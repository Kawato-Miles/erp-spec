### 三、線上單日期原則與急件欄位（欄位實作交 EC 整合另案）

急件欄位：

| 欄位 | 來源 |
|---|---|
| 是否急件 | 沿用 EC 對該項商品的急件判定結果，ERP 不另訂規則（grill.md R5-2） |
| 購買的急件選項 | 接收 EC 訂單時存下客戶所選急件選項的名稱與增減天數；之後中台改主檔或停用該選項，都不影響已存的值 |

日期原則：

| 項目 | 算式 |
|---|---|
| 整單製作天數 | 取各印件「製作天數 ＋ 購買的急件選項的增減天數」的最大值；逐印件先算再取最大，正負都算 |
| 審稿前預計出貨日 | 下單（付款）日 ＋ 整單製作天數，系統推算 |
| 審稿後預計出貨日 | 最後一件印件首次進入「已確認可製作」那天 ＋ 整單製作天數，系統推算；起算在訂單層，所有印件同一天交 |

依賴聲明：本節三個算式的輸入欄（各印件製作天數、下單（付款）日、首次進入已確認可製作時點）正本尚無來源欄；製作天數與增減天數的單位、下限、未購買急件選項的印件怎麼算、整單製作天數是否排除已棄用印件、「最後一件印件」範圍與寫入時點尚未定。這些事項拍板前（延後，見 grill.md），本節日期行為不得寫入 specs；本節只定原則。線上單整合進 ERP 後可否編輯也延後（見 grill.md）。

驗算（grill G22 例，依中台正負號）：甲 7 天、購買「三天急件」（增減 −3）→ 4；乙 10 天、購買「延後 2 天」（增減 ＋2）→ 12；整單 12 天。甲是急件但不在瓶頸，整單天數仍由乙決定，交期不提早。

整單製作天數、審稿前與審稿後預計出貨日只有線上單有；線下單與諮詢訂單沒有這三欄（諮詢訂單的依據見 [[訂單狀態]]）。

### 四、急件標注

判準：印件的「是否急件」為是，且印件的印製維度不是「已棄用」。線上單與線下單同一條判準；線上單的「購買的急件選項」不參與判準。

| 層級 | 推算 | 顯示位置 |
|---|---|---|
| 印件 | 本節判準 | 訂單詳情的印件列；審稿待審清單（判準改為本節判準） |
| 訂單 | 任一有效印件被標注（已棄用印件不算） | 訂單列表（新增「急件」篩選條件，不自動排序）；訂單詳情 |
| 工單 | 所屬印件被標注 | 工單列表；工單詳情；工作印製傳單（拍板用語；[[工單]] 卡的系統單據名為工單單據） |
| 生產任務 | 所屬工單的印件被標注 | 生產任務列表；派工畫面 |
| 其他單據 | 單頭不顯示；子列表中代表訂單、印件、工單、生產任務的列帶出標注 | 轉交單、出貨單的子列；需求單見 ④ H7 |

標注一律即時推算，不另存欄位。「是否急件」或印製維度改動後，所有位置下一次讀取即更新。

### 七、業界對照與否決方案

業界對照：
- 生產工單帶優先權旗標，優先權只用於排程排序與標示，不改承諾日：[ISA-95 生產請求的優先權（priority）屬性](https://en.wikipedia.org/wiki/ANSI/ISA-95)。本案線下單急件只標示、不改日期，與此一致。
- 交期承諾由銷售端對客戶承諾，生產端以承諾日倒推內部目標：[可承諾量與承諾交期（available to promise）](https://en.wikipedia.org/wiki/Available_to_promise)。本案線下單由業務填預計交期，系統倒推內部完成日，與此一致。

| 線下單日期鏈 | 印件預計交期 ＝ 印件內部完成日 ＋ 1 個工作天；是否急件對日期的貢獻為 0 | 業務把預計交期改晚 → 內部完成日同步變晚、非終態工單副本跟著變晚 | 業務把預計交期改早 → 內部完成日同步變早；工單預排完成日若晚於新內部完成日，工單標排程超期（現行機制） |
| 線上單整單製作天數 | 整單 ＝ max（製作天數ᵢ ＋ 購買的急件選項增減天數ᵢ） | 印件購買延後型（正值）或新增更長製作天數 → 整單變長，出貨日變晚 | 瓶頸印件購買提早型（負值）→ 整單變短；非瓶頸印件購買提早型 → 不變 |
| 急件標注 | 訂單被標注 ⇔ 有效印件中「是否急件為是」者 ≥ 1 | 印件勾選是否急件、或新增已勾選的印件 → 標注出現 | 印件取消勾選、或已勾選的印件棄用 → 標注消失 |
| 工單日期副本 | 非終態工單副本 ＝ 印件現值；終態工單副本 ＝ 完成當下的值 | 印件改動 → 非終態副本跟著動；工單離開終態（補做重開）→ 副本維持舊值，等下一次印件改動才同步（H15） | 工單進終態 → 副本凍結，之後印件改動不回寫 |
| 線下單缺預計交期的有效印件數 | 訂單離開草稿後，缺預計交期的有效印件數 ＝ 0；草稿期間 ≥ 0 | 草稿期間新增印件未填、需求單轉入空值 → 增加；離開草稿後的新增與修改存檔必填（R6-5、R6-9），沒有增加路徑 | 業務補填 → 減少；印件棄用 → 退出計數；送審檢查要求降到 0 才能離開草稿（R6-4） |
| 購買的急件選項副本 | 印件副本 ＝ 接收 EC 訂單當下客戶所選選項的名稱與增減天數；主檔事後改動流入量為 0 | 不適用：本案沒有定義接收後的寫入路徑（可否編輯延後，H29） | 不適用：同左；印件棄用時副本保留；整單製作天數是否排除已棄用印件延後（H18） |

### 驗算

例 1（線下，一般日）：預計交期 2026-10-13（二）→ 內部完成日 2026-10-12（一）。業務勾選是否急件：兩個日期不變，交期欄旁出現常駐提示，標注出現，訂單活動紀錄多一筆。之後再開啟這件印件，是否急件仍為勾起狀態，提示仍常駐顯示（R5-13）。

例 2（線下，跨週末）：預計交期 2026-10-19（一）→ 往前減 1 個工作天，10/18、10/17 非工作天跳過 → 內部完成日 2026-10-16（五）。

例 3（線下，預計交期落週六）：預計交期 2026-10-17（六）→ 內部完成日 2026-10-16（五）。全部交完日取內部完成時間加 1 個工作天 → 2026-10-19（一），晚於預計交期（見 H2）。

例 4（線下，取消勾選）：例 1 的印件取消勾選 → 日期不變、是否急件為否所以不出現提示、標注消失；若訂單沒有其他已勾選的有效印件，訂單標注也消失。

例 5（線下，需求單轉訂單）：需求單印件項目勾選是否急件 → 需求單交期欄旁出現常駐提示（R5-10）；轉訂單後印件是否急件為是，印件編輯畫面的交期欄旁常駐顯示提示（R5-9、R5-13）；業務之後取消勾選，需求單的值不變。

例 6（線上，購買選項副本）：客戶購買「三天急件」，接收時印件存名稱「三天急件」、增減天數 −3，顯示「提早 3 天」。中台之後把主檔的三天急件改為 −4：印件仍為 −3。

例 7（線下，送審檢查）：訂單草稿有甲、乙、丙三件印件。甲 2026-11-10、乙空、丙空但已棄用。缺預計交期的有效印件數＝1（乙），業務送審被擋，系統列出乙。業務補填乙 2026-11-12 → 數量＝0，送審成功。進入待業務主管審核後業務加開丁：丁不預填，未填日期不能存檔；填 2026-11-20 後存檔，數量仍為 0。
