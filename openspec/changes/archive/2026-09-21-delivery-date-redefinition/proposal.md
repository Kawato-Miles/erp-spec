# 交期鏈日期定義改版

## Why

### Background

### Problem Statement

wiki 已改，OpenSpec 還停在 2026-09-11 那一版的算式方向與用詞，兩邊對不起來的有下列各處：

| 模組 | 不一致之處 |
|---|---|
| order-management | 算式方向相反：現行條文由業務填的預計出貨日減一天推出內部完成日，拍板改為業務壓未扣急件內部完成日、扣急件天數得印件內部完成日、再推印件預計交期；日期加減仍寫曆日；訂單層沒有任何衍生交期日期，也沒有客戶指定收件日；訂單列表明文不顯示、不篩選交期 |
| work-order | 工單日期仍叫預計完工日與實際完工日；任務日期仍叫預計完成日；排程檢核只有任務層軟提示，送審與核可沒有把關條件；工單沒有準時判定；紙本表頭與摘要卡的欄名未對齊公司用語 |
| production-execution 相關（生產任務） | 任務進入已完成的時間沒有欄位承接，準時率與逾期標示無事實來源 |
| shipment | 沒有實際出貨日的定義，出貨準時無從判定；出貨單的預計出貨日與印件層的日期同名易混 |
| production-overview | 待排區與五指標的日期欄名沿用舊寫法 |
| prepress-review | 待審清單排序鍵的語意跟著印件內部完成日改義，訂單母列的取值未寫明 |
| quote-request | 需求單印件項目仍填預計出貨日，未改為業務壓的未扣急件內部完成日 |

另有幾件事系統現在做不到：印務把任務排到超過內部完成日仍送得出審核，主管核可後才發現趕不上；業務在訂單層看不到「這張單最近一批哪天交、全部何時交完」；客戶說好的收件日沒有地方記。

## What Changes

### 命名對照

| 舊名（所在層級） | 新名 | 說明 |
|---|---|---|
| 印件「預計出貨日」 | 印件預計交期 | 同時改義：由業務手填錨點改為系統依印件內部完成日推得的建議值，業務可改 |
| 印件「內部完成日」 | 印件內部完成日 | 名稱不動、算式反轉：由未扣急件內部完成日扣急件凍結天數推得 |
| 工單「預計完工日」 | 工單預排完成日 | 取數不變（旗下未作廢生產任務的任務預計完成日最大值）|
| 工單「實際完工日」 | 工單實際完成日 | 取工單進入「已完成」的時間 |
| 生產任務「預計完成日」 | 任務預計完成日 | 取數不變（印務手填、系統不預填）|
| 出貨單「預計出貨日」 | 出貨單預計出貨日 | 只改欄名，出貨計畫用途不變 |
| 訂單「審稿前預計出貨日」「審稿後預計出貨日」 | 不改名 | EC 整合另案 |

### 行為變更

- **印件層交期鏈反轉**：業務在需求單印件項目或訂單印件填「未扣急件內部完成日」（選填、可清空）；印件內部完成日 ＝ 未扣急件內部完成日往前扣急件選項凍結天數（工作天），唯讀衍生、空值顯示破折號、畫面註明扣了幾個工作天；印件預計交期 ＝ 印件內部完成日的下一個工作天，系統給建議值、業務可改但不得早於印件內部完成日，內部完成日一改即重算覆蓋並提示。
- **交期欄的可改條件放寬**：訂單非終態且印製維度非「已棄用」即可改，印製維度進入「已送達」後仍可改；每次改動留異動紀錄，並同步旗下非終態工單的印件內部完成日與印件預計交期，終態工單不回寫。
- **工作天**：整條交期鏈的加減天數與逾期天數一律以工作天計，算法引 wiki [工作天規則](../../../memory/Sens_wiki/wiki/erp/04-business-logic/營運規則/訂單到交付/工作天規則.md)；維護表由後端提供，ERP 不開維護介面。**BREAKING**：取代現行條文的曆日計。
- **訂單層衍生日期**：訂單內部完成時間（有效印件的印件內部完成日取最晚）、訂單預計交貨日期（未出貨有效印件的印件預計交期取最早，只依出貨事實滾動）、全部交完日（訂單內部完成時間的下一個工作天）；皆為衍生不存欄。訂單預計交貨日期上訂單列表並可排序篩選。**BREAKING**：取代現行「訂單列表不顯示、不篩選交期」的條文。
- **客戶指定收件日**：訂單層選填欄，業務或諮詢維護，不參與任何計算；填寫或改動時早於旗下印件最晚的印件預計交期即黃色提醒，不擋存檔。
- **訂單逾期標示**：任一印件系統日期超過印件預計交期且未出貨，該印件標逾期、訂單標部分延遲；系統日期超過全部交完日仍有印件未出貨，訂單標整單逾期。純標示、不通知。
- **工單排程硬擋**：送審與核可兩個時點，工單預排完成日晚於印件內部完成日即擋下，畫面列出預排日、內部完成日與相差的工作天數；印件內部完成日為空時不比對、不擋。**BREAKING**：取代「排到超期系統只出提示、接受超期由印務自行決定」。
- **核可後的排程超期標示**：已核可工單的預排完成日晚於印件內部完成日時標「排程超期」，不擋、不通知。
- **任務層軟提示維持**：任務預計完成日晚於所屬工單的印件內部完成日時該筆即時標示，不擋存檔。
- **工單與任務的完成事實**：工單實際完成日取進入「已完成」的時間（重開後再完成取末次）；任務實際完成日取進入「已完成」的時間（涵蓋報工達標自動完成與生管手動完成）；任務今日到期與逾期 N 個工作天標示，終態不標。
- **工單準時**：工單實際完成日不晚於印件內部完成日即準時，否則標逾期 N 個工作天；純標示。
- **實際出貨日與出貨準時**：實際出貨日 ＝ 出貨單首次進入已出貨狀態群（運送中、已送達）的日期，不分出貨方式；印件以首張出貨單的實際出貨日比對印件預計交期判定準時，計入印件準時交貨率。**BREAKING**：取代以送達日為準時錨點的口徑。
- **需求單**：印件項目填未扣急件內部完成日、無急件選項欄（急件視為一般件），並顯示推得的印件內部完成日與印件預計交期；成交轉訂單帶入未扣急件內部完成日原值。
- **運輸天數**：生產任務的預留欄，預設 0、暫不啟用、不參與工單預排完成日，本 change 不實作介面。

### 範圍外（Miles 明示，不在本 change 處理）

起算日、商品工作天與 EC 官網單帶入規則；到期與逾期的通知推送；交期檢核列；運輸天數啟用；訂單「審稿前預計出貨日」「審稿後預計出貨日」改名；公司文件的任務準時率指標。

### 與公司文件的明示差異

- 工單完成判定不以品檢未過阻擋（品檢在印件層、於工單完成後進行），回頭向公司確認。
- 訂單預計交貨日期只依出貨事實滾動，日期已過而未出貨的印件仍停在欄內並標逾期，不因系統日期超過而跳到下一筆。

## Capabilities

### New Capabilities

無。

### Modified Capabilities

- order-management：印件交期鏈反轉與工作天算法、交期欄變更的重算與同步、訂單層衍生日期與逾期標示、客戶指定收件日、訂單列表顯示與篩選訂單預計交貨日期。
- work-order：工單與任務的日期改名、送審與核可的排程硬擋、核可後排程超期標示、工單準時判定、任務實際完成日與到期逾期標示、紙本表頭與待審核列表欄名。
- quote-request：需求單印件項目改填未扣急件內部完成日並顯示推得值、成交轉訂單帶入原值。
- shipment：實際出貨日定義與出貨準時判定、出貨單預計出貨日改名。
- production-overview：待排區欄名對齊、五指標的漏單率改取任務預計完成日。
- prepress-review：待審清單排序鍵語意對齊、訂單母列取印件預計交期。
