## Context

本變更同步場內轉交改版的行為規格。商業規則已落 wiki（正本卡見 proposal § Background），設計已過 plan-audit 三輪、Miles 拍板。Prototype 已實作，本變更不改 Prototype。

現況與改版後的差異：

| 項目 | 現況 spec | 改版後 |
|------|----------|--------|
| 送錯站、已點收 | 建回運單，點收時減記誤收站到料量並解除原單佔用 | 現場溝通後廠務直接搬，系統不另開單 |
| 目的站點修改時機 | 隨製程規劃，限草稿或重新確認製程 | 任務轉已作廢、報廢前皆可改，含已完成 |
| 目的站點修改者 | 印務 | 負責印務、編輯（代理）成員；製程核可後另加印務主管 |
| 改站後已建轉交單 | 不適用 | 不動；作廢重開沿用原單目的地；待搬視圖新建單取新站 |
| 需轉交前置（場內）的到料量 | 目的地為本任務所在站點的已點收量；回運點收時減記 | 前置已點收明細總和，不比對站點，只增不減 |
| 建單時的目的地 | 生管在待搬視圖選 | 取自來源生產任務的目的站點 |

約束：

- spec 不寫欄位表與狀態列舉。轉交單狀態不變，[轉交單狀態](../../../memory/Sens_wiki/wiki/erp/06-state-machines/轉交單狀態.md) 已刪回運分支。
- 角色權責依 [生管](../../../memory/Sens_wiki/wiki/erp/03-roles/生管.md)、[印務](../../../memory/Sens_wiki/wiki/erp/03-roles/印務.md)、[印務主管](../../../memory/Sens_wiki/wiki/erp/03-roles/印務主管.md)。
- 到料量規則依 [工序相依性規則](../../../memory/Sens_wiki/wiki/erp/04-business-logic/營運規則/訂單到交付/工序相依性規則.md)。

## Goals / Non-Goals

### Goals

- production-execution spec 刪除回運單的全部行為。
- 新增目的站點的修改規則，並與需轉交標記的鎖定拆開。
- 場內前置的到料量改為不比對站點。
- work-order 製程規劃的修改時機加目的站點例外。

### Non-Goals

- 外發前置的到料量口徑：另案處理，見 PT-063。
- 計畫設備與任務預計完成日在生產中可否修改：另案處理，見 PT-062。
- 來源任務報廢後重建的轉交單點不了收：另案處理，見 PT-064。
- 主管在生產管理唯讀（D13）：spec 的代行角色只列印務與印務主管，沒有列主管，不需同步。Prototype 已於 b03f7566 實作。
- 改站後通知廠務或生管：不新增通知，印務於系統外告知生管。

## Decisions

| 決策 | 選擇 | 替代方案與否決理由 |
|------|------|------------------|
| 改站後已建的轉交單 | 不動，改站只影響之後新建的單 | 系統把未點收的單目的地一起改：否決。已送達的貨實際在舊站，改目的地後點收權限移到新站、新站手上沒貨 |
| 作廢重開的目的地 | 沿用原單目的地 | 改取任務當下的目的站點：否決。重開多半發生在貨已在路上或已到站，換目的地會讓帳上去處與貨脫鉤；要改去處就從待搬視圖重新建單 |
| 回運單條文 | 移除舊 Requirement「轉交單改單、更正與回運」，新增「轉交單改單與更正」 | 保留原標題只改內文：否決。標題含「回運」會誤導讀者 |
| 目的站點規則的位置 | production-execution 新增獨立 Requirement，work-order 製程規劃只寫例外並引用 | 寫進需轉交標記的 Requirement：否決。兩欄的鎖定條件不同，合寫會讓讀者以為一起鎖 |
| 外發前置的到料量 | 只把不比對站點限定在場內前置；外發前置沿用原條文 | 一體適用：否決。PT-063 拍板前不得進 propose |
| 「生管不改目的站點」的主詞 | 明寫「本條的生管專指生管角色」 | 沿用操作角色 Requirement 的涵蓋讀法：否決。那樣印務主管在核可前也能改，與拍板不符 |

## Risks / Trade-offs

- [改站前在舊站點收的量照樣計入下游到料量，實體位置由現場修正] → 已知代價。系統數量守恆，實體位置不追蹤。
- [一個前置接多個下游時，每個下游各自拿到前置的全部已點收量] → 工序相依性規則既有性質，本變更不改。
- [Prototype 對外發前置也一體套用不比對站點，與 spec 的外發條文不同] → 已知落差，PT-063 拍板後同步。現況 Prototype 外發前置比對下游計畫設備，站點不同時永不放行，屬既存缺陷。
- [既有回運單資料] → 後端交付項處理資料遷移。
