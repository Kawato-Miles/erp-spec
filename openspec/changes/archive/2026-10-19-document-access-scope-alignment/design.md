## Goals / Non-Goals

### Goals

- Prototype 的入口、列表範圍、詳情頁進入、操作鈕，全部依活動清單判定。
- 29 筆測試衝突逐筆改成活動清單的答案；未覆蓋的活動類別各補至少一則測試。
- 介面用詞對齊 wiki。

### Non-Goals

- 後端權限：由 AFT-16、ORD-058、QR-009、QR-015 追蹤。
- 狀態時機（哪個狀態可以做）：維持現況；只有改派（V2-037）與目的站點（V2-063）在本變更修正。
- 欄位與頁籤層級可見性（XM-016）。
- 諮詢單模組、外包與中國線、主檔維護與配方檢視（見 proposal § 範圍外）。
- Linear 更正：Prototype 完成後依 linear-delivery 另案。

## Decisions

### 一、根因

落差盤點的五列根因可歸為三類：

| 根因 | 落差盤點對應 | 使用者看到的結果 |
|------|------------|----------------|
| 只看狀態、不看人 | 訂單詳情各頁籤的編輯入口只看訂單是否終態 | 會計、檢視層級分享成員也能改訂單、帳務、異動、售後 |
| 角色名單寫死在各處 | 動作改用業務（或加諮詢）名單；工單動作先判是否為印務；側欄另一份名單 | 全公司協助角色做不了；任一業務按得到別人的單；有權的人沒入口 |
| 分享與範圍資料不完整 | 分享候選只有業務或印務；詳情頁網址不判範圍 | 活動清單的被分享列無從發生；直連就看得到內容 |

### 二、修法方向：集中一處判斷，依活動表、依據欄位判範圍

| 決策 | 內容 | 替代方案 | 不採的理由 |
|------|------|---------|-----------|
| D1 集中判斷 | 每個模組的權限判斷都改成查同一份「活動表」資料：輸入使用者、單據、操作，輸出可不可以 | 各模組沿用自己的判斷函式，逐條補角色 | 89 筆落差正是各寫一份造成；補完下次 wiki 改又會脫鉤 |
| D2 活動表的來源 | Prototype 內放一份活動表資料，欄位對應活動清單卡的執行角色、範圍、依據欄位、操作；由 wiki 活動清單卡逐列轉錄 | 直接讀 wiki 檔 | Prototype 不能讀 Sens repo；轉錄後以測試核對 |
| D3 範圍判斷 | 依據欄位決定比對哪張單的哪一欄：自己負責比對人員欄（例：訂單接單業務、工單負責人、報工紀錄報工人員）；被分享比對分享成員與層級；所屬產線比對產線欄；全公司不比對 | 依角色硬判範圍 | 依據欄位已寫明看哪張單哪一欄，照著比才不會漏延伸（如售後服務單看訂單） |
| D4 未列即不可做 | 查不到任何活動列就回「不可以」；介面不顯示，系統層擋下 | 預設可以、逐條封鎖 | 與受控清單規則相反，會再長出多給權限 |
| D5 側欄與直連 | 側欄入口、列表範圍、詳情頁進入都用 D1 的同一份判斷；直連無檢視組合時導回預設頁 | 側欄另維護名單 | 側欄與模組頁兩份名單是現行落差來源 |
| D6 分享候選 | 分享候選依活動列判斷有無模組權限：三種單據各只列對該單據至少有一列不靠分享的活動的角色；排除規則維持現況，待 QR-020。規則正本見 wiki〈受控清單〉§ 範圍用詞（G66） | 甲：取全體人員名冊；乙：照舊只列業務或印務 | 甲：後端依活動列設權限，分享給沒有模組權限的人，對方拿不到入口，例如會計、生管被分享訂單；乙：活動清單的被分享列無從發生 |
| D7 mock 人員名冊 | 各模組 mock 的人員名冊統一取 `sessionStore` 的名冊，角色標示一致 | 各模組各自一份 | 需求單 mock 把業務主管標成印務主管，與 sessionStore 不一致（V2-020） |
| D8 大型既有 Requirement | 權限句散在大型既有 Requirement 時，本變更以 ADDED Requirement 承載新承諾，舊句列入 tasks 的 archive 清理清單 | 全部改 MODIFIED | 依 config 規則，巨大且多數不變的 Requirement 可 ADDED 局部修訂、archive 後手動清理；MODIFIED 須全段重寫並補情境卡，工作量與風險不成比例 |

### 三、分批順序（依單據群）

每批固定順序：先改 MOCK-DATA-CHAIN 與 mock，再改測試（應先紅），再改 Prototype（轉綠），最後跑 smoke 與影響章並提交。

| 批次 | 單據群 | 落差編號 | 理由 |
|------|------|---------|------|
| 第一批 | 共用判斷、側欄、直連、分享候選、用詞 | V2-001 至 V2-011、V2-020、V2-036、V2-068 | 之後各批都用同一份判斷；先建好，後面只改各模組呼叫。V2-002 會計離開訂單模組含款項清單的訂單連結，一併在本批處理，因為直連導回會讓清單連結失效 |
| 第二批 | 訂單與印件（含訂單頁籤內帳務、異動、售後入口） | V2-024 至 V2-052、V2-088 | 訂單是 G61 協助角色規則的核心；印件審稿面操作在訂單詳情 |
| 第三批 | 需求單 | V2-013 至 V2-019、V2-021、V2-022 | 範圍獨立；Linear 等著改回 wiki 版 |
| 第四批 | 工單與生產 | V2-053 至 V2-057、V2-060 至 V2-067、V2-069、V2-071 至 V2-074 | G62、G63 印務主管代做與工單關聯單據 |
| 第五批 | 出貨、售後、品檢 | V2-077、V2-078、V2-080 至 V2-087 | 範圍跟著訂單或工單，依賴第二、四批 |
| 第六批 | 帳務清單與輸出 | V2-089 至 V2-092 | 會計離開訂單模組後，從清單承接 |
| 第七批 | 未實作操作補齊 | V2-034 複製訂單、V2-083 補附送達憑證、V2-056 印務自行加開工單 | 新增功能，非權限修正；依 G66 第 66 題留在本變更最後做 |

## Risks / Trade-offs

| 風險 | 緩解 |
|------|------|
| 第一批改共用判斷，影響全站 | `npm run impact` 會判「影響全站」；第一批提交前就跑全套 `npm test` |
| 活動表轉錄出錯，Prototype 照錯的資料放行 | tasks 1.x 補一則測試，抽樣比對活動表與活動清單卡的列數與組合 |
| 會計離開訂單模組，3.11 的三方對帳情境要改走清單 | 測試 3.11 改寫；三方對帳面板仍在訂單詳情，給有訂單檢視的人看 |
| 被分享者沒有模組入口（V2-009、V2-090） | 依 D6，被分享者必定已有該單據不靠分享的活動列，入口依該列判定；列表另含被分享單據 |
| 師傅在工作包改派後是否還看得到原任務（V2-073） | 依 G66 第 64 題：原師傅看不到原任務，這筆報工由生管更正；師傅修正限仍看得到任務時，系統層判斷看報工人員 |
| 後端尚未支援的權限，Prototype 先放行 | proposal 已列對應未解問題；Linear 交付時以 Prototype 為介面正本、後端落差另案 |
