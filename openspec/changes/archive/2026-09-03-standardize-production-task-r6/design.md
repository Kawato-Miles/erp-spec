## Context

前五輪把生產任務的欄位、報工與狀態逐步收成一套。第六輪處理的是剩下那批「系統算得出、但算出來的是假設值」的內容：實際工時、開機費的分攤、由 BOM 參數推出來的數量、由交期倒推出來的日期，以及派單狀態對生產任務的映射。

這五件事有共同的形狀——系統多存一個數，而那個數沒有可信來源或沒有下游消費者。工時的唯一消費者是稼動率，稼動率的分母（固定班內工時）本來就沒人維護；開機費攤回讓預實差額混進攤法假設；倒推的數量與日期印務照樣要逐筆核對；派單映射讓同一筆任務有兩個推進來源。Miles 於 2026-09-02 至 09-03 拍板一併收掉，責任交回填數的人。

## Goals / Non-Goals

### Goals

- 七份 spec 不再出現工時、稼動率、折舊、開機費分攤、外包分項與運費關稅攤回進四分項。
- 生產任務的狀態只有五個值，唯一的推進來源是報工。
- 數量與日期在 spec 內只有一條路徑：印務手填；系統不預填、不倒推、不重算、不對照。
- 前置在 spec 內只有一條路徑：印務逐筆手設。
- 到料量只有一個來源：轉交單已點收量。

### Non-Goals

- 不改報工的三個數量欄與檢核（良品＋不良品 ≤ 生產數量）。
- 不改齊套與完成判定的取數（任務完成取投入端生產數量累計、齊套取產出數量）。
- 不改派單自身的 13 值狀態與回廠點收的三動作兩角色。
- 不改預估成本的四分項算式與計價選項的凍結規則。
- 不動貨運單的建單、秤重與認列流程。

## Decisions

**時間類與折舊類參數整組移除，不改為別的來源。**
報工的實際工時欄、設備主檔的時費率／每印費率／折舊／固定班內工時／準備時間／換料校機時間、`production-overview` 的時間稼動率一併收掉。替代方案是保留工時欄供未來使用，已否決：一個沒有讀數的欄位在現場就是每筆多按一格，而它一旦有值就會有人拿去算，算出來的又是沒有分母基礎的百分比。

**折損率改成「生產數量減良品數」，不再取放損欄。**
報工的放損欄同時移除——它本來就是生產數量減良品與不良品的推導值，落庫等於同一個差有兩個版本。折損率因此直接寫成投入減良品，涵蓋不良品與沒變成任何成品的餘量兩部分。良品數仍需先依 BOM 單位用量換算成投入單位，否則是拿成品張數除大紙張數。

**實際成本改為與預估同四分項、同算式、只換數量來源。**
數量來源為有效報工的生產數量累計。設備費的實際值只取階梯價：開機費是「一次上機」的錢、不是「一筆任務」的錢，要進任務就得攤，攤法本身是第二個假設；折舊同理。派單核定報價、運費與關稅仍算得出來，但歸在派單側、不進四分項——四分項要回答的是「同一條算式估與實差多少」，塞進只有實際側才有的成本，差額就分不出是估錯還是本來就沒估。

**派單狀態不映射生產任務，在途兩值移除。**
生產任務狀態自七值收為五值。外部進程仍完整記在派單的 13 值上，兩個實體不重疊：派單記「那張外發單的細節」、生產任務記「我方的製作帳走到哪」。既有處於在途兩值的任務依報工事實落回待處理或製作中。替代方案是保留映射但改為唯讀顯示，已否決：只要那兩個值還在任務的狀態欄裡，就會有人拿它做轉換條件。

**待派清單只收自有工廠任務，加工廠改走轉交與代報。**
加工廠的活在廠外做，生管沒有機台與人可以排；它需要的是把貨送過去（轉交單）與把結果記回來（印務代報）。連帶結論：加工廠、外包廠與中國廠商的生產任務不進工作包，其報工不受「已派入工作包」這道前提限制，運轉設備改由任務的計畫設備帶入（計畫設備已改為所有任務必填、外發留空）。

**數量與日期全數手填，spec 不留任何預填算式。**
`work-order` 的倒推口徑段、`recipe-expansion` 的展開數量段整段移除；`work-order` 的存量拆欄遷移一併移除（它的兩條反推算法依賴已不驅動任何數量的放損率與固定開機損）。放損率與固定開機損降為唯讀估算參考。任務的排程欄由「預計開工日」改為「預計完成日」，工單的預計完工日改取旗下任務該欄的最大值後預填、印務可改——預填而非唯讀推算，是因為機台排隊與外包廠檔期系統看不到。

**前置全數手設，到料量只認轉交點收。**
展開不再自動連材料型對工序型、不再自動連印件層工序段對各部件末段；製程規劃不再預設帶線性鏈。到料量取消「不需轉交的前置取累計良品數」這條路——沒有實體移動的兩道工序本來就無料可查，硬湊一個數當到料只會擋錯人；標為不需轉交的前置因此不檢查、不擋派工，也不進多前置取最小值的比較。

## Risks / Trade-offs

- **兩個數量欄全空，印務每張工單多填數格** → 這正是拍板要的：填的人為那個數負責。緩解在於欄位就在同一列、單位隨計價方式已顯示，不必跨頁查。
- **前置全空，漏設就不會被擋** → 前置本來就是印務判斷製程結構的結果；系統猜一條鏈出來反而讓印務以為已經設好。漏設的後果是不擋派工，與「不需轉交的前置不擋」同一風險層級。
- **不需轉交的前置不再擋派工** → 同產線連續兩道工序本來就在同一個師傅手上，擋不擋的差別不大；真正需要擋的跨站移動一定開得出轉交單。
- **既有在途任務落回待處理或製作中，外部進度在任務層看不到** → 那段進度改看派單，派單的 13 值比原本的兩值細。
- **存量任務的兩欄無落值口徑** → 已列待裁決，不由本 change 決定。

## Migration Plan

1. delta 併回主 spec；另直接修主 spec 三處與本輪無關 Requirement 內的引用文字（`production-overview` § Purpose 的指標列、`order-management` 兩處對 § 交期倒推建議日期 與預計開工日的引用）。
2. 後端：移除報工的工時與放損欄；移除工作包的開機費與分攤；生產任務狀態值域收為五值並移除派單映射；待派清單過濾改單一廠商類別；到料量取數收為單一來源；移除全部數量與日期的預填運算；任務日期欄改名與語意變更；設備主檔移除六個參數；指標移除稼動率、折損率改式、漏單率改基準。
3. 前端：報工表單、製程規劃、工單排程、成本對照與指標頁同步。
4. 回滾策略：本 change 只改文件，回滾即還原 spec。
