## 1. 取消連鎖與手動推進（order-management 側）

- [x] 1.1 `cancelOrder` 擴充為五層連鎖交易：印件任一非終態轉「已棄用」、非終態工單轉「已取消」、生產任務分流（場內看報工：有→報廢／無→已作廢；外發看發稿：已發稿→報廢／未發稿→已作廢）、進行中工單異動終止、掛被砍任務的派單標「待處理提示」不轉態——驗證：取消一張含五層單據的訂單，逐層檢查狀態落點與分流正確
- [x] 1.2 取消連鎖第五層：未離廠出貨單（未處理／打包中／待出貨）自動作廢＋原因自動記「訂單取消」＋額度逐印件回補；運送中／已送達不動——驗證：取消時同訂單三張不同狀態出貨單，只有未離廠兩張被作廢且額度回補
- [x] 1.3 印件「已棄用」轉態 action 實作（取消連鎖與單印件取消製作共用），已棄用印件的數量鏈凍結——驗證：棄用後印件不再出現於出貨明細可選清單
- [x] 1.4 訂單手動推進：「審核通過」（含）之後的非終態逐格推進＋確認對話（寫明不可逆）、推入終態格另寫文案（明講明細將鎖定）、操作角色業務；草稿與待業務主管審核兩態不提供（拍板 31 收斂，prototype 推進表限定併批 2 修正批）——驗證：連點只推一格、每格有確認、終態格文案不同、待審核訂單無推進動作
- [x] 1.5 訂單完成判定修正：分母＝未棄用印件、打樣條件限未棄用打樣印件、未棄用集合為空不觸發完成並提示走取消、終態後不再評估不回退——驗證：全數棄用訂單不會自動完成；NG-稿件棄用的舊打樣印件不卡完成

## 2. 售後與補做統一（after-sales-ticket＋qc 側）

- [x] 2.1 售後單建單零前提：`canCreateTicket` 改為訂單成立後任何時間可建；受理段新增「相關印件」選填欄——驗證：製作中訂單可建售後單、不勾印件可存檔
- [x] 2.2 決議選項依狀態即時顯示可否：勾的印件未送達→「補做」灰掉附說明；訂單未終態→「退款／補收」灰掉附指引（金額走訂單明細直接調價）——驗證：同一張單在印件送達前後開啟，補做選項可用性不同
- [x] 2.3 決議值域「補印」正名「補做」；廢除補印印件建立與審稿輪次複製機制（`TicketViewDrawer` 補印印件建立段移除）——驗證：全 prototype 無「補印印件」建立路徑
- [x] 2.4 售後觸發補做：決議「補做」後導向印件層既有補做發起動線；`startRemakeProduction` 擴充售後來源（補做來源掛售後服務單）與印件終態例外放行（印件維持已送達、原工單重開異動加開任務）；防重＝同一售後單承接後標已承接、不得二次發起——驗證：已送達印件經售後單發起補做成功、同單第二次發起被擋
- [x] 2.5 補做驗過後數量鏈：完工良品數累計（可超過購買數量照實顯示）、額度長出——驗證：補做 50 驗過後該印件額度＝50

## 3. 出貨建單額度單軌（shipment 側）

- [x] 3.1 建單前提改額度單軌：移除訂單終態禁令、唯一前提＝額度檢核；訂單終態頁建單入口在額度 > 0 時保持可用（不受 readOnly 蓋掉）——驗證：已完成訂單的印件有額度時可建單、額度 0 建不了（與 2.5 串測：補做品出貨走通）
- [x] 3.2 已棄用印件排除於出貨明細可選清單（與 1.3 同批原子任務，不可分批）——驗證：已取消訂單雖有完工良品、其已棄用印件不可選
- [x] 3.3 修改明細增量檢核：未離廠修改出貨明細時檢核基準＝當下額度＋本單原明細佔用——驗證：下修明細數量不再被自己的佔用擋死（揀貨實裝不符改明細對齊實裝走得通）
- [x] 3.4 短出結案後額度回彈再建單放行——驗證：短出結案印件的補做驗過後可再建出貨單、印件狀態維持已送達、累計送達照計

## 4. 派單作廢與目視化（dispatch-order 側）

- [x] 4.1 派單作廢：存在性欄位（有效／已作廢）＋原因必填＋13 值鏈凍結原地（顯示層凍結值＋已作廢標記並存）；任一非終態可作廢、終態不可——驗證：作廢後派單退出工作清單、13 值顯示凍結
- [x] 4.2 已發稿作廢的實付額結清：作廢動作內含供應商報價調整為實付額（附原因）；對應外發任務轉報廢、成本＝實付額——驗證：作廢已發稿派單後任務成本為調整後金額
- [x] 4.3 上游狀態目視化：派單列表與詳情顯示所屬印件印製維度狀態與所屬訂單狀態（唯讀、即時、可篩）——驗證：取消訂單後其派單在列表可依「訂單已取消」篩出
- [x] 4.4 外包補做另開派單：補做外發任務依既有建單流程開新派單（原工單不新建、原派單維持終態）——驗證：外包補做流程走通且派單粒度正確

## 5. 工單異動與生產任務調整（work-order 側）

- [ ] 5.1 生管確認動線：`AdjustmentsTab` 補生管確認 action（審視→確認→重印紙本→離開異動、工單回原狀態）；與既有印務主管核可（需重審補做）並存兩類把關——驗證：兩類異動各走各的確認人
- [ ] 5.2 被移除任務有入庫成品時強制填處置說明（自由文字、填寫人＝發起印務）——驗證：有入庫成品的任務移除跳強制欄、無則不跳
- [ ] 5.3 最後一筆會影響成品的有效任務移除阻擋＋訊息帶出路（指引印件取消製作／棄用入口）；不影響成品任務（如包裝）不計入判定——驗證：只剩印刷＋包裝兩任務時可移除包裝、不可移除印刷
- [ ] 5.4 `removeProductionTask` 改分流 action（`voidTask`／`scrapTask` 取代硬刪）：統一判準分流＋第三分流（已完成品檢的任務維持已完成、附「已由異動排除」標記、品檢紀錄保留）——驗證：三種任務狀態各落正確終態
- [ ] 5.5 補生產承接守衛：雙終態（已送達／已棄用）擋一般補做＋售後單觸發例外放行（與 2.4 串接）——驗證：一般補做在已送達印件被擋並提示走售後
- [ ] 5.6 加開印件入口：「複製原印件規格」加開（回歸單純加購用途）——驗證：加開印件帶入原規格、走正常新印件流程
