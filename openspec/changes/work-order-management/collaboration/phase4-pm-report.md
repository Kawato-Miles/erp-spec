設計理解摘要：

四個 Phase 收斂後的整體方案，是把工單從「依廠拆的排程單」改造成「一印件一製作週期的完整帳本」：建立當下一次凍好三件事（各生產任務的計價快照、工單層製作數量帳含加放留痕、依製程展開的生產任務），完工判定改由單內生產任務收斂決定並與品質帳徹底脫鉤，交付之後的四個下游（派工、報工、品檢、派單）以七條契約掛住而不實作。管理層在此之上取得的不是「成本存下來了」，而是「機台開之前就知道這單的預計成本有多少水分、卡在誰手上、誰多放了料」——CEO 在補強輪主動取消一個恆真的複合指標、降級兩個守門型數字，換來三個計數型訊號與一個改版的預計成本確定率，這個取捨的方向我認同。

不確定 A，假設 B 有兩處：不確定 dispatch 逐字列出的八條編號拍板與 memory 記載的「grilling 九項拍板」是否為同一組（計數口徑差異或有一條未傳達），假設為計數口徑差異、以逐字八條為準並列為確認項；不確定 Prototype「桌面四組」與四個 change 的對應是否嚴格一對一，假設本 change 交付工單管理那一組共四頁（工單列表／工單詳情／製程規劃頁／成本摘要頁）。

**OQ-1｜「工單已交付」觸發條件矛盾**（原 OQ 候選 1，audience: internal）
- 背景：wiki [[工單狀態]]「**全部**任務交付產線後觸發（取最落後）」vs openspec work-order spec「**首個**任務交付時觸發、後續任務交付不影響」。兩份既有正本互相矛盾、非本次拍板造成；不拆廠後一張工單同時含多家廠商，影響面比拆廠時代更大
- A 方向（全部交付）：下游看到「工單已交付」即代表所有廠商都收到、語意乾淨，印務交付追蹤的把關點成立；但單內有一家外包廠遲遲不接單時整張工單卡在「製程審核完成」，現場已開工卻不反映
- B 方向（首個交付）：現場一有動靜即反映；但「工單已交付」不再保證所有廠商都收到，與 wiki 卡「印務確認各負責廠商都收到、下游才看得到」的營運動機直接相反。**且會讓 CEO 營運 3 第三關卡「製程審核完成未交付 > 1 工作日」實質失效**（首家一交付即離開關卡，測不到落後的廠商）
- C 方向（CEO 提）：責任轉移點採全部交付（＝A），另以「已交付 3/5 家」衍生訊號呈現部分交付進度。**顧問確認 C 在狀態機層與 A 完全相同**，實際分歧只有兩個
- 不受影響項（可安心）：派單發送（E2 是任務層動作、不看工單狀態）、收回守衛（看任務層）、CEO 其餘全部指標
- 等待 Miles 拍板；裁決後同步 W2／#13／#21 三處

**OQ-2｜計價快照四分項與 BOM 結構計價引擎五類成本對不上（工序費缺席）**（新，來自顧問 C2-2，audience: internal）
- 背景：[[計價快照]] 四分項為「材料費／開機費／色數加價／裝訂費」，[[BOM結構]] § 計價引擎計算框架（正本）的部件成本為「材料費＋**工序費（P1-P8）**＋裝訂費＋拼版設備費＋非拼版設備費」。影響三處：只走後加工工序（純外包裁切、上光）的生產任務成本主體無處安放、預計成本系統性低估；大圖（E3）設備不走拼版、無開機費與色數，四分項下同樣落空；直接卡住模組 3「應有分項集合」對這類生產任務的定義（判為無應有分項則確定率恆為「確定」、形成假陽性）
- i 方向：「開機費」實為「設備費」的口語稱呼、工序費已被歸入其中 → 四分項需正名，應有分項集合隨之改寫
- ii 方向：四分項確實漏了工序費 → 需確認工序費歸屬（補為第五分項，或裁定工序費不進快照）
- 本 change 暫置：該類生產任務自模組 3 分母排除、另列守門訊號，不造成假陽性
- **這是本次唯一的「商業需求未滿足」項（M2 部分未滿足），依協議選路徑 B 交 Miles 裁決**；等待 Miles 拍板，裁決後回補 W6／W13

**OQ-3｜[[數量換算規則]] 下行取整方向的表述缺口**（原顧問 C-PM-1，audience: internal）

## 第七段：整體設計方案（給 Miles）

本 change 把工單從「依廠拆的排程單」改造成「一印件一製作週期的完整帳本」——建立當下逐筆凍好計價快照（四分項＋金額依據＋應有分項集合＋版本序號）、工單層製作數量帳（換算所需數量與目標數量並存、加放留痕）與依製程展開的生產任務，完工判定改由單內生產任務的判定集合收斂、與品質帳徹底脫鉤，交付之後的派工、報工、品檢、派單以七條契約掛住而不實作。管理層在此取得的是「機台開之前就知道這單的預計成本有多少水分、卡在誰手上、誰多放了料」，而非只是把資料存下來；CEO 在補強輪主動取消一個結構上恆真的複合指標、降級兩個守門型數字，換來三個測「現場想繞過系統的地方在哪裡」的計數訊號。既有規則以 wiki 21 條、openspec 40 條逐條分類覆蓋，取代型變更一律標 MODIFIED、兩段已廢止的品檢模型判 REMOVED、六項介面規範明確留另案。**動工前需你先拍三題**：工單已交付的觸發條件（wiki 與 openspec 既有矛盾，且決定 CEO 一條指標存亡）、計價快照四分項與 BOM 計價引擎工序費缺席的口徑（本次唯一未滿足的商業需求項）、數量換算下行取整方向（決定加放守衛的基準是否有意義）。
