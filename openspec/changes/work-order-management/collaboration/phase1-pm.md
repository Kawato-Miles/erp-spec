設計理解摘要：

本 change 要解決的問題是：生產階段的起點單據（工單）目前只驗證過「建得出來」，但**建立時該把哪些帳一次凍好**沒有定案——成本靠印務人工估算、數量帳分散在人腦與紙本、跨廠情境靠拆單與跨工單依賴硬接，導致日後要做管理指標時底層資料不足、必須重構。核心機制是把工單重新定義為「一印件一製作週期一張、涵蓋完整製程、不依廠拆單、完工帳在單內收斂」的單據，並在建立當下同時凍結三件事：計價快照（四分項，開機費凍參數組）、七個數量帳中屬工單層的製作帳、以及依 BOM 展開的生產任務（含生產單位分流與計畫設備）。與既有系統的整合點有四處：上游承接印件審稿維度「已確認可製作」自動建草稿工單；下游在「製程審核完成」時觸發派單自動產生（派單 change 接）；旁側把品質帳交給印件層品檢紀錄（品檢出貨 change 接）；底層把生產任務交給工作包合批與報工（派工追蹤 change 接）。

不確定 A，假設 B 的部分有三處：不確定「一製作週期」是否等同「打樣一輪／大貨一輪／補印一輪」（打樣 NG 重打會不會算第二個週期），假設是「每一輪各自開單、打樣重打即第二張打樣工單」；不確定 BOM 配方層（[[BOM配方]]／配方工序段）是否落在本 change，假設是「架構掛點在本 change 定義、配方主檔實作另立落點待裁決」；不確定「材料用量帳」是設計歸屬本 change 或落點在報工，假設是「記錄時點與責任者在本 change 定義、實際記錄動作落派工追蹤 change」。

商業需求摘要：

**Miles 原話（逐字引用，出自已拍板 plan mes-erp-lucky-beacon，2026-07-27）：**

觸發來源與痛點：「生產階段（工單建立到出貨）現場仍靠紙本工單與口頭協調；上一版 Prototype 只驗證了工單單據的建立，排程、成本、設備運作對管理層是黑箱；外包（中國線與台灣外包）與場內流程斷開，回場銜接靠人工核對。」預期成效：「完整的生產階段 MES/ERP 系統設計定案（High-level 資料結構與流程，確保日後做管理指標時不需重構底層資料）」。

As-is／To-be 與工單直接相關四列：
- 工單涵蓋範圍：「As-is 依工廠性質（台灣／中國）拆單，跨廠情境靠跨工單依賴串接 → To-be 一印件一製作週期一張工單（打樣／大貨／補印仍各自開單），涵蓋完整製程，不依廠拆單；完工帳在單內收斂。」
- 成本：「As-is 工單成本靠印務人工估算 → To-be 工單建立時凍結計價快照（四分項）；材料用量的帳定好記錄時點與責任者（傾向完工後依配方回推），日後算實際成本不改底層。」
- 補生產：「As-is 口頭協調＋紙本改單 → To-be 場內品檢缺口補做（從品檢紀錄一鍵發起、走工單異動）＋外包大貨 NG 退原廠（新工單新派單衍生與連結）兩條系統路徑。」
- 數量的帳：「As-is 做了幾個、驗過幾個、出了幾個分散在人腦與紙本 → To-be 七個數量帳算完整（目標／生產／良品不良品／處置／完工良品／入庫／出貨），日後加庫存管理不改帳的算法。」

已拍板決策（本 change 直接受約束者）：TPS 為機制層準則、架構骨幹不動（1）；排程／計價／設備總覽三項為 High-level 資料結構與流程設計、Phase 劃分忽略（2）；工單不拆廠（3）；派單粒度＝廠商×工單、明細掛生產任務（4）；派單建立時機＝製程審核完成時自動產生、任務交付＝派單發送（5）；補生產範圍＝品檢缺口補做＋外包 NG 退原廠兩條，加量與售後補印從訂單層進來後即一般工單（6）；Prototype 桌面四組全做、材料用量帳與數量帳納入設計與 Prototype、靜態假資料（7）；四個 change 依序走、每個體積小好驗收（8）。

當日追加五題：訂單管理人工單接觸範圍限分派審稿與交辦前內容檢查；PT-020 七個數量帳統一（齊套邏輯為清單正本、報廢數落處置帳、入庫數分期標註、工單品質帳移印件層）；PT-022 開機費歸集（計價快照凍參數組、工作包唯一發生點＋分攤基礎可設、成本差異新增併批整備效益維度、報工補工作包歸集）；開機費分攤基礎＝拼版分攤；工單頁不顯示品檢進度。

**PM 補完（範疇含意、術語對照、隱含的角色與動作）：**

1. **「一印件一製作週期一張工單」的範疇含意**：這條同時做掉兩件事——(a) 廢掉「依工廠性質拆單」，(b) 確立「製作週期」為拆單的唯一維度。含意是既有 openspec 的「工單區域設定」（region 台灣／中國決定生產任務可選工廠類別、允許同印件拆台灣與中國兩張工單）整段失效，內外之分下沉到生產任務層的「生產單位類別」（自有工廠／加工廠／外包廠／中國廠）。這不是欄位微調，是拆單維度的置換。

2. **「完工帳在單內收斂」的範疇含意**：對照 [[齊套邏輯]] 已拍板的「工單完成判定＝旗下生產任務全部完成（含補做任務）」與 PT-020「工單管製作帳、品質帳歸印件層」，本句在系統語意上等於：一張工單不需要等另一張工單，也不需要等品檢，只要單內全部生產任務收斂即完成。跨廠不再靠跨工單依賴串接，改靠單內生產任務之間的前置依賴。

3. **「工單建立時凍結計價快照（四分項）」的角色與動作**：凍結者是系統、觸發時點是工單建立並依配方展開生產任務的當下，責任者是填製程的印務（因為凍什麼取決於他選的材料、工序、機台、色數）。四分項＝材料費、開機費（凍參數組，非金額）、色數加價、裝訂費。這裡的「工單建立時」與 [[計價快照]] 卡「工單建立、依配方展開生產任務的當下」一致，但需注意快照實際內嵌在生產任務層（1:1 值物件），工單層的預計成本是各生產任務快照的彙總——「工單建立時凍結」是業務講法，資料上凍在生產任務。

4. **「材料用量的帳定好記錄時點與責任者」的範疇含意**：Miles 明說「傾向完工後依配方回推」，但這句是傾向、非拍板；且對照 [[物料消耗記錄]] 已設計的「扣帳時點」欄位（開工發料／完工倒扣兩值），現況設計是雙軌並存（紙張這類關鍵料開工先發、其餘完工倒扣）。本 change 要定的是「哪些料走哪一軌、由誰決定、在工單哪個節點設定」，實際記錄動作發生在報工（屬派工追蹤 change）。

5. **「七個數量帳」在工單層的落點**：七個數量的清單與定義正本已在 [[齊套邏輯]] § 數量帳與額度公式（2026-07-27 拍板），本 change 不重新定義，只需釘死工單層持有哪幾個：目標數量、生產數量（報工累計）、每份印件生產數量（倍數）。良品／不良品、處置數、完工良品數、入庫數、出貨數五項的家在印件層，工單層不設欄位、工單頁不顯示。

6. **「補生產兩條路徑」在本 change 的落點**：兩條路徑的**觸發入口**都不在工單管理（一條在品檢紀錄、一條在派單），但兩條的**承接機制**都在工單——第一條走工單異動加開生產任務（原工單重開），第二條走新建工單（新的製作週期）。本 change 要定的是承接機制與工單建立來源，不是入口介面。

7. **角色對照**（依 [[印件生產流程]] 與各實體卡）：印務主管（加開工單、分派印務、製程審核核可／退回）、印務（填材料清單／工序／參考完稿圖、選計畫設備、設倍數與目標數量、送審、收回、發起異動、外發主責與談價核價）、生管（確認異動內容；派工不在本 change）、訂單管理人（2026-07-27 拍板：只碰分派審稿與交辦前內容檢查，**不做製程規劃**，本 change 須明確排除其對工單製程的操作入口）。

開始 Spec 前需確認的問題（OQ 候選，由協調者觸發 [[oq-manage]] mode B 開卡，本 Phase 不寫檔）：

1. **「工單已交付」的觸發條件矛盾**（wiki [[工單狀態]]「全部任務交付產線後觸發（取最落後）」 vs openspec work-order spec「首個任務交付時觸發、後續任務交付不影響」）
   - A 方向（全部任務交付才推進）影響：下游（含派單發送）看到「工單已交付」時代表所有廠商都收到，語意乾淨；但單內有一家外包廠遲遲不接單時，整張工單卡在「製程審核完成」，現場已開工卻不反映，與「狀態忠於現場事實」原則相衝
   - B 方向（首個任務交付即推進）影響：現場一有動靜即反映；但「工單已交付」不再保證所有廠商都收到，印務交付追蹤的把關點消失，且與 wiki 卡「印務確認各負責廠商都收到、下游才看得到」的營運動機直接相反
   - 備註：不拆廠後一張工單同時含多家廠商，此矛盾的影響面比拆廠時代更大，**必須先拍板才能設計狀態機**

2. **BOM 配方層是否納入本 change**
   - A 方向（納入）影響：線下單引用配方展開、工單沉澱為配方兩項需求一次到位，架構卡 P1「EC 展開＋線下手動」達成；但本 change 需新增配方主檔、配方工序段兩個實體與展開規則，體積顯著超出拍板 8「每個體積小好驗收」
   - B 方向（不納入、只留掛點，另立第五個 change）影響：本 change 體積可控、四 change 依序節奏不變；但工單建立時「依配方展開」在 Phase 1 實際上仍是印務手動展開，計價快照「依配方展開生產任務的當下凍結」這句在無配方層時的實際觸發點需改寫

3. **工單類型二值與中國線工單製作類型六值的收斂結論**
   - A 方向（六值收斂進工單類型，成為多值列舉）影響：一個欄位講完，中國線與台灣線一致；但六值中「大貨檔案同打樣單／大貨檔案有修改」是委外溝通語意，放在工單層會讓台灣線出現用不到的值
   - B 方向（工單層維持二值、六值降為派單層委外製作類型）影響：工單層乾淨、台灣線無冗餘值；但中國線現況以六值辨識製作情境，降層後工單列表看不出區別，需確認印務實務是否需要在工單層辨識

4. **不拆廠後既有 region 欄位的處置**
   - A 方向（移除）影響：拆單維度乾淨；但既有資料與報表若以 region 分群，遷移需另處理
   - B 方向（保留為報表維度或改為生產任務層衍生）影響：管理層仍看得到台灣／中國分佈；但欄位存在容易被誤用回拆單依據，違背拍板 3

5. **外包工序在工單建立當下尚無供應商報價時的計價快照處理**
   - A 方向（照凍、該分項留空或暫估，報價確認後不回頭改快照）影響：凍結時點單一、語意乾淨；但外包佔比高的工單其預計成本嚴重失真，成本差異比對基準無意義
   - B 方向（外包分項待報價確認後補凍，形成分段凍結）影響：預計成本準確；但「工單建立時凍結」變成「部分凍結」，需定義補凍時點、補凍後是否重算合計、以及補凍前工單可否交付

6. **work-order spec 內 QC 類 Requirement 的除役落點**（§ QC 單建立、§ QC 執行與結果記錄、完成度公式中的 requires_inspection／pt_qc_passed）
   - A 方向（本 change 一併除役）影響：工單完成判定與品質帳的矛盾一次清乾淨，不留跨 change 懸空；但需在品檢紀錄模型尚未寫進 spec 前先移除舊模型，中間會有一段「舊的拿掉、新的還沒到」的空窗
   - B 方向（留給品檢出貨 change）影響：新舊模型同步換手、無空窗；但本 change 的工單完成判定改判會與尚未除役的 QC 公式並存矛盾，違反單一正本
   - PM 傾向：完成判定（工單狀態機終態守衛）屬本 change 必改；QC 執行與 NCR 屬品檢出貨 change。但此切法會讓 spec 出現短暫不一致，需 Miles 或顧問確認可接受

7. **work-order spec 介面規範類 Requirement 的除役時程**
   - A 方向（本 change 順帶清理）影響：spec 與「Prototype 為介面互動正本」的分工一次到位；但七項介面 Requirement 的除役會讓 change 體積膨脹、且與商業邏輯無關
   - B 方向（另案除役，本 change 在對照表標「不動」）影響：體積可控；但 spec 內仍留大量介面規範，日後 archive 時容易與 Prototype 正本打架

8. **材料用量帳「記錄時點與責任者」的設計歸屬**
   - A 方向（本 change 定規則、派工追蹤 change 落記錄動作）影響：規則與動作分離但都有家，符合 Miles「定好記錄時點與責任者」的原話；但兩個 change 之間有一段規則已定、動作未實作的空窗
   - B 方向（整包移到派工追蹤 change）影響：一次做完；但 Miles 明列此項於「成本」這一列的 To-be，屬工單成本帳的一部分，移出後本 change 的成本設計不完整

9. **短出下修後工廠端資料處理（承接 PT-012）是否納入本 change**
   - A 方向（納入）影響：訂單下修 → 工單端收尾的閉環在本 change 完成，異常路徑不留缺口；但觸發來源在品檢缺口處置（品檢出貨 change），本 change 會出現「機制先於觸發」
   - B 方向（留給品檢出貨 change）影響：觸發與處理同一個 change；但工單／生產任務改數量或改狀態屬工單層設計，放在品檢出貨 change 會反過來動工單的規則正本

10. **工單建立來源正本清單的落卡位置（承接 PT-025 第 1 點）**
    - A 方向（落 [[工單]] 實體卡新增「建立來源」段）影響：與欄位正本同卡、查得到；但實體卡承載流程性內容，與「卡只承載欄位／關聯／狀態名」的規則正本歸屬聲明有張力
    - B 方向（落 [[印件生產流程]] 商業邏輯卡）影響：流程性內容歸流程卡，符合正本歸屬；但工單卡查不到，實作時容易漏；可在工單卡以 wiki 連結指回，避免雙份維護。

11. **打樣序列守衛是否做成系統強制（承接 PT-025 第 2 點）**
    - A 方向（做成系統守衛：打樣印件未判定 OK 前，同印件不可建大貨工單）影響：從源頭杜絕「樣沒過就投大貨」的整批報廢風險，與 [[印件狀態]]「稿沒定不投產」的既有設計邏輯一致；但客戶催單時業務常要求同步備料開工，硬擋會逼現場繞過系統（改用備註或事後補單），反而讓系統帳失真
    - B 方向（不做強制、只做警示）影響：現場彈性保留、不逼人繞過；但 [[打樣流程]] 的序列強制在系統上等於沒有，「打樣未通過不能做大貨」只剩文件宣示

12. **加印是否納入印件類型列舉（承接 PT-025 第 3 點，跨模組）**
    - A 方向（納入，印件類型由三值擴為四值）影響：加印件在工單建立來源、成本歸屬、交期承諾上有辨識依據，工單列表可一眼分辨；但印件類型是訂單模組的欄位，動它會外溢到訂單、審稿、售後三個模組，超出本 change 範疇
    - B 方向（不納入，維持三值＋隱含設計）影響：本 change 範疇不外溢；但加印工單與原工單在系統上無從區分，管理層要看「加印造成多少額外生產」時取不到數
    - PM 備註：此題主體在訂單模組，建議本 change 只標明「工單建立來源需要辨識加印」這個需求，實際列舉值變更交訂單側處理

13. **印件棄用時工單層連動行為（承接 PI-003）**
    - A 方向（工單隨印件棄用一併轉終態）影響：不留無效工單污染工單列表與待辦；但工單若已有報工成本，終態化後成本結算的入口消失，需另外指定結算落點
    - B 方向（工單維持原狀、只讓底層生產任務走報廢／作廢）影響：成本結算沿用生產任務層既有機制、不必新設；但工單停在「製作中」不動，工單列表出現永遠不會完成的殭屍單
