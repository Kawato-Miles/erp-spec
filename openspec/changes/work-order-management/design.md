# 工單管理 — 設計文件

> 設計經序列協作 Phase 1-4 收斂（2026-07-27，PM 中介來回模型：Phase 2 CEO 2 輪＋Phase 3 顧問 2 輪含 CEO 指標補強輪）。全程紀錄見 [collaboration/](collaboration/)（八份逐字全文），本文件是其收斂後的技術設計正本；驗收對照表（verify consistency 三張）見 [collaboration/phase4-pm-report.md](collaboration/phase4-pm-report.md) 第五段。

## Context

工單是生產階段的起點單據。既有 openspec work-order spec（36 個 Requirement）建立在「依廠拆單＋QC 入庫計完成度＋品檢型任務」的舊模型上，與 2026-07 一系列拍板（工單不拆廠、品檢紀錄歸印件層、品檢型任務廢止、七數量帳統一、開機費凍參數組）已系統性脫節。本 change 把工單重新定義為「一印件一製作週期的完整帳本」，並為後三個 change（派工追蹤／品檢出貨／派單）定好八條跨 change 前提與七條觸發契約。

約束：
- 架構骨幹不動（ISA-95 五層、工作包＝一次上機、任務層保留、延遲待機不進主狀態）。
- 不可推翻的已封存決議：PT-009（加量＝加開新印件）、PT-003（一鍵發起補做）、PT-002、PT-008、SHP-010、SHP-011、PT-017、QC-002（品檢型任務廢止）；2026-07-20 售後責任歸屬移除（不得重新引入責任歸屬概念）。
- wiki 先於 openspec：欄位正本歸 05-entities 實體卡、狀態列舉正本歸 06-state-machines，spec 只寫行為規格。
- wiki 邊界：wiki 只寫商業需求與現況，技術細節（資料形狀、衍生視圖、觸發器機制）歸本文件。

## Goals / Non-Goals

**Goals**
1. 拆單維度置換：不拆廠、一印件一製作週期一單，完工帳在單內收斂。
2. 建立當下凍好三件事：計價快照（逐筆生產任務）、工單層製作數量帳（含加放留痕）、依製程展開的生產任務。
3. 完工判定改判：判定集合收斂，與品質帳徹底脫鉤。
4. 補生產兩條系統路徑的工單側承接機制。
5. 對下游三個 change 的觸發契約（E1-E7）定義完整。
6. 管理層可見性：機台開之前就知道預計成本有多少水分、卡在誰手上、誰多放了料。

**Non-Goals**
- 派工、工作包合批、報工、設備佇列、排程推算（派工追蹤 change）。
- 品檢紀錄、缺口處置介面、入庫與出貨（品檢出貨 change）。
- 派單實體與大陸處理狀態、貨運單、回廠點收（派單 change）。
- BOM 配方層實作（PT-031 未拍板，只留掛點）。
- 物料消耗的實際記錄動作（規則在本 change、動作在派工追蹤）。
- 成品庫存、在製品估值、實際成本類指標（架構已預留掛點）。
- work-order spec 介面規範六項的除役（另案；Prototype 為介面互動正本）。

## Decisions

### D1 拆單維度置換：區域欄棄用、生產單位下沉

工單「區域」欄棄用，內外之分由 [[生產任務]] 既有「生產單位類別」四值（自有工廠／加工廠／外包廠／中國廠）承載，同單四類並存為常態。台灣／中國管理視角改為衍生（旗下生產任務彙總）。為什麼不保留區域欄當報表維度：欄位存在容易被誤用回拆單依據，違背拍板；報表分群用生產任務層資料更準。

### D2 製作輪次＋當前打樣工單指針

- 工單新增「製作輪次」：同印件同工單類型的第幾張（系統遞增、唯讀）。這是「一製作週期」在資料上的落地，也是 [[齊套邏輯]]「六個數量按打樣週期歸零重算」隱含需要的週期識別碼。
- [[印件]] 新增「當前打樣工單」指針（父實體持 FK 指針，而非每張工單掛 is_current 旗標——旗標在並發下會出現 0 或 2 個為真）。數量帳只認指針指到的那一輪。
- 工單類型建立後鎖定（改型別＝棄用建新），否則輪次計數基準錯亂。

### D3 建立來源六值＋雙追溯連結（五建一不建）

建立來源 LOV：審稿確認可製作／印務主管加開／打樣 NG-製程問題重打／外包大貨 NG 退原廠／售後補印／加印。搭「來源工單」「來源派單」追溯連結（業界對應 SAP／JDE 重工單 Parent Work Order 慣例）。「來源派單」是外包重工「依廠商分群」的唯一可靠分群鍵——不拆廠後工單層沒有單一廠商。唯一不建新工單者：品檢缺口補做（走原工單異動加開生產任務）。NG-稿件問題不在此清單（走印件棄用＋複製新印件，屬印件層路徑）。

### D4 計價快照：逐筆凍結＋金額依據＋版本序號

- 凍結時點＝**每一筆生產任務建立當下逐筆凍結**。EC（一次展開一次凍）與線下客製（逐筆加逐筆凍）共用同一規則，PT-031（配方層落點）兩方向皆可承接；「工單建立時凍結」的業務講法不變。
- 四分項各帶「金額依據」三值：主檔價／已確認報價／**暫估**。外包未報價照凍、以暫估值入帳、不留空（留空會讓外包成本佔比系統性低估，Sage X3 委外暫定成本先入的同型做法）、不擋交付。
- 「應有分項集合」凍結當下算出並凍入快照（判定鍵＝bom_type＋計畫設備計價型別 E1 平版／E2 數位／E3 大圖）。不即時計算的理由：主檔事後改版會回頭改變歷史判定，正是快照要防的污染。
- 「快照版本序號」（凍結＝1、補凍 +1）使 PT-033 兩方向（照凍不改／分段補凍）共用同一結構，裁決不改結構。
- 快照仍內嵌生產任務（1:1 值物件），工單層預計成本為彙總、不另存欄位（避免雙份帳）。

### D5 工單層數量帳：兩數並存＋下限守衛

- 「換算所需數量」（＝印件購買數量 × 每份印件生產數量，取整方向依 PT-030 裁決）與「目標數量」並存保存。不保存的後果：短出下修後購買數量變小，事後回推的加放比例被系統性灌水。
- 加放比例＝（目標數量 − 換算所需數量）÷ 換算所需數量，衍生不另存；工單頁三數並列、不告警不擋。
- 送審守衛：目標數量 MUST ≥ 換算所需數量（[[印件生產流程]] 既有規則的系統執行）。
- 生產任務層留「系統建議每份工單需生產數量」掛點（不可被覆寫值蓋掉），加放第二注入點（倍數覆寫差額）待 PT-031 落地後啟用。

### D6 完工判定：判定集合＋重開守衛＋豁免三值

- 判定集合＝旗下生產任務 −{已作廢}−{計入完成度＝不計入}；集合非空且全部已完成 ⟺ 工單完成。報廢的生產任務**留在集合內**（報廢是終態但沒做出東西），出口只有補做或個案豁免。
- 「計入完成度」由布林升 LOV 三值：計入／不計入（準備性工序，建單時定）／不計入（個案豁免，僅可於異動中設定、MUST 帶異動單號）。兩種排除語意共用一個布林會讓齊套統計與短出豁免在彙總層分不開——升 LOV 而非加第二個布林。
- 重開守衛：所屬印件印製維度已達終態（已送達／已棄用）時工單 MUST NOT 重開，補做改走售後補印（邊界待 PT-034 拍板）。「已完成」為衍生判定＋「完成次數／最後完成時間」留痕，補償終態原則的刻意不套用。

### D7 審核流程：審核中標記（效力與留存分離）＋雙原因分類

- 審核中標記（審核人／開始時間／標記狀態「審核中｜已逾時」）。逾時只轉狀態不刪除：收回守衛看「狀態＝審核中」，停滯拆分看「標記是否存在」——刪除式設計會讓「已認領久未決」在最需要區分時退化成「無人認領」。「主管尚未開始審核」首次有了判定條件。
- 退回原因與異動原因各改六值 LOV＋補述（選「其他」補述必填）。收回原因刻意維持自由文字（頻率低、與異動原因重疊，另立分類會互相污染統計）。
- 送審五守衛：至少一筆計入完成度的生產任務／倍數 > 0／目標數量下限／快照齊備／需完成日已填。
- 需完成日：預設自訂單交貨日帶入（印件層查證無獨立交期欄位，見 PI-005）、印務可覆寫、覆寫留痕＋「是否經印務覆寫」衍生標記——沒有合理預設值的必填欄位會變假資料欄位（CEO challenge 採納）。與派工追蹤的「預計完工日」（排程推算）語意不同、不可混用。

### D8 觸發契約 E1-E7（本 change 定義、各自 change 實作）

| 編號 | 事件 | 觸發 | 接收方 |
|------|------|------|--------|
| E1 | 工單製程審核完成 | 狀態 → 製程審核完成 | 派單 change：自動產生派單（依廠商分組的外包生產任務清單） |
| E2 | 任務交付 | 任務 待交付 → 已交付 | 派單 change：派單發送 |
| E3 | 生產任務建立 | 建立完成 | 派工追蹤：工作包合批候選池 |
| E4 | 異動涉及外包生產任務 | 生管確認異動後 | 派單 change：同步派單明細 |
| E5 | 品質缺口待處置 | 品檢累計不通過 > 0 且無處置 | 品檢出貨：印務待辦（收件人＝工序依賴圖終點所在工單負責印務） |
| E6 | 工單層唯讀投影 | 查詢型 | 訂單模組：業務唯讀（需完成日／落後訊號／交付進度，聚合鍵＝印件） |
| E7 | 預計成本基準供給 | 查詢型＋批次可讀訊號（審核完成）＋補凍訊號 | 派工追蹤／成本差異：四分項＋金額依據＋開機費參數組三參數＋暫估清單＋版本序號 |

呈現界線（CEO 三規則）：工單頁 MAY 呈現自身子樹衍生資訊（落後訊號、交付進度）；MUST NOT 呈現印件層的帳（七數量印件層五個、品檢通過數、可出貨額度）；印件層資訊唯一合法形式＝導引連結。成本呈現拆兩處：工單詳情頁成本區塊三項（四分項／場內 vs 外包佔比／未報價暫估清單）；成本摘要頁（獨立一頁、以印件為主體）四項（前三項＋大貨印件預計毛利標預計值）。

### D9 管理指標與稽核（17 條線＋3 訊號＋ActivityLog 15 項）

指標清單與公式見 [collaboration/phase4-pm-report.md](collaboration/phase4-pm-report.md) 第二段與表一。設計要點：
- 兩組對偶指標 MUST 整組帶：加放比例 ↔ 重工批次（壓加放會升重工）；預計毛利率 ↔ 估準度（單獨存在鼓勵低估，後續 change 配對）。
- NSM 層無比率指標（檢核後結論非遺漏——恆真比率比沒有更有害），改三個計數訊號：無異動紀錄的交付後關鍵欄位變更次數／建立→送審極短尾件數／守衛擋下＋警示放行次數。訊號 3 MUST NOT 用於個人考核。
- ActivityLog 15 個 MUST 寫入動作（含守衛被擋下、警示放行、計入完成度變更、關鍵數量欄位變更帶異動單號有無、任務交付、需完成日覆寫）。方法教訓：新增守衛時 MUST 回頭檢查它對既有量測的反作用。
- 四個門檻（極短尾 10 分鐘、停滯 1 工作日、警示放行率、守衛強度）本 change 為固定值，「可設定」登記為後續需求。

### D10 材料軌別三層

[[材料主檔]] 材料規格層設「預設扣帳時點」（預設＝完工倒扣，即 Miles「傾向完工後依配方回推」；紙張類關鍵料主檔設開工發料）→ 工單層可個案覆寫（留痕）→ [[物料消耗記錄]] 記錄動作歸派工追蹤 change。

## Risks / Trade-offs

- **三題阻斷級未拍板**（PT-028 已交付觸發／PT-029 四分項工序費／PT-030 下行取整）：狀態機觸發抽為具名守衛參數、確定率分母暫排除無應有分項者、守衛基準標依賴——三方向承接使 artifact 可先行，但 **apply 前 MUST 拍板**，否則對應 Requirement 無法定稿。
- **QC 兩段先除役的空窗**：只存在於 openspec 行為層（wiki 品檢紀錄＋齊套邏輯為 active 正本無空窗），品檢出貨 change 補行為層。不先除役的代價是完成判定新舊公式並存矛盾，取捨選先除役。
- **規則與動作分離**（材料軌別規則在本 change、記錄動作在派工追蹤）：留一段「規則已定、動作未實作」空窗，屬 Miles 原話的直接要求，可接受。
- **暫估值失真風險**：現場把沒談的外包價填成主檔價可拉高確定率——防範＝併看補凍紀錄筆數（真暫估會留補凍紀錄、假主檔價不會）。
- **豁免濫用風險**：「不計入（個案豁免）」給了印務把沒做完的東西移出判定的能力——防範＝僅可於異動中設定、MUST 帶異動單號、寫 ActivityLog、豁免次數可彙總。
