## 本體

### 一、出貨單狀態

本段決定：出貨單什麼時候產生物流單、什麼時候鎖數量。做錯的後果：物流單號與箱子對不上，或數量鎖不住，額度帳跑掉。

| 狀態 | 說明 | 變動 |
|---|---|---|
| 草稿、未處理、打包中 | 不變 | — |
| 已裝箱 | 完成裝箱回報後進入；**尚無物流單**；出貨明細數量、揀貨數量、增刪箱、修改箱都還能改 | MODIFIED：不再於此產生物流單、不再依物流單計算 |
| 可出貨 | 揀貨人員確認可出貨後進入，系統同時產生物流單；之後依物流單計算，最落後的物流單在可出貨時停在這一格 | 新增（H1、H2、H5） |
| 等待出貨、已出貨、運送中、異常、已送達、已作廢 | 依物流單計算的規則不變 | 物流單的已出貨只剩專車配送與其他（H8）；出貨單的已出貨仍是「最落後為已出貨或可自取」 |

轉換（只列有變動者）：

| 轉換 | 觸發操作 | 條件 | 系統動作 |
|---|---|---|---|
| 打包中 → 已裝箱 | OP-SHP-005 完成裝箱回報 | 同現況 | **不產生物流單**（H2） |
| 已裝箱 → 可出貨 | OP-SHP-023 確認可出貨（新增，揀貨人員） | 揀貨相符（每條出貨明細的揀貨數量＝數量） | 依出貨方式拆單產生物流單，初始狀態可出貨（拆單表沿用 [[出貨單]] § 裝箱資料）；每箱寫入所屬物流單 |
| 可出貨 → 已裝箱 | OP-SHP-024 撤回確認可出貨（新增，揀貨人員） | 本單**全部物流單（含已作廢者）**都在可出貨；且沒有物流單的出貨動作處理中 | 刪除全部物流單，不走作廢、不填未送達數量（H4）；每箱的所屬物流單清空 |
| 可出貨之後 → 依物流單重算 | 物流單各操作與物流商回傳 | 刪去重新同步與補附送達憑證兩個觸發 | 最落後順序起點改為可出貨 |
| 未處理／打包中／已裝箱／可出貨／等待出貨 → 已作廢 | OP-SHP-012 作廢出貨單；系統：訂單取消 | 本單屬未離廠 | 底下物流單一併作廢；整張明細回補；已拋單者物流商端由出貨人員在系統外取消托運（G3） |

- 整張作廢與訂單取消連鎖作廢**含物流單在等待出貨的出貨單**（SHP-030 裁決 B）。物流商端由出貨人員在系統外取消托運；漏取消而物流商仍收件時，系統內沒有回收路徑，此風險經拍板接受。
- 撤回與出貨動作的先後：任一筆物流單的拋單、出貨確認或標記可自取處理中時，撤回擋下；撤回執行中時，這些出貨動作擋下。先成立者為準。

集合詞改依物流單狀態判定（H6）。先定義物流單集合詞「已離廠」＝已出貨、可自取、運送中、例外（任一）、已送達、已自取。

| 集合詞 | 新定義 |
|---|---|
| 未離廠（原「未出貨動作」改名，Q4） | 本單沒有物流單（未處理、打包中、已裝箱），或全部未作廢物流單都在可出貨或等待出貨 |
| 部分離廠 | 至少一筆未作廢物流單已離廠，且仍有未作廢物流單在可出貨或等待出貨 |
| 全數離廠 | 全部未作廢物流單都已離廠 |

「未出貨動作」改名「未離廠」（Q4），只保留為整張作廢與訂單取消連鎖作廢的條件；出貨動作的定義（拋單、出貨確認、標記可自取）不變。原以「未出貨動作」把關改明細、修正揀貨、刪箱的位置，落卡時一律改寫為 § 三的新條件：

| [[齊套邏輯]] | 回補入口「未出貨動作期間調低出貨明細數量」 | 確認可出貨前調低出貨明細數量 |

訂單取消連鎖（MODIFIED [[訂單狀態]] 取消連鎖）：

- 逾期標示、訂單預計交貨日期、印件已離廠量的「已出貨」＝全數離廠，等待出貨不算（SHP-028 裁決 A）。

| 專車配送、其他 | 可出貨 → 已出貨 → 已送達 |

| 修改項目 | 操作 | 可執行條件 |

| 出貨明細數量 | OP-SHP-001 編輯出貨單 | 出貨單狀態為未處理、打包中或已裝箱 |

- MODIFIED [[出貨單狀態]] § 揀貨不符原文「兩數相符即放行，不另設確認關卡」：改為確認可出貨這道關卡，揀貨不符只擋它，不再逐筆擋出貨動作（grill 連帶拍板）。
- 為什麼不在完成裝箱回報當下鎖：已裝箱是揀貨人員修正揀貨數量與增刪箱的窗口；物流單產生前改都不牽動物流單。鎖在完成裝箱回報，揀錯就只能作廢重建。
- 已裝箱時還沒有物流單，新增箱與刪除箱不再牽動物流單。
- 推翻 10-22 G49：確認可出貨後不能新增箱。要多出一箱，處置見 § 必含段③。
- 箱序：三位數、不重排、唯讀；新增箱時先顯示下一個箱序（G22、G24）。
- 箱規固定選項「自訂」改名「自訂箱規」；選它時名稱必填、預設帶「自訂箱規」（G23）。

### 五、北極星「印件準時完工率」（H9、H10）

| 項目 | 定義 |
|---|---|
| 名稱 | 印件準時完工率（原印件準時交貨率） |
| 分子 | 期間內有完工日、且完工日不晚於印件內部完成日的大貨印件數 |
| 分母 | 期間內有完工日、且印件內部完成日有值的大貨印件數 |
| 完工日 | [[印件]] 新增欄位「完工日」（唯讀、系統寫入）：旗下工單**首次**全部完成（齊套，見 [[齊套邏輯]]）的那一天。主路徑即印製維度首次轉入「製作完成」那一天；先出一批路徑（製作中 → 出貨中）不經製作完成，仍在齊套當天寫入。寫入後不變，補做重開工單、工單實際完成日被覆寫都不改它 |
| 短出結案 | 短出結案由系統把未完成工單推成已完成，這一次齊套不寫完工日。已在短出前寫入的完工日照常保留、照常計入。短出結案時還沒有完工日的印件，之後即使售後補做再次齊套也不寫入 |
| 打樣印件 | 不寫完工日（不計入指標；打樣週期重跑時不留舊週期日期） |
| 印件內部完成日 | 取 [[印件]] 現有欄位 |
| 不計入 | 打樣印件；印件內部完成日為空者；已棄用印件；沒有完工日者 |

- 例：乙海報印件內部完成日 11/10。11/10 轉製作完成 → 準時。11/11 轉製作完成 → 未準時。
- 為什麼要存：[[工單]] 工單實際完成日在補做重開後取最後一次，事後算不回首次齊套的那一天（audit-r2 N1）。
- 已知限制（A12 經 Miles 2026-10-23 拍板）：
  - 逾期仍未完工的印件，完工前不進分母（與舊指標「出貨後才計入」同性質）。
  - 先出一批的印件，貨可能已送達，工單晚幾天才收尾（例：生管手動完成生產任務），完工日晚於送達日，算未準時；一直沒收尾則沒有完工日、不進分母。
- ORD-051 卡名隨改名連動（卡內議題「印件內部完成日留空的代表性」仍成立）。
- [[印件]]「送達日」說明中「印件準時交貨率錨點」一句改指新指標。
- [[北極星指標]] 第二項的定位句由「管交不交得出去」改為「管做不做得出來」；「為什麼錨在出貨那一天」段改寫為：出貨日混入出貨排程與物流商收件時間，工廠控不了；印件內部完成日是工廠對自己的承諾，完工準時才能準時交貨（Q3）。
- [[生產績效指標]] 中「漏單率、折損率驅動印件準時交貨率」改名為印件準時完工率。

### 六、訂單逾期標示（K1～K3）

| 層級 | 條件 | 標示 |
|---|---|---|
| 印件 | 系統日期晚於印件預計交期，且該印件尚未出貨 | 逾期 |
| 訂單 | 系統日期不晚於全部交完日，且旗下任一有效印件逾期 | 部分延遲 |
| 訂單 | 系統日期晚於全部交完日，且仍有有效印件尚未出貨 | 整單逾期 |

- 「尚未出貨」沿用 [[訂單]] 訂單預計交貨日期欄的現行定義：含這件印件的出貨單還沒有任何一張屬全數離廠。分批時，第一批全數離廠後即不再算尚未出貨（已知限制，與訂單預計交貨日期一致）。
- 部分延遲與整單逾期互斥，以全部交完日切開（K3）。
- 全部交完日為空時不判整單逾期；任一印件逾期時仍標部分延遲。
- 全部交完日＝訂單內部完成時間的下一個工作天，不變（K1）。
- 印件預計交期被改晚到全部交完日之後時，仍照 K3 只看全部交完日判整單逾期（ORD-060 裁決 A）。

### 七、批次列印與下載中心（G4～G17）

本段決定：出貨人員一次拿到要貼的單與托運總表。做錯的後果：漏印或印錯，貨貼錯單。

列印（[[下載檔案]] 新增 OP-DLF-003 列印物流單，動作類型＝建立；依 [[規範 - 實體]]「從清單勾選多筆、跨多張單據才建立的單據，登記在被建立的單據」）：

| 項目 | 規則 |
|---|---|
| 入口 | 出貨管理列表（子母表）勾選後按「列印」 |
| 勾選 | 勾母列＝勾底下全部未作廢物流單；子列可單選（G5）；勾選範圍沒有任何未作廢物流單時不能列印 |
| 可列印 | 未作廢的物流單；未拋單者在列印檔中缺物流商標籤（G6） |
| 產出 | 一律產「物流單列印」一份；勾選範圍含已拋單的順豐物流單時另產「順豐托運總表」；含已拋單的新竹物流物流單時另產「新竹托運總表」（G4） |
| 物流單列印內容 | 每筆物流單：物流商標籤（有才有）＋一頁出貨明細（整張出貨單的印件與數量，照 EC 版式，不放裝箱資料）（G17） |
| 托運總表內容 | 欄位與版式照 EC 現行版式（G17）；只列勾選範圍內該物流商已拋單（有物流單號）的物流單，未拋單者不列、不算異常；交給物流商的格式沿用 EC 現況，不另做實務驗證 |
| 系統動作 | 每產一份檔案，在下載中心新增一筆下載檔案，狀態等待中 |

### 十、業界範式對照與否決方案

| 本案機制 | 業界範式 | 對照 |
|---|---|---|
| 確認可出貨鎖數量 | SAP 出庫交貨單（outbound delivery）過帳發貨（post goods issue）後不可改數量，要改須先沖銷發貨 | 本案鎖點在確認可出貨；要改須撤回確認可出貨，對應沖銷。參考：[SAP Learning：Executing the Shipping Process](https://learning.sap.com/courses/exploring-sap-s-4hana-sales-essentials/executing-the-shipping-process_e796d891-1485-4b97-874b-f4cbcbd9dbc9) |

| 下載中心非同步產檔 | Shopify 大量匯出改為背景產檔、完成後以連結取得，失敗另行通知 | 本案改為下載中心列狀態，不發通知。參考：[Shopify Help：Exporting orders](https://help.shopify.com/en/manual/orders/export-orders) |

具名否決方案：

| 方案 | 否決理由 |
|---|---|
| 維持完成裝箱回報即產生物流單，只在拋單時鎖數量 | 後端要的是物流單產生前就鎖數量（BE-444）；裝箱回報修正仍會增刪物流單 |
| 在完成裝箱回報當下鎖數量、不設確認可出貨 | 揀錯或箱子要調整時只能作廢重建；已裝箱是修正窗口 |
| 撤回確認可出貨改走作廢物流單 | 物流單從未交出，作廢要填未送達數量又要回補，帳多繞一圈（H4 系統刪除） |
| 列印直接下載、不設下載中心 | 部分成功與失敗的結果沒有地方查、也無法事後再下載（G7～G13 拍板要狀態與異常內容） |
| 保留離廠時間、只刪實際出貨日 | 集合詞仍要兩套依據（時間與狀態）；H6 拍板改依狀態 |

MODIFIED [[物流單]] 營運背景「被否決：物流單到拋單時才產生」：本案物流單在確認可出貨時產生，不是拋單時；已裝箱期間沒有物流單，出貨單在已裝箱以前不依物流單計算、之後才計算，推進規則仍只有「依物流單計算」一套，舊否決理由（推進規則切兩段）不成立。

### ④ 拍板引用與隱含假設段

隱含假設清單（設計者自補，Miles 未明說）：

| 序 | 假設 | 理由 |
|---|---|---|
| A1 | 物流單集合詞「已離廠」含例外（任一）。第三方物流在等待出貨時被物流商回傳例外，也算已離廠。已知限制：貨若其實還在廠內，逾期標示也會解除 | 狀態判定看不出例外的來處；算已離廠時只能逐筆作廢、填未送達數量，較保守 |
| A2 | 可出貨的物流單，在本單有任一物流單（含已作廢者）不在可出貨時可單筆作廢，理由必填、填未送達數量 | 確認後不能刪箱；有其他物流單已推進時撤回走不通，需要這條出口 |
| A3 | 確認可出貨時不檢查訂單是否已取消 | 訂單取消會連鎖處置出貨單；已裝箱的單會被系統作廢，不會留到確認時 |
| A4 | 撤回後再確認可出貨，物流單編號接續原序號、不重用已刪除的序號 | 沿用 [[物流單]] 編號「不重用、不重排」 |
| A5 | 撤回確認可出貨與確認可出貨記在出貨單歷程紀錄（含刪除與產生的物流單編號） | 被刪的物流單沒有歷程可留；查重複建單時要有編號 |
| A6 | 第三方物流保留送達確認作為配達沒回傳時的備援，開放範圍加等待出貨 | G2 只說以物流商狀態為準，沒說刪備援；物流商回傳中斷時，等待出貨沒有人工出口 |
| A7 | 物流商回傳中「已登記追蹤」一類訊息不推進物流單狀態；不預設串接來源 | H8 第三方物流不經已出貨；串接機制由後端決定 |
| A8 | 批次拋單送出本單全部可出貨的物流單；批次拋單鈕在第三方物流一律顯示，沒有可出貨物流單時停用並說明理由 | 沿用 10-22 G39、G53、G55，把已裝箱換成可出貨；揀貨不符已在確認可出貨擋下 |

| A10 | 托運總表只列勾選範圍內該物流商已拋單的物流單，是否已拋單以按列印當下為準；物流單筆數各自計算；沒有已拋單者不產該總表 | G4 依物流商另產總表；未拋單沒有物流單號，列進總表物流商收件時對不上 |
