# 出貨對話框、批次列印、下載中心與「可出貨」狀態 grill 拍板紀錄（2026-10-23）

起因：
- 出貨人員要一次掌握當批貨與要貼的單：要能一次列印多筆物流單與托運總表，檔案集中在一處下載。
- 出貨單對話框的說明文字過多，介面字樣各頁不一致，要收斂成一份通則。
- 後端 Raymond 在 BE-444 提出：數量要有明確的鎖定點，物流單不要隨裝箱回報修正頻繁增刪。Miles 已定案，不另回覆。

前案：change 2026-10-22-shipment-batch-dispatch-box-size（grill G37～G59）、change 2026-10-23-box-spec-dimensions-from-master（grill G60～G62）。本檔 G 序號重新起算，前綴與前案不衝突時一律寫全稱「本檔 G1」。
本檔只記拍板結果，供 proposal、design、plan-audit、wiki-amend 承接。
變動性質：結構性變更。理由：新增出貨單與物流單狀態、新增下載中心模組與下載檔案實體、北極星指標定義變更。稽核走 rubric 加雙盲對抗式情境推演。

## 二、出貨單「可出貨」狀態（BE-444，Raymond 建議）

| 序 | 題目 | 拍板 |
|---|---|---|
| H1 | 新增狀態 | 出貨單新增狀態「可出貨」 |
| H2 | 進入方式 | 揀貨人員完成裝箱回報後，按「確認可出貨」。前提：揀貨相符。系統此時依箱數產生物流單。完成裝箱回報不再產生物流單 |
| H3 | 鎖定範圍 | 確認可出貨後鎖住：出貨明細數量、揀貨數量、增箱、刪箱。箱規、長寬高、裝箱照片、裝箱備註在該箱所屬物流單離廠前仍可改 |
| H4 | 撤回 | 「撤回確認可出貨」由揀貨人員執行，限全部物流單仍在可出貨；系統刪除物流單，不走作廢 |
| H5 | 狀態名 | 出貨單狀態名為「可出貨」；物流單初始狀態同名「可出貨」 |
| H6 | 離廠時間 | 物流單「離廠時間」欄位刪除；集合詞改依物流單狀態判定。未出貨動作＝沒有物流單，或物流單全在可出貨或等待出貨 |
| H7 | 實際出貨日 | 出貨單「實際出貨日」欄位刪除 |
| H8 | 第三方物流路徑 | 第三方物流不經過已出貨：等待出貨 → 運送中 → 已送達 |
| H9 | 北極星改錨點 | 北極星「印件準時交貨率」改為比對：印件印製狀態轉製作完成的日期 vs 印件內部完成日 |
| H10 | 北極星改名 | 改名「印件準時完工率」 |

連帶拍板：
- 部分離廠後新增箱取消（推翻 10-22 grill G49）。
- 揀貨不符只擋確認可出貨，不再逐筆擋出貨動作。
- SHP-024（實際出貨日取最晚離廠後的判定穩定性）失去前提，待結案。
- ORD-051（印件準時交貨率在大面積留空時的代表性）名稱隨 H10 連動。

## 三、日期與逾期（對照公司 2026-09-18《ERP 日期欄位架構定義與算法 v3》，Miles：都以文件為主）

| 序 | 題目 | 拍板 |

| K2 | 印件逾期 | ＝過了印件預計交期仍未出貨（照文件）。取消同場稍早「統一成逾期、看製作完成」的說法 |
