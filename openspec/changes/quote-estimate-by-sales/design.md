## Goals / Non-Goals

### Goals

- 把 `quote-request` spec 的行為對齊 wiki 正本與 Prototype。
- 移除「評估完成限印務主管」「Supervisor 重新指定評估印務主管」兩條既有把關，並寫清替代把關。
- 補齊成本估算編輯寫活動紀錄的 Scenario。

### Non-Goals

下列行為不寫進本變更的 spec。對應 OQ 拍板前不得進 propose。

| 不寫的行為 | 依賴 OQ |
|-----------|--------|
| 印務主管看全部需求單（含未被指派的單） | QR-015 |
| 狀態轉換角色把關的後端強制 | QR-009 |
| 自動編輯授權可改欄位範圍的後端限縮 | QR-016 |
| 成本估算可改時機的後端限縮 | QR-018 |
| 後端活動紀錄補記欄位編輯的實作 | QR-017 |

## Decisions

### D1：評估完成改由業務、諮詢執行，保留「全部填畢」條件

| 選項 | 利 | 弊 |
|------|----|----|
| A：業務、諮詢執行，印務主管無系統動作 | 權限最單純 | 印務主管想自己填成本時沒有入口 |
| B：業務、諮詢執行，印務主管可改被指派單的成本（採用） | 對得上實務，印務主管也能自己填 | 多一組欄位級權限 |
| C：維持印務主管執行 | 不改規格 | 手冊與現場持續不一致 |

採 B（QR-010 裁決）。移除「評估完成限印務主管」的替代把關如下：

1. 保留「全部印件項目成本估算填畢才能評估完成」。
2. 成本估算每次編輯寫一筆活動紀錄，事後查得到誰填。

第 2 項在後端能否成立，要看 QR-017 的裁決。

### D2：成本估算與預計產線用同一套修改者與時機

兩欄都是成本評估的產出，分開規定會讓印務主管改得了一欄、改不了另一欄。議價中不開放直接改：直接改會讓報價依據與報價紀錄對不上，要改就走「重新評估報價」，重估完成時建新報價紀錄。

### D3：評估印務主管改多選，非終態時業務、諮詢可改人選

原規則是「送評估後鎖定，只有 Supervisor 可解鎖」。改人選是業務對這張單的安排，找主管解鎖只會拖慢換人。本變更同時刪除 Supervisor 解鎖的 Scenario 與詳情頁主動作群的「Supervisor：重新指定印務主管」。

被指派者自動取得編輯授權、移出即撤銷，是後端既有機制。後端另有兩個副作用，本變更不寫進 spec：

- 移出時一併撤銷該人另外經分享取得的編輯授權。
- 增選時先撤銷該人原有的檢視授權，再建編輯授權。

這兩項屬後端實作現況，是否要改由 QR-016 一併裁決。

### D4：Slack 通知只在進入待評估成本時發

照後端現況（S-4）。其餘轉換都由業務或諮詢自己執行，通知沒有收件人。原 spec 的「多個關鍵轉換都通知」Scenario 改寫為「其他轉換不發通知」。

### D5：報價紀錄頁籤不依角色隱藏，評估者記按評估完成的人

印務主管重估時要看前幾輪成本（S-8）。評估者記按「評估完成」的人，不另記成本填寫者；誰填了成本看活動紀錄。

### D6：業務主管改派入口在終態不顯示

原 spec 寫「成交、流失後改派入口停用並顯示提示」。Prototype 在終態直接不顯示改派入口。當前狀態用不到的操作鈕直接隱藏，是既有介面原則，spec 依 Prototype 改寫。

### D7：主 spec 的 Data Model 說明歸檔時手動同步

主 spec Data Model 段的「報價紀錄評估者」說明寫「評估者（印務主管）」。這段不在 Requirement 內，歸檔合併不會改到。本變更把「評估者記按評估完成的人」寫進 § 成本評估，歸檔時再手動改 Data Model 說明（見 tasks）。

## Risks / Trade-offs

| 風險 | 緩解 |
|------|------|
| 後端尚未強制角色限制，正式環境中評估印務主管仍可能按到評估完成 | QR-009 拍板前，spec 只寫商業行為；後端交付項標明依賴 QR-009 |
| 後端活動紀錄只記狀態轉換，替代把關在正式環境尚不成立 | QR-017 拍板前，後端移除「評估完成限印務主管」不得進 propose |
| 被指派者的自動授權在後端可改接單業務與評估名單 | 列入 QR-016；spec 只寫被指派者可改成本估算與預計產線 |
| 後端在所有非終態都可改成本，議價中也改得到 | 列入 QR-018；Prototype 已在議價中鎖成本 |
