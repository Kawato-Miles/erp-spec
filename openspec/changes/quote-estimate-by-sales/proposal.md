## Why

### Background

需求單的成本評估分工已於 2026-09-24 拍板並落卡，商業正本如下：

| 正本 | 本變更承接的內容 |
|------|----------------|
| [需求單狀態](../../../memory/Sens_wiki/wiki/erp/06-state-machines/需求單狀態.md) | 「評估完成」改由業務或諮詢執行；轉換條件維持「全部印件項目成本估算填畢」；刪除者排除因評估指派取得的編輯授權 |
| [需求單](../../../memory/Sens_wiki/wiki/erp/05-entities/需求單.md) | 評估印務主管改多選、非終態可改人選；成本估算與預計產線的修改者與時機；線上討論連結沒有值時可補填 |
| [印務主管](../../../memory/Sens_wiki/wiki/erp/03-roles/印務主管.md) | 只協助成本、不推進需求單；被指派的單可改成本估算與預計產線 |
| [需求單評估Slack通知串接約束](../../../memory/Sens_wiki/wiki/erp/04-business-logic/外部約束/需求單評估Slack通知串接約束.md) | 只在進入待評估成本時發通知；首次開串、重返時原串回覆 |
| [需求單報價成交](../../../memory/Sens_wiki/wiki/erp/07-scenarios/需求單報價成交.md) | 業務回填成本並按評估完成；評估完成不通知業務；換評估印務主管與通知失敗的接手 |
| [QR-010 需求單成本評估的實務分工與系統把關落差](../../../memory/Sens_wiki/wiki/erp/08-open-questions/_archives/2026/QR-010-需求單成本評估的實務分工與系統把關落差.md) | 裁決 B：業務部門執行評估完成，印務主管保留編輯成本估算 |

### Problem Statement

實務上，業務送印務評估後，與印務主管在 Slack 討論成本，再由業務回填成本並推進需求單。`quote-request` spec 仍寫「評估完成由印務主管執行」「評估完成後通知業務」「評估印務主管送評估後鎖定、只有 Supervisor 可解鎖」。印務主管為了一顆按鈕要登入系統，操作手冊教的操作也與現場不同。Prototype 已依新正本實作，行為規格落後於商業正本與介面正本。

## What Changes

### New Capabilities

無。

### Modified Capabilities

| 變動 | 現行 spec | 改為 |
|------|----------|------|
| 評估完成的執行者 | 印務主管 | 業務、諮詢；轉換條件不變 |
| 成本估算、預計產線的修改者與時機 | 印務主管填成本；已評估成本由印務主管改 | 業務、諮詢在需求確認中、待評估成本、已評估成本可改；被指派的評估印務主管在待評估成本、已評估成本可改；議價中要改成本走重新評估報價 |
| 評估印務主管欄 | 單選；進入待評估成本後鎖定，僅 Supervisor 可解鎖 | 多選；非終態時業務、諮詢可改人選；被指派者自動取得編輯授權，移出即撤銷 |
| 詳情頁主動作群 | 「PM 或業務：評估完成」「Supervisor：重新指定印務主管」 | 評估完成歸業務、諮詢；刪除 Supervisor 重新指定 |
| Slack 通知 | 多個關鍵轉換都通知 | 只在進入待評估成本時通知；首次開串並回寫線上討論連結；重返時原串回覆；改人選不重發 |
| 評估完成後的通知 | 通知業務 | 不通知 |
| 報價紀錄頁籤 | 限業務、業務主管 | 能開這張需求單的人都看得到 |
| 報價紀錄的評估者 | 印務主管 | 按「評估完成」的人 |
| 線上討論連結 | 通知失敗時業務可補填 | 沒有值時業務、諮詢可補填；有值後唯讀 |
| 刪除者 | 接單業務、建立者或被授權編輯者 | 接單業務、建立者、經分享取得編輯授權者；因評估指派取得的編輯授權不含刪除 |
| 活動紀錄 | 已要求記錄編輯，無對應 Scenario | 補「成本估算每次編輯寫一筆活動紀錄」Scenario |
| 業務主管改派接單業務 | 成交、流失後入口停用 | 成交、流失後入口不顯示；業務不能自己改接單業務 |

**BREAKING**：移除「評估完成限印務主管」與「Supervisor 重新指定評估印務主管」兩條既有把關。替代把關為保留「全部填畢才能評估完成」，並以活動紀錄記下每次成本編輯的人。

### Out of Scope／Pending

下列行為依 plan-audit 第三輪處置帶進本變更的限制：**對應 OQ 拍板前不得進 propose**。本變更的 spec 不寫這些行為，tasks 的後端與 Linear 交付項註明依賴。

| 不納入 | 原因 | 依賴 OQ |
|-------|------|--------|
| 印務主管看全部需求單的權限 | 後端缺「檢視全公司需求單」權限 | [QR-015](../../../memory/Sens_wiki/wiki/erp/08-open-questions/QR-015-印務主管檢視全公司需求單的後端權限未支援.md) |
| 狀態轉換角色把關的後端強制 | 後端狀態轉換只驗編輯授權 | [QR-009](../../../memory/Sens_wiki/wiki/erp/08-open-questions/QR-009-需求單狀態轉換的角色把關後端未擋.md) |
| 自動編輯授權可改欄位範圍的後端限縮 | 被指派者的自動授權可改接單業務與評估名單 | [QR-016](../../../memory/Sens_wiki/wiki/erp/08-open-questions/QR-016-評估印務主管的自動編輯授權可改接單業務與評估名單.md) |
| 成本估算可改時機的後端限縮 | 後端在所有非終態都可改成本 | [QR-018](../../../memory/Sens_wiki/wiki/erp/08-open-questions/QR-018-需求單成本估算可改時機後端未依狀態限縮.md) |
| 後端活動紀錄補記欄位編輯的實作 | 後端只記狀態轉換；spec 的「活動紀錄」Requirement 已存在，本變更不改寫其行為，只補 Scenario | [QR-017](../../../memory/Sens_wiki/wiki/erp/08-open-questions/QR-017-需求單活動紀錄未記欄位編輯.md) |

QR-017 拍板前，「移除評估完成限印務主管」在後端的落地同樣不得進 propose：替代把關之一（活動紀錄記下成本編輯）在後端能否成立，要看 QR-017 的裁決。

## Capabilities

### New Capabilities

- 無

### Modified Capabilities

- `quote-request`：評估完成改由業務、諮詢執行；成本估算與預計產線的修改者與時機；評估印務主管多選且非終態可改；Slack 通知只在進入待評估成本時發；報價紀錄頁籤與評估者；線上討論連結補填；刪除者排除評估指派授權；活動紀錄補成本編輯 Scenario；改派入口在終態不顯示。

- Prototype：erp repo 分支 `prototype/production-stage` 已實作並推送（需求單 92a94b1b、單位同步 57538252）。
- 測試：Sens `erp-prototype-tests` 第一章已同步並通過（1.2、1.5、1.13～1.16 等）。
- 後端與 Linear：角色限制的後端強制、印務主管全見、活動紀錄補記欄位編輯，皆待上表 OQ 拍板後另行交付。
