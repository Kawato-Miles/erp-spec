## Goals / Non-Goals

### Goals

- 報工、點收、搬運數量、品檢、缺口處置、裝箱回報六種紀錄，都用同一套「修正原紀錄、每個被改的欄位留一筆修正紀錄」的承諾。
- 報工修正與作廢的可操作範圍改由入口決定，與新增報工的範圍一致。
- 會動到同一印件待驗量、可出貨額度或同一張出貨單揀貨判定的寫入，都以寫入當下的數字重新檢核。
- 揀貨不符在貨離廠前停下，出貨單停在待出貨直到兩數相符。
- 用詞與 wiki 一致：搬運量、點收量、點收數量、完成數、報工照片、物流單號。

### Non-Goals

- 拋單失敗的處置、第三方狀態對映、物流商配達回傳的介接（SHP-020）。
- 建單人不在時誰改出貨明細（SHP-021）、移除單條出貨明細（SHP-022）。
- 計入完成度任務報廢後已驗量的處理（QC-010）。
- 外包廠與中國廠商任務經工單詳情報工與修正的 Prototype 入口（grill 第 42 題另案）。
- 審稿難易度、發票等其他領域的「更正」用詞。
- 介面版型（側板分區、縮圖欄、對話框分頁）：正本是 Prototype，spec 不寫。

## Decisions

### 一、修正改原紀錄，修正紀錄逐欄位留存

- 選擇：原紀錄就地改值；每次修正對每個被改的欄位各寫一筆修正紀錄（修正前、修正後、修正人、時間、原因），照片欄另留修正前照片。
- 替代方案：品檢沿用負數沖銷紀錄、原紀錄不改。
- 理由：報工已採就地修正，品檢若維持沖銷，同一批貨的兩本帳一本要心算正負號、一本不用；修正紀錄已保留原值，稽核軌跡沒有消失。逐欄位一筆，查單一欄位的修正史最直接（grill 第 44 題）。
- 影響：品檢累計改為各筆修正後的值加總，系統不再產生負數紀錄；既有負數紀錄的資料遷移見 Migration Plan。

### 二、修正範圍掛在入口，不掛在角色

- 選擇：系統依使用者從哪個入口操作，決定渲染哪些報工的修正與作廢，寫入時再照同一範圍檢查一次。
- 替代方案：沿用「師傅限自己提交；生管、印務、印務主管不受此限」的角色例外。
- 理由：入口範圍已由報工權限守門定義，修正沿用同一範圍就不必另開例外；角色例外會讓印務主管在所有生產任務改得動非自己負責工單的外包任務，與工單分享機制衝突。
- 影響：外包廠與中國廠商任務不在所有生產任務，其報工只經工單詳情修正；工單詳情因此新增「檢視」開同一個生產任務側板，不另做一套修正畫面。

### 三、併發寫入以寫入當下重新檢核

- 選擇：先寫入者成立；後到者以寫入當下的數字重新跑自己的擋下條件，檢核不過就擋下並告知卡住的數字。
- 替代方案：鎖定整個印件或整張出貨單，一次只允許一人操作。
- 理由：鎖定會讓品檢人員驗收時，同一印件的報工與出貨全部卡住；重新檢核只在數字真的衝突時擋下，平常不影響並行作業。
- 落點：三個 capability 各加一條 Requirement，各自列出自己那一側的寫入，互相引用，不在單一 spec 集中列全部寫入。

### 四、一次報多筆整批成立或整批不寫入

- 選擇：逐筆跑完全部檢核後才決定寫入；任一筆不過，整批都不寫入，並把原因標在被擋下的那一筆。
- 替代方案：通過的先寫入，被擋下的留在畫面上重送。
- 理由：部分寫入時現場分不清哪幾筆已記進帳，只能回頭逐筆作廢（grill 第 55 題）。

### 五、揀貨不符做成轉換條件，不做成狀態

- 選擇：「揀貨相符」是待出貨離開的轉換條件；不符時拋單、出貨確認、交付確認都不渲染，出貨單停在待出貨，列表加「揀貨不符」標示。
- 替代方案：新增「揀貨異常」狀態。
- 理由：不符時貨仍在廠內、業務與揀貨人員都還改得動，停在待出貨就表示「這張單還不能走」；新增狀態會讓解除後要多一條回到待出貨的弧，狀態機無故變大。兩數相符即自動解除，不另設確認關卡（grill 第 36 題）。

### 六、品檢通過下限取代負額度暫態

- 選擇：品檢修正調低通過時，不得低於未作廢、非異常出貨單的出貨明細合計；系統內因此不再出現可出貨額度為負的暫態。
- 替代方案：沿用「允許完工良品數暫時低於累計已出貨數量，由改單或作廢收斂」。
- 理由：Miles 選擇系統內不出現額度不足（grill 第 28 題）；擋在品檢修正那一刻，順序就固定為業務先調低出貨明細、品檢再修正。
- 影響：shipment § 數量帳守恆鏈的暫態段落改寫；qc 與 production-execution 的逐層修正情境補上「已有出貨明細佔用」這一層。

### 七、物流單號在 Prototype 以拋單即生成模擬

- 選擇：拋單成功時寫入物流單號與物流單；Prototype 以按下拋單即生成一組號碼模擬回傳，不模擬配達回傳。
- 理由：SHP-020 只拍板「物流單號由物流商回傳」，介接方式與失敗處置未決；spec 只承諾欄位由回傳寫入、出貨人員不手填，介接留給 SHP-020。

### 八、前置未到料改以清單標籤呈現

- 選擇：生產管理的任務清單以狀態欄「前置未到料」標籤呈現被前置卡住的任務，等貨說明放在生產任務側板；側板不顯示可做量，師傅工作包任務清單的可做量呈現不變。
- 依據：Prototype 試用後調整（erp 提交 0a7b33c9，情境目錄 14.29、14.39）與 grill 第 26 題。這一項取代收斂 change 底稿中「所有生產任務不呈現前置狀態」一句，是依 Prototype 為介面正本所做的對齊，wiki 對此沒有規則。

### 九、RENAMED 與 MODIFIED 的底稿

- 選擇：production-execution 中由收斂 change 新增的 Requirement（報工前提、已完成任務不可新增報工、點收紀錄的修改與作廢、生產數量錯誤的逐層更正），本 change 以收斂 change 的文字為底改寫，RENAMED 的 FROM 寫收斂 change 的原名。
- 理由：兩個 change 動到同一批 Requirement，分兩次改名會在歸檔時找不到標題。

## Risks / Trade-offs

| 風險 | 緩解 |
|------|------|
| 本 change 早於收斂 change 歸檔時，RENAMED 與 MODIFIED 找不到底稿 | 歸檔順序固定：收斂 change 先歸檔；本 change 歸檔前，以歸檔後的主規格重新比對 MODIFIED 區塊 |
| 品檢改為就地修正後，既有負數紀錄與新算法不相容 | 資料遷移把每組原紀錄與沖銷紀錄合併為一筆修正後的紀錄，沖銷紀錄轉成品檢修正紀錄（見 Migration Plan）；Prototype mock 已轉換 |
| 併發重新檢核在 Prototype 無法重現（mock 存在單一瀏覽器記憶體） | Prototype 與純函式測試只驗「以當下數字判定」；同時寫入的行為留給後端實作時驗證 |
| 揀貨不符擋下出貨後，建單人不在時無人改明細，單會一直停在待出貨 | 屬 SHP-021 未決範圍；期間由揀貨人員照實修正或由業務主管系統外協調，本 change 不另開路徑 |
| 某條明細全數缺貨時揀貨數量無法填 0 或移除該條 | 屬 SHP-022；現況可作廢整張單重建 |
| 處置修正在 Prototype 開放印務與印務主管，wiki 印件卡只寫印務 | spec 只寫「印務可修正、誰可修正見 wiki」，不擴大；落差列入 Open Questions |
