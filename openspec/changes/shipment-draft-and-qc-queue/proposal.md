# 出貨單草稿態與品檢待驗清單改版

## Why

### Background

業務在業務主管審核通過後就開始管理款項與出貨：與客戶談定這一批哪天出、送到哪，當下就要記下來。但可出貨額度要等品檢通過才長得出來，現行「建單即檢核額度」讓審核通過當下建不出任何出貨單，出貨計畫只能散在通訊軟體。品檢側則有兩個漏：待驗清單依「品檢站在站量」推導，末道生產任務漏指品檢站或標不需轉交的印件永遠不會進清單；多部件印件多筆任務各自搬到品檢站時，在站量加總的數字沒有意義。

### Problem Statement

- 業務主管審核通過後建不出出貨單：額度為 0 必被擋，出貨計畫無處可記。
- 待驗清單掛在轉交事實上：漏指品檢站、末道不需轉交、多部件加總三種情形下品檢會漏或數字無意義。
- 點收者依角色判定：品檢站只有品檢人員角色能點收，代班與跨線人員被卡住。
- 第三方物流的送達靠出貨人員查了再回填，與物流商手上的事實脫節。

## What Changes

- **出貨單新增「草稿」初始態**：業務先建草稿排出貨計畫（單頭＋預計出貨印件，只驗預計出貨日），品檢通過後按「建立出貨單」才進未處理。草稿不佔額度、不進揀貨與出貨人員清單、不推進印件與訂單、唯一出口為刪除（人工或訂單取消連鎖）。
- **建立出貨單改兩段檢核**：必填先於額度；額度不足整張擋下、訊息只留一句「可出貨額度不足，出貨單未成立」（原「帶兩條出路」刪除）。
- **「出貨中」觸發點**：首張出貨單由草稿轉未處理時觸發，草稿本身不觸發。
- **新欄位行為**：寄件資訊依訂單帳務公司唯讀帶出；收件三欄預設帶訂單窗口聯絡人可改；出貨方式合一欄六值；出貨確認補重量（選填）。
- **BREAKING（翻案 SHP-015）第三方物流送達**：物流商回傳配達時間自動推進為主，出貨人員手動送達確認為備援；專車與自取不變。
- **BREAKING（翻案 2026-07-21 拍板）待驗清單口徑**：待驗量＝齊套完成數 − 已驗量，只看製作事實、不看轉交與點收；單筆驗收上限改為送出那一刻的待驗量、整筆擋下、輸入框不夾值；多部件與不需轉交不另設規則；貨的位置由轉交單管理回答。
- **點收統一依人員所屬產線**：品檢站與生產站同一條規則、不看角色；生管、印務、印務主管代點收不變。
- **訂單取消連鎖**：出貨單層加「草稿由系統刪除」一段。
- **外發貨進待驗清單**：改由印務報工觸發，轉交與點收只回答貨在哪。
- **plan-audit 第一輪回補（2026-09-20 拍板）**：待驗量基數改各計入完成度任務良品數最小值（QC-009）；報工作廢加「已被品檢驗過」第三道檢核；印件與訂單「製作中 → 出貨中」補弧；物流商回傳只對運送中且托運單號相符者生效、配達＝簽收或取件完成、先寫入者成立；收尾判定集合排除草稿；建立時已棄用重檢；新建畫面一步建立仍經草稿；建立時記下帳務公司；更正下限（累計不得低於 0）；待驗清單加所屬訂單編號與客戶名稱、負值照實。
