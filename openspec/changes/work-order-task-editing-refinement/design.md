## Context

印務每天在工單詳情做兩件事：讀單（確認這張單要做什麼、什麼時候做）與改單（調數量、調順序、補交代）。現行介面把生產任務切成材料／工序／裝訂三段表格，欄寬過寬要橫向捲動，而真實生產順序會交錯（工序 → 材料 → 工序），分段結構表達不了。數量只有一個含放損的目標數量與一個放損率，看不到絕對損耗張數，與現場跟師傅溝通的語言脫節。急件的事實散在訂單布林欄與線上商品售價加成兩處，生產側看不到標示、交期也不反映提前。工單列印目前只有一個樁，紙本工作印製傳單仍靠手工維護。

本 change 承接 2026-08-25 拍板的設計（rubric 稽核全過、wiki 已先落卡），只做商業層已定案的部分。商業規則、欄位與狀態列舉的正本在 wiki；本檔只記為什麼這樣切、以及否決了哪些做法。

分級為結構性變更：新增印件與急件主檔的跨模組關聯、改寫 [[數量換算規則]] 的放損口徑。

## Goals / Non-Goals

### Goals

- 生產任務的投入計畫拆成兩個可編輯欄（預計生產、放損），目標數量退成唯讀加總，讓現場溝通回到絕對張數。
- 生產任務清單改單一平列，順序由印務控制且改順序是一次有意識的動作。
- 急件成為印件層的一筆事實，交期扣減只算一次、生產側看得到標示與扣減後的承諾日。
- 工單能印出交工廠的紙本單據，內容與系統當前已生效的工單一致。
- 每一筆既有生產任務都能拆出兩欄，且目標數量與報工事實不被改動。

### Non-Goals

- 急件成本（售價乘百分比加價）：拍板不做，急件主檔的金額調整欄本案不取用。
- 生產任務排程的急件自動連動：預計開工日已全面改手填，沒有自動值可連動。
- 手改數量後的上下游對照顯示或偏離警示：拍板不做，對齊責任在印務。
- 異動改量的下限校驗：拍板不設。
- 含成本版的工單匯出、正式的 PDF 產生器、列表直接拖曳排序：皆拍板不做或不在本階段。
- 內部製作截止日的口徑調整：維持現況不動。

## Decisions

### D1：投入計畫拆兩欄，目標數量退成唯讀加總

預計生產（要交出的量）與放損（預留損耗，絕對數）皆可編輯，目標數量 ＝ 兩者加總、不可直接輸入。三類 BOM 統一兩欄化，取整方向不變（下行進位、上行捨去）。

- **否決：維持單一目標數量欄加可調放損率。** 同一件事會有兩條改法（改率或改量），事後查不出這筆的損耗是誰用哪種方式決定的；而且師傅要的是張數，百分比得自己換算。
- **否決：目標數量與放損兩欄可改、預計生產當衍生值。** 印務規劃時先決定的是「要交多少」，把它做成衍生值等於逼人反推。
- 業界佐證：印刷業資料交換標準 JDF（CIP4，https://www.cip4.org）在生產意圖上把 Amount 與 Waste 分列為兩個屬性，設備端回報也分開累計。

### D2：放損率降為唯讀參考，且僅工序型任務顯示

自工序主檔帶出後凍結於任務，主檔改率不回寫。材料型與裝訂型不顯示此欄——材料主檔與裝訂主檔本來就沒有放損率參數，硬要顯示只能給 0，讀者會以為那是「這道工序不會損耗」。

### D3：預填只發生一次，手改不重算上游、不顯示對照

建立或展開當下沿相依鏈倒推預填兩欄；之後印務改任一任務的量，系統不重算上游、不顯示上下游落差、不發警示。

- **否決：手改後即時重算上游。** 會把印務刻意調過的上游數字再蓋掉一次。
- **否決：不重算但顯示上下游對照或偏離警示。** Miles 裁決不做——多一個要人看的提示，卻沒有人被要求為它負責；缺料走既有補做與異動、多做走既有成品處置，兩條路都已存在。

### D4：改量不設下限，低於已投入即依既有判定完成

異動下修後的目標數量允許低於已報工的投入累計，該任務依生產任務狀態的既有判定完成，已報工成本照實留在實際成本、數量帳不回沖。

- **否決：擋下並要求以報廢處置多做的部分（原 spec 條文）。** 投入已超過新目標時那批貨就是做完了，硬走報廢只是讓數字好看，反而讓實際成本與真實投入脫節。

### D5：預計開工日全面改手填，不做倒推預填

系統不預填、不自動計算，也不留「手動填寫」標記欄。推算完工日維持依已填的開工日順推，未填不推。工單自動排程功能啟用時才恢復自動計算（預留、本案不實作）。

- **否決：維持依交期與主檔工期倒推預填。** 預填值的基準（哪一個交期減工期）與急件提前後的承諾日互相打架，印務每次都得先判斷這個值是照哪個交期算的。取消預填直接消解矛盾根源，而不是再補一層規則去說明預填值該用哪個基準。
- 代價見 Risks（漏單率的分母隨手填率變動）。

### D6：清單改單一平列卡片，順序值由排序操作區控制

初始順序在建立或展開當下落一次（材料→工序→裝訂），之後全由排序操作區調整，新任務插最後。排序值屬實作規格、不入 wiki 欄位表。

- **否決：維持材料／工序／裝訂三段表格。** 真實順序會交錯，分段表達不了；欄位一多欄寬就過寬要橫捲。
- **否決：卡片清單上直接拖曳排序。** 清單是每天在點的操作區，拖曳誤觸會改掉順序而沒人發現。
- **選定：獨立排序操作區，拖曳後按確定一次生效、取消不生效、送出時比對清單版本。** 版本比對是因為排序期間別人可能加開或作廢任務，寫回過期順序會讓新任務憑空跑到中間。

### D7：急件掛印件層，天數選定當下凍結成快照

印件必填急件選項（單選急件主檔，一般件即天數 0 的一筆資料），選定當下凍結名稱與天數。訂單交期（扣除急件）＝ 客戶交期 − 凍結天數，唯讀推導、日曆日計、早於今日照實顯示。

- **否決：急件掛訂單層。** 一張訂單常只有一件印刷品要趕，訂單層的布林值答不出是哪一件、趕幾天。
- **否決：交期扣減時即時回查急件主檔的天數。** 主檔天數會被維護者調整，即時回查會讓半年前那件印件的承諾天數跟著變，事後查不出當初承諾了什麼；也會讓停用一筆選項連帶影響已成立的訂單。快照做法比照計價快照的既有慣例。
- **否決：新增印件獨立交貨日期欄位（PI-007 原提案）。** 改以唯讀推導欄承載，PI-007 隨本案結案——可填欄會出現「客戶交期 8/20、急件三天、承諾日填 8/22」這種對不起來的資料。

### D8：訂單「是否急件」降為純注記

既有欄位沿用、不新增欄位，語意明確為注記（讓相關人員知悉），不參與任何日期計算。審稿待審清單的急單標示改看印件急件選項。

- **否決：刪除該欄。** 業務習慣在訂單層打個記號提醒同事，留著不礙事；問題只在它不能當計算來源。

### D9：工單預計交期承接扣減後的承諾日，終態工單不回寫

非終態工單隨印件推導值同步，已完成或已取消的工單不回寫。

- **否決：連帶調整訂單的內部製作截止日。** Miles 裁決維持現況不動——生產側以工單預計交期為準，急件單的內部節奏由印務掌握，必要時業務手動調整訂單截止日。機制最少；出貨實務若依賴訂單截止日再翻案。

### D10：急件選項變更走專用通知，通知旗下工單負責印務

通知對象限旗下工單的負責印務（為空則印務主管），不限製作段，沿用既有通知與留痕機制。急件選項不列入「製作後印件規格異動通知」的規格類欄位，避免同一次變更推兩則。

- **否決：併入既有的製作後規格異動通知。** 那條規則的收件人是三組人、且限製作後；改交期在製程規劃階段就得讓排單的印務知道，收件人也只有他。

### D11：單位依計價方法推導，不新增主檔欄位

清單顯示的單位（張／才／本／頁／台）依所引用主檔項目的計價方法對照推導。

- **否決：主檔新增單位欄或任務層手填單位。** 多一個要維護的欄位就會出現「主檔說張、任務說本」的兩個真相；計價方法本來就決定了這道工序算錢的計數單位。

### D12：列印做成列印友善頁，不做 PDF 產生器

本階段做列印友善頁配瀏覽器列印（可自行另存 PDF）；不建單據實體、不留存檔案，每次即時依當前已生效的工單內容產生。

- **否決：後端 PDF 產生器。** 正式的 PDF 產出屬後端實作，不在本案範圍。
- **否決：產生並留存單據快照。** 留存會讓現場紙本與系統內容各自成立，異動確認後該重印哪一版就答不出來。
- **否決：另做含成本版。** 讀這張單的人是工廠與外包廠商，價格不該出門。

## Risks / Trade-offs

| 風險 | 影響 | 處置 |
|---|---|---|
| 手改數量後不重算上游、也不顯示對照，上下游可能對不齊 | 上游少做導致下游缺料，或上游多做形成呆料 | Miles 拍板由印務自行負責。缺料走既有補做與工單異動，多做走既有成品處置；本案不新增提示、不新增主管審核項目 |
| 預計開工日改手填，未填的任務不進漏單率分母 | 漏單率指標的覆蓋度隨印務手填率下降，指標會失真而不是歸零 | 屬手填制的自然結果，本案接受。公式不改，仍以該欄與報工有無計算 |
| 改量無下限，目標可低於已投入 | 該任務立即被判完成，已投入的成本高於計畫 | 拍板不特別處理：已報工成本即實際成本，預實對照本來就會顯示這個落差 |
| 拆欄遷移以放損率反推，反推值不必然等於當初的規劃意圖 | 存量任務的兩欄分配可能與印務原意有小幅落差 | 目標數量一律原值保留、數量帳不動；落差只影響「這裡面有多少是放損」的回溯精度，不影響現場要跑的量 |
| 列印版式未經現場實測 | 印出來的單子欄位順序或欄寬不合現場讀單習慣 | 已開 [PT-049](../../../memory/Sens_wiki/wiki/erp/08-open-questions/PT-049-工單匯出版式的實務驗證方式.md) 追蹤驗證方式，不擋本案實作 |

## Migration Plan

**存量生產任務拆欄**（Prototype 階段直接改 mock 資料）：

| 任務型別 | 預計生產 | 放損 |
|---|---|---|
| 工序型、裝訂型 | 目標數量 ÷（1 ＋ 該任務放損率），無條件進位 | 目標數量 − 預計生產 |
| 材料型 | 目標數量 − 計畫設備固定開機損 | 計畫設備固定開機損 |

- 目標數量一律保留原值，遷移後兩欄加總必須等於原值。
- 已達終態的任務同樣拆欄呈現，報工事實（生產數量、產出數量、良品數）不改寫。
- 印件的急件選項：既有 mock 印件一律補為一般件（天數 0），訂單交期（扣除急件）等於客戶交期，既有交期資料不變動。
- 訂單既有的是否急件欄值原樣保留，只改語意（注記），不做資料轉換。

**回滾**：目標數量原值全程保留，回滾只需停止呈現兩個成分欄、恢復以目標數量為輸入即可還原，不需反向計算。急件選項與推導欄為新增欄，回滾即忽略。
