# Sens 知識庫操作模式

## 一、範圍與語言

- 本檔管 `memory/Sens_wiki/` 的目錄權限、讀取邊界、共用標準、寫入後維護、陷阱與工作流入口。讀寫本目錄樹下任何檔案時生效。
- 內容原則（含 Wiki 憲章）見 [[卡片撰寫共用規範]]。ERP 各主題的入口在 [[erp_index]]；[wiki/index.md](wiki/index.md) 只列產品入口。
- 語言規則見全域 `~/.claude/CLAUDE.md` § 語言與用語。技術代號（skill 名、frontmatter 欄位名）保留原樣，說明文字用繁體中文。

## 二、目錄權限與讀取邊界

| 目錄 | 權限 | 誰讀 |
|------|------|------|
| `raw/` | 唯讀：已存素材不改、不刪；新增 raw 卡與回填狀態只經 `vault-ingest` | 精練與調研查證時讀；設計者不讀 |
| `assets/` | 媒體資產，以 `![[檔名]]` 引用 | 引用處 |
| `wiki/erp/` 01～07 | 可寫，增修經 `wiki-amend` | 業務正本卡。設計者只讀這一層，加上 change 資料夾內的檔 |
| `wiki/erp/11-review-knowledge/` | 可寫，定位與寫入入口見 [[審查知識路由]] | 稽核用；設計者不讀其中的參考模型卡 |

## 三、共用標準

- frontmatter：各 type 的必填欄位與值域以 [[wiki-schema]] 為正本；樣板在 `wiki/範本/` 各骨架卡。
- 內部連結：一律 `[[完整卡名]]`，禁用別名（`[[卡名|別名]]` 的 `|` 會截斷表格儲存格，也容易斷鏈）。補充說明寫在連結外。
- 外部連結：連 vault 外的非實作資源（法規、廠商規格書）用 markdown link。禁指向實作文件（Prototype 原始碼、實作程式碼）。
- 命名：依語意譯成繁體中文，不直譯、不中英夾雜。帶序號的卡用 `前綴-NNN-簡述`（NNN 三位補零）。
- 業務編號禁 `#` 前綴：Obsidian 會把 `#` 開頭的字串解析成 tag。直接寫 `ORD-2026-0512`。
- 禁孤島：每張卡至少被一張卡連到；關聯段以 `[[卡名]]` 連到相關卡。互鏈機制由各主題自定。

## 四、寫入後必維護

- **卡片清單**：新增或刪除卡時不手動更新目錄。[[erp_index]] 的卡片清單由寫入檢查 X1 自動產生；`wiki/index.md` 只列產品入口，新增產品時才動。
- **`wiki/log.md`（操作史）**：全知識庫唯一只追加層。新條目插在檔首說明列之下、既有條目之上（最新在上）。格式：
  ```
  ## [YYYY-MM-DD HH:MM] <動作>(<標籤>) | <一句話簡述>
  - 變更：[[卡A]] 一句話、[[卡B]] 一句話
  - 動機：<業務理由，當下自足；得連 [[OQ卡]]>
  - 衝突：無（或：與 [[C]] 衝突，已開 [[OQ]]）
  ```
  - 動作 enum（繁中）：**納入 / 查詢 / 健檢 / 同步**；次級標籤：納入（ingest-A/B/C、amend）、健檢（audit / pre-check）、同步（oq / misjudgement）、查詢（無標籤）。
  - **寫入當下自足**：條目所有欄位資訊在寫入那一刻必須已存在；禁任何「未來資訊」欄位（如下游 change 名——記條目時 change 尚不存在，BRD 先行）。
  - **log 的世界裡只有 wiki**：觸發寫入的充要條件 = 本次操作動到 `wiki/`。規劃單 / Prototype / Notion 的事件不產生條目。
  - **變更行 MUST 逐卡 `[[卡名]]` + 一句話**，禁「更新多張卡」粗寫——卡的迭代脈絡靠搜 `[[卡名]]` 命中條目，寫粗即永久斷脈絡。
  - **動機行**：實質異動（增修 03/04/05/06 正本卡或 meta 結構）必填，業務語言、BRD 層自足（OQ 拍板 / explore 定案 / Miles 指示）；健檢 / 納入類免（觸發即動機）。動機寫不出來 = 決策未定案 = 不該改卡。

## 五、陷阱

| 陷阱 | 出處 |
|------|------|
| obsidian-cli 省略參數時，靜默改查目前開啟的檔，回一份看似合理的錯答案。指令名與參數語法一律以 skill `obsidian-cli` 為準 | 2026-08-01 實測：backlinks 少報 8 倍 |
| 以 grep 當 vault 稽核手段：grep 只看純文字，解析不了 wiki link 與 vault 索引。搜尋、反向連結、孤島、死鏈一律走 obsidian-cli | 工具限制；2026-05-31 起的既有規則 |
| 發現矛盾就蓋掉舊說法。要開 OQ 卡（`oq-manage`），原處改連結引用 | [[卡片撰寫共用規範]] § 三 |
| 用 git mv 或 Finder 改卡名：Obsidian 視為刪除再新建，反向連結全斷。改名用 obsidian-cli | 2026-05-31 連結斷聯根因調查 |

## 六、工作流入口

| 工作流 | 入口 |
|--------|------|
| 納入：素材進 `raw/`，再精練進 `wiki/` | `vault-ingest` |
| 查詢：讀卡作答，附 `[[引用]]` | [[business-domain-taxonomy]] § 檢索規約 |
| 健檢：矛盾、死鏈、孤島、過時、缺欄位、命名違規 | `vault-audit` |
| 寫卡：03～07 正本卡與 11 層卡的新增與修改 | `wiki-amend`（唯一寫入入口） |
| OQ：開卡、去重、拍板封存 | `oq-manage` |
