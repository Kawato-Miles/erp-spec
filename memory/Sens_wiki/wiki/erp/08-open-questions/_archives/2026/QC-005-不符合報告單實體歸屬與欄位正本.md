# QC-005 不符合報告單的實體歸屬與欄位正本

## 問題描述

「不符合報告單」被印件狀態、生產任務狀態、品檢人員、生產績效指標、齊套邏輯、打樣流程六張卡當成既有載體引用（打樣 NG-製程問題明定「系統自動開一張全欄位預填、即開即結的不符合報告單」作結構化留底），但 `05-entities/` 無此實體卡：

1. 欄位無正本：原因分類、處置分流、數量、關聯印件或工單、即開即結語意皆無定義。
2. 與 [[品檢紀錄]] 的基數未定（一筆品檢紀錄對一張報告單？印件層彙總？），品檢正本卡全文未提及它。
3. QC 不通過的補做／客戶照收／報廢三分流是否共用同一單據未定。

## 待解答

- [x] 是否開獨立實體卡（或併入品檢紀錄為子紀錄）→ 都不；不建此實體，兩條路徑各用既有欄位承載
- [x] 欄位正本與即開即結語意 → 不適用（實體不存在）
- [x] 與品檢紀錄的基數 → 不適用
- [x] 打樣 NG 與 QC 不通過是否共用同一單據 → 不共用，兩條路徑本就是不同人、不同時點、不同判準的動作

## 決議（2026-07-31，Miles 拍板）

**不建「不符合報告單」實體。**品檢不通過與打樣 NG 是兩條要切開的路徑，各自用既有欄位承載，都不另開單據：

| | 品檢不通過 | 打樣結果 NG |
|---|---|---|
| 判定者與時點 | [[品檢人員]]，貨從產線送到品檢站之後 | [[業務]]／[[諮詢]]，樣品已送到客戶手上、客戶看過之後 |
| 在驗什麼 | 我們有沒有做壞（對照工單品檢需求）| 客戶認不認這個效果 |
| 事實記在哪 | [[品檢紀錄]]（分次驗、一次一筆、通過數／不通過數／單一原因）——**只由品檢人員回報，系統不代寫** | [[印件]] 的「打樣結果」欄位（業務填）|
| 處置記在哪 | [[印件]] § 品檢缺口處置（印務對累計缺口決策：補做／客戶照收／報廢）| 不需處置欄位：NG-製程問題一律重打，系統自動建新打樣工單 |

同一批打樣樣品可能品檢通過（我們沒做壞）而客戶仍判 NG（效果不如預期），也可能品檢當場就驗出做壞。兩者綁在同一載體會逼出「客戶說 NG 所以品檢紀錄補一筆不通過」這種假資料，這是切開的理由。

**處置決策掛印件層、不塞回單筆品檢紀錄**：處置的對象是累計缺口、動作者是印務；品檢紀錄是品檢人員的回報，不該混入他人的決策。

**根因分類（紙材／製程／設備／供應商／人為五值）一併不做**：原本掛在本實體上，實體不建即無家；業務只知道客戶說不行、不是能判根因的人，真要追根因是印務在重打工單的製程調整裡處理。與品檢不通過原因（六組現象軸，值域見 [[品檢紀錄]]）不是同一個軸，兩者不混用。

本決議翻案 [[AR-13-打樣NG製程問題下游處理機制]]（已封存）的兩項：「不符合報告單留底」與「製程根因由原因分類承載」。該卡其餘拍板（系統自動建工單、成本歸印件）不變。
