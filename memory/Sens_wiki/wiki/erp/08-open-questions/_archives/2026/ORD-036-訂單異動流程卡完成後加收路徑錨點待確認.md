# ORD-036：訂單異動流程卡「完成後加收路徑」對應 heading 待確認

## 問題描述

US-ORD-026（補收 OA 免主管核可直接執行）的時點框架已由「製作中加買」改為「訂單完成後對客戶加收」（對齊訂單收退款模型重構：完成前增項走明細／OrderExtraCharge 直接改，補收 OA 用於完成後）。

其 frontmatter `related-scenarios` 原錨點 `[[訂單異動流程#旅程 A：訂單期間加印補收（情境 8）]]` 以「訂單期間／製作中加印」為觸發框架，與現行不一致，應改指向 [[訂單異動流程]] 卡中「訂單完成後對客戶加收／完成後金額異動路徑分流」對應 heading。但該 heading 正確名稱未確認（grep [[訂單異動流程]] 卡未找到對應標題），依「勿臆造錨名」原則暫未改，待確認。

## 涉及範圍

- 模組：order-management
- 相關卡：[[訂單異動流程]]、US-ORD-026
- 影響：US-ORD-026 related-scenarios 錨點正確性（wiki link 解析）

## 待解答

- [x] [[訂單異動流程]] 卡是否有「訂單完成後加收／完成後金額異動路徑分流」對應 heading？正確名稱為何？ → 判準本體不在情境卡，在規則卡，見決議
- [x] 若無，是否需於該卡新增此 heading，再回填錨點。 → 不新增獨立段，情境卡以既有的售後補印岔路承接

## 決議

完成後加收的判準本體歸規則卡，錨點為 [[訂單異動規則#訂單完成後金額異動路徑分流]]；情境卡不另立「完成後加收」段，改由既有的售後補印岔路補收分支承接「原單善後的加收」這一條，另一條（新生意另開新訂單）不進情境卡。理由：這是一條 if-then 判準（這筆錢是不是這次客訴處理的一部分），屬商業規則卡職責；情境卡只描述業務怎麼一步步走完，兩者分工不重疊，硬在情境卡開一個同名段會讓判準有兩處正本。

2026-08-03 一併拍板路徑內容本身：完成後加收依性質分流——原單善後的加收（補印分攤、急件重製費）掛在該張售後服務單內建補收訂單異動，客戶趁機追加的新品項另開新訂單。原先「完成後加收一律另開新訂單」的寫法同時作廢。

拍板者：Miles（2026-08-03）

落地去處：[[訂單異動規則]]（§ 訂單完成後金額異動路徑分流改寫為兩條並存）、[[售後服務規則]]（補印收費分流同步）、[[訂單異動流程]]（售後補印岔路的補收分支改寫、範圍外段改為指向規則卡錨點）。原問題提到的 US-ORD-026 錨點回填屬實作規格層，wiki 不承載。
