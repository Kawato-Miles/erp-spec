# BI-25 補收與退款的認列時點是否維持「核可即生效」的對稱設計

## 問題描述

前端在串接訂單異動時指出：文件對「核可之後」的描述互相打架——狀態列舉與編輯規則都寫有「已核可」這一站，但核可的行為卻寫成直接推進「確認可執行」；而「已核可可改金額、核可金額與現值對照」這組設計，在核可直達終態的前提下永遠走不到。

矛盾兩方都在既有正本內，屬既有正本矛盾：

- **舊版（來自 [[BI-9-補收OA立即執行對稱破壞表述]] 2026-06-02 的方案 D）**：補收與退款的「已執行」語意對稱，都等於應收生效；退款經主管核可當下即生效、補收建單當下即生效。
- **新版（[[訂單異動狀態]] 狀態列舉、[[訂單異動規則]] 編輯閘門與應收公式）**：所有退款核可後停在「已核可」，業務與客戶談定金額後執行確認才認列。

範圍宣告：本卡只處理「認列發生在哪一刻」與「補收要不要有中間站」。誰有權核可、金額能不能改、改了要不要重審不在本卡（分別見 [[訂單異動規則]] 與 [[ORD-002-OA核可金額閾值閘門]]）。

## 待解答

- [x] 退款經主管核可後是直接生效，還是停在「已核可」等業務確認金額？ → 停「已核可」，見決議
- [x] 補收是否維持建單當下即生效？ → 不維持，改為先落草稿、業務確認生效

## 決議

**退款採兩段式**：主管核可代表同意「可以退」，單據停在「已核可」、應收不動；業務與客戶談定退多少後執行確認，應收於確認那一刻減去。**補收也改為兩段**：建立時先落草稿，業務覆核後點確認生效，金額於此刻加進應收。

採兩段式的理由：「能不能退」與「退多少」在印刷業實務上是兩件事，退款金額在退錢之前常與客戶再談定，一段式沒有給這個校正留窗口，也讓「核可金額與現值對照」「已核可可改金額不重審」整組設計失去存在意義——這組設計是 [[ORD-002-OA核可金額閾值閘門]] 明確保留的。補收跟著改兩段，是因為建單即終態時打錯一個零沒有任何補救點；先落草稿不增加審核關卡（仍免審），只給業務一次覆核機會。

方案 D（一段式對稱）不成立之處：它把對稱做在「認列時點」上，但兩個方向真正對稱的是「都需要一次人工確認」，不對稱的只有「要不要主管這一關」。把不對稱切在認列時點，等於用錯的軸做對齊。
