# 問題描述

實體卡憲章化反向拆 [[需求單]] 業務可見欄位時，發現規格欄位修改規則多處未明定、且與雛形系統有結構落差。實體卡欄位表受影響各格已標注引用本 OQ。

## 部分拍板（2026-06-12，Miles）

一般欄位**成交／流失終態後全卡鎖定**：成交即轉訂單，後續變化改訂單，需求單轉為參考依據。已落地 [[需求單]] 欄位表各列。spec 回寫待後續 change。

## spec 與雛形系統落差

- 帳務公司欄位：已由 2026-06-12 拍板解決（接單公司即帳務公司、同一概念、業務建單時選擇、廢推導，見 [[需求單]] 欄位表與 wiki/log.md 該筆），**spec Data Model 的「推導唯讀」敘述待同步**——本項只剩 spec 回寫
- 金額三欄（未稅／稅額／含稅總額）：spec 放需求單主表，雛形放印件項目層——層級不一致
- 評估印務主管：spec 標必填，但流程允許未指派即推進——必填性矛盾
- 流失原因選項：雛形有具體七值清單（價格因素／交期無法配合等），spec 只標必填未列舉
- 雛形印件項目有 spec Data Model 未列的業務欄位：難易度（1-10）、是否免審稿、印件檔案備註、已下單數量（散落其他 change 引入，Data Model 未回收）

## 決議（2026-07-31，Miles）

三項一次收齊：

1. **流失原因列出七值**：價格因素／交期無法配合／品質不符需求／客戶預算刪減／競爭對手搶單／客戶取消專案／其他。歸因會隨業務演進，先以這版為主、有修正再迭代。理由：輸單原因要能統計，主管才看得出價格輸幾成、交期輸幾成。
2. **三欄位收進印件項目層**：需求單本質是蒐集需求、會記錄印件內容，但印件實體要到成交轉訂單時才由系統建立，故這三欄掛在需求單的印件項目段，轉訂單時帶入新建的印件。
3. **金額三欄無爭議**：wiki 欄位表原本就寫「印件項目報價的彙總」，與雛形一致；落差只在 OpenSpec 那份仍寫成主表欄位。

**殘留由誰接住**：OpenSpec 需求單 spec 的 Data Model 回寫（金額三欄層級、流失原因值域、三欄位）由下次需求單相關 change 承接，屬 PRD 層同步、不阻斷本卡結案。
