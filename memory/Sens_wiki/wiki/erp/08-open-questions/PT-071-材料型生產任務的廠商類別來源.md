# PT-071 材料主檔沒有承作廠商欄位時，材料型生產任務的廠商類別從哪裡來

## 問題描述

既有正本矛盾，不是本次討論產生。

| 出處 | 寫法 |
|------|------|
| [[生產任務]] 「廠商類別」欄 | 材料／工序／裝訂三類各自的承作廠商決定負責工廠；系統依 BOM 三類的廠商決定，唯讀 |
| [[工序主檔]] 「工序廠商」欄 | 有欄位 |
| [[裝訂主檔]] 「裝訂廠商」欄 | 有欄位（2026-07-30 補，標明缺口補欄位） |
| [[材料主檔]] 欄位表 | 沒有承作廠商欄位 |
| 中台程式碼（sens-print-core develop，2026-10-28 讀取） | 只有工序帶廠商；材料與裝訂都沒有廠商欄位 |

形成經過：2026-07-30 拍板「生產單位類別改由三主檔各自的廠商決定」時，只在裝訂主檔補了欄位，材料主檔沒有同步補（見 wiki/log.md 2026-07-30 00:06 條目）。2026-09-03 生產任務對話框改版時，Miles 選擇 Prototype 先依現行後端做，沒有為材料廠商開 OQ（出處：Claude 記憶紀錄 project_task_form_bom_picker_done，未在 wiki 落卡）。這是 Prototype 的做法，不是規則層的拍板。

不拍板的後果：材料型生產任務的廠商類別沒有正本來源。系統無法依規則帶出它的廠商類別，運送與交付環節也跟著不確定。

範圍：本卡只管材料型生產任務的廠商類別來源。工序型與裝訂型已有欄位，不在本卡範圍。

## 待解答

- [ ] 材料型生產任務的廠商類別從哪裡來？

## 候選方案

- **A（材料主檔補承作廠商欄）**：比照裝訂主檔補欄位，留空＝公司內部執行；三類規則維持一致。代價：中台要新增欄位；同一材料向不同廠商買的情況（2026-09-03 對話框改版時提過）要另想表達方式。
- **B（材料型任務固定為公司內部）**：材料型任務一律視為自有工廠，規則改寫成「工序與裝訂兩類各自綁承作廠商」。代價：材料若由外包廠代備，無法表達。
- **C（材料型任務沿用所服務工序的廠商）**：材料型任務的廠商類別取同一工序段下工序的承作廠商。代價：要定義材料任務與工序任務的對應關係。

不受影響項：工序型與裝訂型生產任務的廠商類別來源；BOM 不規定某類主檔只能配某類廠商這條原則。

裁決後要同步的位置：
- [[生產任務]] 「廠商類別」欄
- 選 A 時：[[材料主檔]] 欄位表
