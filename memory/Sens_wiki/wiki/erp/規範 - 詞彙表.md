# 詞彙表撰寫規範（glossary 層）

## 〇、詞彙表是什麼

| 問 | 答 |
|----|-----|
| 回答什麼問題 | 這個業務名詞是什麼；同一概念還有哪些說法不能用 |
| 第一讀者 | 寫卡的人與代理：寫之前查用詞；讀卡的 PM：點連結看定義 |
| 份數 | ERP 一份（[[ERP 詞彙表]]），線上編輯器一份（另案）。行業通用詞在 [[印刷業共用術語表]] |
| 格式依據 | mattpocock-skills 的 `GLOSSARY-FORMAT.md`，只偏離一處：詞條用三級標題，不用粗體，讓別卡能連到詞條 |

本規範只管詞彙表怎麼寫。全 wiki 的正規化與用語統一規則在 [[卡片撰寫共用規範]] § 二之四。詞彙表只有一張卡，不設骨架與範例卡。

## 一、收什麼、不收什麼

| 收 | 不收（去處） |
|----|-------------|
| 全部 ERP 業務名詞：實體、狀態值、角色、操作名稱、業務概念 | 換一家同業也成立、ERP 用不到的純行業詞（[[印刷業共用術語表]]） |
| 一到兩句「它是什麼」 | 為什麼要有它（實體卡營運背景、角色卡分工理由） |
| 避免用詞 | 欄位表、狀態轉換、規則、流程（各自的正本卡） |
| | 流程用語與工具詞（非商業術語對照表） |

## 二、格式

```markdown
## <業務領域>

### <詞條名>

<一到兩句：它是什麼。>
_Avoid_: <避免用詞>、<避免用詞>

### <狀態機卡名>

#### <狀態名>

<一到兩句：這個狀態是什麼。>
```

| 強度 | 規則 |
|------|------|
| MUST | 以 [[business-domain-taxonomy]] 的業務領域當二級標題分組；一個詞條只放在一個領域 |
| MUST | 詞條用三級標題；詞條名就是連結定位點，別卡寫 `[[ERP 詞彙表#詞條名]]` |
| MUST | 詞條名逐字等同對應的實體卡名、狀態名、角色名、操作名 |
| MUST | 狀態值的詞條用四級標題，放在以狀態機卡名為名的三級標題下；不同狀態機的同名狀態各自定義。別卡寫 `[[ERP 詞彙表#狀態機卡名#狀態名]]` |
| MUST | 定義一到兩句，寫「它是什麼」，不寫「它做什麼」、不寫為什麼要有它 |
| MUST | 同一概念只有一個詞條。其他說法（含行業說法）列在 `_Avoid_` 行，以頓號分隔；沒有其他說法時省略該行 |
| MUST | 同一個避免用詞只列在一個詞條；避免用詞不得同時是詞條名 |
| MUST NOT | 粗體詞條（`**詞**:`）。mattpocock-skills 的 domain-modeling 新增詞條時會寫成粗體，寫入檢查會退回 |
| MUST | 卡頭依 [[wiki-schema]] 的 glossary 型；改寫時不得移除卡頭 |

## 三、相近詞的判定

兩個詞指的是不是同一概念，屬於商業判斷，由 Miles 確認，不自行決定。確認為同一概念時，保留 ERP 用詞為詞條，另一個列為避免用詞；不是同一概念時，兩個都是詞條，各自定義寫出差別。

## 四、寫入入口

增修詞條走 `wiki-amend`，與正本卡相同。新詞條隨各業務領域的遷移批次補齊。

## 五、稽核維度

L1 見 [[卡片撰寫共用規範]] § 四之二。L2：

| # | 維度 | 通過標準 |
|---|------|---------|
| 1 | 定義是「是什麼」 | 每條定義刪掉後讀者就不知道這個詞指什麼；不含流程、規則、理由 |
| 2 | 一概念一詞條 | 沒有兩個詞條指同一概念 |
| 3 | 對得上正本卡 | 實體、狀態、角色、操作的詞條名都找得到同名的正本 |

## 六、機械自檢

由寫入檢查腳本執行（[[卡片撰寫共用規範]] § 四之四）：S7 避免用詞、S8 定義句型、S14 詞彙表格式、X4 詞條齊全、X5 避免用詞不重疊、X6 觸發詞不含避免用詞。
