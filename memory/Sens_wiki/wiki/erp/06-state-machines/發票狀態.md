讀完這張卡，你會知道：

- 認識發票（InvoiceStatus）狀態機涵蓋的生命週期：從業務在收款項目上開立發票（可先存草稿），到開立生效或開立失敗，再到開錯時作廢另開
- 看懂發票有草稿、開立、開立失敗、作廢四種處境，以及只有「開立」計入對帳的發票淨額
- 掌握每個轉換由誰觸發、送出前被擋與送出後失敗的差別、作廢要滿足什麼條件
- 理解為什麼開立前留一格草稿、送出後失敗交給後端人員處置，而開立後只能作廢、不能刪改
- 知道一期只容一張未作廢發票、流水號不重用、作廢即退出對帳的營運理由

## 狀態列舉（正本）

> 本段是發票狀態的唯一正本。狀態的新增與修改是商業決策，直接在此卡維護。

| 狀態 | 說明 | 對應營運需求 |
|------|------|------------|
| 草稿 | 初始；業務在收款項目上開立發票時先存下、尚未送平台的發票。不驗證任何內容，沒有發票號碼；送出前被系統檢核擋下時維持本態 | 開票資訊還沒齊時先存下來；被擋下時改完再送。不計入發票淨額，也不能被折讓單引用 |
| 開立 | 初始（未存草稿、直接送出且開立成功時）；藍新回傳開立成功、正式生效，可被折讓單引用 | 有效發票計入對帳的發票淨額 |
| 開立失敗 | 業務端終態；已送出開立，藍新回傳失敗或逾時沒有回應，記下失敗原因。業務不能再改、再送或作廢，只能等後端人員在系統外處置 | 逾時時平台上可能已經開出，讓業務重送會重複開票；停在這格讓後端人員查明後處置。不計入發票淨額，也不能被折讓單引用 |
| 作廢 | 終態；開錯（金額、抬頭、統編）時作廢並留原因，同一收款項目需要時再開立發票 | 失效發票退出三方對帳，作廢原因留稽核 |

## 狀態機圖（UML）

- 記法：實心圓為初始點、雙圈為終止點、菱形為選擇偽狀態、轉換標籤採「觸發事件 [轉換條件]」格式；「草稿」與「開立失敗」指向終止點的弧代表發票記錄消失，不是新狀態。
- 複合狀態「未作廢」＝發票尚未作廢、仍佔住所屬收款項目的處境（可被他卡規則句引用的集合詞；成員以本圖為正本），一個收款項目同一時間至多一張。
- 「開立失敗」離開的兩條弧都由後端人員在系統外執行，業務端在這一格沒有任何動作，所以稱業務端終態。

```mermaid
stateDiagram-v2
    direction LR

    state c_entry <<choice>>
    [*] --> c_entry : 業務／諮詢人員在收款項目上開立發票 [收款項目未取消·該期沒有未作廢發票]

    state "未作廢" as g_active {
        direction LR
        state "草稿" as s_draft
        state "開立" as s_issued
        state "開立失敗" as s_failed
        s_draft --> s_draft : 業務／諮詢人員自草稿送出開立 [系統檢核未過，擋下並顯示原因]
        s_draft --> s_issued : 業務／諮詢人員自草稿送出開立 [藍新回傳成功]
        s_draft --> s_failed : 業務／諮詢人員自草稿送出開立 [藍新回傳失敗或逾時]
        s_failed --> s_issued : 後端人員於系統外補登發票號碼與開立時間
    }
    state "作廢" as s_void

    c_entry --> s_draft : 儲存草稿
    c_entry --> s_issued : 送出開立 [藍新回傳成功]
    c_entry --> s_failed : 送出開立 [藍新回傳失敗或逾時]

    s_draft --> [*] : 所屬收款項目被刪除或取消 [草稿記錄一併消失]
    s_failed --> [*] : 後端人員於系統外刪除該筆發票紀錄
    s_issued --> s_void : 業務／諮詢人員作廢 [必填作廢原因·無已確認折讓·限申報期限內]
    s_void --> [*]
```

## 轉換條件與觸發事件

| 轉換 | 觸發事件 | 條件 |
|------|---------|------|
| （建立）→ 草稿 | 業務／諮詢人員在收款項目上開立發票並儲存草稿 | 收款項目未取消，且該期沒有未作廢發票（一期一張，見表下說明）；不驗證任何內容；發票欄位於帶入當下取得（發票金額的目標值見 [[付款發票邏輯]]）；訂單任何狀態皆可（含草稿、已取消） |
| （建立）→ 開立 | 業務／諮詢人員在收款項目上開立發票並直接送出開立，藍新回傳成功 | 同上；送出前套用系統檢核（平台硬檢核見 [[發票法規硬約束-ezPay-MIG]]，含稅與未稅目標值檢核見 [[付款發票邏輯]]）。系統檢核未過時擋下、不送平台，也不建立發票 |
| （建立）→ 開立失敗 | 業務／諮詢人員在收款項目上開立發票並直接送出開立，藍新回傳失敗或逾時 | 系統檢核已通過、已送平台；記下藍新回傳的失敗原因，逾時則記逾時 |
| 草稿 → 草稿 | 業務／諮詢人員自草稿送出開立，系統檢核未過 | 擋下、不送平台，顯示原因；業務改完草稿可再送 |
| 草稿 → 開立 | 業務／諮詢人員自草稿送出開立，藍新回傳成功 | 送出前套用系統檢核；以草稿內容送出，不重新帶入 |
| 草稿 → 開立失敗 | 業務／諮詢人員自草稿送出開立，藍新回傳失敗或逾時 | 同（建立）→ 開立失敗 |
| 草稿 →（記錄消失） | 業務／諮詢人員刪除或取消所屬收款項目 | 草稿一併消失、不必作廢；不設草稿單獨刪除，放棄草稿即取消該收款項目（收款項目取消規則見 [[付款發票邏輯]]） |
| 開立失敗 →（記錄消失） | 後端人員查明平台上沒有開出後，在系統外刪除該筆發票紀錄 | 刪除後該期沒有未作廢發票，業務可重新開立發票 |
| 開立失敗 → 開立 | 後端人員查明平台上已經開出後，在系統外補登發票號碼與開立時間 | 不再送平台；補登後與藍新回傳成功的發票同樣計入發票淨額 |
| 開立 → 作廢 | 業務／諮詢人員執行「作廢」並填入原因 | (1) 須無已確認折讓，有折讓先作廢折讓（見 [[折讓單狀態]]）。(2) 限申報期限內，逾期只能折讓（時限與法源見 [[發票法規硬約束-ezPay-MIG]] § 四）。(3) 作廢後流水號不重用，重開時新發票流水號順延。(4) 作廢後同一收款項目可再開立發票 |

- **一期一張**：一個收款項目同一時間至多一張未作廢發票。系統在寫入那一刻檢查；兩人同時送出時，先寫入者成立，後到者被拒。
- **送出前被擋與送出後失敗是兩回事**：系統檢核未過時沒有送到平台，發票不轉開立失敗；只有已送平台、藍新回傳失敗或逾時，才轉開立失敗。
- **隔日財政部上傳失敗不算開立失敗**：發票維持「開立」，處置見 [[發票法規硬約束-ezPay-MIG]]。

> 開發票時機、發票金額怎麼定、收款項目怎麼拆，規則正本見 [[付款發票邏輯]]。

## 關鍵轉換的營運動機

- 開立 → 作廢 → 動機：台灣統一發票制度下，發票開出去就是正式文件，不能刪除也不能修改；開錯（金額、抬頭、統編）只能作廢另開，作廢原因留存供稽核 → 例子：ORD-2026-0512 的發票 INV-01 統編打錯，業務作廢 INV-01 並重開 INV-02。
- （建立）→ 草稿、系統檢核擋下維持草稿 → 動機：開票資訊常要等客戶回覆才齊，先存下來就不必等齊才動手；送出前被擋下時發票有地方停、有原因可看，改完再送，不必重打一次 → 例子：ORD-2026-0925 第 1 期，業務先存草稿等客戶提供統編，客戶回覆後補上統編送出，發票轉「開立」。
- 藍新回傳失敗或逾時轉開立失敗、業務不能再送 → 動機：逾時時系統不知道平台上有沒有開出，業務若重送，平台上可能多開一張、對帳多出一筆；把這張停在業務碰不到的處境，交給能到平台後台查證的後端人員依查證結果處置，就不必另設「送出中」的處境。
- 開立失敗佔住一期一張的額度 → 動機：開立失敗的那張在平台上可能其實已經開出；若業務能在同一期另建一張，平台上就可能有兩張發票對同一期。
- 草稿與開立失敗不計入發票淨額 → 動機：這兩種發票在系統內都沒有確認開出，計入會讓帳面以為客戶已經拿到這張發票（發票淨額的算法正本見 [[對帳一致性]]）。
- 發票序號的唯一性 → 動機：每張發票的序號要能唯一追溯到一筆交易，作廢後重用同一個號碼會讓會計對不出這個號指的是哪一筆。
- 作廢退出對帳 → 動機：作廢的發票不該再撐著帳面，否則對帳會虛報一筆已經失效的金額。
- 作廢前須先作廢已確認折讓 → 動機：折讓是掛在發票底下的減額憑證，發票整張失效前要先清掉掛在上面的有效折讓，否則發票淨額會殘留一筆扣減不存在發票的折讓 → 例子：發票 INV-01 已有一筆已確認折讓 2,100 元，業務要作廢 INV-01 時系統擋下並提示先作廢折讓單。

## 與其他狀態機的關係

- 發票與收款的對應透過收款項目中介（[[收款項目開發票狀態]]、[[收款項目收款狀態]]）：一個收款項目同一時間至多一張未作廢發票（含草稿與開立失敗），收款項目與收款多對多，發票不直接掛款項紀錄。
- 發票轉「開立」（藍新回傳成功或後端人員補登）才帶動收款項目的開發票狀態轉「已開立」；發票停在草稿或開立失敗期間，開發票狀態維持原值（見 [[收款項目開發票狀態]]）。
- 收款項目被刪除或取消時，該期的草稿記錄一併消失；發票作廢後，或開立失敗的紀錄被後端人員刪除後，同一收款項目可再開立發票。
- 折讓單只引用「開立」狀態的發票；草稿與開立失敗沒有號碼，不能被引用，見 [[折讓單狀態]]。
- 發票的建立、開立與作廢不影響 [[訂單狀態]] 或 [[訂單異動狀態]]；訂單狀態也不限制發票的建立與開立。
