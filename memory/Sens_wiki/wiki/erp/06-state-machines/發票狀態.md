讀完這張卡，你會知道：

- 認識發票（InvoiceStatus）狀態機涵蓋的生命週期：從開立生效，到開錯時作廢另開
- 看懂發票只有開立與作廢兩種處境、哪一種計入對帳的發票淨額
- 掌握每個轉換由誰觸發、作廢要滿足什麼條件
- 理解為什麼狀態只切兩格：發票開出去就是正式文件，不能刪改只能作廢另開
- 知道流水號不重用、作廢即退出對帳的營運理由

## 狀態列舉（正本）

> 本段是發票狀態的唯一正本。狀態的新增與修改是商業決策，直接在此卡維護。

| 狀態 | 說明 | 對應營運需求 |
|------|------|------------|
| 開立 | 初始；發票開立成功、正式生效，可被折讓單引用 | 有效發票計入對帳的發票淨額 |
| 作廢 | 終態；開錯（金額、抬頭、統編）時作廢並留原因，同訂單需要時另開新發票 | 失效發票退出三方對帳，作廢原因留稽核 |

## 狀態機圖（UML）

- 記法：實心圓為初始點、雙圈為終止點、轉換標籤採「觸發事件 [轉換條件]」格式。
- 「開立」是持續有效態，多數發票停留於此，只有開錯才走作廢。

```mermaid
stateDiagram-v2
    direction LR

    [*] --> s_issued : 業務／諮詢人員開立發票
    state "開立" as s_issued
    state "作廢" as s_void

    s_issued --> s_void : 業務／諮詢人員作廢 [必填作廢原因·無已確認折讓·限申報期限內]
    s_void --> [*]
```

## 轉換條件與觸發事件

| 轉換 | 觸發事件 | 條件 |
|------|---------|------|
| （建立）→ 開立 | 業務／諮詢人員開立發票 | 開立即生效，不設草稿 |
| 開立 → 作廢 | 業務／諮詢人員執行「作廢」並填入原因 | (1) 須無已確認折讓，有折讓先作廢折讓（見 [[折讓單狀態]]）。(2) 限申報期限內，逾期只能折讓（時限與法源見 [[發票法規硬約束-ezPay-MIG]] § 四）。(3) 作廢後流水號不重用，同訂單重開時新發票流水號順延 |

## 關鍵轉換的營運動機

- 開立 → 作廢 → 動機：台灣統一發票制度下，發票開出去就是正式文件，不能刪除也不能修改，開錯（金額、抬頭、統編）只能作廢另開，作廢原因留存供稽核；因此狀態只需兩格，現階段開立即生效不設草稿，需要草稿流程時再增補狀態 → 例子：ORD-2026-0512 的發票 INV-01 統編打錯，業務作廢 INV-01 並重開 INV-02。
- 發票序號的唯一性 → 動機：每張發票的序號要能唯一追溯到一筆交易，作廢後重用同一個號碼會讓會計對不出這個號指的是哪一筆。
- 作廢退出對帳 → 動機：作廢的發票不該再撐著帳面，否則對帳會虛報一筆已經失效的金額（發票淨額的算法正本見 [[對帳一致性]]）。
- 作廢前須先作廢已確認折讓 → 動機：折讓是掛在發票底下的減額憑證，發票整張失效前要先清掉掛在上面的有效折讓，否則發票淨額會殘留一筆扣減不存在發票的折讓 → 例子：發票 INV-01 已有一筆已確認折讓 2,100 元，業務要作廢 INV-01 時系統擋下並提示先作廢折讓單。

## 與其他狀態機的關係

- 發票與收款的對應透過 [[收款項目狀態]] 中介（收款項目與發票一對一、收款項目與收款多對多），不直接掛款項紀錄。
- 折讓單引用「開立」狀態的發票進行折讓，見 [[折讓單狀態]]；發票作廢不影響訂單或訂單異動的狀態。
