# 帳務規劃連帶矩陣

> 一句話定位：帳務領域規劃前的檢核素材——收付款情境索引（哪 13 種情境、各自的關鍵設計在哪張卡）與七實體連帶矩陣（改哪一種單據，必須一起檢查哪些實體）。`erp-planning-pre-check` Step 2 與 `wiki-amend` Step 2 的連帶影響分析讀本卡。規則本體不在本卡：做法與底線見 [[付款發票邏輯]]、[[訂單異動規則]]、[[對帳一致性]]，欄位見 [[帳務]]、[[訂單]]。

## 三大分類（情境索引）

| 分類 | 數量 | 範圍 |
|------|------|------|
| **特殊發票開立方式** | 8 個（F1-F8）| 預開、拆多筆、有 / 無統編、指定品名、指定日期、跨月、作廢重開、折讓 |
| **特殊收款條件** | 4 個（C1-C4）| 頭尾款、申請後付款、頭尾款指定日期、線下單補收（含異動補收）|
| **訂單異動情境** | 3 個（A1-A3）| 異動不收費（公司吸收）、異動補收、異動退款 |
| **不在範疇** | 2 個 | 跨訂單混合匯款（人工）、重新報價（屬需求單議價）|

## 特殊發票開立方式

| 編號 | 情境 | 關鍵設計 |
|------|------|---------|
| F1 | 預開發票 + 拆 2 筆 + 實際金額調整 | 款項紀錄可不入帳任何收款項目（預收桶）；售後訂單異動 + 折讓單（折讓只關聯發票）|
| F2 | 拆多筆指定金額發票 | 一期一票；要改收幾期就取消原期再新增幾期，收款核銷分配多對多入帳 |
| F3 | 拆多筆有統編 / 無統編 | 發票種類分 B2B / B2C |
| F4 | 指定品名 / 作廢重開 | 作廢需填原因（中文 6 字 / 英文 20 字內，藍新限制）|
| F5 | 指定日期開立 | 收款項目的預計開發票日 排程提醒；手動開立 |
| F6 | 分 2 筆不同月份 | 收款項目拆 2 期、各填預計開發票日 |
| F7 | 作廢重開（多種子情況）| 統編 / 金額錯誤 / 已申報等 |
| F8 | 折讓單情況 | 過期發票不可作廢；折讓單只關聯發票，退款款項不關聯 |

## 特殊收款條件

| 編號 | 情境 | 關鍵設計 |
|------|------|---------|
| C1 | 頭尾款 50% 指定日期 | 收款項目 2 期、各填預計收款日 |
| C2 | 申請後付款（出貨後 N 天）| 先開後付，發票可無款項紀錄對應 |
| C3 | 頭尾款 + 指定開發票日期 + 付款時間 | 兩期收款項目各自填預計收款日 + 預計開發票日 |
| C4 | 線下單補收（含異動）| 訂單異動（訂單期間建立，未關聯售後服務單）+ 業務手動加印件 |

## 訂單異動情境

> 訂單期間與訂單完成後路徑不同，分流規則見 [[訂單異動規則#訂單完成後金額異動路徑分流]]。

| 編號 | 情境 | 訂單期間 | 訂單已完成後 |
|------|------|---------|-------------|
| A1 | 異動不收費（公司吸收）| 工單異動，不建訂單異動 | 售後服務單 + 補做（公司吸收，不建補收訂單異動）|
| A2 | 異動補收 | 訂單異動（補收）+ 收款項目 + 補收發票 | 售後服務單 + 關聯訂單異動（補退）+ 補做生產任務（掛原工單）|
| A3 | 異動退款 | 訂單異動（退款）+ 折讓 / 作廢重開 | 售後服務單 + 關聯訂單異動（退印）+ 折讓 / 作廢 + 退款款項 |

## 七實體連帶矩陣

> 任何「款項 / 發票 / 退款 / 補收 / 訂單異動」異動都必須連帶檢查下列影響範圍。

### 主動實體與連帶影響

| 主動實體 | 連帶實體 | 影響規則 |
|---------|---------|---------|
| **發票草稿建立** | 收款項目（開發票狀態維持原值，見 [[收款項目開發票狀態]]）/ 發票品項（建立當下帶入）/ 訂單（草稿不計入發票淨額，見 [[訂單#金額組成]]）| 草稿的處境見 [[發票狀態]]；五欄硬約束與 [[付款發票邏輯#開發票的含稅與未稅兩個目標值]] 的檢核都延到送出開立時套用 |
| **發票開立**（直接送出或自草稿送出開立）| 發票品項（五欄硬約束）/ 收款核銷分配 / 收款項目（含稅目標值來源）/ 訂單（未稅基準）| 五欄硬約束（ItemCount × ItemPrice = ItemAmt）+ B2B 未稅 / B2C 含稅切換；送出開立當下檢核 |
| **發票作廢** | 折讓單（超過作廢期限改折讓）/ 款項紀錄（退款款項反向）| 作廢期限依齊報稅期規則（見 [[發票法規硬約束-ezPay-MIG]]）+ 超期一律走折讓單 |
| **折讓單確認** | 發票（折讓金額對應）| 折讓只掛發票（不關聯退款款項）+ 隔日上傳財政部 |
| **退款款項（款項類型＝退款、正值）** | 折讓單（金額總額對齊，不建關聯）/ 發票（作廢或折讓）| 退款款項不推進訂單異動（認列已於確認生效時定）+ 折讓與退款金額在對帳總額層對齊 |
| **訂單異動確認可執行** | 款項紀錄（退款核銷對帳的收款差額）/ 發票（作廢或折讓）/ 折讓單（建立）| 確認生效時認列（確認可執行不綁退款款項累計推進，也不倒回前一個狀態）|
| **收款項目自動建**| 訂單（諮詢訂單收尾**不做大貨（來源類型＝諮詢結束無生產）/ 需求單流失（來源類型＝報價流失）**兩情境）/ 發票（業務開立發票帶入內容時取含稅目標值）| 含稅目標值帶入 + 不自動開立發票；**諮詢取消情境不得自動建待開發票**（留存 1000 收入由業務手動開發票、未開發票由對帳差額警示兜底；來源類型的「諮詢取消」保留供業務手動標示）；補收訂單異動不在自動建之列（正本見 [[訂單異動規則]] § 應收總額認列公式）|
| **售後服務單退款** | 訂單異動（售後容器內退款／補收）/ 款項紀錄 / 折讓單 | 跨售後服務單容器 |
| **收款項目刪除或取消** | 發票（只有草稿時草稿一併消失；已開立須先作廢；開立失敗須先由後端人員刪除紀錄）/ 收款核銷分配（一併解除）| 見 [[付款發票邏輯#收款項目重新規劃不設阻擋]] |
| **訂單送主管審核**（線下單）| 收款項目（至少一期）/ 訂單（四格備註）| 送審門檻見 [[訂單狀態]]；業務主管審核時一併檢視各期收款項目 |

### 連帶檢查紀律（規劃時必做）

任何 ERP 規劃 / 設計涉及下列議題，都必須執行連帶檢查：

| 議題類型 | 必檢實體 |
|---------|---------|
| 改退款邏輯 | 款項紀錄（退款款項不推進訂單異動）+ 訂單異動（認列已於確認生效時定）+ 折讓單（金額對齊）+ 發票（作廢或折讓）+ 售後服務單（若訂單已完成）|
| 改發票開立 | 發票（五欄硬約束）+ 發票品項 + 收款核銷分配 + 收款項目（含稅目標值）+ 訂單（未稅基準）+ ezPay 法規 |
| 改訂單異動 | 款項紀錄（退款核銷對帳的收款差額，退款款項不推進訂單異動）+ 發票（補收 / 折讓）+ 折讓單 + 售後服務單（若訂單已完成）|
| 改收款 | 款項紀錄（入帳走收款核銷分配）+ 收款項目（收款狀態推進，見 [[收款項目收款狀態]]）+ 發票（對應）|
| 改補做 | 售後服務單 + 訂單異動（補退）+ 款項紀錄 + 折讓單 + 補做生產任務（掛原工單）|
| 改收款項目 | 訂單（諮詢收尾不做大貨 / 需求單流失觸發、**諮詢取消與補收皆不自動建**見上表；線下單送審門檻）+ 發票（含稅目標值帶入；草稿隨刪除或取消消失）+ 發票品項（五欄）|

### 外部硬約束連帶

任何發票或發票品項的異動都必須對齊 [[發票法規硬約束-ezPay-MIG]] 規範：
- 五欄硬約束（ItemName / ItemCount / ItemUnit / ItemPrice / ItemAmt）
- 作廢有平台時限、超期只剩折讓一條路，正本見 [[發票法規硬約束-ezPay-MIG]]
- B2B 未稅 vs B2C 含稅切換
- 字軌 2 月為 1 期
- 上傳財政部時程（每日 01:00 上傳前日資料）
