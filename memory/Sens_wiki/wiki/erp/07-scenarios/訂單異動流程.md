讀完這張卡，你會知道：

- 說出訂單成立後客戶要求改金額時，為什麼每一筆補收或退款都要從建單一路接力到帳對平（讓應收總額即時反映真實欠款或應退；任何一步漏掉，帳面上看起來處理完了、其實錢沒收回來或沒退出去，月結就會被挑出來回頭查）
- 判斷這段過程從什麼情況啟動：一張已成立的訂單遇到金額要增減，且這筆錢是整筆訂單一起處理、對不上任何一件既有印件
- 走得完補收的接力（判路、建單認列、開發票、收款核銷）；退款建單後的執行交棒見 [[退款執行]]
- 處置退款的各個進入點，以及製作中改規格、完成後售後善後、單據更正、完成前調降多收各條副流程
- 說出走完之後應收總額、已開發票、實際收到三個數字要對齊到什麼程度才算帳對平，對不平時交給誰接手

## 主流程

具體例子：訂單 ORD-2026-0803 製作中，未稅總額 12,501 元、稅額 625 元、應收總額 13,126 元。客戶追加需求、談定整筆加收含稅 1,050 元。這筆錢對不上任何一件既有印件，改走訂單異動：建補收訂單異動 +1,050 元（類型：加印追加）先落草稿，覆核後執行「確認生效」、核可人記為執行者本人，應收總額當場變成 14,176 元；整批貨照常生產不停。隨後就這 1,050 元開一筆收款項目、直接開立發票，客戶付款後登錄收款核銷該收款項目，應收總額、發票淨額、收款淨額三個數字回到 14,176 元對齊（這串數字的完整驗算見 [[對帳一致性]]）。

| 3 | [[收款項目規劃活動清單]] ACT-BPL-001 規劃這張訂單的收款期次 | 自行決定這筆補收要併到哪一期跟客戶收：另建一期，或以 [[收款項目規劃活動清單]] ACT-BPL-004 調整期次的金額、預計日期與款項方式併進既有一期；系統不替人自動建立或調整收款項目（對應關係見 [[收款項目開發票狀態]] 與 [[付款發票邏輯]]） |

| 主流程第 1 步判路之後（獨立發起） | **退款進入點二**：訂單取消 | [[訂單審核活動清單]] ACT-APV-020 收掉不再進行的訂單；要退錢時再以 [[售後受理活動清單]] ACT-AFR-001 受理客戶反映的問題並開立售後服務單，於單內 [[訂單異動活動清單]] ACT-CHG-004 在售後服務單內記下退款或補收 | 引用轉換：[[訂單狀態]] 「終態」以外的任何狀態 → 已取消；下游連鎖見 [[訂單取消]]。**取消與退款是兩件事**：取消不必然退款（客戶未付款、或雙方談定不退都可能）；進終態後**建立**退款一律走售後服務單（見 [[明細時點分界]]；已建立單據的推進不受訂單狀態限制，見 [[訂單異動規則#狀態推進不依訂單狀態]]）。客戶同意把已收的錢改記到重談後的新訂單時，那筆退款走同一條路（規則見 [[訂單異動規則]]）。訂單停在「已取消」，要退的錢已在售後服務單上有一張退款訂單異動，自此同 [[退款執行]] |
| 主流程第 1 步判路之後（獨立發起） | **退款進入點三**：已完成訂單售後退款——訂單已完成後客訴／不良／規格不符，或客戶實測發現不良率過高，不能直接在訂單上開訂單異動 | [[訂單異動活動清單]] ACT-CHG-004 在售後服務單內記下退款或補收 | 在 [[售後服務]] 單容器內建一張標記來源售後服務單的退款訂單異動；依 [[售後服務規則]] 與 [[訂單異動規則#來源售後服務單標記]]，自此同 [[退款執行]]、售後不另開特殊路徑（售後單自身的受理與決議過程見 [[售後受理與決議]]） |
| 主流程第 1 步判路之後（系統自動發起） | **退款進入點四**：諮詢取消退費——客戶於「待諮詢」階段取消 | 系統事件：取消諮詢後系統建立退費訂單異動 | 金額依既定退費政策帶入、不由人判斷；引用轉換：[[訂單異動狀態]] （建立）→ 已核可（關卡見 [[訂單異動規則#諮詢取消退費系統建已核可]]，金額政策正本見 [[諮詢收尾規則]]）。諮詢訂單底下無印件／工單／生產任務，進入點二那種由上往下停掉下游的連動對諮詢訂單為空轉。後續自此同 [[退款執行]]（其副流程的諮詢免審變體），核可人記為系統 |
| 主流程第 1 步判路之後（獨立發起） | **退款進入點五**：預開發票後實作金額低於預估——學校與政府單位常要求先開發票走內部核銷、再依實作結果結算 | [[訂單異動活動清單]] ACT-CHG-001 記下訂單成立後的金額增減，並對先前已開的多張預開發票各以 [[收款項目開立發票活動清單]] ACT-INV-010 沖減已開發票的部分金額 | 就差額建一張退款訂單異動；折讓合計等於退差額。發票拆票與預開的完成過程見 [[收款項目開立發票]]，自此同 [[退款執行]] |
| 主流程第 1 步選了改明細那條路之後 | **完成前調降致多收的錢直接在款項紀錄退**：訂單未進終態，明細調降（少收）後已收的錢超過應收總額 | [[收款核銷活動清單]] ACT-RCV-001 登錄客戶的收款或退款款項 | 直接在款項紀錄建一筆退款款項（款項類型＝退款、金額正值、掛匯款證明），不開退款訂單異動、不送主管核可（適用範圍與理由正本見 [[訂單異動規則#款項紀錄直接建退款]]）；對帳的收款差額歸零，主管事後在活動紀錄看得到那筆調降 |
| 主流程第 1 步之後（訂單已進製作段） | **製作中改規格或追加工序**：廠商或產線缺料要換箔料、紙材或線色；師傅提議追加上膜、上光油或包材保護印件；客戶選的材料在某個工序發現不適合要停機重製。製作中追加工序是這行的常態 | 四條線並行——生產側：[[製程規劃活動清單]] ACT-PLAN-028 發起工單異動調整生產任務（完成過程見 [[工單異動與生產任務調整]]）；訂單側：[[訂單審核活動清單]] ACT-APV-023 維護印件的規格、數量、單價與交期（完成過程見 [[訂單印件規格維護]]）；有價差時依主流程第 1 步的判準選路；客戶端要一份反映最終規格的報價單時：[[報價單簽回活動清單]] ACT-SIGN-010 追加客戶補送的回簽文件（見 [[訂單成立確認]]） | 工單的規格與生產任務已改到位，訂單印件顯示最終製作規格；有價差的那筆錢只由一條路認列。成本上升由公司吸收、不向客戶收時不建訂單異動（依 [[訂單異動規則#零金額不建單]]，紙廠停產換替代紙、我方工單寫錯規格、工廠瑕疵補印、大貨微調補檔都屬這一類），全程無金額單據、只留活動紀錄與通知 |
| 退款進入點三的售後單內（決議含補做時） | **售後善後——補做接力**：訂單已完成後要替客戶重做一批貨 | [[售後受理活動清單]] ACT-AFR-009 送出處理決議（決議「補做」），再以 [[售後處理活動清單]] ACT-AFH-003 依售後決議發起補做 | 單頭層級的決議，不逐印件記數量；補做在客戶反映的那件印件上發起，於原工單加開補做生產任務、設定要補哪幾件與各補多少（執行規則正本見 [[售後服務規則]]）；補做量走完整生產與出貨鏈，與大貨等效。不另建印件也不另建工單，原印件維持「已送達」、審稿零處理 |
| 退款進入點三的售後單內（決議含補做時） | **售後善後——補收分支**：補做要向客戶收費（如補做分攤材料費、加工升級補收、第二次打樣費、紙材成本上漲後重新報價的差額） | [[訂單異動活動清單]] ACT-CHG-004 在售後服務單內記下退款或補收 | 依 [[訂單異動規則#訂單完成後金額異動路徑分流]] 判這筆錢的性質選路——原單善後在同一張 [[售後服務]] 單內建補收訂單異動（自主流程第 2 步起同主流程的補收路徑）、客戶趁機追加的新生意才另開新訂單；這筆加收只落在售後服務單或新訂單其中一處 |
| 退款進入點三的售後單內（決議含補做時） | **售後善後——公司認賠分支**：補做不收客戶錢 | 同 [[售後受理與決議]] 的補做副流程，不建任何金額單據 | 不開訂單異動（無金額變動，依 [[訂單異動規則#零金額不建單]]）；售後單仍提供事件追蹤與品質成本切片價值；訂單的三個金額不動，事件仍在售後服務單上追蹤得到 |
| 任一步建立或推進訂單異動之後 | **訂單異動單據更正——退款金額校正**：主管已核可、退款款項尚未退出去，客戶與公司就退多少談定新數字 | [[訂單異動活動清單]] ACT-CHG-006 修改異動的類型、金額與原因 | 直接校正該退款訂單異動金額，校正窗口與是否需重新送審依 [[訂單異動規則#各狀態可以改什麼]]；系統保留核可金額與當前金額的對照，並寫一筆改金額稽核記錄供事後查核。這個校正窗口對線下退款與諮詢取消退費一致適用；該單金額已是談定的新數字，核可金額與當前金額的對照可查 |
| 任一步建立或推進訂單異動之後 | **訂單異動單據更正——取消建錯的單**：單子建錯、不必要，或談完決定不退了 | 金額尚未認列時：[[訂單異動活動清單]] ACT-CHG-017 收掉建錯或不再需要的異動；金額已認列時：[[訂單異動活動清單]] ACT-CHG-020 收掉金額已認列但建錯的異動 | 引用轉換：[[訂單異動狀態]] 「認列前」的任何狀態 → 已取消；金額已認列時引用轉換：[[訂單異動狀態]] 確認可執行 → 已取消、應收總額同步回退。兩種情況都要填取消原因（認列與否的狀態邊界與判準見 [[訂單異動規則#什麼時候可以取消]]）；取消後不可重開，要更正就重建一張。若先前已依錯誤金額開過發票或收過款，對帳會出現差額，善後過程見 [[對帳與催收]] |

各退款進入點建單之後的核可、認列、退款款項與發票處理，自此同 [[退款執行]]（含諮詢免審變體），本卡不複述。

## 收斂狀態

本卡各條路徑（補收、各進入點的退款、製作中改規格的價差、售後補做的補收、款項紀錄直接退款）最後都回到同一個檢查點——三方對齊（等式正本見 [[對帳一致性]]；三個數字各自怎麼算見 [[訂單#金額組成]]）。

- 補收方向收斂：補收已進「確認可執行」、對應收款項目已開發票並收款核銷，三方對齊、差額歸零。
- 退款方向收斂：退款訂單異動為「確認可執行」（代表有權者已確認、應收總額已減去這筆），退款款項標「已完成」且發票端已折讓或作廢重開，對帳的收款差額核銷歸零。退款款項標「已完成」是退款做完的物理錨點；收款差額沒歸零就代表這筆還沒收付到位，差額正負各代表什麼見 [[訂單#金額組成]]，退款做完的判準見 [[訂單異動規則#退款確認可執行認列]]。
- 無金額變動的收斂：公司吸收成本或認賠補做的情形沒有任何金額單據，訂單的三個數字不動，收斂在工單規格已改到位、通知與活動紀錄留痕。
- 帳對不平時：差額不為零，對帳清單把這筆挑出來催補、補處理後複核——這段查核與催收的完成過程見 [[對帳與催收]]，本卡不複述；實際退款匯出見 [[退款執行]]。

## 範圍外

- 訂單異動各狀態怎麼轉、哪些轉換條件永遠要成立 → [[訂單異動狀態]]（狀態與轉換的標準依據，本卡只引用狀態名）。
- 兩路並行的判準本體、補收免審／退款送審／諮詢取消由系統建已核可的分權規定本體、認列公式、為什麼這樣定 → [[訂單異動規則]]（規則正本，本卡只引用）。
- 直接增減金額明細的完成過程（新增印件、改購買數量與單價、改折扣與其他費用、製作後改規格的通知對象）→ [[訂單印件規格維護]]；明細可改到什麼時候的分界 → [[明細時點分界]]。
- 工單側的規格改寫與生產任務調整怎麼做完 → [[工單異動與生產任務調整]]（本卡只承接金額那一線）。
- 售後服務單本身的受理、處理、結案進度與決議分流規則 → [[售後服務]] 實體卡、[[售後服務規則]] 與 [[售後受理與決議]]。
- 發票開立、折讓、作廢的外部法規硬約束（品項五欄、作廢時限、字軌）→ [[發票法規硬約束-ezPay-MIG]]；款項發票情境分類全貌 → [[帳務規劃連帶矩陣#訂單異動情境]]。
- 補收後收款項目的開發票與收款狀態怎麼推進、拆期稽核 → [[收款項目開發票狀態]]、[[收款項目收款狀態]]、[[收款項目開立發票]]、[[收款核銷分配]]。
- 訂單取消後系統由上往下停掉工單／任務／生產任務時各自停在哪個狀態的細節 → [[訂單狀態]]。
- 月結對帳的差錯偵測、催收與明細匯出的完整過程 → [[對帳與催收]]（本卡的收斂只停在三方對齊的業務事實，不重述查核步驟）。
- 一筆客戶匯款橫跨多張訂單的拆分對帳、同一張訂單混單出貨 → 不做系統化，人工拆分後分別登錄（範疇界定見 [[付款發票邏輯]]），本卡不承載這條路。
- 訂單成立前的重新報價、多個金額版本的報價單、原訂單取消後已收款怎麼接到新訂單 → [[需求單報價成交]] 與 [[訂單成立確認]]（本卡只處理已成立訂單的金額增減）。
- 退款款項實際匯出的排程、第三方電子發票平台與第三方金流的內部運作 → 屬實作規格與外部平台，存在但不在本卡，下游勿據此腦補系統定時批次或自動折讓。
- 對帳差額警示怎麼區分「待開發票」與「退款待執行」兩種善後缺口語意、對外正式措辭怎麼寫 → 屬 [[對帳與催收]] 與上線前的確認項（決議見 [[BI-16-差額警示文案區分待開票與退款待執行]]，已封存）。
- 訂單完成後「向客戶加收」走哪條路的判準本體 → [[訂單異動規則#訂單完成後金額異動路徑分流]]；本卡在售後善後副流程的補收分支承接其中「原單善後的加收」這一條，新生意另開新訂單那一條不在本卡。
