讀完這張卡，你會知道：

- 判斷活動清單查不到的組合該怎麼解讀：沒有列出就是不能做；沒有檢視權的人直接開網址也看不到內容
- 查出活動清單卡的範圍欄能填哪些用詞、各指哪些單據
- 分辨管理權責（誰對單據負責）與操作權限（誰在系統上能動單據）
- 說出誰能在訂單或工單關聯的單據上做負責人能做的動作，以及哪些動作除外
- 查出實體卡操作段的動作類型能填哪些值
- 查出操作編號用哪個單據代碼、活動編號用哪個活動清單代碼
- 說出為什麼這些值要集中在一張卡、不讓各卡自己取

## 現況

本卡只登記已搬入新結構的卡用到的值。後端只有訂單與需求單依單據範圍判定，工單與生產管理尚未依範圍判定。

## 規則

### 未列即不可做

- 活動清單沒有列出的角色、範圍、操作組合，就是不能做。
- 活動清單只列能做的組合，不另列「不能做」；查不到某個組合時，答案是不能做，不是無法判定。
- 檢視活動清單沒有列出某人對某張單據的檢視組合時，這個人直接開該單據詳情頁的網址，系統導回預設頁面，不顯示單據內容。

### 範圍用詞

| 用詞 | 定義 |
|------|------|
| 全公司 | 該模組全部單據 |
| 自己負責 | 該單據的人員欄是本人（看哪一欄由活動清單卡的依據欄位寫明） |
| 被分享（檢視） | 以檢視層級分享給本人且未撤銷的單據 |
| 被分享（編輯） | 以編輯（代理）層級分享給本人且未撤銷的單據 |
| 所屬產線 | 單據的產線在本人的所屬產線內；只用於生產相關模組（所屬產線欄見 [[人員]]） |

- 分享成員的候選限下列角色：對該單據至少有一列不靠分享的活動（範圍為全公司、自己負責或所屬產線）。
- 活動清單的被分享列在執行角色欄寫「所有角色」，即指這些候選角色。
- 例：訂單可分享給業務、諮詢、業務主管、訂單管理人、印務主管、印務、審稿主管、Supervisor；會計、生管等角色不可。
- 「被指派」不是獨立的範圍用詞；被指派到某張單據的人，以該單據的人員欄算自己負責。
- 同一張單據出現在不同模組時，各模組的檢視各寫成自己的活動列，範圍依該列判定。例：工單詳情內的生產任務依工單或訂單的範圍，生產管理單元的生產任務依所屬產線。

### 管理權責與操作權限

- 管理權責是誰對單據負責，例如需求單與訂單由接單業務負責。
- 操作權限是誰在系統上能動某張單，由活動清單決定。
- 編輯層級的分享成員或系統自動授予的人動了單據，管理權責仍在負責人。

### 訂單關聯單據的編輯權

- 對訂單有編輯權限的人，能在訂單直接關聯的單據上做接單業務能做的動作。
- 對訂單有編輯權限的人如下：
  - 自己負責：[[訂單]] 接單業務是本人的業務或諮詢。
  - 被分享（編輯）：[[訂單]] 分享成員以編輯層級列入的人。
  - 全公司協助角色：[[業務主管]]、[[訂單管理人]]、[[印務主管]]、[[印務]]、[[審稿主管]]、[[Supervisor]]。
- 直接關聯的單據：[[印件]]、[[出貨單]]、[[物流單]]、收款項目、發票與折讓、款項紀錄（三者見 [[帳務]]）、[[訂單異動]]、[[售後服務]] 單。
- 下列動作不適用本規則：
  - 審核類動作，例如核准訂單、核可或退回訂單異動、取消已認列的訂單異動。這些動作只限該訂單的審核業務主管本人。
  - 執行角色是其他角色的現場動作，例如揀貨、裝箱回報、拋單、出貨確認、標記可自取、標記例外、送達確認、補附送達憑證。
  - 管理類動作，例如改派接單業務、重新指定審核業務主管、管理分享成員。這些動作見 [[人力調度與職務代理流程群組]]。
- 每個適用的動作，仍在所屬活動清單逐列寫出。查某角色能不能做某件事，以活動清單為準。

### 工單關聯單據的編輯權

- 對工單有編輯權限的人，能在工單直接關聯的單據上做負責印務能做的動作。逐列寫出與查詢的方式，同 § 訂單關聯單據的編輯權。
- 對工單有編輯權限的人如下：
  - 自己負責：[[工單]] 負責人是本人的印務。
  - 被分享（編輯）：[[工單]] 分享成員以編輯層級列入的人。
  - 全公司：[[印務主管]]。
- 直接關聯的單據：[[生產任務]]、[[報工紀錄]]，以及以工單負責人判定範圍的 [[印件]] 操作（製程說明與品檢需求、印務印件檔案、規格備註與包裝備註、缺口處置、發起補做、短出結案）。
- 一件 [[印件]] 底下有多張工單時，以工單判定範圍的印件操作與檢視，看該印件任一張工單：任一張工單的負責人或分享成員都算，不因那張工單已進終態而失去資格。個別操作另有狀態條件者，依該操作所在實體卡（例如製程說明與品檢需求限該工單未進終態）。
- 下列動作不適用本規則：
  - 審核類動作，例如核可或退回製程、核可工單異動、生管確認工單異動。
  - 執行角色是其他角色的現場動作，例如師傅報工、生管派工與排程、品檢、轉交點收。

### 動作類型

| 動作類型 | 定義 |
|---------|------|
| 檢視 | 打開單據看內容，不改任何資料 |
| 建立 | 產生一張新單據，或在本單據上產生一張下層單據 |
| 編輯 | 修改單據上的欄位，不改變狀態 |
| 刪除或作廢 | 讓單據離開生命週期（刪除）或收在作廢類終態 |
| 狀態推進 | 讓單據從一個狀態轉到另一個狀態 |
| 審核 | 核准或退回別人送出的單據；送出者與核准者分屬不同活動 |
| 指派或改派 | 指定或更換單據上的負責人員 |
| 分享管理 | 授予、改層級或收回單據的分享成員 |
| 輸出 | 把單據內容下載或匯出到系統外 |

## 為什麼這樣定

- 直接開網址也要擋，因為列表不列出只是少一個入口；網址不擋，沒有檢視權的人仍看得到單據內容。
- 分享候選依活動列判斷，因為後端依活動列設權限；分享不可讓沒有該模組權限的人取得入口。
- 範圍用詞固定，依單據或依角色查出的權責矩陣才能直接比對，交付開發的權限表才能照抄，後端也能照用詞切權限。
- 所屬產線只用在生產相關模組，因為訂單與需求單的單據沒有產線歸屬。
- 上下層關係不另立範圍用詞：經上層單據取得的範圍沿用上層的用詞與依據欄位，不必每多一種上下層關係，就多一個範圍用詞；上層單據看得到，下層單據就跟著看得到，代理與交接才做得完。
- 管理權責與操作權限分開寫，因為能動單據的人，不一定是負責的人；責任留在負責人，追溯時才找得到該回答的人。
- 訂單關聯單據跟著訂單的編輯權，因為代理或協助處理一張訂單時，最常要動的就是出貨單、售後服務單與帳務；只能動訂單本身，就代理不完。審核類動作排除，送出者與核准者才維持分權。
- 工單關聯單據跟著工單的編輯權，因為印務主管代做或同事代理一張工單時，要動的多半是旗下的生產任務、報工與印件上的缺口處置；只能動工單本身，就代做不完。
- 動作類型逐類列出，寫實體卡操作段時才能逐類走過、不漏動作；審核獨立成類，才查得出送出者與核准者是否分權。
- 代碼集中登記，不同撰寫者取號時才不會撞號，也不會同一張單據用兩個代碼。
- 物流單沿用出貨單的代碼，因為物流單是出貨單的下層單據，不是另一種單據。
