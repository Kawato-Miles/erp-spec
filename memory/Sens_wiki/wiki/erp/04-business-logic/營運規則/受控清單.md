讀完這張卡，你會知道：

- 判斷活動清單查不到的組合該怎麼解讀：沒有列出就是不能做
- 查出活動清單卡的範圍欄能填哪些用詞、各指哪些單據
- 分辨管理權責（誰對單據負責）與操作權限（誰在系統上能動單據）
- 查出實體卡操作段的動作類型能填哪些值
- 查出操作編號用哪個單據代碼、活動編號用哪個活動清單代碼
- 說出為什麼這些值要集中在一張卡、不讓各卡自己取

## 現況

本卡只登記已搬入新結構的卡用到的值。後端只有訂單與需求單依單據範圍判定，工單與生產管理尚未依範圍判定。

## 規則

### 未列即不可做

- 活動清單沒有列出的角色、範圍、操作組合，就是不能做。
- 活動清單只列能做的組合，不另列「不能做」；查不到某個組合時，答案是不能做，不是無法判定。

### 範圍用詞

| 用詞 | 定義 |
|------|------|
| 全公司 | 該模組全部單據 |
| 自己負責 | 該單據的人員欄是本人（看哪一欄由活動清單卡的依據欄位寫明） |
| 被分享（檢視） | 以檢視層級分享給本人且未撤銷的單據 |
| 被分享（編輯） | 以編輯（代理）層級分享給本人且未撤銷的單據 |
| 所屬產線 | 單據的產線在本人的所屬產線內；只用於生產相關模組（所屬產線欄見 [[人員]]） |

- 「被指派」不是獨立的範圍用詞；被指派到某張單據的人，以該單據的人員欄算自己負責。
- 同一張單據出現在不同模組時，各模組的檢視各寫成自己的活動列，範圍依該列判定。例：工單詳情內的生產任務依工單或訂單的範圍，生產管理單元的生產任務依所屬產線。

### 管理權責與操作權限

- 管理權責是誰對單據負責，例如需求單與訂單由接單業務負責。
- 操作權限是誰在系統上能動某張單，由活動清單決定。
- 編輯層級的分享成員或系統自動授予的人動了單據，管理權責仍在負責人。

### 動作類型

| 動作類型 | 定義 |
|---------|------|
| 檢視 | 打開單據看內容，不改任何資料 |
| 建立 | 產生一張新單據，或在本單據上產生一張下層單據 |
| 編輯 | 修改單據上的欄位，不改變狀態 |
| 刪除或作廢 | 讓單據離開生命週期（刪除）或收在作廢類終態 |
| 狀態推進 | 讓單據從一個狀態轉到另一個狀態 |
| 審核 | 核准或退回別人送出的單據；送出者與核准者分屬不同活動 |
| 指派或改派 | 指定或更換單據上的負責人員 |
| 分享管理 | 授予、改層級或收回單據的分享成員 |
| 輸出 | 把單據內容下載或匯出到系統外 |

## 為什麼這樣定

- 範圍用詞固定，依單據或依角色查出的權責矩陣才能直接比對，交付開發的權限表才能照抄，後端也能照用詞切權限。
- 所屬產線只用在生產相關模組，因為訂單與需求單的單據沒有產線歸屬。
- 上下層關係不另立範圍用詞：經上層單據取得的範圍沿用上層的用詞與依據欄位，不必每多一種上下層關係，就多一個範圍用詞；上層單據看得到，下層單據就跟著看得到，代理與交接才做得完。
- 管理權責與操作權限分開寫，因為能動單據的人，不一定是負責的人；責任留在負責人，追溯時才找得到該回答的人。
- 動作類型逐類列出，寫實體卡操作段時才能逐類走過、不漏動作；審核獨立成類，才查得出送出者與核准者是否分權。
- 代碼集中登記，不同撰寫者取號時才不會撞號，也不會同一張單據用兩個代碼。
