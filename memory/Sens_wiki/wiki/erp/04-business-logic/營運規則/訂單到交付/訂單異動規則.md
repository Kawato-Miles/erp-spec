讀完這張卡，你會知道：

- 判斷訂單成立後的金額增減該走哪條路：直接改明細、訂單異動、售後服務單、新訂單還是款項紀錄
- 說出補收為什麼不用主管審、退款為什麼要，以及這條不對稱的界線切在哪裡
- 算出應收總額怎麼組成，以及每一筆增減在哪一刻算進去
- 判斷一張訂單異動在各個處境能改什麼、誰能取消它
- 分辨「該退多少」與「錢退好沒」是兩層各自把關的事

## 現況

印刷廠接單後金額常臨時變動：客戶在製作中追加印量、改急件、補運費，公司多收錢（稱補收）；或因品質、規格不符要退費，公司退錢出去（稱退款）。這兩個方向的營運風險不對稱——錢退出去一旦出錯難追回，客戶加單則是送上門的生意。

主管讀本卡要能驗證的是：這套「補收免審、退款送審」的分權，以及「主管核可把關該不該退、業務執行確認生效時才認列、實際退錢另在對帳核銷」的認列規則，是否符合公司實際的現金管控需求。

## 規則與營運動機

> 本段各條規則依「分權（補收免審／退款送審／諮詢取消退費系統建已核可）→ 認列（退款確認可執行認列／應收總額認列公式）→ 可改與可取消（各狀態可以改什麼／什麼時候可以取消／零金額不建單）→ 動機與來源標記（補收退款不對稱／來源售後服務單標記）→ 完成前後的路徑分流（訂單完成前金額異動兩路並行／訂單完成後金額異動路徑分流／款項紀錄直接建退款／原訂單取消後已收款轉用新訂單）」排列。各條規則要守住的底線集中在「一定要成立的規則」段。

### 補收免審

| 項目 | 內容 |
|------|------|
| 意圖 | 客戶主動加錢不被主管流程卡住，保住加單生意與出貨時程 |
| 規則 | 補收＝金額為正的訂單異動，任何異動類型皆同（類型值域正本見 [[訂單異動]]）：免主管審核。建立時先落「草稿」，業務覆核後點「確認生效」，單據直接推進到「確認可執行」（不經待主管審核與已核可）；確認生效當下寫入核可人（記業務本人）、核可時間與生效時間，這筆要收的錢也在這一刻加進應收總額，而且不用去對任何一筆退款 |
| 營運動機 | 客戶臨時加印是送上門的生意，等主管核可會拖延出貨、可能流失加單；加錢方向風險低（公司是收錢方），授權業務當場拍板。先落草稿是給業務一個覆核金額與訂單的機會（打錯一個零在確認前還收得回來），不是多一道審核。服從 [[現金流出把關]]——把關的鬆緊跟著錢的流向走（進來的可鬆） |

### 退款送審

| 項目 | 內容 |
|------|------|
| 意圖 | 退錢出去前先由主管把關該不該退；退多少由業務與客戶談定後執行「確認生效」，於此刻才認列，實際退錢另在對帳階段核銷 |
| 規則 | 退款（負的）訂單異動（金額是退錢，業務發起）：走路徑——草稿 → 待主管審核 → 已核可 → 確認可執行。主管核可時寫入核可人、核可時間與核可金額，單據停在「已核可」、應收總額此刻不動；業務與客戶談定退多少後執行「確認生效」，單據推進「確認可執行」、寫入生效時間，應收總額於此刻減去這筆金額，不必等實際退錢。之後業務真的把錢匯出去、那筆退款款項標成「已完成」並掛上匯款證明，是在對帳階段把「應該退的差額」核銷歸零（見 [[對帳一致性]]） |
| 營運動機 | 錢退出去出錯難追回，由業務主管把關該不該退（把關擺在核可這一關）；退多少在退錢之前常與客戶再談定，故核可後停「已核可」留一個校正窗口，認列擺在執行「確認生效」那一刻——生效後應收總額就定了、不再回頭改。實際退沒退改由對帳的收款差額盯住（退款款項標已完成才核銷歸零），把「該退」與「退好沒」分兩層各自把關。服從 [[現金流出把關]]——出去的要嚴（嚴在主管核可這一關）|

### 諮詢取消退費系統建已核可

| 項目 | 內容 |
|------|------|
| 意圖 | 諮詢取消退一半是既定規則、不需人工判斷審核，但金額確認仍由諮詢人員把關 |
| 規則 | 諮詢取消退費訂單異動（系統自己建的、不是業務手動開，退費金額固定，金額政策正本見 [[諮詢收尾規則]]）：「負向異動須審核」的規則不破例——因退費金額固定，**審核由系統代行**，建單即自動推進「已核可」（核可人掛在系統名下、生效時間先空著）。已核可階段諮詢人員可調整退款金額（沿用「各狀態可以改什麼」），也可取消這張單（決定不退了）。諮詢人員執行**確認生效**後，單據推進「確認可執行」——**應收總額於此刻認列減去**；後續收尾（實際退款、折讓與發票處置）見 [[諮詢收尾規則]]。此類型為系統專用，業務不可手動建立 |
| 營運動機 | 退費金額固定是既定政策、不需主管再判斷（審核由系統代行，主管的退款審核佇列只留線下單）；建為已核可（而非直接確認可執行）讓諮詢人員在認列前仍能調整金額或決定不退；認列（確認可執行）與物理退款分兩層，退好沒由對帳的收款差額盯住 |

### 退款確認可執行認列

| 項目 | 內容 |
|------|------|
| 意圖 | 退款的「認列」跟著業務執行「確認生效」走，實際退錢另由對帳盯住，兩層分開 |
| 規則 | 退款（負的）：主管核可後訂單異動停在「已核可」（寫入核可人與核可金額，應收總額此刻不動）；業務與客戶確認退多少之後執行「確認生效」，單推進確認可執行、記下生效時間、應收總額於此刻減去這筆，不再等實際退錢、不綁退款款項累計。已核可期間可校正金額（不需重審，每次改留稽核記錄，核可金額不變）或取消（決定不退）。諮詢取消退費同一形狀，差別只在審核由系統代行，見「諮詢取消退費系統建已核可」。實際退錢是另一層：會計依待出金退款清單出金、[[業務]] 掛上匯款證明並把退款款項標成「已完成」（見 [[待出金退款清單組成]]），把對帳的收款差額核銷歸零（見 [[對帳一致性]]），不回頭改這張訂單異動。退款款項的金流記在收款款項那一條（款項類型＝退款、金額正值）、不掛在訂單異動上；退款款項本身要核銷到收款項目（扣減該期已收，見 [[款項狀態]]），訂單異動則不與收款項目關聯。若退款款項建錯：取消它，對帳的收款差額會重新出現、由差額提醒引導業務重退，訂單異動維持確認可執行、應收總額不因此變動 |
| 營運動機 | 把「該退多少」（主管核可該不該退、業務與客戶談定金額後執行「確認生效」認列進應收總額）與「退好沒」（退款款項已完成、對帳核銷）分兩層各自把關：認列擺在「確認生效」那一刻，應收總額即時反映談定的金額、不卡在退款動作上；退沒退改由對帳的收款差額盯住，比用單據狀態硬扣更貼合實務（退款常分次、可能建錯重退）。取消退款款項不回退訂單異動，由對帳差額重現引導重退（見 [[ORD-003-取消退款Payment是否回退OA]]）|

### 應收總額認列公式

| 項目 | 內容 |
|------|------|
| 意圖 | 應收總額即時反映金額增減，但不替業務決定分幾期收 |
| 規則 | 應收總額由哪些項目加減組成，見 [[訂單#金額組成]] 欄位表；本卡管的是其中「訂單異動的異動金額」這一項的認列門檻——只有走到「確認可執行」的訂單異動才計入應收總額，停在草稿／待主管審核／已退回／已核可的都不算。進入「確認可執行」的時點依路徑：補收於業務確認生效時、線下退款與諮詢取消退費於業務或諮詢人員確認生效時——三條路徑統一在此認列，無特例。訂單異動推進到確認可執行時觸發應收總額重算，被取消時該筆退出加總、不再計入應收總額；兩種情況系統都不自動建立或修改 [[收款項目狀態]] |
| 營運動機 | 應收總額要即時反映真實欠款／應退，但「分幾期收、何時開發票」是業務依客戶狀況另行規劃，系統自動動收款項目反而打亂業務既有安排。本認列門檻須服從對帳底線（應收總額 ＝ 發票淨額 ＝ 收款淨額，正本見 [[對帳一致性]] 共用規則卡）|

### 各狀態可以改什麼

| 項目 | 內容 |
|------|------|
| 意圖 | 一張訂單異動在哪個處境能改哪些內容，界線跟著「主管核可的是什麼」與「錢有沒有算進應收總額」走 |
| 規則 | 各處境可改的內容見下表。每次改金額寫一筆金額異動歷史（修改時間／修改人／修改前金額／修改後金額／當時狀態）；改異動類型或異動原因寫入訂單活動紀錄，含改前與改後的內容 |
| 營運動機 | 已核可後現實常變（客戶談妥的退款數字微調），允許改金額不重審以免流程空轉；但同一個處境鎖住異動類型，因為改類型等於換一張單，主管核可的對象就不是原來那張了。已退回三項全開，是因為主管退回常常就是類型選錯或理由寫不清，而且改完必須重新送審、主管會再看一次。確認可執行代表應收總額已認列，再改會破壞對帳，要更正就整張取消。已核可改金額**不通知主管、也不設金額門檻重審**——核可金額與稽核記錄已留痕，主管核可的是「該不該退」，改後的數字是業務跟客戶談出來的；每次推播會變成雜訊 |

| 處境 | 異動金額 | 異動類型 | 異動原因 |
|------|---------|---------|---------|
| 草稿 | 可改 | 可改 | 可改 |
| 待主管審核 | 不可改 | 不可改 | 不可改 |
| 已退回 | 可改，改後重新送審 | 可改，改後重新送審 | 可改，改後重新送審 |
| 已核可 | 可改，不需重新送審 | 鎖定 | 可改 |
| 確認可執行 | 鎖定 | 鎖定 | 鎖定 |
| 已取消 | 鎖定 | 鎖定 | 鎖定 |

### 什麼時候可以取消

| 項目 | 內容 |
|------|------|
| 意圖 | 建錯、不必要或決定不退的單都要有出口，每一筆都要說得出為什麼取消；能不能自己取消則跟著「錢有沒有算進應收總額」走 |
| 規則 | 任一處境都可以取消訂單異動（轉「已取消」，終態不可重開），**取消原因一律必填**。金額尚未認列的（草稿／待主管審核／已退回／已核可）由該單負責業務或業務主管取消，應收總額不動。金額已認列的（確認可執行）另限 [[業務主管]] 取消，這筆金額不再計入應收總額；取消後若應收總額低於已開發票淨額或已收款淨額，對帳出現差額並提示業務處理（作廢發票、開立折讓或補收）。取消一律寫入訂單活動紀錄，含操作者、取消前金額與取消原因 |
| 營運動機 | 訂單異動只影響應收總額，不與任何款項或發票單據綁定，所以取消一張建錯的單不必另建反向單把帳面弄成兩筆對沖。但這筆金額一旦不再計入應收總額，已開的發票與已收的款就可能對不上，所以已認列的取消限主管、原因必填，後續由對帳的差額提醒接住。原因一律必填，是因為取消掉的單事後只剩一行紀錄，沒寫原因就查不出當初為什麼不做了；至於誰能取消則分兩段，因為風險不同——還沒算進應收總額的單取消不影響任何人，算進去的會牽動發票與收款 |

### 零金額不建單

| 項目 | 內容 |
|------|------|
| 意圖 | 沒有金額增減的規格調整不該佔用一張金額訂單異動 |
| 規則 | 純規格變更若金額 ＝ 0：不建立訂單異動。製作後的印件規格異動（非金額類，如規格備註／單位／難易度）由 [[業務]] 直接編輯，系統自動通知相關 [[印務]]／[[印務主管]] 並寫活動紀錄，不走訂單異動 |
| 營運動機 | 訂單異動是金額載具，規格調整無金額時走通知＋活動紀錄即可，避免無金額的空單據混淆對帳 |

### 補收退款不對稱

| 項目 | 內容 |
|------|------|
| 意圖 | 明確記錄「為什麼補收免審、退款送審」這條對稱破壞的營運根據，供主管驗證前提是否成立 |
| 規則 | 補收（補收免審）與退款（退款送審）採不對稱分權：主管把關現金流出方向（退款風險高、出錯難追回），不把關客戶下單追加方向（補收是送上門生意，等審核會拖延出貨、流失加單）。不對稱只切在「要不要主管這一關」——兩個方向都要有人執行一次「確認生效」才認列，差別在執行的人是誰（補收是業務自己，退款是主管核可後再由業務與客戶談定金額並執行）。對齊台灣印刷業實務分權 |
| 營運動機 | 對稱設計（兩方向都送審或都免審）會在「擋不該擋的加單」與「放掉該管的退款」之間二擇一犯錯；不對稱分權讓風險與管控強度匹配。這正是 [[現金流出把關]] 的展開——把關鬆緊跟著錢的流向走，不跟著金額有沒有變動走。這條一邊免審一邊送審的不對稱，怎麼講才清楚見 [[BI-9-補收OA立即執行對稱破壞表述]] |

### 來源售後服務單標記

| 項目 | 內容 |
|------|------|
| 意圖 | 訂單完成後的金額增減沿用同一套異動流程，僅以一個標記區分它是從哪張售後服務單來的 |
| 規則 | 訂單異動上可以標一個記號，註明它是從哪一張售後服務單來的：沒標記號＝訂單進終態前 [[業務]] 在訂單內直接建立；已標記號＝訂單進終態後從 [[售後服務]] 單內建立的訂單異動（同一張售後單也可能同時決議補做，補做的執行規則正本見 [[售後服務規則]]）。標記與否走完全相同的規則——退款一樣送主管審、補收一樣免審先落草稿，可改範圍與取消規則也一致；這個記號一經標上去就不能再改 |
| 營運動機 | 訂單完成後的客訴善後沿用同一套異動流程，不因來源另開例外路徑，主管審核與認列邏輯一致、降低維護負擔；標記只供反查來源，不改變規則本身。哪些完成後的加收該掛在售後單、哪些該另開新訂單，見「訂單完成後金額異動路徑分流」 |

### 訂單完成前金額異動兩路並行

| 項目 | 內容 |
|------|------|
| 意圖 | 訂單完成前的金額增減留兩條路，讓對得上項目的錢改在明細上、整筆訂單一起處理的錢走訂單異動 |
| 規則 | 訂單還沒進入「訂單完成」終態時，同一筆金額增減由 [[業務]] 選一條路走，選哪條依這筆錢對不對得上具體項目判斷。（一）**直接增減明細**——這筆錢對得上具體項目（印件的購買數量、單價、其他費用、折扣金額，含新增印件）時，直接改明細、應收總額隨之重算（時點分界見 [[明細時點分界]]）。（二）**建訂單異動**——這筆錢是整筆訂單一起處理的金額（如整單退一筆錢、整單加收一筆費用），建退款或補收訂單異動；退款走「退款送審」、補收走「補收免審」，兩條路的規則不因訂單還沒完成而改變。同一筆金額增減只能走其中一條 |
| 營運動機 | 兩種形狀的錢混在一條路上都會失真：對得上項目的錢寫成訂單異動，明細就看不出這批貨實際賣多少；整筆處理的錢硬塞進明細，得先挑一個項目掛上去、掛哪一項都不對。所以留兩條路、由業務當場判斷，判斷成本只有一句話（這筆錢有沒有對應的項目）。訂單異動不因訂單還沒完成就關掉，是因為客戶要求整筆退錢與訂單走到哪一步無關；退錢的把關維持在主管核可那一關（見 [[現金流出把關]]），不靠訂單狀態代勞 |

### 訂單完成後金額異動路徑分流

| 項目 | 內容 |
|------|------|
| 意圖 | 訂單一旦進終態（「訂單完成」或「已取消」），金額就不在訂單內直接改，改走哪條善後路徑要分清楚「原單善後」與「新生意」 |
| 規則 | 訂單進入終態（「訂單完成」或「已取消」，見 [[訂單狀態]]）後，明細金額鎖定（見 [[明細時點分界]]），**訂單異動的建立**一律先開一張 [[售後服務]] 單（系統不自動建，由業務要動這筆錢時手動開；已建立單據的狀態推進不受此限，見「狀態推進不依訂單狀態」）。適用範圍為訂單類型線下與線上；諮詢訂單因取消進終態時的系統內生退費不在此限（見「諮詢取消退費系統建已核可」）。開單之後再依這筆錢的性質分流：（一）**原單善後**——退錢給客戶、替客戶重做一批貨（補做）、或就這次瑕疵處理向客戶收一部分費用（如補做分攤、急件重製費）→ 金額動作都掛在該張售後單底下（退款訂單異動走退款送審、補收訂單異動走免審先落草稿），補做走既有補做機制（規則正本見 [[售後服務規則]]）；（二）**新生意**——客戶趁這次機會追加新品項或新需求 → 另開一張新訂單獨立報價收費，不掛在售後單、也不在原訂單內建訂單異動。原訂單取消後已收款要改記到新訂單的那筆退款，屬原單善後、走第（一）條（見「原訂單取消後已收款轉用新訂單」）|
| 營運動機 | 分界是「這筆錢是不是這次客訴處理的一部分」，業務當場就判得出來。原單善後的收付都掛在同一張售後單，事件脈絡完整、事後查得到這次客訴總共退了多少收了多少；新生意開新訂單才能獨立報價、開發票、收款，不會把已結算的原單帳目又拉開。完成後在售後單內加收會讓已完成訂單的應收總額上升，發票與收款不自動建，由業務補開票補收款，對帳的差額提醒會盯住這段落差 |

### 狀態推進不依訂單狀態

| 項目 | 內容 |
|------|------|
| 意圖 | 一張已經合法建立的訂單異動，不因訂單後來進終態而卡死在半路 |
| 規則 | 訂單異動的狀態推進（送審、核可、退回、確認生效、取消）**一律不看訂單當下的狀態**。訂單在製作期間建立的異動，訂單進終態後照樣送審、核可、確認生效；掛在 [[售後服務]] 單底下的異動，該售後單結案後照樣推進。訂單取消的連鎖處置**不含在途訂單異動**——未認列的異動不隨訂單取消而作廢，由 [[業務]] 自行判斷推進或取消（連鎖範圍見 [[訂單狀態]]）|
| 營運動機 | 把關只做在建立那一關：終態後要動這筆錢，先開售後服務單。同一道把關在推進時再做一次，擋掉的不是新的資源流出，而是一張已經存在的在途單據——業務只能作廢重開，帳面多一筆什麼都沒發生的取消紀錄。錢本身的把關沒有放掉：退款仍送 [[業務主管]] 核可（見 [[現金流出把關]]），應收總額仍於「確認生效」那一刻才認列。副作用是業務可在訂單完成前先建草稿、完成後才生效，繞過售後脈絡；這一點由對帳的「完成後仍有異動認列」重核提示留下痕跡（見 [[對帳一致性]]），不另設把關 |

### 款項紀錄直接建退款

| 項目   | 內容                                                                                                                                                                                                                                                                                                             |
| ---- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 意圖   | 完成前因調降而要把已多收的錢退回去，讓業務直接在款項紀錄退、不必再開一張退款訂單異動送主管核可                                                                                                                                                                                                                                                                 |
| 規則   | 本路徑的適用範圍與短出的處置見本表下方列點 |
| 營運動機 | 完成前的調降本身就是業務當場可決定的事（弱把關、事後可見，見 [[明細時點分界]]），調降後把多收的錢退回去屬同一筆操作的收尾，再要求開訂單異動送主管核可會把當場能結的事拖成兩段流程。把關擺在「調降」這個源頭（主管事後看得到），退錢動作不再重複送審；送審的力氣留給訂單完成後的客訴退款——那時明細已鎖定，沒有源頭那一關可倚靠。本路徑的前提是應收總額已隨明細調降下修、已收才會超過應收總額；短出不下修數量、應收總額沒降，直接在款項紀錄退錢會讓收款淨額低於應收總額，打破對帳底線（應收總額 ＝ 發票淨額 ＝ 收款淨額，見 [[對帳一致性]]），所以短出要退差額必須走能讓應收總額下降的退款訂單異動                                                                                                                  |

本路徑的適用範圍與排除：

- 適用範圍只有一種情形：訂單完成前（未進入終態）因明細調降（少收）導致已收的錢超過應收總額。
- 該情形下 [[業務]] 可直接在款項紀錄建一筆退款款項（款項類型＝退款、金額正值、掛匯款證明）。
- 該情形下不需開退款訂單異動、不需 [[業務主管]] 核可。
- 訂單完成後的客訴退款一律不走本路徑，走 [[售後服務]] 單內的退款訂單異動（見「退款送審」）。
- 短出（讓步允收）的收尾一律不走本路徑：短出不下修數量帳、應收總額沒有跟著降（數量帳見 [[齊套邏輯]]、結案轉換見 [[印件狀態]]）。
- 短出談定要退差額時，一律開一張退款訂單異動（走「退款送審」），應收總額於認列那一刻才下降。

### 原訂單取消後已收款轉用新訂單

| 項目 | 內容 |
|------|------|
| 意圖 | 客戶整案重新報價、原訂單不沿用時，讓原訂單與新訂單各自把帳結乾淨，不靠款項在訂單之間搬移 |
| 規則 | 原訂單已收過款、客戶同意把這筆錢用在重談後的新訂單時，三件事分別做完：（一）原訂單開一張 [[售後服務]] 單（售後類型記「其他」、客訴內容記重談原因），在該單底下建一筆退款（負的）訂單異動、金額取原訂單當時的應收總額，走「退款送審」那條路，認列後原訂單應收總額歸零；（二）原訂單那筆款項紀錄取消（款項狀態轉「已取消」，取消款項退出對帳加總，見 [[款項狀態]]），取消備註寫明這筆錢改記在哪一張新訂單上；（三）新訂單依實收金額另建一筆款項紀錄，並核銷到該訂單的收款項目。兩張訂單彼此不關聯——系統不提供款項在訂單之間轉掛、也不設承接標記；原訂單已開過的發票另依作廢或折讓處置（見 [[付款發票邏輯]]）|
| 營運動機 | 原訂單取消不會讓應收總額自己歸零，已收的錢又實際留在公司手上（並沒有退還客戶）。兩邊都不動的話，原訂單帳上看起來要退一筆錢、新訂單看起來還沒收到錢，這兩筆都不是真的錯帳，卻會長期掛在差錯清單裡把真正的漏收漏開稀釋掉；原訂單帳面上那筆「可退的錢」也會讓防超退的上限失真。所以本條把兩張單各自結乾淨，帳都對得平，對帳不必為這種銜接開例外。不做款項轉掛，是因為款項的掛載對象一旦可改，就要另立稽核軌跡與操作權限，而且原訂單已開發票時會出現發票在這張單、款項在那張單；不做承接標記，是因為那會在三方相等的底線上開第一個例外（底線見 [[對帳一致性]]）——兩種做法都為一個低頻情境長出一層要長期維護的結構 |

### 訂單異動只管金額、售後事件走售後服務單

| 項目 | 內容 |
|------|------|
| 意圖 | 訂單異動回歸「純金額異動載具」定位，不再兼任售後容器 |
| 規則 | 訂單異動只處理應收總額的增減（補收與退款），所有 adjustment_type（規格變更／加印追加／退印／折扣／加運費／急件費／補退／其他）皆可於任何訂單狀態下選用，不依訂單狀態推算適用範圍；限制只有一條，訂單進終態後不在訂單內直接建，一律先開 [[售後服務]] 單再掛上去（適用範圍與例外見本卡 § 訂單完成後金額異動路徑分流）；已建立單據的狀態推進不受訂單狀態限制（見本卡 § 狀態推進不依訂單狀態）。訂單進終態後的客訴、不良、規格不符等售後事件改建 [[售後服務]] 單，售後單內部視決議再建關聯訂單異動（退款）或由 [[印務]] 發起補做 |
| 營運動機 | 舊設計讓訂單異動同時承擔「金額異動」與「售後受理」雙重身份，造成業務搞不清楚什麼時候該開訂單異動、什麼時候該開售後單。拆開後：訂單異動只管錢、售後單只管事件追蹤與決議，分工清楚 |

### 金額有無變動決定走哪條流程

| 項目 | 內容 |
|------|------|
| 意圖 | 業務遇到變更需求時，一個判斷就能選對流程：「有沒有向客戶補收或退費」|
| 規則 | 訂單期間有金額變動（向客戶補收或退費）→ 走訂單異動（[[訂單異動狀態]]）。訂單已完成後的售後事件 → 走 [[售後服務]] 單（售後單內依決議建關聯訂單異動或發起補做）。無金額變動（含成本上升公司吸收）→ 走工單異動流程（工單層面處理，不建立金額為零的訂單異動，原因見「零金額不建單」）。「公司吸收成本」在訂單已完成後仍走售後服務單（補做、公司認賠），不建訂單異動，售後單提供事件追蹤與品質成本切片分析的價值 |
| 營運動機 | 金額異動以外的變更（換紙、調工序、補做公司吸收）本質是生產端的調度，讓它們留在工單流程處理，不把訂單異動系統塞滿金額為零的空單據。「金額有無變動」是最直覺的分界線——業務當場就能判斷，不必先去查訂單狀態。服從「零金額不建單」規則 |

例子 1（退款送審，正例）：訂單 ORD-2026-0488 因色差客訴，業務建退款訂單異動 −5000 元送審，業務主管核可後這張單停在已核可（核可金額記 5000、應收總額未動）；業務與客戶確認就退 5000 後執行「確認生效」，單轉確認可執行、生效時間記為執行「確認生效」的時點、訂單應收總額當場減去 5000；此時對帳出現「收款淨額比應收總額多 5000」的收款差額。業務之後實際匯款並建退款款項 5000 元（款項類型＝退款、金額正值）、上傳匯款證明、標成「已完成」，對帳的收款差額歸零——退款款項已完成是退款做完的物理錨點，不回頭改訂單異動狀態。

例子 2（退款送審，分次退款對帳未平，邊界反例）：退款訂單異動 −10000 元經主管核可、業務與客戶談定就退 10000 後執行「確認生效」推進確認可執行、應收總額減去 10000、對帳出現收款差額 10000。業務先退第一筆 5000 元（退款款項 5000、款項類型＝退款、標成已完成），對帳的收款差額剩 5000、還沒歸零——錢只退了一半，差額提醒會繼續盯著這 5000，但訂單異動一直維持確認可執行（認列在執行「確認生效」那一刻就定了，不隨退款進度跳動）。

例子 3（退款確認可執行認列，建錯重退，邊界反例）：訂單 ORD-2026-0488 的退款訂單異動 −5000 元已是確認可執行、應收總額已減 5000。業務發現退款款項建錯、取消那筆已完成退款款項，對帳的收款差額重新出現 5000、由差額提醒引導業務重建一筆正確的退款款項；訂單異動維持確認可執行、應收總額不因此變動（該退的金額在執行「確認生效」時就認列定了，建錯的是退款動作、不是該不該退）。

例子 4（諮詢取消退費系統建已核可，正例）：客戶諮詢後取消，諮詢費原收 2000 元，依規則退一半。系統自動建諮詢取消退費訂單異動 −1000 元、審核由系統代行直接落「已核可」（核可人記為系統）。此時應收總額仍 ＝ 2000（退費尚未確認、不認列）。諮詢人員與客戶談定金額後執行「確認生效」，單據推進「確認可執行」——應收總額於此刻 ＝ 2000 − 1000 ＝ 1000、對帳出現收款差額 1000；後續開立折讓（或作廢重開發票）並實際退款 1000 元、退款款項標成已完成，對帳的收款差額歸零，發票淨額、收款淨額與應收總額三方對平（訂單異動維持確認可執行不變）。

例子 5（什麼時候可以取消，正例）：業務要為訂單 ORD-2026-0512 建一筆 600 元的急件費補收，金額誤打成 6000 並已點「確認生效」，應收總額多算了 5400。業務發現後告知主管，[[業務主管]] 在該張訂單異動上執行取消、填寫取消原因「金額誤植，應為 600」，單據轉已取消、應收總額少掉這 6000，活動紀錄留下操作者、取消前金額與原因；業務接著重建一張 600 元的補收訂單異動。該訂單若已依錯誤金額開過發票，對帳會出現應收總額低於發票淨額的差額並提示業務作廢重開。

例子 6（款項紀錄直接建退款，正例）：訂單 ORD-2026-0512 製作中，原應收總額 50000、客戶已全額預收 50000。客戶臨時砍掉一款印件、業務直接把該印件的購買數量改為 0，小計隨之歸零（明細調降），應收總額降為 42000，主管事後在活動紀錄看得到這筆調降。多收的 8000 元，業務直接在款項紀錄建一筆退款款項 8000（款項類型＝退款、金額正值），會計出金後由業務掛匯款證明、標已完成，不開退款訂單異動、不送主管核可；對帳的收款差額隨之歸零。

例子 7（原訂單取消後已收款轉用新訂單，正例）：訂單 ORD-2026-0803 應收總額 13,126 元、客戶已全額預收 13,126 元（一筆款項紀錄、款項類型＝收款、已完成）。客戶要求整案重新報價、不沿用原單。原訂單轉「已取消」後，業務建一筆退款訂單異動 13,126 元送審，主管核可後執行「確認生效」，原訂單應收總額 ＝ 13,126 − 13,126 ＝ 0；接著取消那筆款項紀錄（款項狀態轉已取消、取消備註寫明改記到 ORD-2026-0810），原訂單收款淨額 ＝ 0，兩個數對平。新訂單 ORD-2026-0810 重談後應收總額 15,000 元，業務在新訂單另建一筆款項紀錄 13,126 元並核銷到該訂單的收款項目，剩下的 15,000 − 13,126 ＝ 1,874 元照收款規劃向客戶收。兩張訂單之間沒有款項轉掛、也沒有承接標記。

## 一定要成立的規則

> 這是系統一定要守住、用來核對帳目的鐵則。業務規則卡的這些鐵則須服從本領域對帳底線（應收總額 ＝ 發票淨額 ＝ 收款淨額）。

1. 退款訂單異動為「確認可執行」 → 代表主管已核可該不該退、業務或諮詢人員已確認退多少（諮詢取消為系統代審後確認），應收總額已減去這筆金額；不要求背後有累計達標的退款記錄（認列與實際退錢已脫鉤）。實際退好沒由第 5 條的對帳的收款差額盯住。
2. 補收訂單異動為「確認可執行」 → 代表業務已確認生效，這筆錢已加進應收總額，而且不用去對任何一筆退款；停在草稿的補收訂單異動不計入應收總額。
3. 應收總額的組成正本見 [[訂單#金額組成]]；訂單異動的異動金額只有走到「確認可執行」才計入應收總額，認列時點依路徑，見 § 應收總額認列公式。
4. 來源售後服務單記號一經標上去就不能再改。
5. 退款做完的物理錨點 ＝ 退款款項標成「已完成」且帳能對平 → 對帳的收款差額歸零；只要收款差額還是負值、沒歸零，就代表還有該退而未退完的錢（收款差額為正值是還沒收足的欠收、走追款；補收這種加錢的不走退款、不對收款差額）。
6. 訂單異動一旦轉「已取消」就退出應收總額加總（原本已認列的，該筆金額不再計入應收總額），且不可重開；每一筆取消都必有操作者與取消原因留痕，已認列的另必為業務主管所為。
7. 同一筆金額增減只由一條路徑認列：改在明細上的不再為它建訂單異動，走訂單異動的不再回頭改明細，兩條路不重複計入應收總額。

- 訂單本身的取消、以及最後落在哪個狀態（例如諮詢取消後那張諮詢訂單最後走到「已取消」）→ [[訂單狀態]]，不在本卡。
- 訂單異動自身的狀態定義、轉換條件、觸發事件（草稿／待主管審核／已核可／已退回／確認可執行／已取消）→ [[訂單異動狀態]]（本卡寫規則與動機，狀態圖在該卡）。
- 收款項目的開發票與收款維度狀態、收款項目變更稽核 → [[收款項目狀態]]；本卡只負責「確認可執行時重算應收總額」，不碰收款項目（見「應收總額認列公式」）。
- 售後服務單本身的受理、處理、結案進度 → [[售後服務]]；本卡只負責售後單內建立的退款／補做收費訂單異動的規則。
- 退款後是否開折讓單或作廢重開發票、把應收總額、發票、實收三個數字對到一致的從頭到尾整段流程 → [[訂單異動流程]]（補收／退款從頭到尾的情境）與 [[付款發票邏輯]] 索引；本卡只管訂單異動這一段規則。
- 補收／退款各情境（公司吸收不建單／補收／退款）的分類全貌與七實體連帶影響 → [[付款發票邏輯#四、訂單異動情境（A1-A3）]] 與 [[付款發票邏輯#五B、七實體連帶矩陣]]。
