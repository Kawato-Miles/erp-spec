# 出貨單（ShipmentRecord）

讀完這張卡，你會知道：

- 說出出貨單在訂單交付裡扮演什麼角色、為什麼每一次出貨都要獨立成一張單
- 說出一次出貨的範圍怎麼定：同一張訂單的多種印件可以合箱、不可跨訂單；裝成幾箱記在哪裡、怎麼拆成物流單
- 找到一張出貨單上看得到的每個欄位，說出它由哪個操作填、什麼時候填、能不能改
- 判斷一次最多能出多少（上限是品檢通過累計出來的完工良品數），以及額度在什麼時候回補
- 說出出貨單上能做哪些操作、各屬哪個動作類型，以及狀態名在哪張卡

## 營運背景

出貨單是一次出貨的指令與紀錄：這一批出哪些印件、各出多少、怎麼送、送到哪，以及送到了沒。

- 為什麼獨立存在：訂單做完不等於交完。同一張訂單常分批出、多種印件合在一起出、用不同方式出（宅配、超商、司機配送或客戶自取），每一批都要能追到送達與否。
- 為什麼獨立存在：出貨額度要對著完工良品數管控（品檢通過才計入、出貨不能超過額度），分批與作廢都要逐印件回算額度，沒有獨立單據這筆帳算不清。
- 出貨單同時是揀貨指令：這一批怎麼出、要不要合箱、每種出多少、送到哪，都寫在這張單上交給倉庫。
- 出貨單是業務排的一批；裝成幾箱記在本單的裝箱資料，交給物流商或自行配送的每一筆托運是 [[物流單]]。
- 被否決的寫法：每一箱記裝了哪些印件、各幾個。每次正常出貨都要多做這份工作；只在作廢物流單或送達時記沒送到的量（[[物流單]] 未送達數量）就夠回補額度。

### 裝箱資料（每筆＝一箱）

完成裝箱回報時至少一箱，每箱至少一張裝箱照片；裝箱回報修正後至少保留一箱。裝箱資料不作廢：新增、修改、刪除箱都經裝箱回報修正，各項可執行的條件見 [[出貨單狀態]] § 揀貨不符與裝箱回報修正；不能再刪的箱要撤掉時改走作廢物流單，不能再改的箱保留為裝箱紀錄。

**拆單**：系統依本單出貨方式的「支援子母單」屬性產生物流單。新增箱與刪除箱可執行的條件見 [[出貨單狀態]] § 揀貨不符與裝箱回報修正。

### 出貨方式（系統設定）

出貨方式與箱規屬系統設定，比照帳務公司，不由業務角色維護。

| 出貨方式 | 支援子母單 | 有外部物流單號 | 出貨動作 |
|---------|-----------|---------------|---------|
| 順豐 | 是 | 是 | 拋單 |
| 新竹物流 | 否（物流商支援，系統尚未串接，見 [[EC 物流串接約束]]） | 是 | 拋單 |
| 7-11 交貨便 | 否 | 是 | 拋單 |
| 全家 | 否 | 是 | 拋單 |
| 自取 | 是 | 否 | 標記可自取 |
| 專車配送 | 是 | 否 | 出貨確認 |
| 其他 | 是 | 否 | 出貨確認 |

- 支援子母單決定拆單（見上方拆單表）。
- 有外部物流單號＝是：出貨動作為拋單，之後狀態由物流商回傳同步。＝否：自取走標記可自取再交付確認，專車配送與其他走出貨確認再送達確認（狀態路徑見 [[物流單狀態]]）。
- 出貨動作是 [[物流單]] 上的 OP-SHP-007 拋單、OP-SHP-008 出貨確認或 OP-SHP-017 標記可自取，逐筆物流單執行；拋單可從本單一次對多筆執行（批次拋單，見下方「操作」段）。

### 箱規（系統設定）

- 所有出貨方式共用同一套箱規。
- 每筆箱規記名稱與長、寬、高（公分，可到小數一位）；沒有尺寸資料的箱體，長、寬、高留空。
- 「自訂」不是一筆箱規，是裝箱資料箱規欄的固定選項。

- 批次拋單不是另一個操作：不另記批次紀錄，每一筆物流單照常記自己的拋單。
- 逐筆托運的操作（拋單、出貨確認、標記可自取、重新同步、標記例外、送達確認、交付確認、補附送達憑證、作廢物流單、下載物流單檔案）登記在 [[物流單]]，操作編號沿用 SHP。

- 出貨方式指向一筆系統設定（N:1）；裝箱資料的箱規指向至多一筆箱規（系統設定，所有出貨方式共用；選「自訂」時不指向箱規）；保密代寄＝否時寄件資訊取 [[帳務]] 帳務公司（N:1）

- 一張出貨單有多筆裝箱回報修正紀錄（1:N，0 起）與多筆歷程紀錄（1:N）：兩者都是本單的子表
- 上游依賴 [[品檢紀錄]]（印件層）：品檢通過累計＝完工良品數，完工良品數決定可出貨額度
