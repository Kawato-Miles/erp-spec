# 需求單（QuoteRequest）

讀完這張卡，你會知道：

- 說出蒐集需求、評估成本、報價議價這段為什麼要獨立成一張單，不直接開訂單，以及談成與談不成各走去哪
- 找到一張需求單上看得到的每個欄位，說出它由哪個操作填、什麼時候填、能不能改
- 看懂幾個不直覺的欄位各在管什麼：帳務公司（用哪家公司名義接單）、收款條件備註、來源諮詢單、難易度
- 分辨一筆印件項目記到什麼細度，以及它跟成交後才實際建立的印件差在哪
- 說出需求單上能做哪些操作、各屬哪個動作類型，以及牽涉哪些單據與狀態名在哪張卡

## 營運背景

需求單是客戶還沒成交、還在談的那段過程的載體：累積需求、掛附件、記報價歷史、追蹤議價。

- 為什麼獨立存在：客戶要印東西時，規格、數量、難易度、交期多半還沒談定，要先蒐集需求、取得成本，再跟客戶來回報價議價；在客戶答應下單之前，需要一個能承載這段過程的對象。
- 為什麼獨立存在：談成了就生成訂單、把談好的條件鎖過去；談不成就記下流失原因關閉。成交與流失的結局都要有記錄，不能等成交才開單。
- 來路：需求單可以直接建立，也可以從諮詢單轉來。客戶先付諮詢費談過一輪、判斷可以做大貨時，諮詢單轉成需求單接著報價。

## 欄位（業務可見）

> 一般欄位於終態（成交／流失）後全卡鎖定。成交即轉訂單，後續變化改訂單，需求單轉為參考依據。
> 填入時點欄標「必填」的欄位，建立需求單（或印件項目）時未填存不下去；未標者選填。

## 關鍵關聯

- 一張需求單底下有多筆印件項目（1:N），每筆項目可掛多個附件（1:N）、可指定多條預計產線（N:M）
- 來自諮詢時關聯來源 [[諮詢單]]（1:1，選填）
- 成交後生成 [[訂單]]（1:1；成交即一次性轉出一張訂單、不分批多次轉單，訂單反向參照回這張需求單）
- 屬於一個客戶（N:1）
