# 報工紀錄（SegmentResponse）

讀完這張卡，你會知道：

- 說出每做完一段活要回報什麼（做了多少、好的幾件、壞的幾件、壞在哪裡），以及這一筆為什麼要獨立成可查、可作廢的事實底稿
- 說明為什麼良品與不良品必須在報工當下就分開記、事後湊不回來
- 說出一筆報工的數字要過哪些檢核才寫得進去
- 追出折損率、良率與實際成本各自取哪幾個報工欄位當事實來源
- 說出一筆報錯的報工怎麼被修正或作廢、事後這筆紀錄還看得到什麼，以及報工紀錄上有哪些操作

## 營運背景

一筆報工紀錄是現場做完一段活之後，對「這一段實際投入多少、做出多少好的與壞的」的事實回報。

- 為什麼獨立存在：它有自己的生命週期（單獨一筆、可查、可修正、可作廢），而且生產、品檢、成本三個環節都圍著「這一筆現場到底做了什麼」轉，必須有一個能被各環節共同指認的事實對象。
- 為什麼不只記一個完成數：只記報工數量只夠推進進度，算不出折損率與良率；要算這兩個數得知道投入多少、產出裡好的幾件、壞的幾件，要算材料成本得知道材料型任務實際投入多少料。
- 為什麼當下就要記：這些都是「一筆報工發生的當下」才知道的事實，當場記下之後就能往上長出績效與成本，事後再補就湊不回來。
- 欄位只收「現在就有下游在用」的那幾項：沒有下游取用的欄位只是讓現場多填幾格，換不到任何讀數。

## 欄位（業務可見）

> 下表多數欄位為**缺口補（現況系統無）**，依業界成熟製程回報範式（ISA-95 製程段回報的物料／設備／人員實績三軸、Odoo 工作中心生產力的損失三分類、Dynamics 完工回報的良品／不良品分流）與生產模組架構設計的 KPI 事實來源需求設計，已於說明欄逐項標明用途與「缺口補」。

一筆報工要填的是生產數量、良品數、不良品數與報工照片（不良品數大於 0 時另填不良原因），另可選填備註，運轉設備由系統帶入。數字一律照現場事實填。能報的前提與各入口能報的範圍見 [[報工規則]]。

### 修正與作廢

**修正**是對一筆已存在的紀錄改欄位值（數量、原因、備註、照片）：必填修正原因，系統留下修正紀錄，一次修正改了幾個欄位就記幾筆（每筆含修正欄位、修正前、修正後、修正人、修正時間、修正原因；照片欄另留修正前的照片）。紀錄有修正紀錄，即視為已修正。生產、品檢、出貨各紀錄的修正都用這個定義，各卡只寫自己有哪些欄位可修正。

**責任原則**：每個欄位有負責的角色，只有負責該欄位的角色能修正該欄位。負責角色指角色，不限填寫者本人；誰在什麼範圍能修正與作廢報工見 [[製作與報工活動清單]]，各入口能修正的範圍見 [[製作與報工活動清單]]。系統照紀錄上的數字決定行為，不另設確認關卡。填寫內容與事實不符時由填寫者承擔，修正紀錄留下是誰、何時、改了什麼。

報錯的報工只判斷一件事：這一筆根本不該存在（如報到錯的任務）就作廢，必要時再重報到正確的任務；這一筆存在但數字不對就修正，修正時可一併修正備註。其中有一部分要算損耗時，良品改少、不良品改多同量，生產數量不變；損耗怎麼來的寫在修正原因，系統不區分。數字錯用修正、整筆不該存在用作廢。作廢正流程與逆流程都可用。修正與作廢的範圍依入口、在什麼數字下被擋下，以及同時寫入的處理，正本見 [[報工規則]]。**修正與作廢都不讓這一筆消失**：修正留下每一次的修正前後值與是誰、什麼時候、為什麼修正；作廢改列為已作廢並留下是誰、什麼時候、為什麼作廢——報工是成本與指標的事實來源，一筆錯報怎麼被修掉，事後要看得出來。成本與指標一律取修正後的值，作廢的報工不計入。

## 操作

| 操作編號 | 操作 | 動作類型 | 前提 |

無操作的動作類型：建立（報工在所屬生產任務上提交，登記在 [[生產任務]] OP-TSK-010 新增報工）、檢視（報工在所屬生產任務的歷程與詳情中檢視，登記在 [[生產任務]] OP-TSK-008 檢視生產任務）、狀態推進（報工本身不走狀態流轉，報工驅動的轉換見 [[生產任務狀態]]）、審核、指派或改派、分享管理、輸出

- 報工在所屬生產任務上提交，新增登記在 [[生產任務]]；修正與作廢是在既有的這一筆報工上發起，登記在本卡。
- 修正報工與作廢報工分立，是因為兩者的系統效果不同：修正留下修正前後值、這一筆仍計入累計；作廢讓這一筆不計入累計。

## 關鍵關聯

- 屬於 [[生產任務]]（N:1）：一個生產任務有多筆報工紀錄，報工累計驅動任務完成（完成判定取生產數量累計，見 [[生產任務狀態]]）
- 一筆報工有多筆報工修正紀錄（1:N），每筆報工修正紀錄指向一位修正人（[[人員]]）
- 一筆報工的良品數通過品檢後成為完工良品 → [[品檢紀錄]]（報工提供生產數量與良品／不良品分流，品檢判定通過良品數）
- 一筆報工的耗料明細 → [[物料消耗記錄]]（1:N）：庫存模組啟用後才成立的掛點，本階段報工不收耗料明細
- 報工的生產數量累計是實際成本的數量輸入，任務實際小計（不含顏色）與各顏色實際費用的算式與預估相同，與 [[計價快照]] 的預估基準並排對照（多筆報工彙總對一筆預估）

## 相關狀態機

無獨立狀態機。報工是「一筆事實」，本身只有有效與作廢兩種存在性，不走生命週期狀態流轉；報工**驅動的**狀態變化發生在 [[生產任務]]（首次報工觸發製作中、生產數量累計達標即完成，見 [[生產任務狀態]]），不在報工這一筆身上。達標那筆報工把任務推進「已完成」時，任務實際完成日取該狀態進入的時間（欄位見 [[生產任務]]），報工這一筆不另存日期欄。報工的前提見 [[報工規則]]；報工修正或作廢讓生產數量累計低於目標時，任務狀態怎麼連動見 [[生產任務狀態]]。
