# 諮詢單（ConsultationRequest）

讀完這張卡，你會知道：

- 說出客戶還沒成交，為什麼要先開一張單、還先向客戶收一筆諮詢費
- 找到一張諮詢單上看得到的每個欄位，分辨哪些是客戶自己填的、哪些任何人都不能改
- 看懂客戶原話與諮詢人員筆記為什麼分兩欄記
- 分辨諮詢談完有哪幾種結局（轉需求單做大貨、收尾建諮詢訂單），各結局把這張單接到哪張單據上
- 說出諮詢單上能做哪些操作、各屬哪個動作類型，以及狀態名在哪張卡

## 營運背景

諮詢單承接「客戶先付諮詢費、談需求、還沒到報價」這段前置互動，並讓那筆諮詢費後續能正確轉移或退還。

- 付款完成、有帳款紀錄後諮詢單才進入系統：只服務真的付了錢的對象，避免沒付款的單據雜訊（未付款的單不追）。
- 為什麼獨立存在：這段過程有自己的金流，先收的諮詢費要掛在某個對象上。
- 為什麼獨立存在：這段過程有自己的認領流程，由諮詢人員自我認領。
- 為什麼不併入需求單：結局不只一種，談完可能轉成正式報價（需求單），也可能就此收尾或取消。

## 欄位（業務可見）

### 客戶表單蒐集（客戶線上填寫、系統自動帶入）

> 客戶填錯時以 OP-CR-004 編輯諮詢單修正，不限這張單的諮詢人員本人（決議見 [[CR-007-諮詢單編號正本缺口與表單欄位修正規則]] 部分拍板），修正寫入活動紀錄；客戶原話唯讀除外。

### 受理與結果

| 介面欄位 | 說明 | 欄位形態 | 填入時點 | 可否修改 |

| 狀態 | 待諮詢／已轉需求單／完成諮詢／已取消 | 單選（依 [[諮詢單狀態]] 定義）| 隨觸發操作推進（轉換正本見 [[諮詢單狀態]]）| 系統計算（不可修改）；終態後定格 |

## 操作

| 操作編號 | 操作 | 動作類型 |
|---------|------|---------|
| OP-CR-001 | 認領諮詢單 | 指派或改派 |
| OP-CR-002 | 代派諮詢人員 | 指派或改派 |
| OP-CR-003 | 改派諮詢人員 | 指派或改派 |
| OP-CR-004 | 編輯諮詢單 | 編輯 |
| OP-CR-005 | 撰寫諮詢人員筆記 | 編輯 |
| OP-CR-006 | 轉需求單 | 建立 |
| OP-CR-007 | 完成諮詢 | 狀態推進 |
| OP-CR-008 | 取消諮詢 | 刪除或作廢 |
| OP-CR-009 | 檢視諮詢單 | 檢視 |

無操作的動作類型：審核（諮詢單不設核可關卡）、分享管理（諮詢單沒有分享成員）、輸出

- 諮詢單由系統依客戶付款成功通知自動建立，沒有使用者發起的建立操作（建立事件見 [[諮詢單狀態]]）。
- OP-CR-004 編輯諮詢單涵蓋客戶表單欄位的修正；OP-CR-005 撰寫諮詢人員筆記自一般編輯另立，是因為能執行的人與修正表單欄位不同。
- OP-CR-001 認領諮詢單、OP-CR-002 代派諮詢人員、OP-CR-003 改派諮詢人員都寫入諮詢人員欄，分立是因為能執行的人不同；三者都不改變諮詢單狀態（見 [[諮詢單狀態]]）。
- OP-CR-006 轉需求單在本單上發起，系統據此建立一張 [[需求單]]；需求單的建立事件引用本操作（見 [[需求單狀態]]）。
- 完成諮詢與取消諮詢後系統建立的諮詢訂單，其建立事件引用本卡操作（見 [[訂單狀態]]）；退費訂單異動的操作登記在 [[訂單異動]]、諮詢費發票的操作登記在 [[帳務]]，活動見 [[訂單異動活動清單]]、[[收款項目開立發票活動清單]]。

## 關鍵關聯

- 一張諮詢單掛多筆諮詢費款項紀錄（1:N）：一開始掛在諮詢單上，轉需求單成交後**收款轉移至主訂單**，規則見 [[付款發票邏輯]]
- 轉需求單時關聯 [[需求單]]（1:1）：客戶原話＋諮詢人員筆記以雙區塊格式合併寫入需求單的需求備註
- 收尾（完成諮詢／取消）時關聯諮詢 [[訂單]]（1:1）：來路為諮詢訂單；取消的退費與收尾規則見 [[諮詢收尾規則]]
