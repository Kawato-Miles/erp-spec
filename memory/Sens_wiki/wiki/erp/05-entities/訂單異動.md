# 訂單異動（OrderAdjustment）

讀完這張卡，你會知道：

- 認出一張訂單異動上業務看得到哪些資料
- 分辨哪些欄位業務能改、改的時機到哪裡為止、哪些是系統寫入後唯讀
- 看懂核可金額與異動金額並列在一起是要對照什麼
- 找到這張單與訂單、售後服務單之間怎麼掛
- 知道金額被改過幾次、誰改的，線索留在哪裡

## 營運背景

印刷廠接單後金額常臨時變動：客戶追加印量、改急件、補運費（補收），或因品質規格不符要退費（退款）。補收與退款的營運風險不對稱——錢退出去一旦出錯難追回，客戶加單則是送上門的生意，因此分權原則是退款須 [[業務主管]] 核可、補收由 [[業務]] 自行拍板（詳見 [[訂單異動規則]]）。訂單異動獨立於主訂單狀態，確保金額增減有完整審核軌跡，不會靜默修改訂單總價。

## 欄位（業務可見）

> 以下是業務使用者在介面上看到的完整欄位。純技術欄位（主鍵、外鍵、時間戳）不列入，但核可時間與生效時間因業務查閱需求保留。

| 介面欄位 | 說明 | 欄位形態 | 來源 | 可否修改 |
|---------|------|---------|------|---------|
| 異動類型 | 規格變更 / 加印追加 / 退印 / 折扣 / 加運費 / 急件費 / 補退 / 其他（另有「諮詢取消退費」為系統內生，介面不顯示）。各類型的金額方向見本卡「異動類型與金額方向」段 | 單選 | 業務建立時選擇 | 草稿與已退回可改（已退回改後重新送審）；送審中與已核可後鎖定 |
| 異動金額 | 含稅金額；正數為補收、負數為退款。以元為單位的整數，不收角分——發票金額只吃整數，帶角分會讓應收總額與發票淨額永遠對不平 | 金額 | 業務填寫 | 草稿與已退回可改（改後重新送審）；已核可可改且不需重審（每次改留一筆金額異動歷史，核可金額不變）；確認可執行後鎖定 |
| 異動金額（未稅） | 未稅金額；由含稅金額依訂單稅率反算，四捨五入至整數 | 金額 | 系統計算 | 唯讀 |
| 異動原因 | 說明本次異動的原因 | 文字 | 業務填寫 | 草稿、已退回與已核可可改，每次修改寫入訂單活動紀錄（含改前與改後內容）|
| 狀態 | 草稿 / 待主管審核 / 已核可 / 已退回 / 確認可執行 / 已取消（獨立狀態機，詳見 [[訂單異動狀態]]） | 單選 | 系統依流程推進 | 不可手動修改 |
| 退回原因 | 主管退回時填寫的退回理由 | 文字 | 業務主管填寫 | 僅退回時可填，之後唯讀 |
| 取消原因 | 取消這張單的理由；不分金額是否已認列，每一筆取消都必填 | 文字 | 取消者填寫 | 僅取消時可填，之後唯讀 |
| 建立人 | 建立這筆訂單異動的人員 | 字串 | 系統記錄 | 唯讀 |
| 核可人 | 核可此訂單異動的業務主管；補收訂單異動免審，記為確認生效的業務本人 | 字串（人員） | 系統於核可或確認生效時寫入 | 唯讀 |
| 核可金額 | 主管核可當下的異動金額，已核可後業務修改金額此值不變，與異動金額並列供事後監督對照 | 金額 | 系統於核可時寫入 | 唯讀 |
| 與核可差額 | 異動金額減核可金額。存它是因為主管監督時要一眼看出業務事後改了多少，不必自己相減；核可前為空 | 金額（唯讀）| 系統計算 | 不可 |
| 最近修改時間 | 這張異動最後一次被改動的時間 | 日期時間（唯讀）| 系統寫入 | 不可 |
| 最近修改人 | 最後一次改動的人 | 單選（人員，唯讀）| 系統寫入 | 不可 |
| 修改次數 | 這張異動被改過幾次。存它是因為改動頻繁本身就是要看的訊號，逐筆翻歷史看不出來 | 數字（唯讀）| 系統累計 | 不可 |
| 核可時間 | 主管核可的日期時間 | 日期時間 | 系統於核可時寫入 | 唯讀 |
| 生效時間 | 訂單異動進入「確認可執行」、金額認列進應收總額的日期時間 | 日期時間 | 系統於確認生效時寫入 | 唯讀 |
| 關聯售後服務單 | 若源自售後服務單則填入連結，訂單進終態前業務直接建立則為空；**訂單已進終態時建立為必填**（諮詢訂單的系統內生取消退費除外，規則正本見 [[訂單異動規則]]）| 連結（指向售後服務單） | 建立時帶入，一經建立不可變動 | 唯讀 |
| 金額異動歷史 | 每次修改金額時系統自動追加紀錄（修改時間 / 修改人 / 修改前金額 / 修改後金額 / 當時狀態），供事後稽核 | 紀錄列表 | 系統自動追加 | 唯讀 |

## 異動類型與金額方向

各類型能填的金額方向固定，填反了系統擋下。這是為了讓應收總額的加減與異動類型對得起來——加印卻記成負數，事後看帳會以為退了錢。

| 異動類型 | 金額方向 |
|---|---|
| 加印追加、加運費、急件費 | 只能是正數（補收） |
| 退印、折扣 | 只能是負數（退款） |
| 規格變更、補退、其他 | 正負皆可 |
| 諮詢取消退費（系統內生） | 只能是負數 |

## 關鍵關聯

- 屬於一張 [[訂單]]（N:1）：一張訂單可有多筆訂單異動
- 可掛在一張 [[售後服務]] 底下（N:1，選填）：訂單完成後的退款與原單善後的加收都經售後單容器建立，未掛者為訂單期間直接建立
