# 帳務（Order Billing）

讀完這張卡，你會知道：

- 分辨一張訂單的錢分成哪三條線各自記，以及為什麼公司選擇讓業務彈性處理、靠對帳確保最終一致
- 認出帳務領域有哪幾種單據，以及它們彼此怎麼掛、各能掛幾張
- 找到業務在一張發票上看得到的每個欄位，包含商品明細記到什麼細度
- 說出折讓單是什麼、什麼時候開，開了之後那張發票還剩多少可折讓
- 看懂客戶實際匯來或退出去的每筆款項紀錄，怎麼核銷分配到各期收款項目

## 營運背景

印刷廠一筆訂單的錢分三條線各自記：業務先算出「這筆訂單客戶應該付多少」（應收）、開了幾張發票合計多少（發票）、實際收到客戶匯來多少（收款）。這三條線是不同人、不同時間、用不同單據各自填進系統的，很容易某一條漏記或填錯。公司的做法不是事先用硬性規定把三條線綁死，而是讓業務照客戶實際狀況自由處理，最後靠對帳把三個數字湊在一起比對——對得起來代表帳沒問題，對不上就要有人去查。「三個數字最後一定要相等」就是這個領域不能退讓的底線。

### 帳務公司（BillingCompany）

| 統一編號 | 營利事業統一編號 | 文字 | 系統管理員設定 | 可（系統管理員） |
| 藍新商店代號 | 對應藍新（ezPay）商店帳號；發票開立／折讓／作廢時送藍新平台使用，同時間須唯一（兩家不可共用，以免違反藍新自訂編號不可重覆） | 文字 | 系統管理員設定 | 可（系統管理員） |

### 發票（Invoice）

發票透過藍新平台開立，對應台灣統一發票。一張發票掛在一張訂單下、對應一個收款項目。

| 買受人地址 | 選填 | 文字 | 訂單客戶地址預填 | 開立前可改 |

| 載具類別 | 手機條碼 / 自然人憑證 / ezPay 載具（B2C 適用）| 單選 | 業務選擇或客戶預設 | 開立前可改 |
| 載具編號 | 載具類別對應的編號 | 文字 | 業務輸入 | 開立前可改 |
| 捐贈碼 | B2C 捐贈發票用；3-7 碼純數字。與載具互斥等開立規則見 [[發票法規硬約束-ezPay-MIG]] | 文字 | 業務輸入 | 開立前可改 |
| 課稅別 | 應稅 / 零稅率 / 免稅 | 單選 | 訂單課稅設定預填 | 開立前可改 |
| 稅率 | 依課稅別自動帶入 | 數字 | 系統依課稅別自動帶入 | 不可（隨課稅別變動） |
| 銷售額（未稅）| 由發票金額（含稅）反推——含稅金額 ÷（1 ＋ 稅率），四捨五入至整數元；每張發票同一條算法，與開沒開滿無關（動機見 [[付款發票邏輯]]）| 金額（未稅） | 系統自動計算 | 不可 |
| 稅額 | 發票金額（含稅）− 銷售額（未稅），以減法導出而非未稅乘稅率正算；各期取整的零頭落在本欄，與「銷售額 × 稅率」可差一元以內（為什麼用減法見 [[付款發票邏輯]]）| 金額 | 系統自動計算 | 不可 |
| 發票金額（含稅）| 發票總計金額；開立時以該收款項目的預計金額（含稅）為目標值帶入，銷售額（未稅）與稅額都由本欄反推，平台硬檢核「發票金額 ＝ 銷售額 ＋ 稅額」因此恆成立（算法見 [[付款發票邏輯]]）| 金額（含稅）| 收款項目預計金額（含稅）帶入 | 不可 |
| 備註 | 自由填寫 | 文字 | 業務輸入 | 開立前可改 |
| 狀態 | 發票目前的開立狀態（開立 / 作廢） | 單選 | 系統自動與手動觸發 | 依狀態機規則 |
| 發票號碼 | 藍新金流回傳；開立後唯讀 | 文字（唯讀） | 藍新金流回傳 | 不可 |
| 開立時間 | 藍新回傳開立成功的時間點；與建立時間分開存——開立失敗的紀錄沒有開立時間 | 日期時間（唯讀） | 藍新金流回傳 | 不可 |
| 作廢原因 | 作廢時必填（限中文 6 字或英文 20 字） | 文字 | 作廢操作時業務輸入 | 作廢時可改 |
| 折讓累計 | 該發票所有已確認折讓單金額合計 | 金額 | 系統自動累計 | 不可 |
| 剩餘可折讓 | 發票金額 - 折讓累計 | 金額 | 系統自動計算 | 不可 |
| 折讓衍生標示 | 無折讓 / 已部分折讓 / 已完全折讓 | 單選 | 系統自動計算 | 不可 |
| 商品明細 | 見下方「發票品項」；預設自訂單印件帶入，品項只在發票上維護 | 子結構 | 訂單印件預填或業務編輯 | 開立前可改 |

| 介面欄位 | 說明 | 欄位形態 | 來源 | 可否修改 |
|---------|------|---------|------|---------|
| 商品名稱 | 上限 30 字；例：彩色名片 | 文字 | 預填或業務輸入 | 開立前可改 |
| 商品數量 | 1 - 99999 | 整數 | 預填或業務輸入 | 開立前可改 |
| 商品單位 | 張 / 本 / 冊 / 份 / 個 / 卷 / 盒 / 套 / 批 / 式 / 組（共 11 項） | 單選 | 預填或業務選擇 | 開立前可改 |

### 折讓單（SalesAllowance）

折讓單是發票已開立後的部分減額憑證（依台灣統一發票使用辦法第 20 條）。ezPay 法定的折讓品項五欄由系統送件時以單一合成品項自動組成（品名帶折讓原因、數量 1、單位「式」、單價與小計為依發票稅率反推的未稅額、稅額補足檢核等式），業務層只記折讓總額、不維護品項明細（決議見 [[BI-021-折讓單缺ezPay折讓品項五欄]]，已封存）。折讓本身不自動建立退款，業務先建退款款項紀錄再開折讓，兩者以訂單活動紀錄串聯。

| 欄位 | 形態 | 說明 |
|------|------|------|
| 折讓金額（含稅）| 整數 | 業務輸入正數 |
| 折讓金額（未稅）| 整數 | 折讓金額（含稅）÷（1 ＋ 發票稅率），四捨五入至整數元；僅供介面顯示，不參與對帳（算法見 [[付款發票邏輯]]）|
| 折讓後剩餘發票金額 | 金額 | 藍新回傳（自動計算）；該張發票扣掉已確認折讓金額後的餘額，各張加總即訂單的發票淨額（見 [[訂單]] § 金額組成）|
| 折讓原因 | 文字 | 必填 |
| 開立時間 | 日期時間 | 藍新回傳開立成功的時間點；唯讀 |
| 開立人 | 單選（人員） | 開立折讓的業務；責任歸屬用，系統自動帶入操作者 |
| 狀態 | 單選 | 已確認 / 已作廢 |
| 藍新折讓號 | 文字 | 藍新回傳的折讓單號碼（A + 14 碼數字），用於對帳；開立後唯讀 |
| 作廢原因 | 文字 | 作廢時填寫 |
| 回簽附件 | 檔案上傳（多檔）| 折讓回簽文件（合併自 SalesAllowanceFile）|

### 款項紀錄（Payment）

款項紀錄記錄客戶每一筆實際付款或退款。款項類型為「退款」時與一般收款分軸。

| 欄位     | 形態       | 說明                                                                                   |
| ------ | -------- | ------------------------------------------------------------------------------------ |
| 款項類型   | 單選       | 定義此筆款項為收款或退款（收款 / 退款）；對帳加總時收款為加項、退款為減項，方向只由本欄決定 |
| 款項狀態   | 單選       | 款項紀錄狀態，列舉與轉換見 [[款項狀態]]（處理中 / 已完成 / 已取消）；只有已完成計入對帳加總，處理中與已取消不計入 |
| 金額     | 金額       | 款項金額（一律以正值輸入，退款亦然；加減方向由款項類型決定）|
| 款項方式   | 單選       | 現金 / 信用卡 / 銀行轉帳 / 支票 / 其他                                                            |
| 付款序號   | 文字       | 銀行入帳序號 / 信用卡授權碼 / 支票號碼（入帳憑證）                                                         |
| 退款收款帳號 | 文字       | 款項類型為退款時填：客戶收款帳號（戶名／銀行／帳號）。每筆退款當次由客戶提供、可能與付款帳號不同；收款情境留空。與「付款序號」語意分清——前者是出金目標、後者是入帳憑證 |
| 款項時間   | 日期時間     | 退款情境對應退款日期                                                                           |
| 紀錄人    | 文字       | 紀錄操作者姓名                                                                              |
| 備註     | 文字       | 退款原因 / 對帳備註                                                                          |
| 取消備註   | 文字       | 款項狀態為已取消時之說明                                                                         |
| 對帳附件   | 檔案上傳（多檔） | 款項的對帳憑證；切「已完成」的把關條件見 [[款項狀態]]                                                          |

> 處理中超過 7 天的款項紀錄會顯示「老化 N 天」提示。

### 收款項目（BillingInstallment）

收款項目把一張訂單的應收款拆成若干期（如訂金 30%、尾款 70%），每期各自追蹤開發票狀態與收款狀態。開發票維度與收款維度完全獨立，支援先收後開 / 先開後收。

| 介面欄位 | 說明 | 欄位形態 | 來源 | 可否修改 |
|---------|------|---------|------|---------|
| 期別 | 1 / 2 / 3 ... | 整數 | 系統依建立順序自動給定 | 不可 |
| 描述 | 訂金 30% / 尾款 70% / 加印款 / 諮詢費 等 | 文字 | 業務填寫或預設值 | 可 |
| 預計金額 | 業務規劃這期要收多少；含稅，以元為單位的整數，不收角分——發票金額只吃整數，帶角分開不出發票 | 金額（含稅） | 業務填寫 | 可（已開立發票或已核銷後仍可改、不需作廢發票，差異由三方對帳警示兜底，見 [[付款發票邏輯]]）|
| 預計金額（未稅） | 預計金額 ÷（1 ＋ 訂單稅率），四捨五入至整數元；僅供介面顯示，不參與對帳（算法見 [[付款發票邏輯]]）| 金額（未稅，唯讀） | 系統自動計算 | 不可 |
| 已收金額 | 該收款項目已手動核銷之收款金額（系統自動累計，唯讀） | 金額（唯讀） | 系統由核銷分配資料自動累計 | 不可 |
| 已退金額 | 該收款項目已手動核銷之退款金額（系統自動累計，唯讀） | 金額（唯讀） | 系統由核銷分配資料自動累計 | 不可 |
| 預計款項方式 | 現金 / 信用卡 / 銀行轉帳 / 支票 / 其他（規劃值，非事實；事實值見款項紀錄的款項方式，兩者值域相同才比對得起來）| 單選 | 業務建立時選擇 | 可 |
| 預計收款日 | 業務追款與對帳撈單的排序依據（核銷為手動勾選，本欄不驅動自動分配） | 日期 | 業務填寫 | 可 |
| 預計開發票日 | 可空；支援尚未決定開發票時點的情境 | 日期 | 業務填寫 | 可 |
| 開發票狀態 | 未開立 / 已開立 / 已作廢 | 單選（唯讀） | 系統依發票開立狀態自動推導 | 不可 |
| 收款狀態 | 未收 / 部分收款 / 已收訖（依核銷分配累計自動推導） | 單選（唯讀） | 系統依核銷累計金額自動推導 | 不可 |
| 備註 | CSV 對帳資料來源 | 文字 | 業務填寫 | 可 |
| 來源類型 | 手動建立 / 諮詢取消 / 諮詢結束無生產 / 報價流失 | 單選（唯讀） | 系統建立收款項目時依流程標記 | 不可 |
| 原始預計收款日 | 這期首次儲存當下的預計收款日，凍結為事後稽核的原始基準 | 日期（唯讀） | 系統於該收款項目首次儲存時寫入 | 不可 |
| 原始預計開發票日 | 這期首次儲存當下的預計開發票日，凍結為事後稽核的原始基準 | 日期（唯讀） | 系統於該收款項目首次儲存時寫入 | 不可 |
| 變更次數 | 收款日 + 開發票日累計變更次數（自動計算）| 整數（唯讀） | 系統在收款日或開發票日修改時自動累算 | 不可 |
| 是否取消 | 業務取消時標記；取消後不入狀態推導與應收計算 | 是 / 否 | 業務手動取消 | 不可直接修改，需透過取消操作變更 |
| 取消原因 | 取消時填寫（如「拆兩期」「業務取消」） | 文字 | 取消操作時業務填寫 | 取消時可填 |

### 收款核銷分配（PaymentAllocation）

收款核銷分配是款項紀錄與收款項目之間的多對多橋接，由業務或會計手動核銷與分配。

| 介面欄位 | 說明                        | 欄位形態       | 來源          | 可否修改       |
| ---- | ------------------------- | ---------- | ----------- | ---------- |
| 分配金額 | 該筆收款/退款分配至該收款項目的核銷金額（一律為正值） | 金額         | 業務或會計手動核銷輸入 | 款項未取消前可改；款項收款完成後仍可改分配（款項本身的金額、類型、收付方式不可改，要改走取消後重建）|

> 稽核事件（BillingActivityEvent）為純稽核用途的結構化事件記錄，記錄收款項目建立、收款日變更、開發票日變更、取消、核銷覆寫等操作，供 KPI 量測與審計查詢，不另建欄位表。
