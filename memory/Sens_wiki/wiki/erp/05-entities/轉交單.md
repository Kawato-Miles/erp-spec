# 轉交單（TransferTicket）

讀完這張卡，你會知道：

- 說出一張轉交單管多少範圍——一趟送往同一條產線的搬運事件，同一條目的產線的貨可跨印件、跨工單裝同一張單
- 說出一張轉交單怎麼生出來——報工累積出可轉交量、在待轉交任務勾選要送的量建單，搬運者只執行搬運與回報
- 分辨哪些搬運走轉交單、哪些不走（場內站間移動走轉交，場外回場的物流不走）
- 找到一張轉交單上看得到的每個欄位、由哪個操作填、什麼時候寫入（含每條明細的每一筆點收紀錄），轉交單上有哪些操作，以及一次最多能轉多少要查哪張卡
- 說出轉交跟下游能不能開工的關係（明細的點收量就是下游的到料量），以及狀態名在哪張卡

## 營運背景

一張轉交單＝**一趟送往同一條產線的搬運事件**，承載這次運送的目的產線、各條明細的目的站點、數量與送達憑證。一趟搬運是以「推車推去哪一條產線」定義的，不是以「車上的貨屬於哪一張訂單」定義的，所以同一條目的產線的貨可以裝同一張單、跨印件也跨工單，各條明細各自記送到該產線的哪一個站點（廠務把甲客戶的名片和乙客戶的貼紙一起推到同一條產線，那就是一趟）；貨屬於誰由每一條明細各自掛的來源生產任務往上推導，單頭不再綁印件。同一筆生產任務可分批開多張單（跨天分批不卡下游）。

這張單串聯上下兩個生產任務：上一道做完的產出，要轉給下一道接著做——誰的貨、從哪到哪、送了多少、到了沒、下游收到沒。它把過去靠紙本工單跟著貨走的流轉，變成系統裡可追蹤、可作為下游到料放行的紀錄。**單據在待轉交任務建立**：報工累積出各任務的可搬量，建單時勾選要送的量成單（可一次勾多筆，各條明細的目的站點由來源生產任務帶出、系統按目的產線分組成單），並指定這趟的負責廠務，系統只通知負責廠務去搬；搬運者只執行搬運與回報（開始搬運、抵達站點附照），不決定送哪幾筆、各送多少，也不填量。作廢這類例外由決定數量的人收掉——數量是誰決定的，錯了就由誰收掉。誰在什麼範圍能建單、修改、作廢、搬運與點收，見 [[廠內外流轉活動清單]]；為什麼這樣分工見 [[生管]]、[[廠務]] 的分工理由。

本階段的轉交涵蓋兩類場內路徑：產線 → 產線（工序之間）、生產任務 → 品檢線的品檢站（最後一道工序之後）。兩者的來源都是**生產任務**（場內產線上的任務，以及回台點收後的外發生產任務）、來源量都是報工良品、目的地都有人收。外發回台的貨在暫存區完成回廠點收、對該外發生產任務報工之後，即以該外發生產任務為來源建一張目的站點為品檢站的轉交單，自暫存區搬到品檢站、在品檢站點收——建單、搬運、點收三段機制與場內兩類路徑完全相同。**涉及暫存區的三類路徑（產線 → 暫存區、品檢站 → 暫存區、暫存區 → 產線）不擴充**——貨進了暫存區之後它屬於哪一筆生產任務已經沒有意義，明細該掛的是印件層或庫存批；這個理由對**場內做完擺進暫存區**的貨成立，對**外發回台**的貨不成立（外發的貨在暫存區時歸屬明確、就是那筆外發生產任務，點收時已逐筆對上，故上一句那條路徑照走轉交單）。品檢完成品也不產生新的建立路徑——它留在品檢區（＝出貨區）就地揀貨裝箱、常態不移動，例外移置（品檢區擺不下、客戶自取件）搬到暫存區並以現場標示卡與 Slack 轉交回報通道留痕，不成單（過程見 [[品檢通過入庫]]）。場外回場內的物流本身走 [[貨運單]]（中國線）與 [[派單狀態]]，非轉交單範圍；台灣外包回場直接對生產任務做回廠點收、再以報工收斂（點收機制依 [[PT-008-外發回廠流轉的系統設計範圍]] 決議），見 [[印件生產流程]] § 外發回場銜接。

轉交單是 [[工序相依性規則]] 中「需轉交才可製作」的載體——下一道工序的到料量看轉交明細的**點收量**，到料量大於 0 即可開工、滾動累積（數量級放行，正本見 [[工序相依性規則]]）。送達是搬運方單方面的宣稱，點收是接手方照實填下收到多少，放行由要動手做的那個人說了算。收到的量與搬運數量對不上時，點收前可作廢重建，也可照實點收、差額留在明細上看得見；貨補到了，對同一條明細再點收一次、新增一筆點收紀錄（處置見 [[場內轉交與修正]]）。生產任務**預設需轉交**，製程規劃時只標例外「不需轉交」；標為不需轉交的前置不檢查到料、不擋派工（欄位見 [[生產任務]]）。

貨送錯站、或送到了填錯的目的站點時，系統不另開一張單把貨搬回來：現場溝通後直接把貨搬到正確的站，系統不留這趟搬運的紀錄（處置見 [[場內轉交與修正]]）。系統不必追蹤貨實際在哪一站，因為下游到料量只看明細的點收量、不看貨在哪一站（正本見 [[工序相依性規則]]）。目的站點本身填錯時，改的是來源 [[生產任務]] 的目的站點，不是已建的轉交單。

負責廠務回報開始搬運與抵達站點，通道走 Slack 表單，前提有四項：正本在系統（單據與數量的正本在本單）；通知帶單預填（表單帶著已經存在的那張單，廠務不從零填）；保留補登路徑（Slack 回報失敗或漏報時，系統端補得回來）；身分對映（Slack 帳號對映到 ERP 的廠務人員，回報者身分不靠人工填）。Slack 表單做不到逐條上傳簽收照片時，改在系統端上傳。

## 欄位（業務可見）

> 標注「由 OP-TT-001 建立轉交單設定」的欄位在建單時決定（目的產線與目的站點的來源見欄位表）。開始搬運之後，明細的生產任務不可改（換一筆生產任務就是另一趟搬運，改它事後就查不出到底搬了什麼）；搬運數量只能經修正，每次修正填修正原因並留搬運數量修正紀錄（見下方「搬運數量修正紀錄」，檢核見 [[轉交單狀態]]）。明細建錯或數量不對時，點收前的單可作廢重開，已點收的單不可作廢（哪些狀態可作廢見 [[轉交單狀態]]）。

### 點收紀錄（每條轉交明細可有多筆，每次點收一筆）

> 點收只有一個動作，不分首次或再次。讓單頭轉「已點收」的那次點收，每條明細各新增一筆、點收數量皆大於 0（有明細完全沒到就先不點收，條件見 [[轉交單狀態]]）；之後補到的貨，對該條明細再新增一筆，單頭狀態不變。數字錯就修正那一筆；整筆不該存在（如點到別張單）就作廢那一筆，作廢後該筆不計入點收量，本單點收紀錄全部作廢時單頭退回已送達（轉換見 [[轉交單狀態]]）。誰在什麼範圍能點收、修正與作廢點收紀錄，見 [[廠內外流轉活動清單]]；點收修正與點收紀錄作廢在什麼數字下被擋下，正本見 [[工序相依性規則]]。

## 操作

| 操作編號 | 操作 | 動作類型 |
|---------|------|---------|
| OP-TT-001 | 建立轉交單 | 建立 |
| OP-TT-002 | 重開轉交單 | 建立 |
| OP-TT-003 | 編輯轉交單 | 編輯 |
| OP-TT-004 | 開始搬運 | 狀態推進 |
| OP-TT-005 | 抵達站點 | 狀態推進 |
| OP-TT-006 | 點收 | 狀態推進 |
| OP-TT-007 | 修正點收 | 編輯 |
| OP-TT-008 | 作廢點收紀錄 | 刪除或作廢 |
| OP-TT-009 | 作廢轉交單 | 刪除或作廢 |
| OP-TT-010 | 檢視轉交單 | 檢視 |

無操作的動作類型：審核、指派或改派（負責廠務於 OP-TT-001 建立轉交單與 OP-TT-003 編輯轉交單時指定，執行者與一般編輯相同，不另立操作）、分享管理、輸出

- 建立轉交單是從待轉交任務一次勾選多筆生產任務發起，系統按目的產線分組成單，不屬單一張上層單據，登記在本卡。
- OP-TT-002 重開轉交單與建立轉交單分立，是因為系統效果不同：重開以已作廢的原單為底，新單沿用原單的目的產線、各條明細的目的站點與負責廠務。
- OP-TT-003 編輯轉交單涵蓋待搬運態的改單與開始搬運後的搬運數量修正，兩者的執行者相同；開始搬運後只開放搬運數量，且必填修正原因。
- OP-TT-007 修正點收與 OP-TT-008 作廢點收紀錄自一般編輯另立，是因為能執行的人與一般編輯不同（點收的人在目的地）。
- 點收只有一個操作，不分首次或再次；讓單頭轉「已點收」的是本單第一筆未作廢的點收紀錄，之後再點收不改單頭狀態（轉換見 [[轉交單狀態]]）。

## 關鍵關聯

> 基數與方向的唯一正本見 [[ERP 資料結構總覽]]，生產領域視角見 [[生產領域資料結構總覽]]，本段為本卡視角摘要。

資料約束（本卡自身的完整性條件）：

- 一張轉交單的所有明細必須同一條目的產線（一張單＝一趟送往同一條產線的搬運，各條明細的目的站點可不同；不同目的產線各自成一張）
- 同一筆生產任務不可在一張轉交單的明細出現兩次
- 每條明細的搬運數量受來源生產任務的轉交可申請上限管制（算式正本見 [[生產任務]]）；建單與改單的檢核時點、超額處置見 [[轉交單狀態]]
- 建立前置：貨要先存在才有得搬——本階段兩類路徑均以來源生產任務已有報工良品為前提
