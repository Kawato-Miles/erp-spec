# 轉交單（TransferTicket）

讀完這張卡，你會知道：

- 說出一張轉交單管多少範圍——一趟搬運事件，同一個目的地的貨可跨印件、跨工單裝同一張單
- 說出一張轉交單怎麼生出來——師傅報工累積出可轉交量、生管在待搬視圖建單，廠務只執行搬運與回報
- 分辨哪些搬運走轉交單、哪些不走（場內站間移動走轉交，場外回場的物流不走）
- 找到一張轉交單上看得到的每個欄位、誰填、什麼時候寫入，以及一次最多能轉多少要查哪張卡
- 說出轉交跟下游能不能開工的關係（已點收量就是下游的到料量），以及狀態名在哪張卡
- 分辨一般轉交單與回運單差在哪（回運是把送錯站的貨搬回來，不吃額度、點收後對誤收站的到料量減記）

## 營運背景

一張轉交單＝**一趟搬運事件**，承載這次運送的目的地、數量與送達憑證。一趟搬運是以「推車推去哪一站」定義的，不是以「車上的貨屬於哪一張訂單」定義的，所以同一個目的地的貨可以裝同一張單、跨印件也跨工單（廠務把甲客戶的名片和乙客戶的貼紙一起推到裁切站，那就是一趟）；貨屬於誰由每一條明細各自掛的來源生產任務往上推導，單頭不再綁印件。同一筆生產任務可分批開多張單（跨天分批不卡下游）。

這張單串聯上下兩個生產任務：上一道做完的產出，要轉給下一道接著做——誰的貨、從哪到哪、送了多少、到了沒、下游收到沒。它把過去靠紙本工單跟著貨走的流轉，變成系統裡可追蹤、可作為下游到料放行的紀錄。**單據由 [[生管]] 在待搬視圖建立**：師傅報工累積出各任務的可搬量，生管勾選要送的量與目的地成單（可一次勾多筆，系統按目的地分組成單），系統再通知 [[廠務]] 去搬；廠務只執行搬運與回報（起搬、卸貨送達附照），不決定送哪幾筆、各送多少。作廢與改路徑這類例外一樣歸生管——數量是誰決定的，錯了就由誰收掉。

本階段的轉交涵蓋兩類場內路徑：產線 → 產線（工序之間）、生產任務 → 品檢站（最後一道工序之後）。兩者的來源都是**生產任務**（場內產線上的任務，以及回台點收後的外發生產任務）、來源量都是報工良品、目的地都有人收（下游師傅或品檢人員）。外發回台的貨在暫存區完成點收、[[印務]] 依點收結果報工之後，[[生管]] 即以該外發生產任務為來源建一張目的地為品檢站的轉交單，[[廠務]] 自暫存區搬到品檢站、[[品檢人員]] 點收後該批進待驗清單——建單、搬運、點收三段機制與場內兩類路徑完全相同。**涉及暫存區的三類路徑（產線 → 暫存區、品檢站 → 暫存區、暫存區 → 產線）不擴充**——貨進了暫存區之後它屬於哪一筆生產任務已經沒有意義，明細該掛的是印件層或庫存批；這個理由對**場內做完擺進暫存區**的貨成立，對**外發回台**的貨不成立（外發的貨在暫存區時歸屬明確、就是那筆外發生產任務，點收時已逐筆對上，故上一句那條路徑照走轉交單）。品檢完成品也不產生新的建立路徑——它留在品檢區（＝出貨區）就地揀貨裝箱、常態不移動，例外移置（品檢區擺不下、客戶自取件）由 [[廠務]] 搬到暫存區並以現場標示卡與 Slack 轉交回報通道留痕，不成單。場外回場內的物流本身走 [[貨運單]]（中國線）與 [[生產任務狀態]] 在途狀態，非轉交單範圍；台灣外包回場銜接由 [[揀貨人員]] 直接對生產任務點收，[[印務]] 依點收結果報工收斂（點收機制依 [[PT-008-外發回廠流轉的系統設計範圍]] 決議），見 [[印件生產流程]] § 外發回場銜接。

轉交單是 [[工序相依性規則]] 中「需轉交才可製作」的載體——下一道工序的到料量看「轉交單**已點收**的數量」，到料量大於 0 即可開工、滾動累積（數量級放行，正本見 [[工序相依性規則]]）。送達是搬運方單方面的宣稱，點收是接手方的確認，放行由要動手做的那個人說了算。生產任務**預設需轉交**，印務在製程規劃時只標例外「不需轉交」（欄位見 [[生產任務]]）。

貨送錯站而且已經被點收時，要的不是把狀態倒回去，而是把貨真的搬回來：生管建一張**回運單**——同一個轉交單實體、來源與目的地對調的一趟搬運。回運單不受可轉交上限管制（回運的來源是誤收站上的實體貨，不是那條產線的報工良品），自己也不消耗來源任務的額度；它被點收之後對誤收站的到料量減記，同時解除原誤送那筆明細對來源任務的佔用，生管就能再建一張單送去正確的站。

## 欄位（業務可見）

> 本段是該實體的欄位正本。標注「建單時設定」的欄位由 [[生管]] 在建單畫面決定（目的地從下一道任務的產線帶出、數量預設帶可搬全量）；起搬之後單上的明細與數量一律不可改，要更正走作廢重開（改已經發生過的搬運事實，事後就查不出廠務到底搬了什麼）。

## 關鍵關聯

> 基數與方向的唯一正本見 [[生產領域資料結構總覽]]，本段為本卡視角摘要。

- 關聯到多張 [[印件]]（N:M，經明細承載——單頭不綁印件，由明細的來源生產任務往上推導）
- 明細指向多筆 [[生產任務]]（可跨工單、跨印件，同一目的地）
- 回運單指向被誤送的那張 [[轉交單]]（自我參照，回運單側 0..1）
- 作為 [[工序相依性規則]] 中下游任務的到料依據（已點收量計入下游到料量、滾動放行）

資料約束（本卡自身的完整性條件，數量上限公式正本在 [[生產任務]] 的「轉交可申請上限」欄、放行規則正本在 [[工序相依性規則]]）：

- 一張轉交單的所有明細必須同一個目的地（一張單＝一趟搬運，不同目的地各自成一張）
- 同一筆生產任務不可在一張轉交單的明細出現兩次
- 建單受可搬量上限管制：每條明細各受該來源生產任務的轉交可申請上限管制；檢核以**按下建立的那一刻**的最新額度計（畫面上顯示的可搬量只是參考值，開著畫面期間額度可能被別張單吃掉或被作廢回補），額度不足時整張單擋下並顯示當下可搬量，不做部分成立
- 回運單不受可轉交上限管制、也不消耗來源任務的額度（來源是誤收站上的實體貨，不是那條產線的報工良品）
- 建立前置：貨要先存在才有得搬——本階段兩類路徑均以來源生產任務已有報工良品為前提
