# 貨運單（Waybill）

讀完這張卡，你會知道：

- 說出貨運單記的是哪一趟物流——中國供應商把外發製作完成的貨集中運回台灣，誰承運、申報多少運費、發了多重、回台收了多少、實秤多重
- 說出為什麼這趟物流要獨立成一張單，而不併進生產任務或對客戶的出貨單
- 數得出一張貨運單載了幾張訂單、幾個生產任務的貨（集運合併）
- 算出整趟的運費與關稅怎麼按重量佔比攤回原本的生產任務，以及攤算明細與關稅單據各記什麼
- 找到大陸申報重量與台灣實秤對不上時要看哪個欄位，並說出認列狀態為什麼列在欄位而不另開狀態機卡

## 營運背景

貨運單有兩條建單路徑：**中國供應商發貨時建立**（A4 定案 2026-08-05）——供應商填承運商、發貨日期、運費、運單號碼與發貨照片後送出，系統建立該趟貨運單（待認列）；以及**管理端建立**——在一張表單裡一次輸入多組運單號碼，系統據此建出多張貨運單（一組號碼一張單，運費按重量比例拆，見下方運單號碼欄）。兩條路徑產出的是同一種貨運單，差別只在誰填、何時填。中國線的稿件外發給中國供應商製作，做完之後貨不是一張單一張單分開寄，而是交給集運商集中、整批運回台灣——一趟運送往往同時載著好幾張訂單、好幾個生產任務的貨（集運合併）。這趟運送本身有自己的承運商、申報運費、發貨重量、回台收貨與秤重憑證，而且整趟的運費與關稅要按各筆貨的重量佔比，攤回它們原本所屬的生產任務當作實際成本。這些資料不屬於任何單一生產任務，也不屬於對客戶的出貨單，所以獨立成一張貨運單來承載。

為什麼不併進 [[出貨單]]：出貨單管的是台灣對客戶的交付（貨送到客戶手上），貨運單管的是中國到台灣的內部跨境回場。兩者的對象、方向、成本歸屬都不同，併在一起會造成一單兩用。

## 欄位（業務可見）

> 本段是該實體的欄位正本。欄位忠於既有貨運單管理與運單詳情的現況平台，未經訪談確認的推測欄位不收。
> **現行系統的修改路徑（as-is）**：中國端建單時填的那些欄位（承運商、發貨日期、分批出貨標記、申報運費、大陸發貨重量、出貨箱數／張數、運單號碼、出貨照片、供應商備註、供應商認列清單）**送出後沒有任何修改路徑**，供應商端的出貨表單上也明寫「送出後發貨資訊不可再更新」；建立後還寫得進去的只有台灣端的點收與秤重、以及認列明細。

### 回台收貨與秤重（台灣端）

> 現況平台此段介面名為「QC 認列與秤重」：實際收貨後確認訂單並填寫點收數量與實際重量（公斤），介面即時顯示台灣實際秤重合計、大陸申報重量與差異提示（吻合或差異公斤數）。台灣端點收由[[揀貨人員]]在暫存區執行：對工單逐筆明細清點數量、秤重量——這是數量與狀態確認，不是品檢任務（品質把關仍在入庫前最終品檢）。**點收確認的連動**：該批貨登記在暫存區掛回工單；對應 [[生產任務]] 的完成由 [[印務]] 依點收結果報工推進（同場內報工規則，不由點收自動推——B1 定案 2026-08-05）。下游工序的到料放行**不因點收啟動**，仍依 [[工序相依性規則]] 的到料量兩軌計算——點收當下印務尚未報工、也尚無轉交單，下一站不會因點收本身放行。點收發現短少或明顯損壞，回報[[印務]]處理（對外部廠商追補屬印務外發主責）。

| 介面欄位 | 說明 | 欄位形態 | 來源 | 可否修改 |
|---------|------|---------|------|---------|
| 收貨點收數量 | 台灣端實際收到的數量（逐筆明細點收，見明細子表） | 整數 | 揀貨人員點收時填寫 | 收貨時可填 |
| 台灣實際秤重 | 台灣端實際秤得的重量合計（公斤） | 數字（公斤） | 揀貨人員點收時填寫 | 收貨時可填 |
| 重量差異 | 台灣實秤合計與大陸申報重量的差額（台灣實秤 − 大陸申報）；**只在畫面上提示，不寫回、不設差異原因欄、不阻擋認列** | 數字（公斤，唯讀） | 系統自動計算 | 不可 |

## 明細（每條＝一筆貨在這趟運送中的攤算）

> 明細以工單／生產任務為單位逐筆列出，承載各筆貨的點收、實秤與運費關稅分攤。分攤的計算政策正本在 [[印件生產流程]]。

| 欄位 | 說明 |
|------|------|
| 工單／生產任務 | 這條明細是哪張工單、哪個生產任務的貨（含稿件編號） |
| 派單數量 | 這筆貨外發出去的數量 |
| 點收數量 | 台灣端實際收到的數量 |
| 實際重量 | 這筆貨在台灣端實秤的重量（公斤） |
| 重量佔比 | 這筆貨的實際重量佔整趟實秤合計的百分比 |
| 分攤運費 | 依重量佔比攤到這筆貨的運費（人民幣＋新臺幣），攤回該生產任務 |
| 分攤關稅 | 依重量佔比攤到這筆貨的關稅（整趟關稅為單筆金額，按重量佔比攤提），攤回該生產任務；稿件層的累計分攤見 [[派單]] 委外金流 |

## 關稅單據（一張貨運單一筆）

> 一張貨運單**最多一筆**關稅單據，整筆關稅金額按明細重量佔比攤到各筆貨；稅單號碼全域唯一並跨運單查重（同一張稅單不會被登錄兩次）。一筆生產任務可累加多張貨運單攤來的關稅。

| 欄位 | 說明 |
|------|------|
| 運送方式 | 這筆關稅對應的運送方式：順豐／集運／新竹 |
| 承運商 | 經手這筆關稅的承運業者 |
| 貨運單號 | 對應的貨運單號 |
| 報單號碼 | 這筆關稅的報單號碼 |
| 稅單號碼 | 這筆關稅的稅單號碼 |
| 關稅金額 | 這筆關稅的金額（整數） |
| 箱數／件數 | 這筆關稅涵蓋的箱數與件數 |
| 收費日期 | 收取這筆關稅費用的日期 |
| 付款人 | 這筆關稅由誰繳納 |
| 款項方式 | 這筆關稅的繳納方式 |

## 關鍵關聯

> 基數與方向的唯一正本見 [[生產領域資料結構總覽]]，本段為本卡視角摘要。

- 由一家中國 [[中國廠商]] 發貨（中國供應商）。
- 與 [[派單]] **多對多（N:M）**：一趟集運合併載多張派單的貨、一張派單分批出貨跨多趟貨運單（B7 定案 2026-08-05）。
- 貨運單明細每行指向一筆 [[生產任務]]（記這趟運了多少＝點收數量、多重、攤到的運費關稅），一趟運送載多張訂單、多個生產任務的貨（集運合併）。
- 運費與關稅按重量佔比攤回各 [[生產任務]]（成本回生產任務），計入各生產任務的實際成本（外包分項）。
- 與台灣對客戶的 [[出貨單]] 分離（不同對象、不同方向、不同成本歸屬，不互相帶入）。
- 外發製作的進程歸屬 [[派單狀態]]（貨運單只承接「回台物流」這一段，外發委外的製作進程不在本卡）。

## 相關狀態機

認列狀態為簡單兩態（待認列 / 已認列），標記這趟運費與關稅的會計認列是否完成，列在欄位即可，不另開狀態機卡。已認列不鎖資料、可再次送出（見認列狀態欄），所以也沒有轉換條件要描述；若後續認列需要更細的轉換條件或鎖定規則，再評估是否升級為獨立狀態機卡，本卡不硬編。
