# 資料結構總覽卡撰寫規範（structure-overview 層）

## 〇、總覽卡是什麼（先懂定位再動筆）

| 問 | 答 |
|----|-----|
| 回答什麼問題 | 這個領域「什麼連什麼（含基數）、單據依什麼順序產生、值怎麼流」——關聯與資料流的**唯一正本** |
| 第一讀者 | 規劃前做範圍確認的 PM 與稽核者：不讀齊全領域卡也能看清結構，名詞定義或實體關係錯誤在設計前就被擋下 |
| 與實體卡的分工 | 實體卡管欄位與一句話定位；關聯（基數與方向）正本在本卡，實體卡「關鍵關聯」段降為視角摘要 |
| 與狀態機卡的分工 | 切開——本卡不畫任何狀態轉換，接縫處只標狀態名＋wiki link（2026-08-05 Miles 拍板） |

## 一、判斷表（何時建、何時不建）

| 情況 | 判定 |
|------|------|
| 一個領域一張，該領域已有 | 不新建，改既有卡（本卡型不允許同領域第二張） |
| **結構性變更的規劃碰到無總覽的領域** | **建卡是設計的前置步驟**（MUST）——結構性設計本來就要讀齊領域卡，建總覽是把同一份閱讀固化成正本；未建完成不得進 `plan-design` |
| 局部變動碰到無總覽的領域 | 不強制建；但 `plan-audit` 評分表 MUST 明標「本次 5-2 無總覽基準、關係比對為逐卡人工」（覆蓋降級攤開、不靜默通過） |
| 其他領域預先補齊 | 不做（範圍紀律：哪個領域先有結構性規劃需求，哪個先建） |

## 二、前提確認（MUST 全部已確認才能動筆）

| 前提 | 確認方式 |
|------|---------|
| 三源互盲抽取已完成 | 實體卡／狀態機＋情境卡／規則卡三源各自抽取關聯、單據流、資料流，互不知結果（來源鐵則：禁 09-canvases、禁 08-open-questions、openspec 除非 Miles 另指示不列入） |
| 三源矛盾已裁決 | 交叉比對出的矛盾逐條附各源原文呈 Miles，**裁決完畢才建卡**——矛盾未解就建卡等於把錯誤固化成正本 |
| 領域 tag 存在於 enum | 依 [[business-domain-taxonomy]]；命中不到即先補 enum |

## 三、撰寫規則

| 層級 | 規則 | 為什麼 |
|------|------|--------|
| MUST | 三視圖＋一表缺一不可：結構視圖（ER＋基數）、單據流視圖（產生順序與觸發）、資料流視圖（值的推導鏈）、關聯明細表（文字正本，圖是它的視覺化） | 三個視圖回答三個不同提問，缺任一個就留一類盲點（關係錯／方向錯／推導錯） |
| MUST | 實體名與欄位名與各正本卡**逐字一致**，禁簡稱（「貨運單明細」不得寫「明細」）；禁「N 個」式彙稱，一律逐欄點名 | [[稽核誤判記錄]] § 一第 6 條；數量會變、名詞漂移即斷鏈 |
| MUST | mermaid `erDiagram` 正規記法、中文實體名加雙引號、逐關聯標基數；as-is 現況關聯標（as-is）並註明遷移歸屬 | 不標基數的關聯就是這個卡型要消滅的東西 |
| MUST | 單據流每個節點標「由誰建、什麼觸發」；有裁決依據的附裁決編號 | 建立時機與觸發者是方向性誤解（誰認列誰）的主要來源 |
| MUST | 資料流節點寫「哪張單據的哪個欄位」；守恆式與排除規則只引用規則卡、不複寫公式 | 單一正本；公式正本在 04 規則卡 |
| MUST | 跨領域只寫「跨領域接口」段（邊界實體＋方向），不畫鄰域內部 | 一領域一張，越界即與鄰域總覽雙寫 |
| MUST NOT | 收實體定義、欄位表、狀態列舉、狀態轉換、名詞解釋、計算公式本體 | 各有正本（實體卡／狀態機卡／規則卡），收了就是雙寫 |
| SHOULD | 圖過大時拆子圖（同卡內分段），不拆卡 | 卡是正本單位，拆卡即回到雙寫 |

## 四、修改既有卡前的檢查

- 動任何關聯（增／改／刪／基數變）：**先改本卡**，再同步受影響實體卡的視角摘要——`wiki-amend` 落點表強制檢查此順序。
- 設計案帶來的關聯變動：`plan-design` 必含段①附「總覽差異」小節（動了哪幾條＋基數），落卡時照差異改。
- 每次修改追加 wiki/log.md（逐卡點名）。

## 五、邊際情境處理

- **一條關聯橫跨兩個領域**（如訂單↔印件）：正本歸關聯「業務主場」的領域總覽（誰的流程擁有這條連結的建立時機），鄰域總覽只在跨領域接口段引用。
- **as-is 與設計定案並存**：兩條都列，as-is 行標（as-is）＋遷移歸屬；不可只列其一。
- **實體卡與本卡不一致**：以本卡為準、回頭修實體卡；發現本卡錯了走矛盾呈報，不靜默改。

## 六、停下條件（共用四條見 [[卡片撰寫共用規範]] § 三）

- 三源對同一關聯說法不一致且無裁決紀錄 → 停下呈 Miles，禁自行調和。
- 某關聯的基數在所有來源都查不到 → 標「未標」呈報，禁自行推斷。

## 七、產出格式

段落順序照 [[範本 - 資料結構總覽]] 骨架：讀完你會知道 → 一、結構視圖 → 二、單據流視圖 → 三、資料流視圖 → 四、關聯明細表 → 五、跨領域接口 → 六、維護規則 → 範圍外 → 相關卡。關聯明細表欄位固定五欄：實體 A｜實體 B｜基數｜業務意義｜建立時機。範圍外段必填，逐條寫本卡不承載什麼並指明去處卡（內容依 § 八 不收清單）。

## 八、不收清單

實體定義與一句話定位（實體卡）／欄位表（實體卡）／狀態列舉與轉換（狀態機卡）／計算公式本體（規則卡）／名詞解釋（各卡一句話定位）／UI 與操作動線（Prototype）／OQ 內容（08 佇列）。

## 九、擴張準則

一領域一張；新領域依 [[範本 - 資料結構總覽]] 起手、走本規範全流程（三源抽取 → 矛盾裁決 → 建卡）。本卡型不設「全公司單張大總覽」——圖不可讀、變動衝突集中。

## 十、稽核維度（goal-driven；稽核者逐項勾）

| # | 維度 | 通過標準 |
|---|------|---------|
| 1 | 三視圖一表齊備 | 結構／單據流／資料流三視圖與關聯明細表都存在且非空殼 |
| 2 | 基數全標 | 明細表每行有基數（或明標「未標」＋呈報紀錄）；ER 圖與明細表基數一致 |
| 3 | 名詞逐字一致 | 抽查全部實體名與欄位名可在對應正本卡逐字找到；無簡稱、無「N 個」彙稱 |
| 4 | 建立時機與觸發者可溯源 | 單據流每節點的「由誰建、什麼觸發」能對應狀態機卡、情境卡或裁決紀錄 |
| 5 | 單一正本無雙寫 | 卡內無狀態轉換、欄位表、公式本體；守恆式與排除規則為引用非複寫 |
| 6 | 雙向可達 | 領域內核心實體卡的關鍵關聯段都有「正本見本卡」指回；本卡登錄於 wiki index 與 [[erp_index]] |
| 7 | 跨領域不越界 | 接口段只有邊界實體＋方向，無鄰域內部關聯 |
| 8 | as-is 標注完整 | 現況與定案並存的關聯都有（as-is）標記與遷移歸屬 |
