# Ragic 訂單流程單據狀態變化圖（現況）

Ragic 現行系統的一張跨階段大圖，橫軸為五個階段（評估／訂購／審稿／打樣印製／出貨），縱軸為 11 種單據的狀態列，並附狀態切換條件與部分未決批註。以下逐項為圖上文字的整理，**未經與 wiki 現行設計比對**，屬現況素材。

## 一、需求單狀態

確認需求 → 待評估成本 → 已評估成本 → 議價中 → 成交，另有流失。

| 狀態 | 圖上說明 |
|---|---|
| 確認需求 | 收到客戶需求，但尚須釐清 |
| 待評估成本 | 已確認需求內容，待製程審核人評估成本與售價 |
| 已評估成本 | 確認成本與售價，可提供報價 |
| 議價中 | 待客戶確認是否需調整 |
| 成交 | 需求成立，可開立正式報價單 |
| 流失 | 需求流失，不需開立報價單；可「重啟此需求進行報價」 |

另註：「重新提供方案，需與製程審核人討論」。

## 二、訂單（報價單）狀態

供會員、審稿、諮詢確認此筆訂單進度，依訂單中的稿件審核、製作、出貨結果改變狀態；**若有多印件，取最落後的狀態**。

業務接單／諮詢線下單：報價草稿 → 報價待審核 → 報價已審核 → 報價待回簽 → 已回簽 → 稿件未上傳 → 審稿階段 → 製作等待中 → 工單已交付 → 製作中 → 製作完成 → 出貨中 → 訂單完成

客製化訂單／官網訂單：等待付款 → 已付款 → 待補件

推進條件（圖上標註）：

- 審稿階段：該訂單中的所有印件，審稿狀態皆變更為「等待審稿（含之後狀態）」
- 製作等待中：該訂單中的所有印件，審稿狀態皆變更為「確認可製作」
- 工單已交付：該訂單中的所有印件，印製狀態皆變更為「工單已交付」
- 製作中：該訂單中的所有印製，印製狀態皆變更為「製作中」
- 製作完成：訂單中所有印件的印製狀態＝製作完成
- 出貨中：需通知訂單負責人（通常是業務）確認是否可出貨
- 訂單完成：訂單中所有印件的出貨數量大於等於印件數量
- 待補件：若印件中存在任一審稿被退件則進入，都完成補件後回到等待審稿
- 補收款未付款：訂單中有建立補收款訂單但尚未付款

未決批註（圖上 @Miles Jian）：

- 「要補業務確認製作狀態」
- 「要補業務主動退回流程」
- 「需規劃因規格異動，重新報價補收款流程」
- 「訂單需有職代，避免人員休假無法處理訂單」

## 三、發票狀態

尚未開立 → 開立成功，另有作廢。

註：EC 訂單出貨後自行建立發票；線下訂單回簽後，業務依照收款方式預先建立預計收款資料。

## 四、付款狀態

未付款 → 已付款。註：預計收款資料皆已收款，則此訂單變更為已完成收款。

## 五、審稿狀態（印件層）

記錄訂單中各稿件審核狀態，合格後進入印製。

待分配 → 稿件未上傳 → 等待審稿 → 合格 → 已確認可製作，另有不合格、已補件、待改稿。

| 轉換 | 圖上條件 |
|---|---|
| → 稿件未上傳 | 上傳／產生稿件於 ERP 中 |
| → 不合格 | 稿件有異常不合格，需重新補件 |
| → 已補件 | 重新上傳／產生稿件於 ERP 中；上傳新稿件後建立一筆新的審稿輪次 |
| 合格 → 已確認可製作 | 線上單自動切換；線下單業務確認沒問題後手動切換 |

## 六、印製狀態（印件層）

等待中 → 製程已確認 → 工單已交付 → 製作中／部分工單製作中 → 製作完成 → 出貨中 → 已送達，另有已棄用。

| 狀態或轉換 | 圖上條件 |
|---|---|
| 製程已確認 | 線上單：審稿合格後自動進入，並依印件中所設定製程、材料相關內容產生工單。線下單：訂單管理人手動切換，切換後自動建立一筆工單草稿，供印務主管分配工單 |
| 工單已交付 | 該印件中的所有工單，工單狀態皆變更為「工單已交付」 |
| 部分工單製作中 | 該印件中的任一工單，工單狀態變更為「製作中」 |
| 製作中 | 該印件中的所有工單，工單狀態皆變更為「製作中」 |
| 出貨中 | 入庫數量 ≥ 印件目標生產數量 |
| 已棄用 | 僅有打樣工單會到此狀態，代表打樣有問題，且需重新建立新印件、完成審稿與製作流程（規則：打樣結果＝NG-稿件問題）|
| 回到等待中 | 若打樣工單需重新製作，則需建立新工單，該印件印製狀態回到等待中（規則：打樣結果＝NG-製程問題）|

## 七、打樣結果（印件層欄位）

供業務紀錄打樣結果，以利判斷是否可進行大貨製作或需重新打樣；僅打樣印件會在 UI 顯示與開放填寫。

| 值 | 圖上說明 |
|---|---|
| 等待中 | — |
| OK | — |
| NG-製程問題 | 業務改為此內容代表檔案沒問題但需重新製作，需建立新的打樣工單；系統自動觸發印製狀態 → 等待中 |
| NG-稿件問題 | 業務改為此內容代表需重新建立印件，需重走審稿與印製；該印件的印製狀態會變更為已棄用 |

## 八、工單狀態

用於製作階段中追蹤工作進度。當生產完畢並通過 QC 後，代表印製階段結束可入庫、等待出貨。工單可分為打樣、大貨工單。

草稿 → 製程確認中 → 製程審核完成 → 工單已交付 → 製作中 → 已完成，另有已作廢、異動。

| 轉換 | 圖上條件 |
|---|---|
| → 工單已交付 | 印務提交工單給內部／外部工廠後手動調整 |
| → 已完成 | QC 通過累計 ≥ 工單目標生產數量 |
| → 異動 | 任一任務的任務狀態變更為「異動」 |
| 異動 → 製作中 | 所有任務的任務狀態皆改回「製作中」 |
| 重新確認製程 | 調整工單後重新送審；若有異動，使用收回功能重新修改後送審 |

## 九、任務狀態（依廠商類別分三種流程）

當製程確認後，追蹤派發給各工廠的任務，每個任務中會有 1～N 筆生產任務。廠商類別分自有工廠、加工廠、外包、中國廠商。

| 流程 | 狀態鏈 |
|---|---|
| 自有工廠／加工廠 | 待交付 → 已交付 → 製作中 → 已完成（任務中的所有生產任務皆為已完成）|
| 中國廠商 | 待印務提供工單 → 印務已提供工單 → 已送集運商 → 運送中 → 已完成 |
| 外包 | 已作廢、異動 → 已確認異動內容 → 運送中 → 已完成（印務使用異動工單；生管已確認異動內容並重新印製工單）|

另註：生管改為製作中、任務中任一生產任務改為「製作中」；印務自行調整。

## 十、生產任務狀態

印製過程中的最小單位，用於追蹤每個生產任務的進度。

待處理 → 製作中 → 已完成 → 已轉交，另有已作廢、報廢。

| 狀態 | 圖上條件 |
|---|---|
| 已完成 | 此生產任務中的報工數量加總 大於等於 生產數量 |
| 已轉交 | 此生產任務中的轉交數量加總 大於等於 生產數量 |
| 已作廢 | 尚未進入生產但取消的生產任務 |
| 報廢 | 已進入生產但取消的生產任務，以此生產任務中的所有報工完成數量計算成本 |

## 十一、出貨單狀態

一張出貨單可同時出多貨印件，每次出貨可自行決定出貨數量（出貨數量不可大於入庫數量）。

未處理 → 打包中 → 待出貨 → 出貨中 → 已出貨 → 運送中 → 已送達

## 十二、廠客資料（圖上附帶分類）

- 廠商：數位印刷、自有工廠（馬克杯、壓克力）
- 客戶：一般客、企業客

## 十三、圖上其他批註

- 「現行營收、現金流預估如何進行？」——營收依 pipeline 判斷（如預計售價 × 各階段成交機率百分比）；現金流依報價單收款資料、預計收款日期預估
