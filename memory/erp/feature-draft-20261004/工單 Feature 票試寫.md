## 一、Project：中台 - 工單管理

### 概述

工單是一件印件在廠內怎麼做的規劃書：由哪些生產任務組成、用什麼材料與設備、做多少、何時完成。印務規劃、印務主管審核、生管接手派工，三方在同一張單上接力。

現行製程寫在紙本工單與 Slack 訊息，印務改了製程現場不一定知道，主管核可沒有留痕，掉單與做錯版的事後追不到是哪一步漏的。

### 使用情境

1. 訂單管理人確認印件製作細節後，系統建出空的草稿工單。
2. 印務主管把草稿工單分派給一位印務，必要時再加開工單。
3. 印務登打製程：建生產任務、選材料與設備、填目標數量與預計完成日，送審。
4. 印務主管審核製程，核可或附原因退回。
5. 印務把核可後的生產任務交付產線，生管接手派工。
6. 製程要改時，印務發起工單異動，由生管確認或印務主管重審。

### Scope

| Feature 票 | 做完後使用者能做到什麼 |
|-----------|---------------------|
| 工單製程規劃與審核 | 印務主管分派工單，印務登打製程送審，印務主管核可或退回，印務把核可的任務交付產線 |
| 工單異動 | 印務在製程定案後加開、移除、調整生產任務，生管或印務主管把關 |
| 工單分享與改派 | 印務把工單授權同事代理，印務主管在人員異動時換負責人 |
| 工單紙本與成本對照 | 印務與生管列印紙本工單，印務看預估與實際成本並排 |

Out of Scope：生產任務的派工、報工、轉交歸中台 - 生產管理。印件層的品檢與可出貨帳歸中台 - 品檢。配方展開歸中台 - 配方管理。

### 狀態機

工單狀態機圖依 wiki 工單狀態卡轉繪，此處略。

## 二、Feature 票：工單製程規劃與審核

標題：[ Feature ] - 工單製程規劃與審核
Milestone：工單主流程

### 概述

這張票做完，印務主管能把草稿工單分派給印務，印務能登打製程送審，印務主管能核可或退回，印務能把核可後的生產任務交付產線。
工單的狀態流轉見中台 - 工單管理的工單狀態機。

### 權限

| 權限名稱 | 動作 | 範圍 |
|---------|------|------|
| 檢視工單模組 | 檢視工單列表 | 自己負責，或被分享 |
| 檢視工單詳情 | 開啟任一工單詳情 | 全公司 |
| 檢視全公司工單 | 檢視工單列表、待分派印件、待審核工單列表 | 全公司，含未分派 |

>>> ### 工單分派

身為印務主管，我要把系統建出的草稿工單指定給一位印務並指定審核主管，以讓每張單從一開始就有人負責到底。

**實體關係**

1. 一張工單只有一位負責印務與一位審核主管。
2. 一件印件可有多張工單，分派以印件為單位一次處理多張，可只分派其中幾張。

**驗證規則**

1. 工單尚無負責印務且不在終態才可分派。已有負責人的工單改走改派。
2. 分派時驗證負責印務與審核主管是否皆已指定，缺一則無法送出。

**驗收**

1. 假設 PI-2026-0904 旗下 WO-2026-0904 已分派周建宏、WO-2026-0905 未分派，當印務主管吳國豪在待分派印件頁開啟該印件，則只有 WO-2026-0905 可勾選分派。
2. 假設吳國豪把 WO-2026-0905 分派給蔡明修、審核主管吳國豪，當送出，則 WO-2026-0905 負責人為蔡明修，PI-2026-0904 自待分派印件頁消失。
3. 假設吳國豪只指定負責印務未指定審核主管，當送出，則無法送出。

>>> ### 製程規劃

身為印務，我要在自己的工單上建生產任務、選材料設備、填數量與日期，以讓現場拿到做得出來的規劃。

**實體關係**

1. 一張工單有多筆生產任務，每筆對應一個 BOM 引用（材料、工序或裝訂）與一台計畫設備。
2. 生產任務可指定前置任務，前置任務必須在同一張工單內。
3. 每筆生產任務有「計入完成度」旗標，預設為否。計入者另填每份工單需生產數量。

**驗證規則**

1. 工單在草稿或重新確認製程才可規劃製程。製程確認中要改須先收回；製程審核完成後要改走工單異動。
2. 新增或修改生產任務時驗證必填欄位是否填寫，未填齊則無法儲存。

**算式**

```
目標數量 ＝ 預計生產數量 ＋ 放損數量
```

1. 預計生產數量與放損數量皆由印務填寫，放損以絕對數量表達。
2. 工序主檔的預設放損率、配方的用量倍率、設備的固定開機損只供計價與參考，不預填任何數量。

**驗收**

1. 假設 WO-2026-0901 的印刷任務預計生產 3,000、放損 90，當儲存，則目標數量 3,090。
2. 假設 WO-2026-0901 停在草稿，當負責人周建宏新增裁切任務並指定前置為印刷任務，則任務清單四筆、裁切的前置顯示印刷。
3. 假設 WO-2026-0906 停在製程確認中，當周建宏修改生產任務，則系統拒絕。

>>> ### 製程送審

身為印務，我要把填好的製程送給審核主管，以讓主管在現場開工前把關。

**實體關係**

1. 送審時系統記下送審人與送審時間，待審核工單列表依送審時間早者在前。

**驗證規則**

1. 工單在草稿或重新確認製程才可送審。
2. 至少一筆有效生產任務計入完成度，否則不可送審，系統提示「至少一筆任務須計入完成度」。
3. 工單預排完成日晚於印件內部完成日時不可送審，系統列出兩個日期與相差工作天數。任一為空時不比對。

**驗收**

1. 假設 WO-2026-0901 四筆任務皆未計入完成度，當周建宏送審，則系統拒絕並提示至少一筆任務須計入完成度，狀態仍為草稿。
2. 假設 WO-2026-0901 的摺紙任務已勾計入完成度，當周建宏送審，則狀態轉製程確認中，待審核工單列表出現該單。
3. 假設 WO-2026-0906 的局部上光任務預計完成日 2026-09-24、印件內部完成日 2026-09-18，當周建宏送審，則系統拒絕並列出兩個日期。

>>> ### 製程審核

身為印務主管，我要核可或附原因退回送審的製程，以在開工前擋下做不出來或排不進的規劃。

**實體關係**

1. 退回時系統記下退回原因，工單詳情頂部顯示，印務修改後可重新送審。
2. 核可當下，含外包廠或中國廠商生產任務的工單由系統建立派單，核可確認框預告派單張數。

**驗證規則**

1. 工單在製程確認中才可核可或退回。
2. 退回時驗證退回原因是否填寫，未填則無法退回。
3. 核可時重新比對工單預排完成日與印件內部完成日，晚於者不可核可，系統列出兩個日期與相差工作天數。

**驗收**

1. 假設 WO-2026-0907 停在製程確認中、全為自有工廠任務、排程正常，當吳國豪核可，則狀態轉製程審核完成，確認框不出現派單預告。
2. 假設 WO-2026-0906 的局部上光任務預計完成日晚於印件內部完成日，當吳國豪核可，則系統拒絕並列出兩個日期。
3. 假設吳國豪退回 WO-2026-0907 且未填原因，當送出，則無法退回。
4. 假設吳國豪填原因退回 WO-2026-0907，當送出，則狀態轉重新確認製程，工單詳情頂部顯示該原因。

>>> ### 工單收回

身為印務，我要把送出去還沒被動的工單收回來改，以不必等主管退回。

**實體關係**

1. 收回時系統記下收回原因，工單詳情頂部顯示曾由誰收回。

**驗證規則**

1. 工單在製程確認中可收回。
2. 工單在製程審核完成時，所有生產任務尚未交付且旗下無派單才可收回，否則提示改走工單異動。
3. 收回時驗證收回原因是否填寫，未填則無法收回。

**驗收**

1. 假設 WO-2026-0907 停在製程確認中，當蔡明修填原因收回，則狀態回草稿，詳情頂部顯示收回原因。
2. 假設 WO-2026-0908 停在製程審核完成、三筆任務皆未交付、無派單，當周建宏填原因收回，則狀態回草稿。
3. 假設 WO-2026-0908 已交付名片雙面四色印刷一筆，當周建宏收回，則系統拒絕並提示改走工單異動。

>>> ### 生產任務交付

身為印務，我要把核可後的生產任務交付產線，以讓生管接到活開始排工。

**實體關係**

1. 交付以生產任務為單位，可逐筆或批次，畫面依生產單位分組呈現。
2. 全部生產任務交付後工單轉工單已交付；交付後生管可接收。

**驗證規則**

1. 工單在製程審核完成、工單已交付或異動才可交付生產任務。
2. 工單有待核可的重審異動時不可交付，系統提示在等誰。

**驗收**

1. 假設 WO-2026-0908 停在製程審核完成、三筆任務皆未交付，當周建宏交付一級卡 300g 名片八開一筆，則該筆標已交付，工單仍為製程審核完成。
2. 假設上一條再交付名片雙面四色印刷與名片裁切分盒，當送出，則工單轉工單已交付。
3. 假設 WO-2026-0910 負責人為蔡明修，當周建宏開啟該單，則沒有交付產線的動作。

>>> ### 空草稿工單刪除

身為印務主管，我要刪掉系統多建或規劃到一半不要的空草稿，以讓待分派清單只剩真的要做的單。

**驗證規則**

1. 工單在草稿且旗下無生產任務才可刪除。
2. 打樣重打週期起點的草稿不可刪除，系統提示改走工單取消。

**驗收**

1. 假設 WO-2026-0905 為草稿且無生產任務，當吳國豪刪除，則 WO-2026-0905 自列表消失，PI-2026-0904 旗下只剩 WO-2026-0904。
2. 假設 WO-2026-0901 為草稿且已有兩筆生產任務，當吳國豪刪除，則系統拒絕並提示先清空製程或改走工單異動。

## 三、試寫觀察

| 問題 | 結果 |
|------|------|
| 權限表撐不撐得住每個動作權限不同 | 撐得住。九個權限、九列，動作欄列清楚哪些動作共用一個權限。沒有一個動作找不到權限 |
| 「被指派」範圍 | 審核工單製程用上了：審核主管是分派時指定的人，不是任何印務主管 |
| 檢視要拆幾個 | 拆三個：列表只帶自己的、詳情全公司可開、全公司列表含未分派。對應 wiki 印務角色卡「列表只帶自己負責或被分享，別人的工單要看得直接開」 |
| 狀態條件放驗證規則 | 每節第一條都是狀態條件，讀起來順；權限表不用再疊狀態 |
| 擋下條件的拒絕提示 | Prototype 有既定提示文案的直接引用（「至少一筆任務須計入完成度」）。沒有的只寫系統拒絕並列什麼 |
| 排程硬擋 | 送審與核可兩節各寫一次，因為兩個動作都要比對。這是同一條規則出現在兩節，依規範應檢查拆法；判斷為同一張票內兩個動作共用一條驗證，不算跨票重複 |
| 具名案例 | 第一版誤判沒有「製程審核完成」停點的樣本。錨例訂單 ORD-2026-0803 旗下 WO-2026-0908、0909、0910 正停在該站、皆未交付、無派單，收回與交付兩節改用它們，不需補鏈 |
| 放損的寫法 | 第一版誤判 wiki 與 Prototype 矛盾。核對 Prototype 程式後，兩邊一致：放損由印務填絕對數量，放損率是主檔帶出的唯讀參考值、不乘出放損。本票算式段依此寫，不需改 wiki |
