# 設計：需求單成本評估分工改版（局部變動）

分級：局部變動。理由：只改需求單一個模組的轉換觸發者、欄位修改權與通知，不新增實體、狀態或角色。
前置：pre-check 報告 [precheck-presales.md](precheck-presales.md)；需求對齊拍板 [grill-decisions.md](grill-decisions.md) D1、D2、S-1～S-8。

## 本體

### 問題

業務送印務評估後，實務上是業務與印務主管在系統外（Slack）討論成本，由業務回填成本估算並推進狀態。wiki 與 openspec 規定「評估完成」由印務主管按，Prototype 也限被指派的印務主管按。印務主管為了一顆按鈕要登入系統，手冊教的操作也與現場習慣不同（[[QR-010-需求單成本評估的實務分工與系統把關落差]]）。

### 角色權責（改後）

| 動作 | 業務 | 諮詢 | 評估印務主管 | 依據 |
|---|---|---|---|---|
| 指定、改評估印務主管 | 可 | 可 | 不可 | [[業務]]、[[諮詢]] |
| 送印務評估 | 可 | 可 | 不可 | 同上 |
| 編輯成本估算、預計產線 | 可 | 可 | 可（限被指派的單，待評估成本、已評估成本） | [[印務主管]] |
| 評估完成 | 可 | 可 | 不可 | [[需求單狀態]] |
| 重新評估報價、重新啟動 | 可 | 可 | 不可 | 同上 |
| 進入議價、成交、流失 | 可 | 可 | 不可 | [[需求單狀態]] |
| 刪除 | 限接單業務、建立者、經分享取得編輯授權者（變動 11） | 同左 | 不可 | 變動 11 |
| 改接單業務 | 不可（業務主管改派） | 不可 | 不可 | [[業務主管]] |

後端強制：上表的角色限制目前只在 Prototype 成立。後端狀態轉換只驗編輯授權（[[QR-009-需求單狀態轉換的角色把關後端未擋]]），被指派者的自動編輯授權可改接單業務與評估名單（QR-016）、活動紀錄不記欄位編輯（QR-017）、可在所有非終態改成本（QR-018）。QR-017（活動紀錄記欄位編輯）拍板前，移除「評估完成限印務主管」在後端的落地同樣不得進 propose。這幾張議題卡拍板前，角色限制的後端強制不得進 propose；本設計的商業規則照上表落 wiki。

沿用既有機制：成本在系統外討論沿用 Slack 討論串；誰填了成本由活動紀錄記下，不新增欄位。

移除既有把關的替代（準則標準 3 對稱項）：移除「評估完成限印務主管」，替代把關為 (1) 保留「全部填畢才能評估完成」；(2) 成本估算每次編輯寫活動紀錄，事後查得到誰填。第 2 項 openspec「活動紀錄」Requirement 已要求記錄編輯，但後端與 Prototype 目前只記狀態轉換：Prototype 本次補上；後端缺口見 QR-017。

## ① 邊界完整性表

| 實體 × 動作 | 建立 | 修改 | 作廢 | 查詢 |
|---|---|---|---|---|
| 需求單 | 不變（業務、諮詢建立） | 成本估算、預計產線、評估印務主管、線上討論連結的修改者或時機改動（見變動 3、4、10）；其餘欄位不變 | 需求單不作廢，改用刪除（軟刪除）：刪除者改動見變動 11，評估印務主管不可刪 | 印務主管可看全部（變動 5，待 QR-015） |
| 報價紀錄（評估快照） | 評估完成時系統建立，觸發者改為業務部門 | 不適用：快照唯讀，不變 | 不適用：快照不作廢，不變 | 能開需求單者皆可見（變動 8） |

| 狀態 | 進入路徑 | 離開路徑 |
|---|---|---|
| 待評估成本 | 需求確認中送印務評估；議價中重新評估報價；流失重新啟動（皆不變，後兩者觸發 Slack 串內回覆） | 業務部門按評估完成 → 已評估成本；任一時點流失 → 流失 |
| 已評估成本 | 業務部門按評估完成（改） | 進入議價 → 議價中；流失 → 流失（不變） |

總覽差異：售前領域無資料結構總覽卡。本案不動任何實體關聯，只改欄位修改權與轉換觸發者，免附。

## ② 管理指標段

本案不新增指標。既有指標「利潤率」（需求單層，算式正本 [[生產績效指標]]）來源欄位為成本估算與小計，兩欄仍存在，公式不變。成本估算的填寫者改變，不影響指標的可算性。

## ③ 情境分類表

| 情境 | 分類 | 說明 |
|---|---|---|
| 業務送評估，與印務主管在 Slack 討論，業務回填成本並按評估完成 | 主情境・系統內 | 送評估、回填、評估完成都在系統內；討論在 Slack 串，串連結由系統回寫 |
| 印務主管自己回填成本，業務再按評估完成 | 主情境・系統內 | 印務主管限被指派的單可改成本 |
| 議價後客戶嫌貴，業務重新評估報價 | 主情境・系統內 | 回待評估成本，Slack 原串回覆通知印務主管 |
| 流失後客戶回頭，業務重新啟動 | 主情境・系統內 | 同上 |
| 送評估後要換評估印務主管 | 邊界・系統外 | 誰做：業務或諮詢；作業程序：在系統改評估印務主管欄（後端自動調整編輯授權），再到該需求單的 Slack 討論串提及新人選；資料回系統：人選在系統欄位，討論在原串，不需回填 |
| 某件印刷品不需估成本 | 邊界・系統內 | 成本估算填 0，沿用「全部填畢才能評估完成」條件 |
| 印務主管要看未被指派的需求單 | 邊界・系統內（待 OQ） | Prototype 開放；正式環境待 [[QR-015-印務主管檢視全公司需求單的後端權限未支援]]。QR-015 拍板前此行為不得進 propose |
| 議價中發現成本要改 | 主情境・系統內 | 業務按「重新評估報價」回待評估成本，Slack 原串回覆，重估後建新報價紀錄（既有規則） |
| Slack 通知發送失敗 | 邊界・系統外 | 誰做：業務；作業程序：在 Slack 需求單頻道手動提及評估印務主管；資料回系統：串連結手動填入需求單線上討論連結欄（欄位已存在，沒值時可填）。後端另有自動重試 |
| 評估完成後接單業務不是按的人（諮詢或代理人代按） | 邊界・系統內 | 狀態轉已評估成本，活動紀錄記下按的人；不另發通知 |

## ④ grill 拍板紀錄段

| 題 | 問題 | 拍板 | 理由 |
|---|---|---|---|
| D1 | 成本估算由誰填、評估完成由誰按 | B：業務部門按評估完成，印務主管保留編輯成本估算 | 實務是業務回填；印務主管想自己填時也能填 |
| D2 | 印務主管從哪進需求單 | B：側欄加需求單管理、列表看全部；送評估是 Slack 通知，不做系統內通知 | 讓印務主管找得到單；業務、諮詢在 Slack 與印務討論 |
| S-1 | 業務、諮詢能否改成本估算 | 可以，三者皆可，活動紀錄記填寫者 | 符合實務 |
| S-2 | 評估完成是否擋成本估算全部填畢 | 保留 | 報價前一定有成本依據，利潤率算得出來 |
| S-3 | 評估完成後通知業務 | 不通知（原選一律通知，依後端現況翻為不通知） | 後端無此通知；業務自己按，通知用途小 |
| S-4 | Slack 通知時點 | 照後端：只在進入待評估成本時通知 | Miles 指定依後端現況 |
| S-5 | Slack 規則落點 | 新建外部約束卡 | 比照審稿討論 Slack 串接約束前例 |
| S-6 | 印務主管看全部的後端缺口 | 開議題卡，比照檢視全公司訂單新增權限 | 沿用後端既有做法 |
| S-7 | 評估印務主管形態 | 多選，送評估後業務、諮詢可改人選 | 照後端現況 |
| S-8 | 報價紀錄頁籤可見 | 能開需求單者皆可見 | 照後端現況；印務主管重估時要看前幾輪成本 |

主對話暫定（Miles 設定「一路做到 Prototype 完成」目標，依其已表態原則暫定，可翻案）：
- R1-a 議價中不可直接改成本，照既有規則走重新評估報價（既有規則不改）。
- R1-b 成本估算編輯寫活動紀錄（openspec 既有要求）；後端缺口開 QR-017。
- R1-c 線上討論連結照 Prototype：沒值時可補填、有值後唯讀；wiki 標修改。
- R1-d 評估印務主管不可刪除、流失、成交、進入議價、改接單業務（D1 範圍）；後端強制見 QR-009、QR-016、QR-018。

隱含假設（設計者自補，Miles 未明說）：
1. 印務主管編輯成本估算的時機限「待評估成本」「已評估成本」（Prototype 現況）；業務、諮詢限需求確認中、待評估成本、已評估成本（R1-a）。
2. 報價紀錄的「評估者」記按評估完成的人，不另記成本填寫者；誰填了成本看活動紀錄。
3. 評估印務主管在非終態都能改，取代「送評估後鎖定、只有接單業務能重選」。
4. 改評估印務主管人選時 Slack 不重發通知（後端現況只在轉換時發）。
5. 「重新評估報價」「重新啟動」的執行者維持業務部門（業務、諮詢），不變。

## ⑤ 守恆段

| 量 | 流動等式 | 本案影響 |
|---|---|---|
| 需求單印件金額 | 小計（未稅）＝ 單價 × 數量（算式正本 [[報價邏輯]]） | 不變。本案只改誰填成本、誰推進狀態 |
| 成本估算 | 需求單成本估算合計 ＝ Σ 印件項目成本估算；進入已評估成本時全數寫入報價紀錄快照 | 上升與下降方向同一套：已評估成本時直接改成本，不退回、不建新快照（既有規則，[[需求單狀態]]），快照保留評估當下的值、現值以欄位為準；議價中要改成本必須走重新評估報價，重估完成時建新快照，已評估成本改過成本後進入議價，議價期間快照保留評估當下的值、與現值不同，現值以欄位為準 |
| 評估印務主管的編輯授權 | 因評估指派取得的編輯授權 ＝ 評估印務主管名單（增選一人加一筆；移除一人撤銷該人的有效編輯授權） | 雙向成立（後端既有機制）。副作用：移除時一併撤銷該人另外經分享取得的編輯授權；增選時先撤銷其原有的檢視授權再建編輯授權 |
