## 一、頁面清單提案

### 單元結構

新增一個單元、兩個主題群，接在單元五生產管理之後。Prototype 選單群組名為「品檢與出貨」（layout.js:140-146）。

| 層 | 值 |
|---|---|
| UNITS | `{ key:'u6', nav:'單元六　品檢與出貨管理', title:'單元六　品檢與出貨管理（品檢驗收到送達客戶）', carrier:'', note:'', intro:null }` |
| DATA 主題群一 | `key:'qc'`、`role:'品檢管理'`，1 概覽＋2 操作 |

### 頁面清單

| 頁 id | 標題 | 操作角色 | 一句話說明 |
|---|---|---|---|
| i-overview | 品檢管理概覽 | 品檢人員、印務、印務主管、生管、主管 | 當師傅報出良品時，這批良品就列進品檢站的待驗清單。 |
| i-inspect | 驗收做出來的良品 | 品檢人員 | 當品檢站的待驗清單出現待驗量時，品檢人員驗收現場的貨。 |
| i-correct | 補更正紀錄 | 品檢人員 | 當品檢紀錄記錯時，品檢人員補一筆更正紀錄沖銷。 |
| s-overview | 出貨管理概覽 | 業務、揀貨人員、出貨人員 | 當客戶談定這一批怎麼出時，業務先開出貨單草稿排計畫。 |
| s-draft | 建立出貨單草稿 | 業務 | 當客戶談定這一批哪天出、送到哪時，業務建立出貨單草稿。 |
| s-create | 建立出貨單 | 業務 | 當要出的印件品檢通過時，業務開出貨單草稿點「建立出貨單」。 |
| s-pick | 揀貨與裝箱回報 | 揀貨人員 | 出貨單成立後，揀貨人員在出貨管理頁開單，推進到開始揀貨。 |
| s-ship | 出貨確認 | 出貨人員 | 當出貨單轉「待出貨」時，出貨人員依出貨方式交寄、發車或當場交付。 |
| s-deliver | 確認送達或標記異常 | 出貨人員 | 貨離廠後，出貨人員追蹤這批貨有沒有送到。 |
| s-adjust | 實裝不符時改明細或作廢 | 業務 | 當揀貨人員回報實裝數量與明細不符時，業務開出貨單處置。 |

### 切頁依據

| 判斷 | 依據 |
|---|---|
| 驗收與更正分兩頁 | 時點與觸發不同：驗收隨報工節奏做；更正在發現記錯或印務判定照收之後才做 |
| 刪除草稿不另開頁 | 草稿刪除只一個動作、無欄位，放在建立出貨單草稿頁的常見問題 |
| 改明細與作廢合一頁 | 同一決定的兩個方向：實裝不符時業務選改數量或作廢重建（wiki [[出貨單狀態]] 打包中 → 待出貨列） |
| 出貨確認與送達確認分兩頁 | 同一操作者、不同時點：出貨在交寄當天，送達在貨到之後。自取一次完成，寫在出貨確認頁 |
| 揀貨裝箱回報列入（s-pick） | 出貨單狀態鏈含揀貨段兩態（wiki [[出貨單狀態]]）。缺這頁，出貨單停在「未處理」走不下去。只寫出貨單的揀貨段，不寫揀貨人員在派單管理的貨運單點收（手冊已捨棄派單外發範疇） |
| 送達與異常合一頁 | 同一決定的兩個方向：貨送到沒有 |
