## 二、定義矛盾

依共用規範 § 三矛盾呈報固定格式。共 7 筆（D1～D7）。D2、D4、D6、D7 為寫錯的那邊不是正本或寫法明顯有誤，正本清楚，影響較小。

### D1 決議「補做」能不能選，要不要看相關印件已送達

| 段 | 內容 |
|----|------|
| 兩邊說法與來源 | A：「決議處理方式的全部選項都可選；決議段不依訂單狀態或印件狀態擋」，動機寫「決議選項的把關只看當下做不做得到的事實」（[[售後服務規則]] § 規則「決議不依訂單或印件狀態擋」L36；[[售後受理與決議]] 主流程第 3 步 L32 照此寫）。B：「決議『補做』能不能選要看這些印件是否已送達」（[[售後服務]] 相關印件欄第 3 點 L52）；「各選項當下能不能選依訂單與相關印件的事實判定」（同卡決議處理方式欄第 3 點 L54）；「補做在客戶反映的那件已送達印件上發起」（[[售後受理與決議]] 副流程 L41）。[[印件]] OP-PI-020 發起補做的前提欄為「—」 |
| 商業例子逐個驗算 | 訂單 ORD-2026-0601 有兩件印件，名片已出 300 張後客戶取消訂單，訂單轉「已取消」。假設名片的印製維度此時不是「已送達」。客戶反映收到的 300 張有色差，要求重做。照 A：決議可選「補做」，之後在名片上發起補做。照 B：名片不是已送達，「補做」不能選，只能選退款或不處理 |
| 影響 | 決議欄的選項何時可選、[[印件]] OP-PI-020 要不要補前提、[[售後服務規則]] 拆卡後「決議不依訂單或印件狀態擋」這張卡的規則本體。不裁決時，Prototype 與 Linear 會照不同卡做出不同的選項開放條件 |
| 建議 | 先確認實務，再定正本：若補做要求已送達，把「已送達」寫進 OP-PI-020 前提欄，規則卡改寫為「不依訂單狀態擋，只依前提」；若不要求，刪 [[售後服務]] 兩處說法與情境卡「已送達」字樣 |
| 要使用者回答的實務問題 | 訂單取消前已出過一部分的印件，客戶事後反映品質問題，業務可以決議重做嗎？ |

### D2 預計出貨印件與印件的建立時機（ERP 資料結構總覽寫錯）

| 段 | 內容 |
|----|------|
| 兩邊說法與來源 | A：「建立時機：揀貨人員完成裝箱回報時選」（[[ERP 資料結構總覽#預計出貨印件與印件]] L1339 起）。B：「系統於 [[訂單]] OP-ORD-001 建立出貨單草稿時預設帶入」（[[出貨單]] 預計出貨印件欄填入時點 L55）；「業務建草稿時系統預設帶入所屬訂單全部未棄用的印件」（[[履約與售後資料結構總覽]] § 四 L182）。領域總覽 L194 該列寫「同上」，上一列是裝箱資料與箱規，全系統總覽照字面抄成了箱規的建立時機 |
| 商業例子逐個驗算 | 業務在 ORD-2026-0512 建出貨單草稿，系統帶入 A5 型錄 × 500。照 A：預計出貨印件要等揀貨人員完成裝箱回報才連到印件，但那時本單早已離開草稿、預計出貨印件已轉成出貨明細，關聯不可能在那時成立。照 B：建草稿時就連上 |
| 影響 | 只動 [[ERP 資料結構總覽]] 一個標題；它是關聯的唯一正本（G4），寫錯會被各領域總覽與 Linear 照抄 |
| 建議 | 改全系統總覽為「業務建出貨單草稿時系統預設帶入；建立出貨單前可移除、加回」，領域總覽 L194 的「同上」一併刪除 |
| 要使用者回答的實務問題 | 業務建草稿時，系統帶出的印件清單是不是馬上就能刪改？ |

### D3 受理段只擋一項，還是兩項

| 段 | 內容 |
|----|------|
| 兩邊說法與來源 | A：「受理段只擋訂單未進終態這一項，其餘不設把關」（[[售後服務規則]] § 規則「受理只擋訂單未進終態」L34）。B：OP-ORD-007 建立售後服務單前提「[[訂單狀態]] 的終態；本訂單沒有未結案的 [[售後服務]] 單」（[[訂單]] L229）；「建單前提（訂單已進終態、該訂單沒有其他未結案售後單）…除此之外受理段不設把關」（[[售後受理與決議]] L30）；「同一訂單已有未結案售後單時，新客訴記在這裡而非另開單」（[[售後服務]] 客戶補述紀錄欄 L56） |
| 商業例子逐個驗算 | ORD-2026-0512 已完成，已有一張處理中的售後單 AFT-2026-0042。客戶另打來反映內頁裝訂鬆脫。照 A：只看終態，可開第二張售後單。照 B：擋下，新客訴記進 AFT-2026-0042 的客戶補述紀錄 |

| 要使用者回答的實務問題 | 同一張訂單已有一張還沒結案的售後單，客戶又反映另一件事時，業務是記在原單，還是另開一張？ |
