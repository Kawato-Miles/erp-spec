# BOM 卡重構 grill（2026-10-28）

正本重構流第 3 步產出。載體：`memory/erp/bom-card-restructure-20261028/`。

## 起因

急件主檔的計價方式有三種（％數計價、件數計價、固定計價），BOM結構卡的總流程仍寫「最終售價＝加成後售價 ×（1＋急件加成%）」。Miles 指出生產端只看成本、和售價無關，要求另開 grill 討論 BOM 卡重構。

## 全局現況調查（第 2 步）

| 項目 | 現況來源 | 查證結果 |
|------|---------|---------|
| 加成設定位置 | 後端 API 專案（sensation-api）商品模型 | 設在 EC 商品：計價方式四種（成本計算、毛利率計算、成本計算（級距）、毛利率計算（級距））、計價比率、計價比率級距 |
| 計價引擎 | 獨立套件 pricing-core，後端引用固定版本 be5a892 | 最終售價＝加成後售價＋急件費；急件費依三種計價方式算；急件費使售價歸零或為負時擋下 |
| 急件主檔 | 中台 sens-print-core develop | 三種計價方式；％數計價用價格調整，件數計價與固定計價共用數量區間 |

| EC 商品範圍 | [[EC 商品管理]]（Miles 2026-10-14 G59） | EC 商品本身不在 ERP 範圍 |
