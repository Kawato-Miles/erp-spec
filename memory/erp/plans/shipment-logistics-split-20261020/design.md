變動分級：結構性變更。理由：新增實體（物流單、未送達數量），出貨單狀態改由物流單計算（狀態機層級變動）。稽核加跑對抗式情境推演。
拍板正本：[grill.md](grill.md)（G1～G28、D1～D20）；規劃前盤點：[precheck.md](precheck.md)；稽核：[audit-r1.md](audit-r1.md)、[audit-r2.md](audit-r2.md)。

## 本體

### 一、要解決的問題

出貨單現在一張只能有一個箱規、一組物流單號，狀態掛在整張單。順豐支援子母單：多箱共用一個主單號，每箱一個子單號。不支援子母單的物流商，每箱一個物流單號。現行結構表達不了「一張出貨單、多箱、多個物流單號」，也表達不了「一箱被退、其他箱已送達」。

### 二、三層分工

| 層 | 一句話定位 | 狀態 | 主要角色 |
|---|---|---|---|
| [[出貨單]]（既有） | 業務排的一批出貨：哪天、出哪些印件各多少、送到哪、用什麼出貨方式 | 有；已裝箱之後由物流單計算 | 業務、揀貨人員 |
| 裝箱資料（新增，出貨單子表） | 這一批裝成幾箱、每箱的箱規、照片、備註 | 無 | 揀貨人員 |
| 物流單（新增實體） | 交給物流商或自行配送的一筆托運：一個物流單號、它的進度與送達 | 有，沿用 EC 物流狀態 | 出貨人員、物流商回傳 |

既有機制為什麼吸收不了：出貨單單頭只能放一組物流單號與一個狀態。EC 現行做法是多箱開多張出貨單；在 ERP 會把業務排的一批拆成多張，可出貨額度與揀貨清點都要跨單計算（G4）。

### 三、出貨方式（系統設定，D2）

| 出貨方式 | 支援子母單 | 有外部物流單號 | 出貨動作 | 對應 EC 串接 |
|---|---|---|---|---|
| 順豐 | 是 | 是 | 拋單 | sf |
| 新竹物流 | 否（物流商支援，ERP 尚未串接） | 是 | 拋單 | hct |
| 7-11 交貨便 | 否 | 是 | 拋單 | payuni |
| 全家 | 否 | 是 | 拋單 | familymart |
| 自取 | 是 | 否 | 標記可自取 | 無 |
| 專車配送 | 是 | 否 | 出貨確認 | 無 |
| 其他 | 是 | 否 | 出貨確認 | 無 |

| 屬性 | 決定什麼 |
|---|---|
| 支援子母單 | 是：全部箱子合成一筆物流單。否：一箱一筆物流單 |
| 有外部物流單號 | 是：出貨動作＝拋單，之後狀態由物流商回傳同步。否：自取走「標記可自取 → 交付確認」，其餘走「出貨確認 → 送達確認」 |

出貨方式不分層（G25）。原「超商」選項刪除，拆成 7-11 交貨便與全家。

### 四、箱規（系統設定，D2）

每筆箱規標所屬出貨方式；揀貨時只列本出貨單出貨方式的箱規。自取、專車、其他共用公司自有箱規（G20）。

### 五、欄位變動

出貨單單頭：

| 欄位 | 變動 |
|---|---|
| 箱數 | 改為系統計算＝裝箱資料筆數（G1） |
| 箱規、裝箱照片 | 刪除，改到裝箱資料（G1、G2） |
| 出貨確認、物流單號、物流單檔案、送達確認、送達憑證 | 刪除，改到物流單（G5） |
| 異常理由 | 刪除；例外理由改在物流單（G10） |
| 實際出貨日 | 改為系統計算：全部未作廢物流單都有離廠時間時，取最晚那筆；否則無值（G13） |
| 作廢理由 | 人工作廢必填；系統作廢不要求（D15） |
| 出貨方式 | 選項改為 § 三；流程依屬性決定 |

出貨明細：新增「送達數量」，系統計算、唯讀。出貨單轉已送達時寫入＝揀貨數量 − 本出貨單全部物流單的該印件未送達數量合計（G14）。出貨動作要求揀貨相符，凡能填未送達數量的時點，揀貨數量都等於明細數量（§ 八之一）。

裝箱資料（新增子表）：

| 欄位 | 說明 |

| 箱序 | 系統，三位數，不重排 |
| 箱規 | 必填，只列本出貨方式的箱規 |
| 裝箱照片 | 至少一張 |
| 裝箱備註 | 選填，不與明細比對 |
| 所屬物流單 | 系統依拆單規則寫入 |
| 子單號 | 系統；支援子母單且有外部物流單號時，拋單成功由物流商回傳 |

物流單（新增實體）：

| 欄位 | 填入 |
|---|---|
| 物流單編號 | 系統＝出貨單編號＋三位序號（例：SH-2026-0901-001）；不重用、不重排；一張出貨單上限 999 筆 |
| 所屬出貨單；出貨方式、收件資訊（帶入、唯讀） | 系統 |
| 箱數 | 系統計算 |
| 狀態 | 見 § 六之二 |
| 物流單號、物流單檔案 | 有外部物流單號者，拋單成功時物流商回傳 |
| 出貨動作失敗原因 | 拋單失敗時物流商回應 |
| 離廠時間＋操作人 | 第三方＝拋單成功的時刻（對齊 [[SHP-020-ERP出貨單承接EC物流串接的狀態對映與拋單失敗處置]] 2026-09-22 拍板）；專車與其他＝出貨確認；自取＝標記可自取 |
| 送達時間＋操作人 | 物流商回傳配達，或送達確認、交付確認 |
| 送達憑證 | 專車與其他＝司機交付照；自取＝現場點交照；第三方可補附 |
| 例外理由、例外來源 | 人工標記時理由必填；來源記人工或物流商回傳 |
| 欄位修改 | 只經狀態操作、物流商回傳與補附送達憑證；其餘不可人工改 |
| 作廢理由 | 人工作廢必填 |
| 未送達數量（子表，每印件一筆） | 見 § 八之一 |
| 歷程 | 狀態變更、回傳、重新同步、作廢，逐筆記時間、操作人、事件、前後值 |

### 六、狀態

#### 六之一、出貨單狀態

| 狀態 | 進入 | 離開 |
|---|---|---|
| 草稿 | 業務建立草稿 | 建立出貨單；刪除草稿；系統於訂單取消時刪除（沿用 [[訂單狀態]]） |
| 未處理 | 業務建立出貨單（額度檢核） | 開始揀貨；作廢 |
| 打包中 | 揀貨人員開始揀貨 | 完成裝箱回報；作廢 |
| 已裝箱（原名待出貨） | 揀貨人員完成裝箱回報，系統產生物流單 | 出貨動作後依物流單重算；作廢（出貨動作前） |
| 等待出貨 | 系統：未作廢物流單最落後＝等待出貨 | 依物流單重算 |
| 已出貨 | 系統：最落後＝已出貨或可自取 | 依物流單重算 |
| 運送中 | 系統：最落後＝運送中 | 依物流單重算 |
| 異常 | 系統：任一未作廢物流單在例外狀態；優先於已裝箱到已送達的所有計算結果 | 例外物流單恢復或作廢後重算 |
| 已送達 | 系統：至少一筆未作廢物流單，且全部已送達或已自取；寫入送達數量 | 終態 |
| 已作廢 | 業務作廢；系統（全部物流單作廢、訂單取消連鎖） | 終態 |

最落後順序：已裝箱 → 等待出貨 → 已出貨（可自取）→ 運送中 → 已送達。專車、其他、自取不經等待出貨與運送中。

集合詞重新定義（取代 [[出貨單狀態]] 現行兩個集合詞）：

| 集合詞 | 新定義 | 被誰引用 |
|---|---|---|
| 未出貨動作 | 出貨單從未執行過出貨動作（含尚無物流單的未處理至打包中，以及已裝箱且從未按過出貨動作） | 作廢出貨單、裝箱回報修正、編輯出貨單、訂單取消連鎖 |
| 部分離廠 | 已執行過出貨動作，但仍有未作廢物流單沒有離廠時間（出貨動作失敗待重試；全部失敗也歸此類，依 G18、D9 已鎖住） | 訂單取消連鎖 |
| 全數離廠 | 全部未作廢物流單都有離廠時間，出貨單有實際出貨日 | [[北極星指標]] 首張出貨單、[[訂單]] 訂單預計交貨日期、[[印件]] 已離廠量 |

三個集合詞互斥，涵蓋草稿以外的全部未作廢出貨單。集合詞不與狀態名同名。

#### 六之二、物流單狀態

| 狀態 | 第三方物流 | 專車、其他 | 自取 |
|---|---|---|---|
| 已裝箱 | 產生時 | 產生時 | 產生時 |
| 等待出貨 | 拋單成功，回傳物流單號；寫入離廠時間 | 不經過 | 不經過 |
| 已出貨／可自取 | 物流單號登記到追蹤服務成功 | 出貨確認；寫入離廠時間 | 標記可自取；寫入離廠時間 |
| 運送中 | 物流商回傳；超商到店也對映此態（D14） | 不經過 | 不經過 |
| 已送達／已自取（終態） | 物流商回傳配達，或送達確認 | 送達確認 | 交付確認 |
| 例外：未送達、無追蹤中包裹、例外事故 | 物流商回傳（等待出貨之後）；或出貨人員標記（等待出貨、已出貨、運送中） | 從已出貨標記 | 從可自取標記 |
| 已作廢（終態） | 作廢 | 作廢 | 作廢 |

狀態推進規則：

| 規則 | 內容 |
|---|---|
| 只往前 | 回傳只會讓狀態往最落後順序的後方走；倒退的回傳不改狀態、只寫歷程。唯一例外：物流單在例外狀態時，同步結果可讓它回到物流商當下的狀態（見下方例外的離開路徑） |
| 終態不動 | 已送達、已作廢收到任何回傳不改狀態，只寫歷程 |
| 先寫入者成立 | 人工確認與物流商回傳同時到，以先寫入者為準，後到者只寫歷程 |
| 人工例外不被覆蓋 | 出貨人員人工標記的例外，自動同步不改狀態；出貨人員按重新同步才取物流商當下狀態 |

例外的離開路徑：

| 出貨方式 | 離開例外 |
|---|---|
| 第三方 | 物流商回傳的例外：自動同步或重新同步；人工標記的例外：只有重新同步；兩者皆可送達確認（可填未送達數量）或作廢 |
| 專車、其他 | 送達確認；作廢 |
| 自取 | 交付確認；作廢 |

作廢物流單的開放狀態（D7）：

| 狀態 | 可否作廢 | 物流商端 |
|---|---|---|
| 已裝箱（出貨動作失敗後） | 可 | 無需處理 |
| 等待出貨 | 可 | 系統向物流商取消；取消失敗則不作廢，顯示失敗原因 |
| 例外三態 | 可 | 不動；出貨人員先向物流商確認貨況（系統外，見 ③）。等待出貨時物流商取消失敗、又一直沒有回傳，出貨人員可標記例外後作廢 |
| 已出貨、運送中 | 不可，要先轉例外 | — |
| 已送達 | 不可（G15） | — |

狀態對映：第三方物流的原始代碼由 EC 收斂到上表；ERP 接 EC 收斂後的值（G9）。順豐子單不回傳狀態，物流單看主單（G19）。

| 檢視物流單 | 出貨單內 | 與檢視出貨單相同 | 有物流單 | 無 |

### 八、連帶規則

#### 八之一、可出貨額度與送達量（每印件）

| 名詞 | 定義 |
|---|---|
| 單張佔用量 | 未作廢出貨單的明細數量 − 該出貨單全部物流單（已作廢與已送達）的該印件未送達數量合計；不為負（未送達上限與編輯明細檢核共同保證） |
| 累計已出貨數量 | Σ 單張佔用量（只加總未作廢出貨單；已作廢出貨單整張不計，底下物流單的未送達也不再扣，不重複回補） |
| 可出貨額度 | 完工良品數 − 累計已出貨數量（等式不變） |
| 未送達數量上限 | 同一出貨單同一印件，全部未送達數量合計 ≤ 明細數量 |
| 系統預填 | 作廢的是最後一筆未作廢物流單時，未送達數量＝明細數量 − 已填未送達合計，不可改（D11 改寫）；此時出貨單轉已作廢 |
| 單筆作廢的預設 | 非最後一筆時預設 0，業務逐印件填 |
| 送達數量 | 見 § 五出貨明細 |
| 累計送達數 | Σ 已送達出貨單的送達數量（G14） |
| 已離廠量 | Σ 全數離廠且未作廢出貨單的單張佔用量 |

以明細數量為上限基準的理由：作廢物流單與送達確認都在執行過出貨動作之後，此時揀貨相符，揀貨數量＝明細數量；佔用量以明細計，上限用明細才能剛好還回（audit-r1 T9）。

### ⑤ 守恆段

本次涉及的量：印件數量、箱數。

印件數量（每印件、每出貨單）：

| 等式 | 說明 |
|---|---|
| 完工良品數 ＝ 可出貨額度 ＋ 累計已出貨數量 | 不變的額度式 |
| 單張佔用量 ＝ 明細數量 − 該單全部物流單未送達合計 | 只對未作廢出貨單計算；未送達來自作廢物流單或送達確認、交付確認 |
| 已送達出貨單：明細數量 ＝ 送達數量 ＋ 已作廢物流單未送達合計 ＋ 已送達物流單未送達合計 | 未送達合計 ≤ 明細數量，送達數量不為負 |

雙向驗算例：明細 100，3 筆物流單。

| 步驟 | 動作 | 單張佔用量 | 回補累計 |
|---|---|---|---|
| 1 | 建立出貨單 | 100 | 0 |
| 2 | 作廢物流單 A，未送達 30 | 70 | 30 |
| 3 | 作廢物流單 B，未送達 40 | 30 | 70 |
| 4 | 作廢最後一筆 C，系統預填 100 − 70 ＝ 30，出貨單轉已作廢 | 出貨單不計（0） | 100 |

步驟 4 之後，已作廢出貨單整張不計，底下 A、B、C 的未送達不再扣，回補合計 100＝明細數量，沒有重複回補。

| 方向 | 機制 |
|---|---|
| 額度增加（回補） | 入口：作廢物流單、作廢出貨單、送達確認或交付確認填未送達、未出貨動作期間調低明細數量（須不小於本單未送達合計）；異常不回補 |
| 額度減少（佔用） | 建立出貨單時檢核；未送達合計有上限，佔用量不為負；品檢修正調低通過量時，下限取累計已出貨數量（含異常出貨單），額度不為負 |
