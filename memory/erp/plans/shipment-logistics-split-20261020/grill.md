# 出貨單裝箱資料與物流單拆分 grill 拍板紀錄（2026-10-20）

目的：出貨單要相容支援子母單的物流商。出貨單擴充裝箱資料；拋單單位從出貨單改為物流單。
本檔只記拍板結果與前後資料結構、操作流程，供後續 plan-design、plan-audit、wiki-amend 承接。
變動性質：結構性變更（新增物流單實體與狀態機、出貨單狀態改由物流單計算、新增箱規主檔）。稽核須跑 rubric 加對抗式情境推演。

## 一、拍板清單

| 序 | 題目 | 拍板 |
|---|---|---|
| G1 | 單頭箱數與箱規 | 刪除單頭「箱規」；「箱數」改系統計算＝裝箱資料筆數 |
| G2 | 每箱是否記內容 | 不記印件×數量；每箱加「裝箱備註」（選填、自由文字、不與出貨明細比對）；裝箱照片從單頭改掛到每箱；出貨明細的揀貨數量、每箱幾個維持（每箱幾個已由 G29 刪除） |
| G3 | 每箱照片 | 每箱至少一張照片才能完成裝箱回報 |
| G4 | 三層分工 | 出貨單＝業務排的一批出貨；裝箱資料＝出貨單子表；物流單＝拋單與追蹤單位，參考 EC 物流單 |
| G5 | 物流單範圍 | 所有出貨方式都有物流單，含自取、專車配送；原出貨單的離廠後操作與物流單號相關功能改在物流單上 |
| G6 | 物流單產生時點 | 完成裝箱回報時，系統依裝箱資料與出貨方式產生；起始狀態「已裝箱」 |
| G7 | 拆單規則 | 出貨方式「支援子母單」＝是：全部箱子合成一筆物流單；否：一箱一筆物流單 |
| G8 | 出貨方式主檔 | 兩個屬性：支援子母單、有外部物流單號；選項與屬性值見 § 二之五；出貨方式選項以 § 二之五為準（G25 修正） |
| G9 | 物流單狀態 | 沿用 EC 物流狀態；不沿用 EC 的「打包中」「過期」；初始態命名「已裝箱」 |
| G10 | 出貨單狀態 | 與 EC 物流單同顆粒；已裝箱之後取未作廢物流單的最落後狀態；新增計算型「異常」（任一未作廢物流單在例外狀態即異常，優先於等待出貨到已送達，非終態、不回補）；「待出貨」改名「已裝箱」 |
| G11 | 例外時的出貨單顯示 | 統一寫「異常」，具體例外名稱只留在物流單 |
| G12 | 作廢物流單 | 業務執行；逐印件填未送達數量並附理由；系統依此回補可出貨額度；作廢最後一筆未作廢物流單時，系統預填全部揀貨數量；未送達數量合計不得超過該印件在本出貨單的揀貨數量 |
| G13 | 實際出貨日 | 出貨單取未作廢物流單中最晚離廠那一筆的離廠時間；取法改為直接取物流單離廠時間。目前 ERP／MES 無畫面使用，只改定義 |
| G14 | 累計送達數 | 正面表列：出貨明細新增「送達數量」（系統計算、唯讀），出貨單轉已送達時寫入＝揀貨數量 − 未送達數量合計；印件累計送達數＝送達數量加總 |
| G15 | 已送達物流單 | 不可作廢 |
| G16 | 拋單方式 | 出貨單批次拋單，一次送出全部已裝箱的物流單；單筆入口只用於重拋失敗的那筆；已轉等待出貨的物流單系統不再送出（防重複拋單） |
| G17 | 部分拋單失敗 | 成功的轉等待出貨；失敗的留在已裝箱並顯示失敗原因；出貨單取最落後，仍為已裝箱 |
| G18 | 單箱修正 | 拋單前開放逐箱新增、修改、刪除（修正原因必填，記入裝箱回報修正紀錄）；拋單後全部鎖住，含照片與備註 |
| G19 | 順豐子單狀態 | 事實：順豐子單不回傳狀態；物流單一律看主單狀態，子單號只顯示 |
| G20 | 箱規主檔 | 每筆標所屬出貨方式，揀貨時只列該出貨方式的箱規；自取、專車、其他共用公司自有箱規（G25 後超商拆為 7-11 交貨便與全家，各自有箱規） |
| G21 | 人工推進 | 固定動作，依出貨方式只顯示可用的下一步；另開「重新同步」動作處理物流商誤報；不開放人工任意改狀態 |
| G22 | 自取流程 | 已裝箱 → 標記可自取 → 交付確認 → 已自取；自取實際出貨日取「標記可自取」時間 |
| G23 | 物流單全數作廢 | 最後一筆未作廢物流單被作廢時，系統自動把出貨單轉已作廢；不自動帶作廢原因文字 |
| G24 | 設計範圍 | 本次只處理流程與資料正確；介面呈現有必要再另提 |

被否決且具決策價值的方案：

| 方案 | 否決理由 |
|---|---|
| 物流單在拋單時才產生 | 已裝箱期間無物流單，出貨單推進規則要切兩段 |
| 只有第三方物流有物流單 | 自取、專車仍要另一套推進規則；G5 統一為所有出貨方式都有物流單 |
| 出貨單不設異常、用標示 | 一對一（子母單、自取、專車）時狀態欄不誠實，唯一一筆被退仍顯示運送中 |
| 出貨單寫具體例外名稱 | 一對多時只呈現多筆例外中的一筆，一筆恢復後名稱跳成另一筆，業務會讀錯 |
| 物流單異常即回補額度 | 例外可能只是資料未同步；回補改在作廢物流單時依未送達數量 |
| 每箱記印件×數量 | 每次正常出貨都加工作；只有作廢時填未送達數量即可 |
| 一次新增多箱（D20，2026-10-20 補定） | Miles 試用後撤回（G29），保留逐箱新增 |
| 逐筆拋單 | 第一筆送出後發現他箱裝錯會卡住；批次拋單消除部分送出的時間窗 |
| 物流單人工改狀態用下拉選單 | 送達憑證、揀貨相符等把關失效 |

## 二、前後資料結構

> 本節至 § 四為 grill 當下的衍生表，稽核後已有修正；落卡與實作以 [design.md](design.md) 為準。

### 二之一、出貨單（單頭）

| 欄位 | 現行 | 改後 |
|---|---|---|
| 所屬訂單、建單人、出貨單預計出貨日、收件人、收件人電話、收件地址、寄件資訊、裝箱指示、出貨方式 | 有 | 不變 |
| 狀態 | 人工操作推進 | 草稿至已裝箱由出貨單操作推進；之後由物流單計算（見 § 三） |
| 箱數 | 揀貨人員手填 | 系統計算＝裝箱資料筆數 |
| 箱規 | 單選一種 | 刪除，改到裝箱資料逐箱 |
| 裝箱照片 | 單頭多檔 | 刪除，改到裝箱資料逐箱 |
| 出貨確認（時間＋操作人） | 單頭 | 刪除，改到物流單 |
| 物流單號、物流單檔案 | 單頭一組 | 刪除，改到物流單 |
| 送達確認、送達憑證 | 單頭 | 刪除，改到物流單 |
| 實際出貨日 | 首次進入已出貨狀態群的日期 | 系統計算＝未作廢物流單中最晚離廠那一筆的離廠時間 |
| 異常理由 | 出貨單標記異常時填 | 刪除；例外理由改在物流單 |
| 作廢理由 | 業務作廢時填 | 業務手動作廢時填；系統因物流單全數作廢而作廢時不帶文字 |

### 二之二、出貨明細（出貨單子表）

| 欄位 | 現行 | 改後 |
|---|---|---|
| 印件、數量、揀貨數量、每箱幾個 | 有 | 不變 |
| 送達數量 | 無 | 新增；系統計算、唯讀；出貨單轉已送達時寫入＝揀貨數量 − 該印件在已作廢物流單的未送達數量合計 |

### 二之三、裝箱資料（出貨單子表，新增）

| 欄位 | 說明 | 填入 | 可否修改 |
|---|---|---|---|
| 箱序 | 第幾箱 | 系統 | 不可 |
| 箱規 | 只列本出貨單出貨方式的箱規 | 揀貨人員完成裝箱回報時選，必填 | 拋單前可經裝箱回報修正；拋單後鎖住 |
| 裝箱照片 | 至少一張 | 揀貨人員完成裝箱回報時附，必填 | 同上 |
| 裝箱備註 | 自由文字，不與出貨明細比對 | 選填 | 同上 |
| 所屬物流單 | 這箱歸哪一筆物流單 | 系統依拆單規則寫入 | 系統計算 |
| 子單號 | 支援子母單且有外部物流單號時，物流商回傳 | 系統於拋單成功時寫入 | 不可 |

### 二之四、物流單（新增實體）

| 欄位 | 說明 | 填入 |
|---|---|---|
| 所屬出貨單 | 連結 | 系統於完成裝箱回報時產生 |
| 出貨方式、收件資訊 | 帶入所屬出貨單，唯讀 | 系統 |
| 箱數 | 歸屬本物流單的裝箱資料筆數 | 系統計算 |
| 狀態 | 見 § 三之二 | 拋單、物流商回傳、固定動作推進 |
| 物流單號 | 有外部物流單號者由物流商回傳；自取、專車、其他無 | 系統於拋單成功時寫入 |
| 物流單檔案 | 物流商回傳的托運單據，可下載 | 同上 |
| 拋單失敗原因 | 拋單失敗時物流商回應 | 系統 |
| 離廠時間＋操作人 | 第三方＝拋單成功；專車＝出貨確認；自取＝標記可自取 | 系統於對應動作寫入 |
| 送達時間＋操作人 | 物流商回傳配達，或送達確認、交付確認 | 系統 |
| 送達憑證 | 專車＝司機交付照；自取＝現場點交照；第三方＝物流商回傳配達時間，可補附 | 出貨人員 |
| 例外理由 | 人工標記例外時必填 | 出貨人員 |
| 作廢理由 | 必填 | 業務 |
| 未送達數量（子表，每印件一筆） | 作廢時逐印件填；作廢最後一筆未作廢物流單時預填全部揀貨數量 | 業務 |

## 三、狀態

### 三之一、出貨單狀態

| 序 | 狀態 | 推進 |
|---|---|---|
| 1 | 草稿 | 業務建立（不變） |
| 2 | 未處理 | 業務建立出貨單（不變） |
| 3 | 打包中 | 揀貨人員開始揀貨（不變） |
| 4 | 已裝箱 | 揀貨人員完成裝箱回報；系統同時產生物流單（原名待出貨） |
| 5 | 等待出貨 | 系統：未作廢物流單最落後為等待出貨 |
| 6 | 已出貨 | 系統：最落後為已出貨或可自取 |
| 7 | 運送中 | 系統：最落後為運送中 |
| 8 | 已送達 | 系統：未作廢物流單全部已送達或已自取；寫入送達數量 |
| 9 | 異常 | 系統：任一未作廢物流單在例外狀態；優先於 5 到 8；非終態、不回補 |
| 10 | 已作廢 | 業務手動作廢（全部未作廢物流單在已裝箱，或拋單前）；或最後一筆物流單作廢時系統自動 |

### 三之二、物流單狀態（沿用 EC）

| 狀態 | 第三方物流 | 專車配送 | 自取 |
|---|---|---|---|
| 已裝箱 | 產生時 | 產生時 | 產生時 |
| 等待出貨 | 拋單成功 | 不經過 | 不經過 |
| 已出貨／可自取 | 物流單號登記成功 | 出貨確認（發車） | 標記可自取 |
| 運送中 | 物流商回傳 | 不經過 | 不經過 |
| 已送達／已自取 | 物流商回傳，或送達確認補上 | 送達確認 | 交付確認 |
| 例外：未送達、無追蹤中包裹、例外事故 | 物流商回傳或標記例外 | 標記例外 | 標記例外 |
| 已作廢 | 業務作廢（已送達除外） | 同左 | 同左 |

對映：第三方物流各家原始代碼由 EC 收斂到上表狀態；ERP 接 EC 收斂後的值。

## 四、操作流程

### 四之一、主流程

| 步驟 | 角色 | 動作 | 出貨單 | 物流單 |
|---|---|---|---|---|
| 1 | 業務 | 建立出貨單草稿 | 草稿 | — |
| 2 | 業務 | 建立出貨單（額度檢核） | 未處理 | — |
| 3 | 揀貨人員 | 開始揀貨 | 打包中 | — |
| 4 | 揀貨人員 | 完成裝箱回報：逐明細揀貨數量、每箱幾個；逐箱箱規、照片、備註 | 已裝箱 | 系統依拆單規則產生，已裝箱 |
| 4a | 揀貨人員 | 拋單前單箱修正 | 已裝箱 | 系統調整受影響的物流單 |
| 5 | 出貨人員 | 第三方：出貨單批次拋單（揀貨相符才可） | 依物流單計算 | 等待出貨，回傳物流單號、子單號、物流單檔案 |
| 5 | 出貨人員 | 專車：出貨確認 | 依物流單計算 | 已出貨 |
| 5 | 出貨人員 | 自取：標記可自取 | 依物流單計算 | 可自取 |
| 6 | 系統 | 第三方物流商回傳 | 依物流單計算 | 已出貨 → 運送中 → 已送達 |
| 6 | 出貨人員 | 專車送達確認、自取交付確認 | 依物流單計算 | 已送達／已自取 |
| 7 | 系統 | 全部未作廢物流單送達 | 已送達，寫入送達數量 | — |

### 四之二、副流程

| 情況 | 處置 |
|---|---|
| 部分拋單失敗 | 失敗的留在已裝箱並顯示原因；出貨單再按一次拋單只送出未成功的，或單筆重拋 |
| 物流商回傳例外 | 物流單轉例外，出貨單轉異常；出貨人員重新同步，恢復後出貨單重算 |
| 確定送不到 | 業務作廢該物流單，填未送達數量；回補額度；另開出貨單補出 |
| 全部物流單作廢 | 出貨單系統自動轉已作廢 |
| 拋單前發現裝錯 | 揀貨人員單箱修正 |
| 拋單後發現裝錯 | 業務作廢受影響的物流單，填未送達數量，另開出貨單 |
| 拋單前整批撤銷 | 業務作廢出貨單 |
