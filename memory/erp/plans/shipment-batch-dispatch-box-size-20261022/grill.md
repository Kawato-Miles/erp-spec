# 出貨單子母表、批次拋單與裝箱長寬高 grill 拍板紀錄（2026-10-22）

目的：出貨單與物流單的三項延伸需求。
- 列表以子母表呈現出貨單（主層）與物流單（子層）。
- 出貨單可批次拋送底下的物流單，單筆物流單也可各別拋送。
- 裝箱明細加長、寬、高，依箱規自動帶入，可選自訂。

前案：[[出貨單裝箱資料與物流單拆分 grill]]（正本 `memory/erp/plans/_archives/2026/shipment-logistics-split-20261020/grill.md`，G1～G36）。本檔序號接續前案。
本檔只記拍板結果，供後續 plan-design、plan-audit、wiki-amend 承接。
變動性質：局部變動（只動出貨單模組，不新增實體、不動狀態列舉）。稽核走單一稽核者完整 rubric。

## 六、pre-check 後補答（2026-10-22）

pre-check 稽核（precheck.md 第六節）列出 grill 未答的問題，回 grill 補答如下。

| 序 | 題目 | 拍板 |
|---|---|---|
| G48 | 長寬高的用途 | ERP 留存供每月對帳；業務向客人說明這次有幾箱、每箱多大，讓自取客人評估怎麼載走；不送物流商（事實：順豐建單介面可帶每件長寬高但選填，EC 現行未送） |
| G49 | 離廠後裝箱資料的鎖法 | 任一筆物流單離廠後：還在已裝箱的物流單底下的箱子可修改（箱規、長寬高、照片、備註）；可新增箱，系統依拆單規則產生新的已裝箱物流單；不可刪箱，改走作廢物流單；不可改揀貨數量；修正原因照舊必填（修正 G18）。理由：刪箱時系統不知箱內數量，須經作廢物流單填未送達數量，送達數量才守恆；新增箱只是重新分裝，揀貨數量不變。支援子母單的方式只有一筆物流單，依物流單鎖與全鎖結果相同 |
| G50 | 物流商收不了的箱子 | 系統不擋不提示；由物流商拋單拒收，依 G38 顯示錯誤，揀貨人員依 G49 改箱規後重拋 |
| G51 | 批次拋單結果呈現 | 規格不綁同步或背景；處理中的物流單標示「拋單處理中」（標示，非新狀態），處理完成前不能再拋；失敗的物流單保留最近一次失敗訊息，拋單成功或作廢後清除（修正 G32「不存失敗原因」）。補註：拋單預期即時完成，處理中標示是防重複的保護（事實：EC 批次拋單為背景逐筆執行） |
| G52 | 其餘細節 | 批次拋單＝對多筆物流單各執行一次既有拋單，不另設批次操作與批次紀錄，每筆物流單照舊記拋單紀錄；選自訂時箱規欄存「自訂」，對帳看長寬高；長寬高一律選填（含自訂與沒有尺寸的箱規），改成沒有尺寸的箱規時清空（修正 G43、G44 的必填）；箱規主檔維持系統設定、不開維護活動、本次不做停用與刪除 |
| G53 | 批次拋單鈕顯示 | 第三方物流出貨單一律顯示，不依物流單狀態或筆數判斷；無法拋單時按下擋下並說明理由：還沒完成裝箱回報、物流單都已拋過、揀貨不符未解除、訂單已取消（修正 G45 顯示條件與 G52 隱藏規則；本條只適用批次拋單，不改「階段未到直接隱藏」通則） |

## 七、plan-audit 第一輪後拍板（2026-10-22）

| 序 | 題目 | 拍板 |
|---|---|---|
| G54 | 離廠後新增箱的時點 | 只在本單還有箱子沒寄出時可新增；全部寄出、已送達、已作廢後隱藏（判斷依據由 G55 改寫） |

| G59 | 拋單處理中（取代 G51） | 拋單（單筆或批次）當下顯示處理中畫面，期間操作者不能做其他操作；逾時視為該筆失敗，物流單停在原狀態；處理中畫面結束後逐筆列出成功與失敗及錯誤訊息，不另存欄位（回到 G32 原意）；處理中畫面樣式參考其他模組。不設「拋單處理中」標示，第 22 題停用表撤銷。先例：發票開立不設處理中狀態，逾時轉開立失敗。逾時後物流商才建單的重複建單風險開 OQ 交後端 |
