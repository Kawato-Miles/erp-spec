# Linear 三層格式改版 grill 拍板紀錄（2026-10-12）

以需求單為試行模組。本檔只記拍板結果；執行計畫見同目錄 `execution-plan.md`。

## Task 票格式

| 編號 | 拍板 |
|---|---|
| T1 | 一張 Feature 配一張 BE、一張 FE，Task 單一歸屬不變 |
| T2 | BE 票：要做什麼、要開的 API（只列資料操作名稱，用 Feature 動作詞）、不用自己做 |
| T3 | FE 票：要做什麼、頁面與控制元件（頁面 → 動作按鈕、對話框、側板、頁籤，只列名稱）、不用自己做 |
| T4 | 不寫新增或調整、新建或加功能標記；不寫規則出處；FE 不寫串哪支 API |
| T5 | Task 票不寫驗收、不寫「這次不做」（歸 Feature 另案處理） |
| T6 | 不附 Prototype 連結、project 不加查找指引；開發看得到 wiki |

規範檔 § 六已依 T1 至 T6 改寫（未提交，等範本、範例一起提交）。

## 需求單範圍用詞（第一段盲測標準答案）

| 用詞 | 定義 |
|---|---|
| 全公司 | 全部需求單，不受其他條件限制 |
| 自己負責或建立 | 接單業務或建立者是本人；後端兩者權限無差別。諮詢轉入的需求單建立者記諮詢 |
| 被分享（檢視） | 以檢視層級分享給本人且未撤銷，只能查看 |
| 被分享（編輯） | 以編輯層級分享給本人且未撤銷；不論本人角色，都能做接單業務能做的事 |

- 被指派不是獨立用詞：指定評估印務主管時系統自動給一份編輯分享，移出名單即撤銷；該分享列在分享成員清單；被指派者能做編輯成員能做的事（照後端）。
- 印務主管等角色看全公司需求單：照 2026-09-23 拍板，後端待改（QR-015）。
- 以上裁決推翻 Prototype、印務主管角色卡、PM-1207／1215／1338 的既有寫法，需先修上游。
