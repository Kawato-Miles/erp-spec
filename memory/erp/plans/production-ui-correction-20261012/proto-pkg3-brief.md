   - 每條出貨明細新增 `picked_qty`（揀貨數量）、`per_box_qty`（每箱幾個）。已裝箱回報的單（SH-2026-0601、SH-2026-0602）明細照原值填（0601：picked_qty 3000、per_box_qty 500；0602：2000、500）；未回報的為 null。
   - 出貨單層保留 `boxes`、`box_spec`、`packing_photos`、`weight_kg`；`tracking_no` 欄位代號沿用，中文名改「物流單號」。
   - 新增 `packing_corrections`（裝箱回報修正紀錄，空陣列）與 `history`（歷程）。已出貨的兩張補歷程事件：建立出貨單、開始揀貨、裝箱回報、出貨確認、送達確認，各帶時間、操作人、事件、前後值（狀態變化）、附件（裝箱照片、送達憑證），時間與人員取自 mock 既有欄位。
2. MOCK-DATA-CHAIN 出貨段落同步說明：揀貨數量與每箱幾個逐條記在明細；不符判定；拋單即由系統生成物流單號（模擬物流商回傳）；歷程事件類別。
3. 檢查所有讀 `actual_qty`、`per_box_qty` 的地方（store、頁面、訂單詳情、印件等）改讀明細。

### B. 出貨單檢視與編輯改為對話框（grill 22）

1. 出貨單的「檢視」與業務「編輯」改開對話框（取代 `ShipmentDetailDrawer` 側板），版型比照工單的新增生產任務對話框（`TaskFormDialog.js`）。
2. 上方固定單頭（不分頁）：出貨單編號、所屬訂單與客戶、出貨方式、物流單號、出貨單預計出貨日、實際出貨日、收件人與電話、收件地址、寄件資訊、裝箱指示、備註、建單人；狀態標籤放標題列。
3. 下方兩個分頁：
   - 「出貨明細」：明細表欄位依序為完稿縮圖（固定左）、印件、出貨數量、揀貨數量、每箱幾個；表下方包裝區：箱數、箱規、重量、裝箱照片（縮圖）。業務編輯時沿用既有可編輯欄位與檢核。
   - 「歷程」：時間軸，新到舊；呈現方式沿用生產管理既有的歷程元件寫法（就地組，不跨模組 import；若必須共用元件，停下回報）。
4. 原側板的「進度」頁籤（裝箱回報、出貨確認、送達確認、異常或作廢理由五區）拿掉，內容改由歷程與單頭呈現。

### C. 裝箱回報與裝箱回報修正（grill 18、23、24、29）

1. 「裝箱回報」對話框改為逐條明細填揀貨數量與每箱幾個（不預填），再填箱數、箱規、裝箱照片。
2. 新增「修正」列上鈕與對話框內入口（揀貨人員、待出貨、已有裝箱回報才渲染）：可修正明細的揀貨數量、每箱幾個，出貨單的箱數、箱規、裝箱照片；修正原因必填；每個被改的欄位記一筆裝箱回報修正紀錄（照片欄留修正前照片），並寫入歷程。
3. 運送中以後不渲染修正鈕。

### D. 揀貨不符擋出貨（grill 32、36）

1. 任一條明細揀貨數量 ≠ 出貨數量即不符。不符未解除前，拋單、出貨確認、交付確認的列上鈕不渲染（依「用不到的鈕直接隱藏」；若現行寫法是送出時擋，改為不渲染並在列上顯示「揀貨不符」狀態標籤或欄位）。
2. 解除：業務改明細數量（未離廠三態，既有），或揀貨人員修正揀貨數量；兩數相符即放行，不另設確認。
3. 出貨單列表加一欄或標籤標示不符（用既有 Tag 元件）。

### E. 拋單與物流單（grill 21、22 補）

1. 第三方物流的「出貨確認」改名「拋單」；對話框拿掉托運單號輸入，保留選填重量。送出時系統生成一組物流單號寫入（格式比照物流商慣例，如 `HCT-` 開頭加數字），單轉運送中、寫實際出貨日。
2. 新增列上鈕「下載物流單」：第三方、已拋單、出貨人員才渲染；點擊下載一個示意檔（純文字或 PDF 皆可，內容含出貨單編號與物流單號；不需真檔可用 Blob 產生）。
3. 專車「出貨確認」、自取「交付確認」不變（拿掉手填托運單號的地方若有）。
4. 拋單後可補填重量（比照專車）。

### F. 列表與訂單詳情的縮圖欄

1. 出貨單列表（`qc-shipping/shipments/page.js`）加「裝箱照片」縮圖欄（第一張；無則佔位圖或無值符號）；「實際裝箱數量」欄改為明細揀貨數量的呈現（例如「揀貨／出貨」逐件或不顯示，依你判斷保持可讀，不加總不同印件）；「托運單號」欄改名「物流單號」。
2. 訂單詳情出貨單頁籤（`orders/_components/detail/ShipmentsTab.js`）加「裝箱照片」縮圖欄；「實際裝箱數量」比照列表處理。

### G. 用詞

托運單號→物流單號；實際裝箱數量→揀貨數量；出貨確認（第三方）→拋單；修改裝箱回報→修正。
