# 設計方案：生產與出貨的修正機制統一、數量呈現收斂、出貨明細揀貨下放（2026-10-12，第三版）

依據：[grill.md](grill.md)（第 1～40 題）、[precheck.md](precheck.md)、[audit-r1.md](audit-r1.md)、[audit-r2.md](audit-r2.md)。稽核分級：**結構性變更**（品檢紀錄規則翻案、出貨單欄位層級與子表變動、出貨單新增歷程與轉換條件、跨生產與履約兩領域的修正範圍改寫）。

## 本體

### 一、修正機制統一

**名詞**（新，依據 grill 19 與隱含假設）：**修正**＝對一筆已存在的紀錄改欄位值（數量、原因、備註、照片）；必填修正原因；系統留修正紀錄（修正欄位、修正前、修正後、修正人、修正時間、修正原因；照片欄另留修正前的照片）。取代既有用詞「修改」「更正」。原紀錄標「已修正」。

**責任原則**（grill 36）：每個欄位有負責填寫的角色，只有負責角色能修正該欄位。系統照紀錄上的數字決定行為，不另設確認關卡。填寫內容與事實不符時由填寫者承擔，修正紀錄留下是誰、何時、改了什麼。

**分工句**（沿用並改名）：數字錯用修正、整筆不該存在用作廢（正本 [[報工紀錄]] § 修改與作廢，改名為 § 修正與作廢）。

| 紀錄 | 可修正欄位 | 作廢 | 現況 → 本次 |
|------|----------|------|-----------|
| 報工紀錄 | 生產數量、良品數、不良品數、備註 | 有 | 用詞改名；修正範圍改依入口（見 § 三） |
| 點收紀錄 | 點收數量、備註 | 有（點收紀錄作廢） | 用詞改名；作廢入口由子層移到母層 |
| 轉交明細 | 搬運數量（開始搬運後） | 只能作廢整張轉交單（現況） | 用詞改名 |
| 品檢紀錄 | 通過數量、不通過數量、不通過原因、品檢照片（可補可換，至少留一張） | 不設 | **翻案**：負數沖銷 → 修正原紀錄 |
| 裝箱回報 | 出貨明細的揀貨數量、每箱幾個；出貨單的箱數、箱規、裝箱照片 | 不設 | **新增** |
| 品檢缺口處置紀錄（[[印件]]） | 處置數量、瑕疵品去向（執行者 [[印務]]） | 不設 | **翻案**：「決策後留痕、不可修改」→ 可修正（grill 39）；不另設補做限制；擋下：修正後報廢類處置合計不得超過不通過累計（未處置缺口不為負，與新增處置的現況檢核同一條） |

品檢紀錄不設作廢：現況也沒有；判定錯誤用修正重新分配即可，不另開機制（沿用優先）。

**併發**：凡是會動到同一印件待驗量、同一印件可出貨額度、同一張出貨單不符判定的寫入（報工與其修正、作廢；點收與其修正、作廢；品檢驗收與修正；出貨單建立、明細增減、作廢；裝箱回報與其修正；拋單或出貨確認），比照 [[報工規則]] 既有寫法：先寫入者成立，後到者以寫入當下的數字重新檢核。

### 二、品檢紀錄修正規則（翻案 C3、C4、C5）

| 規則 | 內容 |
|------|------|
| 執行者 | [[品檢人員]]，在品檢站的品檢紀錄表上修正（grill 27）。品檢站現況已列出「本週期已有品檢紀錄」的印件，驗完的件仍可找到 |
| 總數上限 | 修正後該筆通過＋不通過 ≤ 本筆原通過＋本筆原不通過（grill 33）。新到的量一律新增一筆驗收 |
| 通過下限 | 修正後該印件通過累計 ≥ 該印件未作廢、非異常出貨單的出貨明細數量合計（含未離廠；grill 20、28） |
| 不通過下限 | 修正後該印件不通過累計 ≥ 已報廢類處置數量合計。沿用 [[印件]] 現況定義「未處置缺口＝不通過累計 − 報廢類處置合計」，使未處置缺口不為負。補做是承接標記，不參與數量判定（[[生產任務]] 補做來源欄） |
| 擋下訊息 | 命中通過下限時列出佔用的出貨單編號與數量；命中不通過下限時列出報廢類處置紀錄；新增驗收被待驗量擋下時提示先確認上游報工 |
| 不通過原因 | 一筆一個原因；修正時選主要原因（grill 34）。不通過數量修正為 0 時原因清空 |
| 揀貨發現瑕疵 | [[揀貨人員]] 照實填揀貨數量（出現不符）→ [[揀貨人員]] 現場通知 [[業務]] → [[業務]] 轉 [[印務]] → [[印務]] 判定為瑕疵後，[[業務]] 改出貨明細數量 → [[印務]] 請 [[品檢人員]] 修正改判不良（沿用正本轉介鏈；順序由通過下限強制）。找不到的量同樣走這條路，不通過原因選「數量不足／缺件」 |
| 照收 | [[印務]] 決定照收後請 [[品檢人員]] 修正，不通過改為通過。若印務先前誤記報廢，先修正處置紀錄（報廢改照收），品檢修正才不會被不通過下限擋下 |
| 累計 | 通過與不通過累計取各筆修正後的值；不再有負數紀錄 |

### 六、出貨單結構與轉換條件（翻案 C6、C7、C8）

| 層級 | 欄位 | 變動 |
|------|------|------|
| 出貨單（單頭） | 既有出貨資訊欄位；托運單號改名**物流單號** | 物流單號由物流商回傳寫入，不手填 |
| 出貨單（包裝） | 箱數、箱規、裝箱照片、重量 | 實際裝箱數量、每箱幾個移出 |

| 歷程紀錄 | 建立出貨單、編輯、開始揀貨、裝箱回報、裝箱回報修正、拋單或出貨確認、交付確認、送達確認、異常、作廢、狀態變化；每筆記時間、操作人、事件、前後值、附件 | 新增欄，比照 [[生產任務]] § 歷程紀錄 |

**揀貨不符（新轉換條件，grill 32）**：任一條明細「揀貨數量 ≠ 數量」即不符。不符未解除前，擋下拋單、出貨確認、交付確認，提示「揀貨數量與出貨明細不符」；出貨單列表標示不符。解除方式：
1. [[業務]] 改出貨明細數量（未離廠三態，現況）。
2. [[揀貨人員]] 裝箱回報修正揀貨數量。

兩條解除方式依責任原則：業務只改明細數量，揀貨人員只修正揀貨數量，兩數相符即放行，不另設確認。現況的不符處置規則（[[出貨單狀態]]：系統外通知業務、業務改明細或作廢）保留。業務在待出貨改明細時，現場照新數量重裝，揀貨人員照實修正揀貨數量。

**裝箱回報修正**：比照品檢修正，修正紀錄保留修正前照片，出貨單標「已修正」。

**拋單（grill 21、22 補）**：第三方的出貨確認改名拋單；拋單時出貨人員選填重量，拋單後可補填（比照專車）；系統寫入實際出貨日（SHP-020 部分拍板）；物流單號與物流單由物流商回傳。SHP-020 拍板前，拋單失敗的相關行為不進 propose。

**「物流單號」「物流單」名詞依據**：SHP-020 部分拍板「托運單號改由物流商回傳」；grill 21、22 補用詞。
