# 設計方案：印務印件檔案與檔案備註搬到印件層

分級：局部變動（生產執行、印前審稿兩領域內搬兩個欄位，不新增實體、不動狀態機、不新增角色）。
前置：erp-planning-pre-check 已跑（2026-09-24，量化矩陣已涵蓋 17／待修補 4／OQ 4）；grill 拍板見必含段④。

---

## 一、問題

| 項目 | 現況 | 問題 |
|------|------|------|
| 欄位歸屬 | 印務印件檔案與檔案備註是 [[工單]] 的欄位 | 一個印件有多張工單時，每張工單各一份。印務在印刷工單上傳的參考檔，裝訂工單看不到 |
| 權限 | 只有該張工單的負責人與編輯（代理）成員能改 | 同一印件的其他工單負責人與印務主管不能補件 |
| 狀態 | wiki 已寫「不依工單狀態設限」，但印件狀態、已取消工單的負責人、產生新印件時是否帶入都沒定義 | 交付撰寫者反覆把這些列為另案 |
| 上限 | 沒寫 | 撰寫者反覆列為另案 |

## 二、設計本體

### 2.1 欄位變動

| 實體 | 動作 | 欄位 | 內容 |
|------|------|------|------|
| [[印件]] | 新增 | 印務印件檔案 | 印務製作期間上傳的稿件檔案，供工廠製作參考。一個印件一份清單，旗下每張工單都顯示同一份。可多檔。與審稿檔案完全分開：不是審稿輪次的檔案、不改變審稿結果與當前合格輪次、不改變工單建立時鎖定的完稿縮圖與審稿後檔案。不隨工單單據列印 |
| [[印件]] | 新增 | 檔案備註 | 印務對這份檔案清單寫的內容說明。一個印件一則，不是每個檔案一則 |
| [[工單]] | 刪除 | 印務印件檔案、檔案備註 | 改由工單詳情顯示所屬印件的值 |

### 2.2 規則

| 規則短名 | 內容 | 依據 |
|---------|------|------|
| 可維護者 | 該印件任一張工單的負責人、該工單編輯（代理）層級的分享成員，以及印務主管，可以新增、移除檔案與修改檔案備註 | grill 第 2 題；角色組合比照製程說明與品檢需求，狀態限制不同（grill 第 20 題） |
| 不設狀態限制 | 不依工單狀態、也不依印件狀態設限；已取消工單的負責人與編輯成員仍算可維護者 | 09-23 拍板；grill 第 15、16 題 |
| 其他人唯讀 | 可維護者以外、看得到這張工單的人，看得到檔案與備註，不能改 | grill 第 2 題的反面 |
| 顯示位置 | 只在工單詳情頁顯示；印件詳情頁不顯示 | grill 第 3 題；沿用 09-04 裁決 |
| 不設上限 | 檔案數量、單檔大小、格式、備註字數本階段不設上限 | grill 第 4 題 |
| 產生新印件不帶入 | 打樣後稿件問題棄用重建、加開印件時，新印件的這兩欄從空白開始 | grill 第 17 題 |
| 獨立於審稿檔案 | 是印件自己的欄位，不屬於審稿輪次與印件檔案（PrintItemFile） | grill 第 18 題 |
| 工單單據不附 | 工單單據附完稿縮圖，不附印務印件檔案；工廠看完稿縮圖了解成品 | 09-23 拍板 |
| 外部廠商可視範圍 | 併入 [[PT-057-門戶可視範圍與稿件保密邊界]]，本案不定 | grill 第 14 題 |

「看得到這張工單」沿用 [[單據分享與職務代理]] 的工單可見範圍，本案不重定。

## 必含段③ 情境分類表

| 分類 | 情境 | 走法 |
|------|------|------|
| 主情境・系統內 | 印刷工單負責印務上傳燙金位置圖並寫備註；裝訂工單負責印務打開工單詳情看到同一份 | 可維護者規則＋工單詳情顯示所屬印件的值 |
| 主情境・系統內 | 印務主管替缺席的印務補上參考檔 | 可維護者含印務主管 |
| 主情境・系統內 | 印件已送達後，印務補上下次追加要參考的檔 | 不設狀態限制 |
| 邊界情境・系統內 | 同一印件的兩位負責印務，一位移除了另一位上傳的檔 | 不區分上傳者（grill 第 2 題否決選項 C「只有上傳者本人能移除」）；其他可維護者看得到並可重新上傳 |
| 邊界情境・系統內 | 裝訂工單被取消後，原負責印務仍需補檔 | 已取消工單的負責人仍算可維護者 |
| 邊界情境・系統內 | 打樣後稿件有問題，棄用重建新印件 | 新印件從空白開始；舊檔留在舊印件，舊印件的工單詳情仍看得到 |
| 邊界情境・系統內 | 同一印件之後新開工單（打樣 NG 製程問題重打、售後補做、外包大貨 NG 另開），新工單看得到原有的檔案與備註 | 欄位在印件層，新工單詳情顯示所屬印件的值；這是本案預期行為，和改版前每張工單各一份不同 |
| 邊界情境・系統內 | 可維護者甲寫的檔案備註，被可維護者乙改寫 | 一個印件一則備註，最後一次存檔為準；不記錄改寫者（隱含假設 3），其他可維護者看得到並可再改 |
| 邊界情境・系統內 | 印件唯一的空草稿工單被刪除，檔案暫時沒有入口 | 印務主管加開工單後，新工單詳情再度看得到並可維護 |
| 邊界情境・系統外 | 工廠需要看成品樣貌 | 誰做：印務或生管列印工單；照什麼：工單單據附完稿縮圖；資料回系統：不需要，工廠只讀 |
| 不支援 | 外部廠商在派單或門戶上看印務印件檔案 | 併入 PT-057 待裁決 |
| 不支援 | 在印件詳情頁看印務印件檔案 | grill 第 3 題裁定不顯示 |

## 必含段④ grill 拍板紀錄

| 題 | 問題 | 拍板 | 理由 |
|----|------|------|------|
| 09-23 | 工單結束後能不能改 | 先不擋，檔案與備註都可以改 | 製作結束後仍可能要補件或補說明，鎖住只會逼出系統外補洞 |
| 09-23 | 工廠怎麼拿到這些檔案 | 工單印出時附預覽圖，工廠看預覽圖了解成品；不開 OQ | 完稿縮圖已隨工單印出 |
| 1 | 檔案備註是一張工單一則還是每檔一則 | 一則；且不是跟工單，是跟印件，同印件多工單都看得到 | 稿件檔案是跟著印件的 |
| 2 | 搬到印件後誰能改（選項 A：任一工單負責人或編輯成員＋印務主管；B：同 A 但不含印務主管；C：只有上傳者本人能移除自己上傳的檔，其他照 A） | A | 角色組合與製程說明、品檢需求一致；C 要記錄上傳者，超出需求範圍，否決 |
| 3 | 在哪些頁面出現 | 只在工單詳情頁，印件詳情頁不顯示 | 需求是多工單看得到；印件詳情顯示屬未提出的需求 |
| 4 | 數量、大小、格式、字數要不要設上限 | 本階段不設上限，wiki 明寫 | 沒有實際問題需要門檻；寫明可免交付文件重複列另案 |
| 5 | 走哪條流程 | 局部變動，走新規劃流 | 只搬兩欄，不新增實體與狀態機 |
| 6～13 | （同一輪 grill 的其他議題：需求單規格同步、Linear 交付規範細節，與本設計無關，不列） | — | — |
| 14 | 盤點的待確認項怎麼處理 | 現在逐題問；外部廠商可視範圍併入 PT-057 | 前三項會直接改變印件卡寫法 |
| 15 | 印件終態後能不能改 | 印件任何狀態都可以改 | 與不依工單狀態設限同一理由 |
| 16 | 已取消工單的負責人算不算 | 算 | 不因狀態擋人；改錯時其他可維護者看得到也改得回 |
| 17 | 產生新印件要不要帶入 | 棄用重建與加開印件都不帶入 | 新印件通常代表稿件或規格變了，舊參考檔最可能過時 |
| 18 | 算審稿檔案的一種還是印件自己的欄位 | 印件自己的欄位，與審稿檔案完全分開 | 這批檔案存在的理由就是不動已合格的審稿結果 |
| 19 | 檔案備註要不要改名 | 先不改名 | — |
| 20 | 「和製程說明同一套權限」指什麼（甲：只指角色組合相同，狀態限制各自不同；乙：製程說明與品檢需求也改成不設狀態限制） | 甲 | 補件不該被擋對參考檔成立；製程說明會印在紙本工單上，鎖定有其理由；乙會擴大範圍到已結案功能 |

### 隱含假設（設計者自補，Miles 未明說）

| # | 假設 | 依據 |
|---|------|------|
| 1 | 「看得到檔案與備註」的範圍，等於看得到該印件任一張工單的範圍 | 顯示位置只在工單詳情，看得到工單詳情才看得到 |
| 2 | 印件層不另設分享機制，編輯（代理）層級沿用各工單自己的分享成員 | 比照製程說明前例 |
| 3 | 不記錄每個檔案的上傳者，也不記錄檔案備註的改寫者 | wiki 未要求；單據分享情境卡寫明工單操作者留痕只記在異動紀錄與報工紀錄 |
| 4 | 印件棄用後欄位保留、仍可修改 | 由「印件任何狀態都可以改」推得 |

## 必含段⑤ 守恆段

本案涉及的量只有「印務印件檔案的檔案數」，不涉及金額、數量、庫存、產能與工時。

| 量 | 等式 | 上升方向 | 下降方向 |
|----|------|---------|---------|
| 印件的印務印件檔案數 | 目前檔案數 ＝ 累計上傳數 − 累計移除數 | 可維護者上傳；新印件從 0 開始，不從舊印件帶入 | 可維護者移除；移除只影響該印件，不影響審稿輪次與完稿縮圖 |
