## 三、要做的事

### A. MOCK-DATA-CHAIN.md

1. 品檢段落（約 130 行與 211 行附近）說明文字：「更正紀錄」「代數和」「沖銷」改為修正寫法——品檢紀錄可由品檢人員修正原紀錄，留品檢修正紀錄；累計取各筆修正後的值；修正受品檢修正界線約束（總數不超過本筆原合計、通過累計不低於出貨明細佔用、不通過累計不低於報廢類處置合計）。
2. mock 資料：既有品檢紀錄如有負數或標為更正的紀錄，轉為對原紀錄的修正（原紀錄改值＋一筆品檢修正紀錄）；若沒有，只改文字。品檢缺口處置 mock 若為空，不新增資料。

### B. 品檢站（`qc-shipping/inspection/page.js` 與相關 store）

1. 「補更正紀錄」改為「修正」：品檢紀錄列上的修正鈕開對話框，預填原值，可改通過數量、不通過數量、不通過原因、品檢照片（可補可換、至少留一張），修正原因必填。送出後原紀錄改為新值，新增一筆品檢修正紀錄（修正欄位、修正前、修正後、修正人、修正時間、修正原因、修正前照片）。
2. 檢核（命中整筆擋下，數字不改）：
   - 總數上限：修正後通過＋不通過 ≤ 本筆原通過＋原不通過。擋下訊息提示新到的量請另按驗收。
   - 通過下限：修正後該印件通過累計 ≥ 該印件未作廢、非異常出貨單的出貨明細數量合計。擋下訊息列出佔用的出貨單編號與數量。
   - 不通過下限：修正後不通過累計 ≥ 該印件報廢類處置數量合計。擋下訊息列出報廢類處置紀錄。
   - 不通過數量修正為 0 時，不通過原因清空。
3. 品檢紀錄表最左兩欄固定：「完稿縮圖」「品檢照片」（第一張；無預覽網址顯示佔位圖），點開看那一張。原「照片」檔名欄拿掉。
4. 修正過的紀錄可看到修正紀錄（例如展開列或修正鈕旁的歷程），呈現方式沿用既有頁面元件；修正過的紀錄不另加「已修正」欄（wiki 定義：有修正紀錄即視為已修正）。
5. 新增驗收被待驗量擋下時，訊息加「請先確認上游報工」。
6. 移除負數沖銷的寫法與相關驗證（更正紀錄至少一欄不為 0、代數和不低於 0 等）。

### C. 印件詳情品檢頁籤（`print-items/_components/detail/QcTab.js` 與 store）

1. 歷次品檢紀錄表加「品檢照片」縮圖欄（同一件印件，不加完稿縮圖），固定最左；原「照片」檔名欄拿掉。修正過的紀錄同樣看得到修正紀錄。
2. 品檢缺口處置：印務可對既有處置紀錄按「修正」，可改處置數量與瑕疵品去向，修正原因必填，新增一筆處置修正紀錄。檢核：修正後報廢類處置合計不得超過不通過累計（處置修正界線），命中整筆擋下。不另設補做限制。「缺口是否補做」與處置備註不在可修正欄位內。
3. 誤記報廢後要照收的路徑：印務先修正處置紀錄（報廢改照收），品檢人員再修正品檢紀錄把不通過改通過。

本包涉及畫面：更正→修正、補更正紀錄→修正、現場照片→報工照片（若有）。一般語意「修改」不改。
