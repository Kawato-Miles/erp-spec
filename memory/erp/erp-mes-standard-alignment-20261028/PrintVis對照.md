# 現況對 PrintVis 式最佳實踐的對照（2026-10-29）

來源：`raw/2026-10-29-claude-research-PrintVis承接印刷業務範圍的覆蓋與導入方法.md`（95 條外部來源，主對話抽查 13 條相符）。本檔只做對照，不寫設計。括號內「來源 N」對應該 raw 卡的來源編號。

PrintVis 是建在 Microsoft Dynamics 365 Business Central（下稱 BC）內的印刷管理資訊系統。下表標【PrintVis】的是 PrintVis 自己的功能，標【BC】的是 BC 標準功能。

## 一、PrintVis 有沒有我們各段的場景

| 我們的範圍 | PrintVis 或 BC 承接 | 程度 | 備註 |
|---|---|---|---|
| 線下接單、報價、成交轉訂單 | 【PrintVis】案件（Case）、估價、狀態碼；【BC】商機 | 完整 | PrintVis 有自己的報價系統，取代 BC 銷售訂單（來源 2）。報價轉訂單時保留報價行、新增訂單行，版本號加一（來源 18） |
| 線上電商（規格品、題目選項） | 【PrintVis】Web2PV 訂單匯入介面 | 部分 | 只有訂單匯入介面，沒有網店本身。網路可選的產品群組、格式碼、後加工類型要勾旗標（來源 16）。「選項綁材料、工序、設備」官方頁沒寫 |
| 諮詢服務 | 無 | PrintVis 無此場景 | 製前訂單是不涉及印刷的案件，不是諮詢服務（來源 34） |
| 訂單、印件 | 【PrintVis】案件、工作（Job）、工作項目（Job Item） | 完整 | 工作號碼是一個獨立產品；工作項目是產品組件的技術定義（來源 18、44）。這與我們「訂單明細兼產品定義」同向 |
| 稿件審稿、打樣 | 【PrintVis】製前訂單加 JDF 對接 Esko | 部分 | 步驟頁面沒寫（來源 34） |
| 品項主檔、工序與裝訂主檔、設備與產線、配方 | 【PrintVis】成本中心、組態、計算單位；【BC】品項表 | 完整，以 PrintVis 方式取代 BC 製造 | 估價取代 BC 的製程路線與物料清單（來源 2） |
| 工單與生產任務、派工、報工 | 【PrintVis】規劃單位、產能單位、電子工單 | 完整 | 排程到產能單位；派給個人官方頁沒寫（來源 30、53） |
| 場內轉交與點收 | 【PrintVis】生產標籤 | 近似，無同名流程 | 標籤隨件在成本中心間移動，掃描標記消耗（來源 54） |
| 外包派單 | 【PrintVis】虛擬品項加採購引導；【BC】採購單 | 完整 | 發票過帳後成本進工作成本（來源 8） |
| 成本計算 | 【PrintVis】工作成本三層（報價、訂單、實際） | 完整 | 工時 = 時數 x 成本中心時薪；沒有獨立機台費率（來源 20、50） |
| 在製品 | 【PrintVis】生產標籤（實體）；WIP 日記帳（會計） | 完整 | 實體在製品不入庫存帳；會計面有四種方法（來源 28、54） |
| 品檢 | 【PrintVis】品質保證檢核表 | 部分 | 只有檢核表，沒有檢驗批、抽樣、不合格處置（來源 14） |
| 完工入庫 | 【PrintVis】釋出成品（選配） | 完整但選配 | 官方說接單生產公司通常不用（來源 3、21） |
| 出貨、物流、送達 | 【PrintVis】出貨卡；第三方 nShift、EasyPost | 出貨完整；物流部分 | 送達確認官方頁沒寫（來源 23、41） |
| 售後服務單 | 【PrintVis】客訴登記 | 部分 | 有客訴碼與貸項，沒有獨立服務單與狀態機（來源 10、11） |
| 補做 | 無專用流程 | PrintVis 無此場景 | 近似工具：額外工作碼、複製案件（來源 12、13） |
| 收款、發票、對帳、退款 | 【PrintVis】組發票內容；【BC】銷售發票、收款、對帳 | 開發票完整；收款與對帳靠 BC；退款只見客訴貸項 | 台灣統一發票未查（來源 6、27） |

結論：PrintVis 完整承接按單生產廠的估價、排程、報工、工作成本、外包、出貨。審稿打樣、諮詢服務、補做、獨立售後服務單，PrintVis 沒有完整場景。庫存、採購、發票、收款、對帳是 BC 的功能（來源 2、3、27）。

## 二、導入夥伴做法對我們現況的落差

PrintVis 官方沒有公開的導入階段表，也沒有夥伴問客戶的問卷清單。下表混用 PrintVis 官方設定導引、夥伴 Sabre Limited 的公開頁面、Microsoft 的通用導入指南。

| 顧問會做的事 | 來源 | 我們現況 | 落差 |
|---|---|---|---|
| 先做 fit-to-standard：用流程目錄比對標準流程，每個專案都做，再配置，之後才做 fit-gap | Microsoft（來源 85） | 先以業務情境卡與 grill 對齊需求，再設計 | 我們沒有「標準流程目錄」可比，但有情境卡可當比對基準。無結構落差 |
| 「盡量採用標準，只在有理由時調整」；不複製舊系統 | Microsoft（來源 85、87） | 自行設計，不套用現成產品 | 不適用。我們是自建，沒有「標準」可採用；可借鏡的是「不為了照搬舊流程而設計」 |
| 先建主檔再建交易：部門、成本中心、費率、品項、設定套件，依序 | PrintVis 官方（來源 64） | 規劃從訂單層往生產層推，主檔層（品項主檔只有原物料）最後補 | 順序相反。PrintVis 先決定部門結構再設成本中心，成本中心費率決定估價準確度（來源 69、70） |
| 部門結構先拍板，再設成本中心 | PrintVis 官方（來源 70） | 產線下設站點，站點與設備已建模 | 對應的是「資源層級先定」。我們已有，無落差 |
| 計算單位先於估價建好；工序行與品項行同在一個單位 | PrintVis 官方（來源 22、67） | 配方是製法範本，用量只作參考 | 見第三節「估價與配方」 |
| 用樣本工作驗證估價 | 官方未寫；Microsoft 通用做法是系統整合測試與使用者驗收測試各測一次遷移（來源 88、90） | Prototype 親身試用，無真實資料樣本重算 | 與 Salesforce 對照結論同：沒有拿真實品項跑過配方展開與成本 |
| 登記粒度要與估價計量單位一致，否則看不到逐作業差異 | PrintVis 官方（來源 20） | 成本以報工數量重算計價快照 | 我們也要先定粒度。報工的數量單位與工序計價單位是否一致，沒有一句話宣告 |
| 模擬切換、回退計畫、上線與否的決策標準 | Microsoft（來源 82、89） | 無上線流程（現階段 Prototype） | 待上線階段 |
| 資料遷移：配置資料與遷移資料分開，載入順序與相依寫成策略 | Microsoft（來源 88） | 無舊系統資料遷移規劃 | 待 Phase 規劃 |
| 夥伴套件分級：有無製造與成本分析、有無倉儲、有無 JDF、有無客製 | Sabre（來源 56） | 範圍已由 grill 拍板 | 無落差。分級判準可當第一版範圍檢核項 |
| 流程對齊與乾淨遷移資料是成敗關鍵 | Sabre 文章（來源 39） | 有情境卡與服務藍圖 | 無落差 |

## 三、生產段最佳實踐對我們現況的逐項對照

### 品項與工作

| PrintVis 做法 | 我們現況 | 落差或可借鏡 |
|---|---|---|
| 成品品項是選用。官方明說商業印刷或接單生產不需要成品品項，可不用任何 BC 品項就出貨與開票（來源 3） | 品項主檔現階段只收原物料，無成品與半成品品號 | 同向。PrintVis 的按單生產做法也不建成品品號 |
| 重複生產的成品可建成品品項當範本載體，指向範本案件（來源 3） | 再下單靠印件複製 | PrintVis 的做法只在重複生產時才建品項。接單生產占多數的我們，是否需要品號層取決於 EC 規格品比例（推論） |
| 半成品沒有專屬品號，以生產標籤追蹤（來源 54） | 半成品品號無；生產任務的印件部位是文字欄 | 同向 |
| 紙張、油墨用 BC 品項放寬、長、重量與「庫存單位、價格單位」兩套單位，自動換算（來源 3、24） | 品項主檔有計價方式、採購與銷售單位 | PrintVis 換算例：估價用公斤、庫存用張（來源 24）。我們沒有庫存單位，沒有此換算需求 |
| 產品定義在工作加工作項目（印張、組件、頁數、色數、拼版、紙張），不在品項（來源 44） | 印件承載產品定義 | 同向 |

### 估價與配方

| PrintVis 做法 | 我們現況 | 落差或可借鏡 |
|---|---|---|
| 估價是報價、建立訂單、規劃生產的共同來源（來源 46） | 計價快照在報價與生產各凍結一次 | 同為「一份資料多處取用」。PrintVis 的估價直接產生規劃單位，我們的配方展開不預填數量日期（見比對矩陣） |
| 計算單位含工序行（時間）與品項行（材料），用公式算數量或時間（來源 22） | 配方分部件配方與印件配方，工序與材料同段，用量只作參考 | 用量的角色不同：PrintVis 的用量進成本與材料需求，供採購使用（來源 24）；我們的用量不驅動成本與採購 |
| 公式掛在成本中心組態與計算單位，速度表、損耗表、價目表在組態內（來源 66、68） | 算式掛在主檔項目的計價方法（材料、工序、裝訂、設備各自算法） | 相近。兩邊都把算法放在資源主檔 |
| 估價取代 BC 的製程路線與物料清單，不需 Premium 授權（來源 2） | 部件配方合併承載物料清單與製程路線 | PrintVis 也是「一份結構承載兩者」。官方沒有正式把計算單位對應為物料清單（來源 22） |
| 估價複製不套用現行費率，需重算（來源 12） | 計價快照凍結預估 | 同向 |
| 估價變更後規劃單位怎麼處理，官方頁沒寫（來源 30） | 異動流程有定義 | 無可借鏡處 |

### 工單與報工

| PrintVis 做法 | 我們現況 | 落差或可借鏡 |
|---|---|---|
| 工作是案件內的產品單位，不是 BC 生產單；BC 標準製造是另購選配（來源 31、56） | 印件、工單、生產任務三層 | PrintVis 沒有獨立「工單」物件。規劃單位由計算單位翻譯而來，是它最接近生產任務的東西（來源 52） |
| 報工：電子工單開始、停止計時；產出數量附在工時登錄上；可即時過帳或交他人核准（來源 19、53） | 報工紀錄記良品、不良品、原因、照片 | PrintVis 的產出數量不分良品與不良品欄位（頁面只列已生產量，來源 19）；我們分得更細 |
| 工時與耗料登在消耗日記帳；品項行轉入 BC 品項日記帳（來源 20） | 無庫存，無品項日記帳 | PrintVis 靠 BC 底座才有；我們沒有此層 |
| 案件換到指定狀態碼時自動入帳工時與消耗（來源 51） | 生產任務以報工的良品數累計完成度 | PrintVis 以狀態碼觸發入帳，我們以報工數量累計，觸發方式不同 |
| 生產標籤在成本中心間移動表達在製品；標籤消耗後保留記錄，案件封存時才移除（來源 54） | 轉交單與點收 | 相近。PrintVis 的標籤不入庫存帳 |
| 排程到產能單位行事曆；派給個人官方頁沒寫（來源 30） | 工作包：生管合批派工、指派師傅 | 我們的派工比 PrintVis 公開資料更細 |

### 成本

| PrintVis 做法 | 我們現況 | 落差或可借鏡 |
|---|---|---|
| 三層並列：報價估價、訂單估價、實際工作成本，顯示金額與百分比（來源 50） | 計價快照凍結預估，實際以報工數量重算 | 同向。PrintVis 的三層並列報表是現成呈現方式 |
| 實際成本來源：工時、庫存品項、財務分錄、外包採購發票（來源 20） | 實際成本只含報工重算 | 外包發票進工作成本的時點（發票過帳後）值得對照我們的外包成本回貼時點 |
| 費率只有成本中心時薪與作業專屬時薪，沒有獨立機台費率（來源 20） | 設備計價參數與固定開機損 | 我們的設備層比 PrintVis 公開資料更細 |
| 在製品會計四種方法；成品釋出入 WIP 庫存科目（來源 28） | 無在製品帳、差異科目 | PrintVis 靠 BC 的總帳。我們沒有庫存與總帳，此層無對應 |
| 錯誤成本與客戶額外工作成本各有欄位（來源 50） | 補做走原工單加開生產任務 | 見「外包與重工」 |

### 品檢與入庫

| PrintVis 做法 | 我們現況 | 落差或可借鏡 |
|---|---|---|
| 品檢是檢核表，必填題擋住工作完成或計時（來源 14） | 品檢紀錄掛印件層，有缺口處置 | 我們比 PrintVis 公開資料多了判定與處置；PrintVis 用「擋住下一步」做把關 |
| 釋出成品是選配；接單生產公司通常不用（來源 3、21） | 沒有成品倉；待驗、完工良品、可出貨額度是印件層算出的數字 | 同向 |
| 要入庫時成本取估價、工作成本、品項成本或零值，過帳後不調整（來源 21） | 無入庫 | 無對應 |
| 出貨時可「放入庫存」，背景建銷售訂單（來源 3） | 出貨單、物流單承載出貨，沒有成品倉 | 無對應 |

### 外包與重工

| PrintVis 做法 | 我們現況 | 落差或可借鏡 |
|---|---|---|
| 外包用虛擬品項（不可消耗過帳、庫存值零），經採購引導建採購單（來源 8、42） | 派單承載外包 | PrintVis 用「品項」承載外包成本佔位；我們用派單，不經品項 |
| 外包報價：基本價、每千件加價、固定開辦費，數量變動自動重算（來源 9） | 外包由派單承載 | 外包報價結構是否需要建模，待設計時判斷（推論） |

| PrintVis 做法 | 我們現況 | 落差或可借鏡 |
|---|---|---|
| 製前訂單：不涉及印刷的案件，到客戶打樣核准為止；JDF 對接 Esko（來源 34） | 審稿輪次、打樣 NG 自動建打樣工單 | PrintVis 沒有審稿輪次物件，步驟頁面沒寫。與 Salesforce 同結論：此段 PrintVis 沒有可借鏡的完整做法 |

## 四、這份調研能對 Miles 擔心的生產段說什麼

PrintVis 是比 Salesforce 更接近生產段的對照基準，因為它完整承接按單生產廠的估價、排程、報工、成本、外包。重點有四項。

1. 「缺成品與半成品品號」不是缺陷。PrintVis 官方明說接單生產不需要成品品項，可不用任何 BC 品項出貨與開票（來源 3）。反例：PrintVis 仍用 BC 品項表放紙、版、油墨與外包佔位品，並做單位換算（來源 3、24），所以它不是完全沒有品項層。我們的現況與 PrintVis 在「不建成品品號」上同向。
2. 兩邊真正的差別在「用量」。PrintVis 的計算單位把工序行與品項行放在一起，用公式算數量，用量進估價成本，也進材料需求供採購（來源 22、24）。我們的配方用量只作參考。若將來要讓用量驅動成本或採購，PrintVis 的計算單位是現成的結構參照。
3. PrintVis 的完工與庫存靠 BC 底座。庫存分類帳、在製品會計、差異分析都來自 BC（來源 3、28、58）。我們沒有庫存模組，這層無法照搬。PrintVis 的實體在製品用生產標籤追蹤、不入庫存帳（來源 54），與我們「完工後以印件層數字取代庫存狀態」的精神接近。
4. PrintVis 沒有的場景與 Salesforce 部分重疊：諮詢服務、補做專用流程、獨立售後服務單、審稿打樣步驟。這些場景要靠我們自己設計，查不到可借鏡的 PrintVis 做法。

導入方法端，可借鏡的是「主檔先於交易」的建置順序：部門、成本中心、費率、品項、再到估價（來源 64）。PrintVis 官方與夥伴都沒有公開估價驗證方法，也沒有公開商業分析問卷，這兩項只能靠 Microsoft 的通用導入指南補（來源 85、88、89）。
