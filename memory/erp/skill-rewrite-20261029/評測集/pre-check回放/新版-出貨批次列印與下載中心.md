# 規劃前盤點：出貨批次列印、下載中心、可出貨狀態、出貨動作對話框、第三方物流撤回與作廢

- 盤點日期：2026-11-04
- 依據：`.claude/skills/erp-plan/SKILL.md` 順序第 1 到 5 步、`references/盤點方法.md`、`references/調研判斷.md`
- 需求句（Miles）：出貨人員一天幾十筆托運，物流單檔案只能逐筆或逐張出貨單下載列印，托運總表要另外整理，想做批次列印跟下載中心。出貨單要有一個「可出貨」的狀態讓出貨人員知道哪些能拋單。出貨動作的對話框也要整理，物流單逐筆拋單、出貨確認、送達確認的操作要一致。第三方物流的撤回跟作廢怎麼處理也要定。
- 分級初判：結構性變更。理由：出貨單狀態機要新增狀態（狀態機層級變動）；下載中心可能成為新單據。此判定尚未亮給 Miles，標「初判」。

## 七、調研建議

| 欄 | 內容 |
|----|------|
| 建議 | 要 |
| 理由 | 無參考模型卡（`11-review-knowledge/` 下沒有參考模型目錄）；分級為結構性（初判）；碰守恆量：是（撤回與作廢會動未送達數量與可出貨額度回補） |
| 調研主題 | 出貨作業中「可出貨」狀態、批次列印與交寄清單、背景匯出取檔、物流單取消與攔截退回的業界做法 |
| 建議來源 | SAP S/4HANA 外向交貨單（Outbound Delivery）與延伸倉儲管理（EWM）、Oracle NetSuite 出貨履行（Item Fulfillment）、ShipStation 與 Shopify Shipping 的批次標籤與交寄清單、EasyPost 與 Shippo 的標籤作廢說明、順豐與黑貓的退件攔截說明 |

調研問題：

1. 業界倉儲與出貨系統怎麼定義「可出貨」（待出貨、已揀已包）狀態？進入條件是系統依揀貨相符自動判定，還是人工確認？
2. 可出貨狀態掛在出貨單整張，還是逐包裹或逐托運單？分批交寄時整張單怎麼顯示？
3. 批次列印托運標籤怎麼選範圍（依日期、物流商、出貨單）？已列印過的標籤怎麼標示、怎麼防止重印或漏印？
4. 每日交寄清單（manifest，物流商收件時點交的托運總表）包含哪些欄位？依物流商分開還是合併？誰簽收？
5. 背景匯出與下載中心的常見做法：檔案保留多久、誰能取檔、權限是否沿用原單據？
6. 托運標籤作廢（void）的時限與條件為何？物流商已收件後的攔截退回（intercept、return to sender）怎麼記錄？
7. 撤回或作廢後，庫存或可出貨量在什麼時點回補？貨實際退回前回補，還是退回點收後回補？

調研之後的步驟依 `調研判斷.md` § 三：grill 第一題由 Miles 確認是否調研；同意後經 `vault-ingest` 派 `erp-researcher`。設計者不讀調研結果。
