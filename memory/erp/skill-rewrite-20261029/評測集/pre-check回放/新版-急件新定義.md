# 規劃前盤點：急件重新定義

- 議題：急件重新定義（業務改填出貨日、系統倒推；線上單急件起算；訂單層急件標注；急件判準統一；急件主檔正負號校正）
- 盤點日期：2026-11-04
- 盤點基準：回放環境 wiki（`memory/Sens_wiki/wiki/erp/`）與 `openspec/specs/`；未讀 change、git 歷史、`memory/erp/`
- 用詞對照：Miles 說的「出貨日」，wiki 正式名稱是印件層的「印件預計交期」（客戶看到的寄出或可自取那一天）。「出貨單預計出貨日」是另一個欄位，只是單張出貨單的出貨計畫。本文以下一律用「印件預計交期」。

## 一、涉及領域與載入卡

### 1-1 判領域（第 1 步）

「急件」不在任何領域的觸發詞清單內（零命中）。依 [[business-domain-taxonomy]] § 檢索規約第 1 條，零命中時應先問 Miles。本次回放不等回覆，改用下列初判，標「待 Miles 確認」。

| 領域 | 判入理由 | 判定 |
|------|---------|------|
| 訂單管理 | 印件三個日期欄、訂單層急件標注、訂單日期衍生欄都在本領域 | 主要領域 |
| 售前 | 業務最早在需求單印件項目填日期；急件主檔標本領域 | 涉及 |
| 生產執行 | 工單與生產任務承接印件內部完成日、顯示急件標示；急件主檔標本領域 | 涉及 |
| 印前審稿 | 待審清單的急單標示判準在本領域情境卡 | 涉及 |
| 履約與售後 | 印件預計交期是出貨逾期的基準；出貨單預計出貨日與「出貨日」撞名 | 連帶（只載與日期相關的卡） |
| 款項與發票 | 急件費走訂單其他費用與訂單異動，本議題不改金額 | 不判入整個領域。[[訂單異動規則]]、[[明細時點分界]] 兩張規則卡只標本領域，但承載印件日期改動規則，經關鍵詞掃描命中後個別載入 |

矛盾呈報 A：急件判準

| 出處 | 寫法 |
|------|------|
| [[印件審稿]] § 範圍外待審清單段 | 急單標示取印件的急件選項，「非一般件即標示」 |

- 兩寫法在下列情形結果不同：主檔另有一筆天數 0、名稱不是「一般件」的選項；或「一般件」被改名。
- 兩寫法都會把延後型選項（天數為負）標成急件。延後的印件被標急件，與「急件」字義相反。
- 本盤點不判哪一方對，交裁決二。

| [[審稿分配規則]] | 只在動機段提到業務了解印件預計交期 |
| [[訂單客戶與聯絡資料維護]] | 只指向 [[訂單印件規格維護]] 為改急件選項的去處 |

## 七、調研建議

| 欄 | 內容 |
|----|------|
| 建議 | 要 |
| 理由 | 無參考模型卡：回放環境 `11-review-knowledge/` 下沒有參考模型資料夾，訂單管理、售前、生產執行都沒有對應卡。分級初判為結構性變更（未亮給 Miles）：改變印件準時完工率比對日期的來源（影響 KPI），訂單層急件標注可能新增訂單對急件主檔的關聯，需求單帶入印件的欄位對應改變。碰守恆量初判為否：本議題改日期與判準，不改金額、數量、庫存 |
| 調研主題 | 業界 ERP 與印刷管理系統怎麼定義急件、怎麼從客戶承諾日倒推內部完成日 |
| 調研問題 | 1. 業界 ERP 的訂單明細有哪些日期（客戶要求交貨日、承諾出貨日、物料可用日），輸入哪一個、其他怎麼倒推（逆向排程）？<br>2. 業界怎麼記錄急單：用優先權屬性，還是用「比標準工期縮短幾天」判定？延後交件的選項會不會被算成急單？<br>3. 明細層的優先權怎麼彙總到訂單層（取最高、或訂單自有欄位）？<br>4. 印刷管理系統與線上印刷平台的趕件等級（rush、turnaround）從哪個時點起算：付款、稿件核可，還是下單？標準製作天數掛在商品還是訂單？<br>5. 「增減天數」這類偏移量的正負號，業界慣例是「正數＝提前」還是「直接加到日期上」？ |
| 建議來源 | ISA-95 第 2 部與 B2MML 的生產需求優先權（OperationsRequest Priority）；SAP S/4HANA 銷售模組的交貨排程（Delivery Scheduling）與交貨優先權（Delivery Priority）；Oracle Order Management 的要求日、排定出貨日、到貨日；Odoo 的承諾日與安全前置時間；印刷管理系統 EFI Pace、PrintVis、Tharstern 的交期與急件設定；線上印刷平台的製作天數與趕件選項說明頁 |

- 設計者不讀調研結果；調研結論不寫進 03～07 業務正本卡。
