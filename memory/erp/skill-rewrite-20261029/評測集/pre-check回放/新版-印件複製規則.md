# 規劃前盤點：印件複製規則統一

- 盤點日期：2026-11-04
- 需求句（Miles）：印件複製的規則要統一。訂單複製建單、客戶加做一件（複製加開）、需求單轉訂單、打樣 NG 重建新印件，各自帶入哪些欄位、哪些不帶，寫法散在各卡還互相不一致。想定一套印件複製規則：內容類欄位帶入、歷程與產出類不帶、免審稿之類的例外怎麼處理、數量帳跟品檢紀錄要不要跟著走。
- 讀取範圍：回放環境的 wiki（`memory/Sens_wiki/wiki/erp/`）與 `openspec/specs/`。未讀 `openspec/changes/`、git 歷史、`memory/erp/`。
- 本檔由盤點子代理寫成，第 1、2 步的主對話動作一併記在本檔，不等 Miles 回覆。

### 分級初判（尚未亮給 Miles）

| 項目 | 判斷 |
|------|------|
| 初判 | 局部變動 |
| 理由 | 改的是既有關聯上流動的欄位（需求單到印件、訂單到訂單、印件到印件），不新增實體、不改狀態列舉與轉換 |

### 矛盾呈報 G2：複製加開的帶入清單

| 段 | 內容 |
|----|------|
| 兩邊說法與來源 | 甲：[[訂單印件規格維護]] § 副流程（複製加開）：「印件名稱以外的印件屬性、單位、是否急件、難易度、規格備註、印件配方、出貨方式、包裝備註、預計產線、免審稿、稿件備註」預填，未列單價。乙：OpenSpec order-management § 加開印件：帶入清單含單價、不含出貨方式；業務「可於加開當下改寫印件名稱」。丙：[[印件]] 出貨方式欄：「訂單期間加開的印件預設取 [[訂單]] 的出貨方式」 |
| 商業例子逐個驗算 | 訂單 ORD-2026-0512 製作中，訂單出貨方式＝自取。來源印件名片：單價 100、出貨方式＝第三方物流。業務複製加開一筆，購買數量填 300。甲：單價空白要手填，出貨方式＝第三方物流。乙：單價＝100，小計＝30,000，出貨方式沒寫。丙：出貨方式＝自取 |
| 影響 | 出貨方式有三種結果；單價有「要手填」與「帶入」兩種結果，帶入時應收總額立即多 30,000。影響卡：[[訂單印件規格維護]]、[[印件]] 單價欄與出貨方式欄、規格 order-management。不裁決時，介面與後端各照一份做 |
| 建議 | 以統一規則的「內容類帶入」為準：單價與出貨方式都視為內容類，取來源印件的值。理由：複製加開是「同一款再買一批」，單價與出貨偏好跟著這一款走 |
| 要使用者回答的實務問題 | 同一款再加做一批時，業務實際上會沿用上一批的單價嗎，還是多半要依新數量重談單價？加做那一批的出貨方式，通常跟原印件一樣，還是跟整張訂單一樣？ |

## 七、調研建議

| 欄 | 內容 |
|----|------|
| 建議 | 要 |
| 理由 | 無參考模型卡：`11-review-knowledge/` 下沒有參考模型目錄。分級：局部（初判，尚未亮給 Miles）。碰守恆量：是，數量帳（完成數、待驗量、可出貨額度）與金額（單價、小計、應收總額） |
| 調研主題 | 業界 ERP 與印刷管理系統複製單據時，欄位帶入的控制方式，以及品質與歷程紀錄的處理 |
| 建議來源 | SAP 銷售模組複製控制說明文件；Odoo 開發文件（欄位複製屬性）；Microsoft Dynamics 365 銷售訂單複製說明；印刷管理系統 EFI Pace、PrintVis、Avanti Slingshot 的重複訂單說明；ISO 9001:2015 § 8.5.2 識別與追溯 |

調研問題：

1. SAP 銷售模組的複製控制（copy control）怎麼逐欄定義「報價轉訂單」與「訂單複製訂單」帶入哪些欄位？價格沿用來源還是重新定價（定價類型）？
2. Odoo 與 Dynamics 365 的單據複製，預設不帶哪幾類欄位（狀態、編號、日期、關聯單據、核准紀錄）？判斷依據是什麼？
3. 印刷管理系統處理重複訂單（再印同一款）時，上一次的稿件核准狀態沿不沿用？沿用的前提條件是什麼？
4. 打樣退件要重做時，業界系統開新版本還是開新項目？核准歷程與檢驗紀錄掛在哪一個？
5. ISO 9001 的追溯要求下，複製或重建出的生產對象，是繼承前一對象的檢驗紀錄，還是只以來源關聯指回前一對象？
