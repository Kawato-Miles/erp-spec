## 三、逐處證據

### J1　準時完工率件數下降方向漏「轉已棄用」（隱蔽）

| 項目 | 內容 |
|---|---|
| 為什麼錯 | 已有完工日的印件之後轉已棄用，會移出分母。⑤ 下降方向沒列這條流出 |
| 設計內證據 | 第 142 行 § 五不計入含「已棄用印件」；第 308 行 ① 印件列「印件作廢走既有已棄用，完工日保留、指標排除」 |
| 正本證據 | [[印件印製狀態]]（e2e4e96）第 106 行：「進行中」任何狀態可轉已棄用，觸發含訂單取消連鎖、OP-PI-019 取消製作。製作完成、出貨中都在進行中，這時完工日已寫入 |
| 推演（兩步） | 第 1 步：乙海報 11/08 首次齊套，寫入完工日，進分母。第 2 步：11/12 客戶取消訂單，印件轉已棄用。⑤ 下降方向沒有對應機制，分母等式在這一步失衡 |
| 為何數字看似合理 | 其餘兩條下降機制都對；刪的是一個從句，不是一格 |
| 後果 | 落卡與寫 specs 時漏掉已棄用的排除時點，指標可能把已取消的印件留在分母 |
| 第一份沒有這類的原因 | 第一份六處沒有一處落在⑤守恆段。第一份 J5 是欄位分類錯，稽核靠 1-5 推演抓到，但等式本身沒動 |

### J3　舊列印檔情境改判系統內、刪掉協作要素（隱蔽）

| 項目 | 內容 |
|---|---|
| 為什麼錯 | 舊列印檔是紙本，在出貨人員手上。系統刪舊物流單、留編號，吸收不了紙本；撤回的是揀貨人員，出貨人員不會知道舊單作廢。這一步必須有人在系統外交棒 |
| 設計內證據 | 第 26 行、第 232～233 行：撤回由揀貨人員執行；第 235 行：列印由出貨人員執行；第 394 行 A15、第 338 行：本案不新增系統通知；第 383 行 A4：再確認後物流單編號接續、不重用，新舊單號不同 |
| 準則依據 | 4-3：系統外邊界情境要有誰做、照什麼作業、怎麼回系統。4-2：系統內邊界情境要寫吸收機制，本列寫的機制不涵蓋紙本 |
| 推演（三步） | 第 1 步：出貨人員列印 ORD-…-L001～L003。第 2 步：揀貨人員撤回確認可出貨、修正後再確認，新物流單為 L004～L006。第 3 步：出貨人員手上仍是舊紙本，沒有人告知；貼上 L001 的出貨明細頁出貨。§ 七第 170 行寫明的後果「貨貼錯單」成立 |
| 第一份沒有這類的原因 | 第一份 J6 是吸收機制寫錯（機制不存在）；本處是把需要人交棒的情境整個歸到系統內，連協作要素一起消失 |

|---|---|

### J6　隱含假設 A1 被換成無害的文件假設（很隱蔽）

|---|---|

| 項目 | 內容 |
