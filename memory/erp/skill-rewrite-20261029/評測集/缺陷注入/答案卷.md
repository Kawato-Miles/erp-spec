## 二、逐處證據

### J1　① 訂單修改格漏打樣 NG（明顯）

| 項目 | 內容 |
|---|---|
| 為什麼錯 | 同檔 ⑤ 第 157 行寫「打樣 NG 重建：新印件帶入購買數量與單價，商品小計增加一份新印件小計」。① 寫「不變」，兩處自相矛盾 |
| 正本證據一 | [[訂單]] 第 119 行商品小計算式：「sum(印件.小計)」，沒有排除已棄用印件的取數範圍。原印件轉已棄用後仍在加總內，新印件再加一份，商品小計會變 |
| 正本證據二 | prepress-review 主規格第 1197 行：「訂單的印件數 SHALL 遞增」；第 1215 行 THEN 句「訂單印件數遞增」。印件組成確實改變 |
| 後果 | 落卡與寫 specs 時會漏掉打樣 NG 重建對訂單的影響 |
| 仿照來源 | 本案 audit-r1 檢核項 1-1 第 (2) 點、修正清單 F2「邊界表訂單修改格漏打樣 NG」 |

### J2　打樣 NG 原印件免審的情境改成照帶免審（明顯）

| 項目 | 內容 |
|---|---|
| 為什麼錯 | 與 G4 相反，也與同檔第 29 行「例外（G4）：打樣 NG-稿件問題重建時，免審稿重設為『否』」、第 87 行例外理由互相矛盾 |
| grill 原句 | grill.md G4：「打樣 NG-稿件問題重建時，免審稿重設為『否』。理由：觸發原因本身證明稿件要審」；否決選項「照 G1 帶入原值：否決。原印件若免審，新印件會跳過人工審稿」 |
| 正本證據 | [[印件複製規則]] 第 35 行「稿件問題重建免審稿重設為否」：「打樣結果判定為 NG-稿件問題而重建的新印件，免審稿重設為否」 |
| 後果 | 主情境寫成跳過人工審稿，與 [[打樣後稿件問題重審]] 主流程（新印件重審）不符；specs 驗收條目會照錯的行為寫 |
| 仿照來源 | 無本案直接前例。同類為 rush-order-definition audit-r4 檢核項 5-1（缺陷 E1：設計敘述與拍板內容不符） |

### J3　準時完工率影響描述錯誤（中等）

| 項目 | 內容 |
|---|---|
| 為什麼錯 | 分母條件是「有完工日」。建立當下有印件內部完成日，不會讓印件進分母 |
| 正本原句 | [[北極星指標]] 第 25 行：「分母＝期間內有完工日、且印件內部完成日有值的大貨印件數」；第 34 行：「逾期仍未完工的印件，在完工之前不進分母」 |
| 後果 | 指標影響判讀錯誤，誤導拍板者以為複製會讓指標提早變動 |
| 仿照來源 | 本案 audit-r1 檢核項 2-1、修正清單 F4（第 1 版原文「新印件建立當下就有印件內部完成日，提早進入分母」） |

### J4　待分派離開路徑寫成系統自動分派（中等）

| 項目 | 內容 |
|---|---|
| 為什麼錯 | 複製訂單產生的新訂單一律是線下單（同檔 H4，[[訂單狀態]] 轉訂單／複製訂單 [訂單類型＝線下]）。線下單的分派由人執行、不依難易度。只有線上單由系統依難易度自動分派 |
| 正本原句一 | [[審稿分配規則]] 第 37 行：「線下單（B2B）於訂單回簽後，由 [[訂單管理人]]（或 [[審稿主管]]，同權）手動為各印件分派審稿人員」；第 39 行「線下單不用難易度分派」 |
| 正本原句二 | [[稿件審查活動清單]] 第 39 行 ACT-ART-004「安排印件的審稿人員」擁有角色為 [[訂單管理人]]、[[審稿主管]]；[[訂單管理人]] 第 30 行「線下單的分派由人統一執行、不由系統決定」；[[印件審稿狀態]] 第 80 行「待分派 → 稿件未上傳｜[[印件]] OP-PI-004 分派審稿人員｜線下單」 |
| 後果 | 狀態離開路徑的執行者錯置；寫 specs 時會把線下單新印件寫成系統自動分派，訂單管理人失去調度 |
| 仿照來源 | shipment-print-download-center audit-r1 檢核項 1-3（執行角色與角色卡分工理由不符）；rush-order-definition audit-r1 檢核項 1-3（執行角色未依活動清單） |

### J5　品檢缺口處置歸到內容類（隱蔽）

| 項目 | 內容 |
|---|---|
| 為什麼錯 | 品檢缺口處置是原印件對自己品檢缺口做的處置紀錄，屬「上一件產出了什麼」。帶入新印件後，數量帳會失衡 |
| grill 原句 | grill.md G1-b：歷程與產出類「一律不帶」，列舉含「印製狀態與數量帳」 |
| 正本原句一 | [[印件複製規則]] 第 32 行：「原印件旗下的 [[審稿輪次]]、[[工單]]、[[品檢紀錄]] 與品檢缺口處置都不複製到新印件」；同卡第 61 行歸類為歷程與產出類 |
| 推演（兩步） | 第 1 步：[[印件]] 第 120 行報廢數算式「sum(品檢缺口處置.處置數量)」，新印件帶入處置紀錄後報廢數大於 0。第 2 步：新印件沒有品檢紀錄，不通過累計為 0；第 121 行未處置品檢缺口＝不通過累計 － 報廢數，結果為負 |
| 正本原句二 | [[印件]] 第 144 行處置數量檢核：「報廢類處置合計不得大於不通過累計，未處置缺口因此不為負」。帶入後的新印件一建立就違反這條 |
| 後果 | 新印件的品質帳一開始就失衡；之後記錄缺口處置會被整筆擋下 |
| 仿照來源 | 本案 audit-r2 檢核項 1-1 第 (3) 點、修正清單 R2-2（欄位分類與 [[印件]] 算式不一致，新印件初始值與算式衝突） |

### J6　加開沒改數量的吸收機制寫錯（隱蔽）

| 項目 | 內容 |
|---|---|
| 為什麼錯 | 送主管審核只在草稿期存在。訂單離開草稿後的複製加開沒有送審這一關，設計宣稱的吸收機制不存在 |
| 推演（兩卡） | 第 1 步：[[訂單印件規格維護]] 第 28 行主流程具體例子是「訂單 ORD-2026-0512 製作中」加開印件，結尾寫「不必開單、不必等主管核可」。第 2 步：[[訂單狀態]] 第 186 至 187 行，送主管審核與核准只有「草稿 → 待業務主管審核 → 審核通過」這一段，訂單離開草稿後沒有再送審的轉換。製作中加開推演至存檔即斷：沒有送審步驟可檢查金額 |
| grill 原句 | grill.md § 五：「經手者沒改數量就存檔，訂單應收總額會多出原印件全額」，列為已知影響、不重開拍板 |
| 後果 | 離開草稿後的邊界情境被誤判為已有系統吸收，拍板者看不到這段沒有把關 |
| 仿照來源 | 本案 audit-r1 標準 4 情境分類、修正清單 F6（第 1 版原文「業務在送審前檢查金額（既有送審流程吸收）」） |
