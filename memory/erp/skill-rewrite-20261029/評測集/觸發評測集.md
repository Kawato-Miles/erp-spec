# 觸發評測集

用途：量各 skill 在 Miles 口吻需求句下是否被正確觸發，以及純查詢句是否誤觸發。新舊版各跑兩次，兩次差異當噪音（重構計畫 § 3.1）。

## 一、組成

| 類別 | 句數 | 來源 | 應觸發 |
|---|---|---|---|
| 規劃 | 105 | 盤點主表 132 個 change 主題改寫 | 規劃入口 |
| 規格同步 | 10 | 同上（主題是把已定規則同步到 spec 或清整 spec） | 規格入口 |
| 介面 | 16 | 同上（主題是純版型、元件、排版） | 不觸發規劃 skill |
| 模糊 | 1 | 同上（#26 資料一致性檢查，路由表可判查詢也可判規劃） | 不計分 |
| 指名 | 20 | 各 skill description 的觸發詞與 CLAUDE.md 路由表 | 該 skill |
| 反例 | 20 | 純查詢句 | 不觸發任何 skill |

句子原文與標註存 `觸發評測句.tsv`（欄位：編號、類別、應觸發、來源、句子），重放腳本直接讀這個檔。

應觸發的判分：

| 標註 | 嚴格判對 | 寬鬆判對 |
|---|---|---|
| 規劃入口 | 第一個 Skill 呼叫是 `erp-planning-pre-check` | 第一個 Skill 呼叫屬下列之一：`erp-planning-pre-check`、`opsx:new`、`openspec-new-change`、`opsx:explore`、`openspec-explore`、`grilling` |
| 規格入口 | 第一個 Skill 呼叫是 `opsx:new` 或 `openspec-new-change` | 另含 `erp-planning-pre-check` |
| 不觸發規劃 skill | 沒有呼叫上列規劃入口 skill | 同左 |
| 不觸發 | 沒有任何 Skill 呼叫 | 同左 |
| 指名 skill | 第一個 Skill 呼叫是該 skill | 同左 |

重構計畫 § 6-2 R5 要求的檢查「規劃句是否先觸發 pre-check」，看規劃類的嚴格判對率。

切分：規劃類奇數編號為訓練集，偶數編號為測試集；指名與反例全部屬測試集。改寫 skill 描述時只看訓練集失敗。

## 二、跑法

| 項目 | 內容 |
|---|---|
| 指令 | `claude -p "<句子>" --output-format stream-json --verbose --no-session-persistence --strict-mcp-config --disallowedTools "Edit Write NotebookEdit Bash Agent Workflow" --max-budget-usd 0.8`（旗標已用 Claude Code 2.1.209 的 `claude --help` 確認存在） |
| 工作目錄 | 以待測版本的提交開一個乾淨工作樹（`git worktree add --detach <暫存路徑> <提交>`），避免模型讀到本評測集 |
| 判讀 | 讀輸出紀錄，遇第一個 Skill 呼叫即停；最多看 8 個工具呼叫或 180 秒 |
| 腳本 | `觸發重放腳本.py`：`MODEL=<模型代號> EVAL_DIR=<工作樹路徑> python3 觸發重放腳本.py 觸發評測句.tsv <輸出.jsonl> <輪次標籤> 6`。腳本只把句子欄送給模型。碰到 API 錯誤（額度、登入、版本）就停止送出，結束碼 2，該句不寫入。同一輪次標籤可續跑 |
| 防寫入 | 停用寫檔、Bash、子代理與所有 MCP 伺服器；遇 Skill 呼叫立刻結束程序，skill 本體不會執行 |

## 三、2026-10-29 執行狀態：無頭重放不可用

| 項目 | 事實 |
|---|---|
| 旗標 | 可用（`-p`、`--output-format stream-json`、`--verbose`、`--disallowedTools`、`--strict-mcp-config`、`--max-budget-usd`、`--no-session-persistence`） |
| 實跑結果 | 失敗。輸出「Failed to authenticate: OAuth session expired and could not be refreshed」 |
| 原因 | 命令列版 Claude 的登入已過期；桌面 App 的登入不共用。重新登入要 Miles 本人在終端機操作 |
| 預設模型 | 初始化事件回報 `claude-fable-5`。重放時要指定與 Miles 實際工作階段相同的模型（加 `--model`），否則量到的不是日常行為 |
| 處置 | 改列人工判讀表（§ 四）。登入後用 § 二指令直接重跑，結果填入表中「舊版第 1 次」「舊版第 2 次」兩欄 |

## 四、人工判讀表

判讀方式：比對每句是否含 CLAUDE.md 路由表與 `erp-planning-pre-check` description 的觸發詞。路由表的規劃列要求「規劃、設計、修改 X 邏輯」加業務領域詞同時出現。

| 命中 | 定義 |
|---|---|
| 高 | 同時含規劃動詞與領域詞 |
| 中 | 只含其中一種 |
| 低 | 兩種都沒有 |

規劃動詞：規劃、設計、修改、我想做、想做、要怎麼、怎麼處理。領域詞：諮詢、報價、需求單、訂單、工單、審稿、QC、品檢、出貨、售後、款項、發票、收款、對帳、OA、退款、補收、折讓、期次、老化、帳務、付款、分期。

統計：

| 類別 | 高 | 中 | 低 | 判讀 |
|---|---|---|---|---|
| 規劃（105） | 6 | 73 | 26 | 只有 6 句完全符合路由表寫法。舊版觸發倚賴模型自行推斷，預期觸發率偏低 |
| 規格同步（10） | 0 | 4 | 6 | 規格入口的觸發詞「寫 spec」「修改規格」在本類句中少見 |
| 介面（16） | 0 | 8 | 8 | 8 句含領域詞，有誤觸發規劃 skill 的風險 |
| 指名（20） | 0 | 10 | 10 | 指名句以 skill 自己的觸發詞為主，本表的規劃詞表不適用 |
| 反例（20） | 0 | 10 | 10 | 10 句含領域詞，有誤觸發風險 |
