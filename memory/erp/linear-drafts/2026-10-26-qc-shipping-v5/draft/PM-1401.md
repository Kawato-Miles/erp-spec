## 概述

這張票做完，出貨人員能在 <project id="2ba2439d-73c6-426c-a384-af08eafb815d" href="https://linear.app/sensationdeveloper/project/%E4%B8%AD%E5%8F%B0-%E5%93%81%E6%AA%A2%E8%88%87%E5%87%BA%E8%B2%A8-555eb8966074/overview">中台 - 品檢與出貨</project> 對物流單做出貨動作、從出貨單批次拋單、標記例外、確認送達並下載單筆物流單檔案。第三方物流的物流單依物流商回傳推進。業務能作廢送不出或送不到的物流單。

出貨單與物流單的狀態流轉見 <project id="2ba2439d-73c6-426c-a384-af08eafb815d" href="https://linear.app/sensationdeveloper/project/%E4%B8%AD%E5%8F%B0-%E5%93%81%E6%AA%A2%E8%88%87%E5%87%BA%E8%B2%A8-555eb8966074/overview">中台 - 品檢與出貨</project> 的出貨單狀態機與物流單狀態機。

>>> ## 出貨動作執行

身為出貨人員，我要對物流單做出貨動作，以留下誰在何時把貨交出去的紀錄。

**實體關係**

1. 出貨動作依出貨方式不同，對每一筆物流單的動作不同：

| 出貨方式 | 出貨動作 |
| -- | -- |
| 順豐、新竹物流、7-11 交貨便、全家 | 拋單 |
| 專車配送、其他 | 出貨確認 |
| 自取 | 標記可自取 |

2. 出貨確認與標記可自取在物流單上逐筆執行。
3. 拋單可在物流單上逐筆執行，也可從出貨單批次執行，見物流單批次拋單節。
4. 出貨動作成功時，物流單歷程記時間與操作人。
5. 各筆物流單的出貨動作各自獨立。一筆失敗，不影響其他筆。
6. 出貨單為異常時，其他仍在可出貨的物流單照常可做出貨動作。
7. 出貨動作不檢查揀貨相符。揀貨相符在確認可出貨把關，見 <issue id="95674851-df70-449a-ab05-0fb7e99ce068" href="https://linear.app/sensationdeveloper/issue/PM-1400/feature-揀貨與裝箱回報">PM-1400</issue>。

**驗證規則**

1. 物流單在可出貨，才可做出貨動作。
2. 所屬訂單已取消時，不受理出貨動作。
3. 所屬出貨單撤回確認可出貨執行中時，不受理出貨動作。
4. 出貨動作會與下列動作搶同一張單：撤回確認可出貨、裝箱回報修正、作廢出貨單、作廢物流單。
5. 兩筆同時寫入時，先寫入者成立。後到者以寫入當下的資料重新檢核，檢核不過時不寫入，系統告知卡住它的原因。

**驗收**

1. 假設兩張新竹物流出貨單各出 100，揀貨人員各回報揀貨數量 80、裝箱 2 箱，兩張的確認可出貨都被擋下。當出貨人員查看這兩張單，則列上只有「檢視」，沒有「批次拋單」，出貨單對話框的物流單表沒有資料。業務把第一張明細改為 80、揀貨人員把第二張揀貨數量修正為 100，揀貨人員再對兩張確認可出貨之後，兩張各產生兩筆可出貨的物流單，物流單列內每一列長出「拋單」，列上的「批次拋單」可按。
2. 假設承品檢驗收各建一張自取單與一張新竹物流單，各 2 箱，走完揀貨並由揀貨人員確認可出貨。當出貨人員看兩張單的列，則自取單列上沒有任何出貨動作鈕，新竹物流單列上只有「批次拋單」一顆出貨動作。在自取單的物流單列上按「標記可自取」，則物流單轉可自取，出貨單轉已出貨。
3. 假設所屬訂單已取消，一張 7-11 交貨便單三筆物流單分別在運送中、等待出貨、可出貨。當出貨人員對可出貨那一筆送出拋單，則不受理，該筆物流單列不顯示出貨動作。

>>> ## 物流單拋單

身為出貨人員，我要把第三方物流的物流單拋給物流商，以取得物流單號並交寄。

**實體關係**

1. 拋單把出貨資料送給物流商。物流單號與物流商標籤由物流商於拋單成功時回傳，寫入物流單。
2. 支援子母單的物流單，物流商另回傳每一箱的子單號。子單號記在該箱的裝箱資料。
3. 出貨人員不手填物流單號。
4. 拋單成功的物流單在等待出貨，貨仍在廠內，不算離廠。
5. 物流商回傳失敗，或送出後等不到物流商回應而逾時，都算拋單失敗。
6. 拋單失敗時，物流商回傳的錯誤訊息在這次拋單處理結束時顯示給操作者。物流單不存失敗原因與嘗試次數。
7. 排除原因後，對同一筆物流單再執行一次拋單即重拋。不設單筆重試。

**驗證規則**

1. 拋單失敗時，物流單不推進，留在可出貨。

**驗收**

1. 假設承品檢驗收建立的一張順豐單，裝 3 箱，揀貨人員已確認可出貨。當出貨人員開出貨單對話框，在物流單列上按「拋單」，則確認框沒有任何欄位。拋單處理結束後物流單轉等待出貨，物流單號有值，三箱各有一個子單號，出貨單轉等待出貨、仍屬未離廠，物流單歷程多一筆「拋單成功」。
2. 假設承品檢驗收建一張順豐單，揀貨人員裝 2 箱並確認可出貨，這筆物流單拋單時物流商回傳錯誤。當出貨人員在物流單列上按「拋單」確認，連按兩次，則每次處理結束時都以訊息顯示物流商回傳的錯誤，確認框不關。物流單留在可出貨，物流單列內沒有「單筆重試」，仍有「拋單」，出貨單仍是可出貨。揀貨人員把兩箱箱規改成另一種箱規並填修正原因，出貨人員再按「拋單」，則物流單轉等待出貨，寫入物流單號，出貨單轉等待出貨。
3. 假設承品檢驗收建一張新竹物流單，2 箱，揀貨人員已確認可出貨。當出貨人員在兩筆物流單的列上各按一次「拋單」，則各生成一個物流單號。只拋第一筆時出貨單仍取最落後的可出貨，兩筆都拋完才轉等待出貨。
4. 假設承品檢驗收建一張新竹物流單，出 100，裝 1 箱，確認可出貨後物流商在時限內沒有回應。當出貨人員在物流單列上按「拋單」並確認，則處理結束時告知這一筆逾時失敗。物流單維持可出貨，沒有物流單號與物流商標籤，出貨單維持可出貨，物流單列仍有「拋單」。

>>> ## 物流單批次拋單

身為出貨人員，我要從出貨單一次拋出可出貨的物流單，以免多箱時逐筆按拋單。

**實體關係**

1. 批次拋單只用於出貨動作為拋單的出貨方式：順豐、新竹物流、7-11 交貨便、全家。批次拋單不是另一個操作，執行角色與範圍同權限表的拋單列。
2. 批次拋單對本單每一筆狀態為可出貨的物流單，各執行一次拋單。其他狀態的物流單不送。
3. 各筆結果獨立。成功與失敗的處理同物流單拋單節。
4. 處理結束時，系統逐筆列出結果。成功的帶物流單號，失敗的附物流商回傳的錯誤訊息。結果不存。
5. 批次拋單不另記批次紀錄。每一筆物流單照常在自己的歷程記拋單成功。
6. 一次送出的筆數上限，以及同步或背景執行，由後端決定。

**驗證規則**

1. 本單沒有狀態為可出貨的物流單時，不受理批次拋單。
2. 所屬訂單已取消時，每一筆物流單都不受理，結果逐筆列為失敗。

**驗收**

1. 假設承品檢驗收建一張新竹物流單，出 100，裝 3 箱並確認可出貨，第 3 筆拋單時物流商回傳錯誤。當出貨人員在列上按「批次拋單」並確認，則：
   * 確認框列出本單狀態為可出貨的三筆物流單。
   * 處理結束時逐筆列出結果。第 1、2 筆成功並帶物流單號，第 3 筆失敗並附物流商回傳的錯誤訊息。
   * 第 1、2 筆轉等待出貨，各有物流單號。第 3 筆停在可出貨，沒有物流單號。
   * 出貨單仍為可出貨、屬未離廠，列上仍有「批次拋單」。
   * 每一筆成功的物流單歷程多一筆拋單成功，出貨單歷程不另記批次事件。
   * 之後再按一次「批次拋單」，確認框與結果只有第 3 筆。
2. 假設承品檢驗收建一張順豐單，出 100，裝 5 箱，確認可出貨後合成一筆物流單。當出貨人員按「批次拋單」，則只送出那一筆物流單，主單號與五個子單號寫入，物流單與出貨單轉等待出貨，之後列上不再有「批次拋單」。
3. 假設承品檢驗收建四張單：已裝箱的新竹物流單、可出貨的新竹物流單、物流單全部在等待出貨的新竹物流單、可出貨的自取單。當出貨人員、揀貨人員與業務各看這些單的列，則只有出貨人員在可出貨的新竹物流單上看到「批次拋單」，其他三張單沒有。揀貨人員與業務都看不到「批次拋單」。
4. 假設一張出貨單為異常，第 1 筆物流單為物流商回傳的例外，第 2 筆在等待出貨，第 3 筆在可出貨。當出貨人員按「批次拋單」，則只送出第 3 筆。第 1、2 筆不變，出貨單仍為異常。送完後「批次拋單」停用並顯示理由。
5. 假設所屬訂單已取消，一張出貨單屬部分離廠，一筆物流單在運送中、一筆在可出貨。當出貨人員按「批次拋單」，則可出貨那一筆被擋下、維持可出貨，結果列出失敗與理由，運送中那一筆不變。

>>> ## 物流單貨況更新

身為出貨人員，我要看到第三方物流單隨物流商回傳更新的貨況，以回答客戶貨到哪了。

**實體關係**

1. 第三方物流的物流單，狀態只依物流商回傳推進。
2. 物流商回傳只讓狀態往前走。
3. 倒退的回傳不改狀態，只寫歷程。
4. 已送達、已自取、已作廢的物流單收到任何回傳，都只寫歷程。
5. 物流商回傳的「已登記追蹤」一類訊息，不推進物流單。
6. 配達只認簽收或取件完成。7-11 交貨便與全家的到店算運送中，取貨算已送達。
7. 支援子母單的物流單，狀態只看主單。子單不回傳狀態。
8. 例外中的物流單，物流商回傳可讓它回到物流商當下的狀態：等待出貨、運送中或已送達。
9. 狀態以物流商最近一次回傳為準，不另設延遲顯示。

**驗證規則**

1. 第三方物流的物流單沒有人工推進狀態的操作。配達回傳沒進來時，只能以送達確認補上，見送達確認節。

**驗收**

1. 假設承品檢驗收建立的 7-11 交貨便單裝 3 箱、成三筆物流單，皆已拋單、在等待出貨。當物流商只回傳一筆到店，則出貨單仍為等待出貨。三筆都回傳到店，則三筆轉運送中，出貨單轉運送中。
2. 假設接上一條。當物流商回傳其中一筆為無追蹤中包裹，則出貨單轉異常。物流商下一次回傳該筆為運送中後，出貨單恢復為運送中。物流單列沒有人工取回物流商狀態的操作。
3. 假設順豐唯一一筆物流單在等待出貨。當物流商依序回傳已登記追蹤、在途、配達，則已登記追蹤不改變狀態。在途轉運送中，配達轉已送達，不經已出貨。出貨單依序轉運送中、已送達，不要求出貨人員另做送達確認。
4. 假設一筆物流單已作廢，作廢時填未送達 40。當物流商之後回傳配達，則物流單維持已作廢，回傳只寫入歷程，未送達數量維持 40，出貨單狀態與可出貨額度不變。

>>> ## 物流單例外標記

身為出貨人員，我要在專車配送、其他或自取的貨況有問題時先把物流單停在例外，以便問清楚再決定作廢或送達。

**實體關係**

1. 例外分為下列種類：未送達、無追蹤中包裹、例外事故。
2. 標記例外時選一種，並填理由。
3. 物流單記錄例外理由與例外來源。例外來源是人工標記或物流商回傳。
4. 第三方物流的例外只由物流商回傳，不開放人工標記。
5. 標記例外不回補可出貨額度，物流單照常佔用。

**驗證規則**

1. 出貨方式為專車配送、其他或自取，物流單在已出貨或可自取，才可標記例外。
2. 標記例外必選一種例外並填理由，未填無法標記。

**驗收**

1. 假設承品檢驗收建立一張專車出貨單並走到已出貨，出貨數量 100，裝 2 箱，一筆物流單。當業務看這張單，則物流單列內沒有「標記例外」。出貨人員在物流單列內按「標記例外」，不選種類也不填理由送出，則單不變。選「例外事故」、填「客戶拒收」送出，則物流單轉例外事故，記理由與來源（人工標記），出貨單轉異常，歷程各多一筆。
2. 假設接上一條。當回印件列表看已出貨與可出貨額度，則已出貨仍 100，可出貨額度仍 400。
3. 假設新竹物流的一筆物流單在運送中。當出貨人員繞過畫面送出標記例外，則不受理，物流單維持運送中。

>>> ## 送達確認

身為出貨人員，我要在貨到客戶手上時確認送達，以讓每一筆物流單收尾都查得到誰確認、何時。

**實體關係**

1. 送達確認用於第三方物流、專車配送與其他。自取的同一件事叫交付確認。
2. 送達確認與交付確認記送達時間與操作人，不附照片。
3. 第三方物流的人工送達確認是備援。配達回傳沒進來時，出貨人員查得配達資訊後回填配達時間。
4. 自取先標記可自取。客戶到廠後，出貨人員做交付確認，物流單轉已自取。
5. 送達確認與交付確認時，可選填逐印件的未送達數量。未送達數量不預填，預設 0。上限與回補同作廢物流單。
6. 出貨單轉已送達時，系統寫入各出貨明細的送達數量。

**驗證規則**

1. 第三方物流的物流單在等待出貨、運送中或例外，才可送達確認。
2. 專車配送與其他的物流單在已出貨或例外，才可送達確認。
3. 自取的物流單在可自取或例外，才可交付確認。
4. 第三方物流的人工送達確認必填配達時間。
5. 人工確認與物流商回傳同時到時，先寫入者成立。後到者只寫歷程，不改任何欄位，並提示重新整理。

**算式**

```
送達數量 ＝ 揀貨數量 － 本單全部物流單的該印件未送達數量合計
```

**驗收**

1. 假設承品檢驗收的一張新竹物流單已拋單，物流商回傳在途，物流單在運送中，配達回傳沒進來。當出貨人員在物流單列內按「送達確認」並回填物流商配達時間，則物流單轉已送達，確認人記為該出貨人員。後到的第二次送達確認不改任何欄位，操作者看到「此單已收尾，請重新整理」。
2. 假設承品檢驗收的一張專車配送單已走完揀貨、確認可出貨並出貨確認。當出貨人員在物流單列內按「送達確認」，不附照片送出，則物流單轉已送達，出貨單依物流單計算為已送達。專車配送只有送達確認這一條路收尾。
3. 假設一筆新竹物流物流單在等待出貨，在途與配達回傳都沒進來。當出貨人員回填配達時間做送達確認，則物流單自等待出貨轉已送達，確認人記為該出貨人員。
4. 假設承品檢驗收取得可出貨額度 500 後，建一張自取單，出 100，裝 2 箱，確認可出貨後已標記可自取。當出貨人員按「交付確認」，不附照片，未送達數量填 30，則物流單轉已自取，出貨單轉已送達，送達數量 70。單張佔用量 70，可出貨額度 500 － 70 ＝ 430。

>>> ## 物流單作廢

身為業務，我要把確定送不出或送不到的物流單作廢並填沒送到的量，以讓這一筆收掉、額度回補，其他物流單照常送達。

**實體關係**

 1. 作廢物流單記錄理由與未送達數量。未送達數量逐印件填，印件必須是所屬出貨單出貨明細上的印件。
 2. 未送達數量回補該印件的可出貨額度。
 3. 其餘物流單尚有未作廢者時，未送達數量預設 0，由業務逐印件填。
 4. 其餘物流單都已作廢時，未送達數量由系統預填，不可改。預填值是明細數量扣掉已填的未送達合計。
 5. 已填的未送達合計，含本出貨單全部物流單已填的量。含已作廢與已送達的物流單。
 6. 其餘物流單都已作廢時，這一筆仍須填作廢理由。出貨單隨之轉已作廢，出貨單不另填理由。
 7. 出貨單轉已作廢後整張不計佔用，底下物流單的未送達數量不另扣。額度共回補一次，不重複回補。
 8. 所屬訂單已取消，且出貨單部分離廠時，仍在可出貨與等待出貨的物流單由業務作廢。業務並填未送達數量。
 9. 等待出貨、運送中與例外的物流單作廢前，由出貨人員在系統外向物流商確認貨況。
10. 系統不通知物流商取消托運。

**驗證規則**

1. 物流單在等待出貨、運送中或例外時可作廢。等待出貨與運送中只有第三方物流會出現。
2. 物流單在可出貨時，本單有任一物流單（含已作廢者）不在可出貨，才可作廢。全部物流單都在可出貨時，改以撤回確認可出貨或作廢出貨單處理。
3. 已出貨、可自取的物流單，先標記例外才可作廢。
4. 已送達、已自取的物流單不可作廢。
5. 作廢必填理由，未填無法作廢。
6. 同一張出貨單的同一件印件，未送達數量合計不得大於明細數量。

**驗收**

1. 假設承品檢驗收建立的 7-11 交貨便單，明細 100，裝 3 箱成三筆物流單，出貨人員已逐筆拋單、皆在等待出貨，印件可出貨額度 400。當業務作廢第一筆物流單，填理由，未送達 30，則這一筆直接轉已作廢，單張佔用量 70，可出貨額度 430。作廢第二筆，未送達 40，則單張佔用量 30，可出貨額度 470，出貨單仍依剩下的物流單計算。作廢第三筆，其餘兩筆都已作廢，系統預填未送達 100 － 70 ＝ 30，欄位不可改，則出貨單轉已作廢，整張不計佔用，額度共回補 100。
2. 假設承品檢驗收建立一張專車出貨單並走到已出貨，出貨數量 100，一筆物流單，印件可出貨額度 400，出貨人員已標記例外事故。當業務對這筆物流單按「作廢物流單」，未送達數量由系統預填 100，則出貨單轉已作廢，已出貨歸 0，可出貨額度加回 100，印件詳情同時變。
3. 假設新竹物流單一筆在等待出貨、兩筆在運送中，可出貨額度 0。當業務作廢前兩筆，未送達 50、30，則直接成立，額度變 80，出貨單依第三筆計算為運送中。另一張專車單的物流單在已出貨，業務看不到「作廢物流單」，繞過畫面送出也不受理。出貨人員標記例外後，業務才能作廢。
4. 假設新竹物流單第 1、2 筆在等待出貨，第 3 筆拋單一直失敗、仍在可出貨。當業務作廢第 3 筆，未送達 20，則成立，額度回補 20。另一張全家單兩筆物流單皆在可出貨，業務看不到「作廢物流單」，繞過畫面送出也不受理。
5. 假設所屬訂單已取消，一張 7-11 交貨便單三筆物流單分別在運送中、等待出貨、可出貨，出貨單屬部分離廠。當業務作廢等待出貨與可出貨兩筆並各填未送達數量，則未送達數量回補，出貨單依運送中那一筆重算為運送中。

>>> ## 物流單檔案下載

身為出貨人員，我要在只需要某一筆物流單時直接下載它的檔案，以補貼或單獨列印。

**實體關係**

1. 物流單檔案含物流商標籤與一頁出貨明細。出貨明細頁列所屬出貨單全部印件與數量，不放裝箱資料。
2. 物流商標籤由物流商於拋單成功時回傳。還沒拋單的物流單，檔案沒有物流商標籤。專車配送、自取與其他沒有物流商標籤。
3. 下載物流單檔案直接下載，不經下載中心，不產生下載檔案。
4. 下載不改物流單與出貨單的狀態。
5. 下載物流單檔案只對單筆物流單執行。出貨單沒有一次下載全部物流單檔案的操作。

**驗證規則**

1. 未作廢的物流單才可下載物流單檔案。

**驗收**

1. 假設 SH-2026-0921 為專車配送 1,200 份、4 箱，可出貨，物流單 SH-2026-0921-001 在可出貨、還沒有物流商標籤。當出貨人員在這筆物流單列內按「下載物流單」，則系統直接提供檔案下載，內容含出貨明細頁 PI-2026-0924 × 1,200，沒有物流商標籤。下載中心沒有新增任何下載檔案，物流單與出貨單的狀態都不變。
2. 假設接上一條，同一張單另一筆物流單已作廢。當出貨人員看那一筆，則不提供下載，兩筆物流單與出貨單的狀態都不變。
3. 假設 SH-2026-0601 為順豐，已送達。當出貨人員開 SH-2026-0601 的出貨單對話框，則物流單列內有「下載物流單」，出貨單列上沒有下載鈕。
