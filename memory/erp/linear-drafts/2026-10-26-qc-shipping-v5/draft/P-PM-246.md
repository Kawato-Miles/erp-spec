## 概述

品檢與出貨承接生產完成之後的最後一段。品檢人員驗收做出來的貨，通過的量成為可出貨額度。業務依額度安排出貨，揀貨人員逐箱裝箱並確認可出貨，出貨人員列印要貼的單，把每一筆物流單交運並確認送達。

現行品檢回報與裝箱回報混在一起發出，出問題時難以定位。業務與客戶談定的出貨日期，現行散在通訊軟體裡。一張出貨單常裝成多箱，一箱被退時其他箱照常送達，單頭只放得下一組物流單號與一個狀態，表達不了。出貨人員要一次掌握當批貨與要貼的單。

## 使用情境

### Use Case

 1. 品檢人員對送到品檢站的貨分次驗收，每次附品檢照片。通過的量隨驗隨成為可出貨額度。
 2. 品檢人員記錯時修正原紀錄。已被出貨單佔用的量，業務先改出貨明細，品檢人員才修正得動。
 3. 驗出缺口時，印務決定補不補，以及瑕疵品報廢或客戶照收。印務誤記報廢時，先修正處置，品檢人員再把不通過改為通過。
 4. 業務與客戶談定出貨日期後，先建出貨單草稿。品檢通過、額度足夠後，業務把草稿建立為出貨單。
 5. 揀貨人員開始揀貨，逐條回報揀貨數量，逐箱回報箱規、長寬高、裝箱照片與備註。
 6. 揀貨數字與明細不符時，揀貨人員照實填，並現場通知業務。業務改出貨明細數量，或揀貨人員修正揀貨數量與裝箱資料。
 7. 兩數相符後，揀貨人員確認可出貨。系統此時依出貨方式把箱子拆成物流單，數量與箱數自此鎖住。物流單都還在可出貨時，揀貨人員可撤回確認可出貨，回頭修正後再確認。
 8. 出貨人員對物流單做出貨動作。第三方物流拋單，可從出貨單一次拋出全部可出貨的物流單，也可逐筆拋單。專車配送與其他逐筆出貨確認，自取逐筆標記可自取。第三方的物流單號由物流商回傳。
 9. 拋單失敗或逾時，物流單都不推進。拋單處理結束時，畫面逐筆顯示物流商回傳的錯誤訊息。原因在箱子時，揀貨人員先修正那一箱，出貨人員再拋一次。
10. 出貨人員勾選要出的物流單一次列印，系統產出物流單列印與托運總表。出貨人員到下載中心取檔，貼箱交寄。只要某一筆時，直接下載那一筆的物流單檔案。
11. 第三方物流的物流單只依物流商回傳推進。配達回傳沒進來時，出貨人員做送達確認補上。專車配送與其他做送達確認，自取做交付確認。
12. 第三方物流的例外由物流商回傳，出貨人員向物流商確認貨況。專車配送、其他與自取貨況不明時，出貨人員標記例外。確定送不到的那一筆，業務作廢物流單並填沒送到的量，額度回補。要再出就建新出貨單。
13. 貨還沒離廠就建錯單或客戶取消，業務作廢出貨單。已拋單的物流單，出貨人員在物流商端取消托運。

* 向物流商取消托運：不做。已拋單的物流單或出貨單作廢後，物流商端的取消托運、攔截或退回，由出貨人員在系統外處理。
* 物流商端多建的托運單：系統外處理。拋單逾時，或等待回應期間單據被他人作廢，物流商端仍可能已建單。系統不防重複建單，也不向物流商取消。多出的托運單，物流商到場不收件，也不計價。重拋被物流商以重複為由拒絕時，出貨人員通知後端人員。後端人員到物流商後台查出物流單號後補登。
* 一次對多張出貨單拋單：不做。批次拋單只對一張出貨單底下的物流單。
* 自取、專車配送與其他一次對多筆出貨確認或標記可自取：不做。這些出貨方式一張出貨單只有一筆物流單。
* 撤回確認可出貨後，已印出的舊列印檔作廢：系統外處理，由撤回的揀貨人員通知出貨人員，重新列印。
* 下載檔案的保存期限與刪除：不做，紀錄一律保留。
* 產檔完成或失敗的通知：不做，結果看下載中心。
* 下載中心的筆數與狀態統計：不做。
* 出貨方式與箱規的維護：屬系統設定，不開維護功能。箱規不做停用與刪除。
* 運費與物流對帳：後續批次。箱數、箱規與長寬高只留存。
* 長寬高送給物流商：不做，只留在出貨單。
* 各物流商收得下的箱子尺寸上限：不記，系統不擋也不提示。超過上限由物流商拒收。
* 成品入庫成為獨立交易、成品倉庫存：後續批次。
* 品檢完成品移到暫存區的現場留痕：延後批次，隨廠務 Slack 表單回報一起。
* 退回實物的場內處理：不進系統，現場人工處理。
* 貨不回台的海外直發訂單：本輪範圍外。

* 可出貨之後的推進是歸納型轉換：物流單一有變化就重算，畫成選擇節點。
* 草稿不是出貨指令，出口是刪除。
* 揀貨不符不是狀態。它擋下確認可出貨，見 <issue id="95674851-df70-449a-ab05-0fb7e99ce068" href="https://linear.app/sensationdeveloper/issue/PM-1400/feature-揀貨與裝箱回報">PM-1400</issue>。
* 異常不是終態。

出貨單依物流單計算：

| 規則 | 內容 |
| -- | -- |
| 計算來源 | 只看未作廢的物流單。已作廢的物流單保留可查，不參與計算 |
| 最落後 | 取未作廢物流單在「可出貨、等待出貨、已出貨、運送中、已送達」順序上最落後的狀態。可自取視同已出貨，已自取視同已送達 |
| 異常優先 | 任一未作廢物流單在例外，出貨單為異常，不論其他物流單在哪一格。例外解除或該物流單作廢後重算 |
| 已送達 | 至少一筆未作廢物流單，且全部未作廢物流單已送達或已自取。轉入後為終態，不重算 |
| 全部作廢 | 未作廢物流單筆數歸零時，出貨單轉已作廢 |

出貨動作是拋單、出貨確認或標記可自取，對物流單執行。拋單可從出貨單一次對多筆物流單執行。出貨單的集合詞依底下未作廢物流單的狀態判定。物流單在已出貨、可自取、運送中、例外、已送達或已自取，算已離廠。等待出貨的物流單已拋單，貨仍在廠內，不算離廠。各集合詞互斥，涵蓋草稿以外的全部未作廢出貨單：

| 集合詞 | 定義 |
| -- | -- |
| 未離廠 | 本單沒有物流單，或全部未作廢物流單都在可出貨或等待出貨。含未處理、打包中與已裝箱 |
| 部分離廠 | 至少一筆未作廢物流單已離廠，且仍有未作廢物流單在可出貨或等待出貨 |
| 全數離廠 | 全部未作廢物流單都已離廠。這一批的印件算已出貨 |

```mermaid
    sync --> s_waiting : 物流商當下為等待出貨
    sync --> s_transit : 物流商當下為運送中
    sync --> s_arrived : 物流商當下為已送達
    Exc --> s_arrived : 送達確認 · 第三方物流、專車配送與其他
    Exc --> s_picked : 交付確認 · 自取
    Exc --> s_void : 作廢物流單 · 附理由與未送達數量
    s_ready --> s_void : 作廢物流單 · 所屬出貨單有任一物流單不在可出貨／系統：所屬出貨單作廢
    s_waiting --> s_void : 作廢物流單 · 附理由與未送達數量／系統：所屬出貨單作廢
    s_transit --> s_void : 作廢物流單 · 附理由與未送達數量

    s_arrived --> [*]
    s_picked --> [*]
    s_void --> [*]
```

* 物流單在確認可出貨時產生，初始為可出貨。撤回確認可出貨時刪除，不走作廢。所有出貨方式都有物流單。拋單失敗或逾時，物流單都不推進，仍在可出貨。
* 各出貨方式經過的狀態：第三方物流為可出貨、等待出貨、運送中、已送達，不經已出貨。專車配送與其他為可出貨、已出貨、已送達。自取為可出貨、可自取、已自取。
* 「已離廠」框內的狀態都算已離廠，例外也算。等待出貨不算。
* 第三方物流的例外只由物流商回傳，不開放人工標記。離開例外回到物流商當下狀態的弧，落入哪一格看物流商回傳。
* 所屬出貨單作廢時，可出貨與等待出貨的物流單一併作廢。
