>>> ## 物流單批次列印

身為出貨人員，我要勾選物流單一次列印物流單與托運總表，以一次掌握當批貨與要貼的單。

**實體關係**

1. 列印可跨多張出貨單。
2. 每次列印產出的檔案如下表，每份檔案各成一筆下載檔案：

| 涵蓋範圍 | 產出的檔案 |
| -- | -- |
| 一律 | 物流單列印一份 |
| 含已拋單的順豐物流單 | 另產順豐托運總表一份 |
| 含已拋單的新竹物流物流單 | 另產新竹托運總表一份 |

3. 下載檔案建立時為等待中，記建立時間、檔案類型、物流單筆數與建立人。
4. 物流單列印收涵蓋範圍內全部未作廢的物流單。
5. 托運總表只收該物流商已拋單的物流單。還沒拋單的物流單不收，也不算異常。
6. 產哪幾份檔、每份收哪幾筆，以按下列印當下為準。之後才拋單的物流單，不補進已建立的托運總表。
7. 物流單列印收每筆物流單的物流單檔案。
8. 順豐、新竹托運總表的欄位與版式，照電商網站（EC）現在產出的托運總表；後端從 EC 的程式取得。
9. 列印不改物流單與出貨單的狀態。
10. 一份下載檔案涵蓋多筆物流單。一筆物流單可被多次列印。

**驗證規則**

1. 涵蓋範圍沒有任何未作廢的物流單時，不受理列印。

**驗收**

1. 假設 SH-2026-0601 為順豐，一筆物流單 SH-2026-0601-001 已拋單；SH-2026-0921 為專車配送，一筆物流單 SH-2026-0921-001 在可出貨。當出貨人員在出貨管理勾選 SH-2026-0601 與 SH-2026-0921-001 後按「列印」，則下載中心新增兩筆等待中的下載檔案：
   * 物流單列印，物流單筆數 2。
   * 順豐托運總表，物流單筆數 1，只收已拋單的 SH-2026-0601-001。
   * 兩筆的建立時間為這次列印的時間，建立人為該出貨人員。
   * 沒有新竹物流的物流單，不產新竹托運總表。
   * 兩筆物流單的狀態不變。
2. 假設接上一條。當揀貨人員與業務看出貨管理，則沒有「列印」。業務繞過畫面送出列印物流單，也不受理。
3. 假設一張新竹物流單三筆物流單皆已拋單、在等待出貨。當出貨人員列印這三筆，則建立物流單列印（物流單筆數 3）與新竹托運總表（物流單筆數 3），三筆物流單維持等待出貨。
4. 假設出貨人員跨出貨單一次勾選順豐一筆已拋單的物流單，以及新竹物流三筆物流單，其中兩筆已拋單、一筆拋單失敗仍在可出貨。當出貨人員按「列印」，則建立物流單列印（物流單筆數 4）、順豐托運總表（物流單筆數 1）、新竹托運總表（物流單筆數 2）。可出貨那一筆收進物流單列印，不收進新竹托運總表。之後該筆再拋單成功，已建立的新竹托運總表維持 2 筆、不補進。重新列印時，依當下涵蓋範圍另建新的下載檔案。

>>> ## 下載檔案產檔

身為出貨人員，我要看得到每份列印檔產成了沒、哪幾筆沒產出，以知道要重印哪幾筆。

**實體關係**

1. 系統開始產檔時，已刪除或已作廢的物流單不產出。異常內容分別記「物流單編號：物流單已刪除」「物流單編號：物流單已作廢」。
2. 產檔出錯的物流單不產出。異常內容記「物流單編號：錯誤訊息原文」。
3. 異常內容每筆物流單一行。
4. 還沒拋單而缺物流商標籤的物流單照常產出，不記異常。
5. 狀態為成功或部分成功時，系統寫入產出的檔案。
6. 重新列印時產生新的下載檔案，舊的下載檔案保留、不改寫。
7. 物流單被撤回確認可出貨刪除後，下載檔案只保留該物流單的物流單編號。

**驗證規則**

1. 產檔結束時，物流單筆數必須等於成功產出筆數加異常內容行數。

**驗收**

1. 假設一份下載檔案涵蓋三筆物流單。當系統產檔，三筆全部產出，則下載檔案依序轉處理中、成功，異常內容空，檔案寫入。
2. 假設一份物流單列印涵蓋十筆物流單 SH-2026-0901-001 至 -010，開始產檔前 -003 被作廢。當系統產檔，則下載檔案轉部分成功，異常內容一行「SH-2026-0901-003：物流單已作廢」，物流單筆數維持 10。
3. 假設出貨單 SH-2026-1023 三筆可出貨物流單已列印，下載檔案在等待中。當揀貨人員撤回確認可出貨後系統產檔，則下載檔案轉失敗，異常內容三行，各寫「物流單編號：物流單已刪除」，檔案不寫入。
4. 假設一份順豐托運總表涵蓋兩筆，其中一筆產檔出錯。另一份物流單列印涵蓋兩筆，其中一筆還沒拋單。當系統產檔，則順豐托運總表轉部分成功，異常內容一行寫該筆物流單編號與錯誤訊息原文。物流單列印的兩筆都產出，還沒拋單那一筆不附物流商標籤、不記異常，該檔案轉成功。
5. 假設一份順豐托運總表為失敗。當出貨人員對同一批物流單重新列印，則下載中心另建一筆等待中的新紀錄。原本失敗的那一筆保留、維持失敗。

>>> ## 列印檔下載

身為出貨人員，我要到下載中心下載產好的列印檔，以貼箱交寄並把托運總表交給物流商。

**實體關係**

1. 出貨人員看得到其他出貨人員建立的下載檔案。
2. 下載不改下載檔案的狀態與內容，可重複下載。
3. 下載檔案不刪除，也不過期。

**驗證規則**

1. 下載檔案在成功或部分成功，才可下載。

**驗收**

1. 假設下載中心有出貨人員曾志偉與另一位出貨人員建立的下載檔案，五種狀態各至少一筆。當另一位出貨人員打開下載中心，則列出全部下載檔案，含曾志偉建立的。成功與部分成功的資料列有下載鈕，可重複下載，下載後狀態不變。等待中、處理中、失敗的資料列沒有下載鈕。
2. 假設下載中心最早一筆下載檔案在 2026-06-18 建立，狀態成功。當出貨人員找這一筆，則它仍在下載中心、可下載，沒有刪除下載檔案的操作。
3. 假設下載中心有等待中、處理中、失敗的下載檔案。當出貨人員繞過畫面對這些資料列送出下載，則不受理。
4. 假設業務打開系統。當業務找下載中心，則側邊選單沒有下載中心，直連被導回預設頁面。業務繞過畫面送出下載，也不受理。
