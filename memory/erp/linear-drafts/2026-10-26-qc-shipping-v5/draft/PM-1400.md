## 概述

這張票做完，揀貨人員能在 <project id="2ba2439d-73c6-426c-a384-af08eafb815d" href="https://linear.app/sensationdeveloper/project/%E4%B8%AD%E5%8F%B0-%E5%93%81%E6%AA%A2%E8%88%87%E5%87%BA%E8%B2%A8-555eb8966074/overview">中台 - 品檢與出貨</project> 依出貨單開始揀貨、逐條回報揀貨數量、逐箱回報裝箱資料、修正填錯的裝箱回報，並確認這一批可以出貨或撤回確認。

出貨單的狀態流轉見 <project id="2ba2439d-73c6-426c-a384-af08eafb815d" href="https://linear.app/sensationdeveloper/project/%E4%B8%AD%E5%8F%B0-%E5%93%81%E6%AA%A2%E8%88%87%E5%87%BA%E8%B2%A8-555eb8966074/overview">中台 - 品檢與出貨</project> 的出貨單狀態機。

（[參考留言](<https://linear.app/sensationdeveloper/issue/PM-1400#comment-37c993c3>)）

>>> ## 開始揀貨

身為揀貨人員，我要按開始揀貨，以讓業務看得到倉庫已在處理這張單。

**實體關係**

1. 出貨單即揀貨指令。揀貨人員依單清點入庫的成品。
2. 開始揀貨寫入出貨單歷程。

**驗證規則**

1. 出貨單在未處理才可開始揀貨。

**驗收**

1. 假設承品檢驗收建立的 ORD-2026-0820 出貨單處於未處理。當揀貨人員在列上按「開始揀貨」並確認，則狀態由未處理轉打包中，歷程多一筆「開始揀貨」。

>>> ## 完成裝箱回報

身為揀貨人員，我要逐條回報揀貨數量、逐箱回報箱規、長寬高與照片，以讓裝箱結果與每箱大小留在單上。

**實體關係**

1. 揀貨數量逐條記在出貨明細，不預填。
2. 裝箱資料逐箱記錄，一箱一筆，記箱規、長寬高、裝箱照片與裝箱備註。
3. 一箱可有多張裝箱照片。裝箱備註選填。
4. 裝箱資料不記每箱裝了哪些印件與各幾個。
5. 箱序為三位數，不重排。
6. 箱規從全部箱規或「自訂箱規」擇一。所有出貨方式共用同一套箱規。
7. 選「自訂箱規」時，箱規存手填的名稱，不指向任何一筆箱規。
8. 箱規記名稱與長寬高，單位公分。沒有量過的尺寸留空。箱規如下：

| 箱規 | 長 | 寬 | 高 |
| -- | -- | -- | -- |
| F12 箱 | 15 | 11 | 4.5 |
| N3 箱（3 號箱） | 30 | 15 | 15 |
| F13 箱 | 29 | 21 | 6 |
| K1 箱 | － | － | － |
| MIX 箱（新 Mix 散件） | 35 | 25 | 15 |
| 300 拼圖箱 | 35.5 | 45.5 | 4.5 |
| 1 號箱 | 45 | 30 | 15 |
| 感官箱 | 32 | 24 | 36 |
| 馬克杯箱 | 50 | 45 | 36 |
| 1000 拼圖箱（地墊箱） | 80 | 55 | 7.5 |

 9. 每箱各存一份長寬高。箱規日後改尺寸，已存的值不變。
10. 長寬高依箱規欄的選擇帶入，完成裝箱回報與裝箱回報修正都一樣：

| 箱規欄的選擇 | 長寬高 |
| -- | -- |
| 選一筆箱規，含改選另一筆箱規 | 照該箱規的長寬高帶入，不可改。箱規沒記的欄位空白 |
| 選「自訂箱規」 | 空白，選填手填 |
| 從一筆箱規改成「自訂箱規」 | 保留原值，可修改 |

11. 完成裝箱回報不產生物流單。物流單在確認可出貨時產生，見可出貨確認節。
12. 揀貨數量與出貨明細數量不符時，揀貨人員照實填，並現場通知業務。
13. 揀貨人員不自行改明細。系統不發通知，也不設異常回報。
14. 瑕疵或找不到的量，照實填揀貨數量。處置在系統外協調。
15. 任一條出貨明細的揀貨數量不等於出貨數量，即為揀貨不符。

**驗證規則**

1. 出貨單在打包中才可完成裝箱回報。
2. 每條明細的揀貨數量必填。
3. 至少一箱。每箱的箱規必填，至少一張裝箱照片。
4. 選「自訂箱規」時，名稱必填。
5. 漏填時不受理，出貨單不推進。
6. 選一筆箱規時，長寬高必須等於該箱規記的值，箱規沒記的欄位必須空白，不符時不受理。
7. 揀貨不符不擋裝箱回報。出貨單照常轉已裝箱。
8. 完成裝箱回報、裝箱回報修正與編輯出貨單修改明細數量，會搶同一張單的揀貨不符判定。
9. 兩筆同時寫入時，先寫入者成立。後到者以寫入當下的數字重新判定，檢核不過時不寫入，系統告知卡住它的原因。

**驗收**

1. 假設承品檢驗收建立、已開始揀貨的 ORD-2026-0820 順豐出貨單。當揀貨人員在「裝箱回報」逐條填揀貨數量，再按三次「新增一箱」，每箱選箱規並各附一張照片後送出，則出貨單轉已裝箱。每條明細有揀貨數量，裝箱明細有三箱，每箱的所屬物流單與子單號都是空的，物流單表沒有資料。歷程多一筆「裝箱回報」，附裝箱照片。
2. 假設承品檢驗收建立、已開始揀貨的順豐出貨單。當揀貨人員漏填揀貨數量就送出，則對話框不關閉，單不推進。補填後把裝箱明細全部移除送出，則提示「至少要有一箱」。新增一箱只選箱規、不附照片送出，則提示「至少要附一張裝箱照片」。三種情形單都留在打包中。補齊後送出，則轉已裝箱。
3. 假設承品檢驗收建立、已開始揀貨的出貨單明細 500。當揀貨人員把該條明細的揀貨數量填 470 並送出，則出貨單照轉已裝箱，列表在狀態旁標「揀貨不符」，系統不自動改明細數量。
4. 假設承品檢驗收各建一張順豐單與 7-11 交貨便單，各出 100。當揀貨人員各開裝箱回報，則兩張單的箱規選項相同，列出全部箱規：F12 箱、N3 箱（3 號箱）、F13 箱、K1 箱、MIX 箱（新 Mix 散件）、300 拼圖箱、1 號箱、感官箱、馬克杯箱、1000 拼圖箱（地墊箱），最後一項為「自訂箱規」。
5. 假設承品檢驗收建一張新竹物流單、一張全家單與一張專車配送單，各出 100，皆已開始揀貨。當揀貨人員完成裝箱回報，則：
   * 新竹物流單一箱選「1 號箱」，長寬高帶入 45、30、15 且不可改，送出後裝箱明細顯示 1 號箱與 45、30、15。
   * 全家單一箱選「K1 箱」並附照片送出，長寬高照箱規空白且不開放填寫，空白不擋下，送出後箱規為 K1 箱、長寬高無值。
   * 專車配送單三箱都選「自訂箱規」：第一箱名稱改為「展架長箱」並填 60、40、30，第二箱名稱維持預設、長寬高留空，第三箱清空名稱。送出時整張擋下，出貨單維持打包中。補回第三箱名稱後成立，第一箱箱規存「展架長箱」、60×40×30，第二箱箱規存「自訂箱規」、長寬高無值。
   * 繞過畫面對 1 號箱送出不同的長寬高，或對 K1 箱送出任何長寬高，系統不受理。

>>> ## 裝箱回報修正

身為揀貨人員，我要修正填錯的裝箱回報，或改掉被物流商拒收的那一箱，以讓出貨單的裝箱資料與現場一致。

**實體關係**

1. 修正直接改原值，不改出貨單狀態。
2. 可修正明細的揀貨數量，以及新增箱、修改箱與刪除箱。修改箱時可改箱規、長寬高、裝箱照片與裝箱備註。
3. 修改箱規時，長寬高依完成裝箱回報節的帶入表調整。
4. 修正後至少保留一箱。
5. 出貨單在已裝箱時還沒有物流單。新增箱與刪除箱不牽動物流單。
6. 每次修正，每個被改的欄位新增一筆裝箱回報修正紀錄。
7. 紀錄記修正前後值、修正人、修正時間與修正原因。修正裝箱照片或刪除箱時，被換掉或刪掉的照片留在紀錄。
8. 修正寫入出貨單歷程，帶前後值與原因。

**驗證規則**

1. 各修正項目在下表條件成立時才可執行：

| 修正項目 | 可執行條件 |
| -- | -- |
| 揀貨數量 | 出貨單在已裝箱 |
| 新增箱 | 出貨單在已裝箱 |
| 刪除箱 | 出貨單在已裝箱 |
| 修改箱 | 出貨單在已裝箱；或確認可出貨之後，該箱所屬物流單在可出貨或等待出貨 |

2. 已離廠或已作廢物流單底下的箱不可修正，保留為裝箱紀錄。
3. 確認可出貨之後要調整箱數，先撤回確認可出貨。撤回走不通時要撤掉一箱，改走作廢該箱所屬物流單，見 <issue id="ce13f397-c990-4c83-8287-07d541ba440a" href="https://linear.app/sensationdeveloper/issue/PM-1401/feature-出貨交運與送達">PM-1401</issue>。
4. 修改箱選一筆箱規時，長寬高必須等於該箱規記的值，箱規沒記的欄位必須空白，不符時不受理。
5. 修正原因必填，未填無法修正，不改任何欄位。
6. 修正後，系統重新判定本單的揀貨不符。
7. 修正與出貨動作或物流商回傳同時寫入時，先寫入者成立。後到的修正以寫入當下的條件重新檢核，含不可修正的項目時整筆不受理。系統告知卡住它的原因，如該箱所屬物流單已離廠、不能再修正。

**驗收**

1. 假設承品檢驗收自建一張新竹物流單，出貨數量 500。揀貨人員已回報揀貨數量 480、裝箱 2 箱，單在已裝箱、尚無物流單。當揀貨人員按「修正」，把揀貨數量改為 500、新增一箱並選箱規、附照片、刪除第 1 箱後送出，則：
   * 先不填修正原因送出時，對話框不關閉，不改任何欄位。
   * 填修正原因再送出，揀貨數量與裝箱明細更新，每個被改的欄位各留一筆裝箱回報修正紀錄，歷程多一筆「裝箱回報修正」帶前後值與原因，出貨單維持已裝箱。
   * 系統不產生也不刪除物流單。新箱箱序為 003，不重用 001。
   * 之後揀貨人員確認可出貨，產生 -001、-002 兩筆物流單，出貨人員對第一筆拋單成功。此時揀貨人員列上仍有「修正」。揀貨數量不可改，沒有新增一箱與移除箱的鈕，兩箱的箱規、長寬高、照片、備註仍可改。
2. 假設兩張新竹物流出貨單各出 100，揀貨人員已各回報揀貨數量 80，業務已把第一張的明細數量改為 80。當揀貨人員把第二張的揀貨數量修正為 100 並填修正原因，則第二張兩數相符，「揀貨不符」標籤消失。
3. 假設承品檢驗收建一張順豐單，揀貨人員裝 2 箱並確認可出貨，這筆物流單拋單時物流商回傳錯誤。當出貨人員按「拋單」失敗，則揀貨人員列上仍有「修正」。揀貨人員把兩箱箱規改成另一種箱規並填修正原因後，出貨人員再拋單成功。此時揀貨人員的「修正」仍在、只開放修改箱。
4. 假設承品檢驗收建一張 7-11 交貨便單，出 100，裝 4 箱都選「1 號箱」，揀貨人員確認可出貨產生 -001 至 -004。出貨人員批次拋單後，第 1、2、4 筆轉等待出貨，第 3 筆被物流商拒收、停在可出貨。當揀貨人員把第 3 箱改成「F13 箱」並填修正原因送出，則：
   * 修正對話框中揀貨數量不可改，沒有新增一箱與移除箱的鈕，四箱可改。
   * 送出後第 3 箱長寬高重新帶入 29、21、6。修正紀錄有第 3 箱箱規、長、寬、高各一筆。
   * 第 1、2、4 箱與揀貨數量不變，出貨單箱數仍為 4。
   * 出貨人員對第 3 筆拋單成功後，物流單與出貨單轉等待出貨。
5. 假設承品檢驗收建一張 7-11 交貨便單，出 100，三箱都選「1 號箱」並完成裝箱回報，單在已裝箱。當揀貨人員以裝箱回報修正把第一箱改成「F13 箱」、第二箱改成「K1 箱」、第三箱改成「自訂箱規」，填修正原因送出，則第一箱帶入 29、21、6 並鎖住，第二箱帶入空白並鎖住，第三箱保留 45、30、15、可修改，箱規存預設名稱「自訂箱規」。修正紀錄中第一箱與第二箱各有箱規、長、寬、高四筆，第三箱只有箱規一筆。

>>> ## 可出貨確認

身為揀貨人員，我要在揀貨數量與明細相符後確認這一批可以出貨，以讓數量與箱數定案，物流單不隨裝箱修正一再增刪。

**實體關係**

1. 確認可出貨時，系統依出貨方式的「支援子母單」屬性產生物流單：

| 支援子母單 | 產生物流單的方式 |
| -- | -- |
| 是 | 全部箱子合成一筆物流單 |
| 否 | 一箱一筆物流單 |

2. 物流單產生時為可出貨。系統把每箱的所屬物流單寫入。
3. 物流單編號是出貨單編號加三位序號。序號不重用，撤回確認可出貨刪掉的序號也不重用。一張出貨單至多 999 筆物流單。
4. 確認可出貨後，出貨明細數量、揀貨數量與箱數鎖住。之後還能修正的項目，見裝箱回報修正節。
5. 確認可出貨寫入出貨單歷程，記系統產生的物流單編號。

**驗證規則**

1. 出貨單在已裝箱才可確認可出貨。
2. 揀貨不符時不受理，系統告知揀貨數量與出貨明細不符。出貨單維持已裝箱，不產生物流單。
3. 確認可出貨與編輯出貨單修改明細數量、裝箱回報修正同時寫入時，先寫入者成立。後到者以寫入當下的資料重新檢核，檢核不過時不寫入，系統告知卡住它的原因。

**驗收**

1. 假設 SH-2026-0922 為順豐 600 份、3 箱，已裝箱、尚無物流單、揀貨相符。當揀貨人員在列上按「確認可出貨」並確認，則：
   * 出貨單轉可出貨，系統產生一筆物流單 SH-2026-0922-001，在可出貨，三箱的所屬物流單皆為它。
   * 出貨單歷程多一筆「確認可出貨」，記物流單編號 SH-2026-0922-001、時間與操作人。
   * 接單業務與出貨人員都沒有「確認可出貨」。
   * 揀貨人員的修正只開放三箱的箱規、長寬高、裝箱照片與裝箱備註，揀貨數量、新增一箱、移除箱都不開放。
2. 假設已裝箱的全家單明細 100、揀貨 80、3 箱。當揀貨人員按「確認可出貨」，則系統提示「揀貨數量與出貨明細不符」，出貨單維持已裝箱，不產生物流單。業務把明細改為 80 後，揀貨人員再確認可出貨，則出貨單轉可出貨，產生三筆物流單。
3. 假設承品檢驗收各建一張順豐單與 7-11 交貨便單，各出 100、各裝 3 箱，已裝箱。當揀貨人員各按「確認可出貨」，則順豐三箱合成一筆物流單 -001，三箱的所屬物流單同一個。7-11 交貨便三箱各成一筆物流單 -001、-002、-003，每箱各屬自己的物流單。物流單都在可出貨。
4. 假設可出貨的新竹物流單明細 300、揀貨 300、3 箱 3 筆物流單皆在可出貨。當揀貨人員繞過畫面送出揀貨數量改為 290，或新增一箱，則都不受理，揀貨數量、裝箱資料與物流單不變。
5. 假設已裝箱的新竹物流單明細 100、揀貨 100，揀貨人員開著確認框時，業務把明細改為 80 並先寫入。當揀貨人員隨後送出確認可出貨，則系統提示「揀貨數量與出貨明細不符」，出貨單維持已裝箱，不產生物流單。

>>> ## 可出貨確認撤回

身為揀貨人員，我要在物流單都還沒交出時撤回確認可出貨，以回到已裝箱修正數量或箱數後再確認。

**實體關係**

1. 撤回時，系統刪除本單全部物流單，不走作廢，不填未送達數量。可出貨額度不變。
2. 每箱的所屬物流單清空，出貨單回到已裝箱。
3. 撤回寫入出貨單歷程，記刪除的物流單編號、時間與操作人。被刪除的物流單與它的歷程不留在系統。
4. 再確認可出貨時，物流單序號接續，不重用刪掉的序號。
5. 刪除的物流單已列印過時，下載中心的下載檔案保留，狀態、物流單筆數與檔案不變。

**驗證規則**

1. 本單全部物流單都在可出貨，且沒有已作廢的物流單，才可撤回。
2. 任一筆物流單的出貨動作處理中時，不受理撤回，系統告知有物流單的出貨動作處理中。
3. 撤回與出貨動作同時發生時，先成立者為準。

**驗收**

1. 假設 SH-2026-0921 為專車配送 1,200 份、4 箱，可出貨，一筆物流單 SH-2026-0921-001 在可出貨，PI-2026-0924 剩餘可出貨額度 900。當揀貨人員按「撤回確認可出貨」並確認，則：
   * 物流單 SH-2026-0921-001 被刪除，不轉已作廢，系統不要求未送達數量。
   * 四箱的所屬物流單清空，出貨單轉已裝箱。可出貨額度撤回前後都是 900。
   * 出貨單歷程多一筆「撤回確認可出貨」，記刪除的物流單編號 SH-2026-0921-001、時間與操作人。
   * 揀貨人員修正新增一箱並填修正原因後再確認可出貨，則箱數為 5，產生 SH-2026-0921-002，不重用 -001。
2. 假設一張新竹物流單第 1 筆拋單成功在等待出貨，第 2、3 筆拋單失敗仍在可出貨。另一張 7-11 交貨便單第 1 筆已作廢，第 2、3 筆在可出貨。當揀貨人員看兩張單的列，則都沒有「撤回確認可出貨」。繞過畫面送出時不受理，物流單與裝箱資料不變。
3. 假設 7-11 交貨便單明細 400、4 箱 4 筆物流單 -001 至 -004 皆在可出貨，額度 100。當揀貨人員撤回後新增第 5 箱、再確認可出貨，則產生 -005 至 -009 五筆，不重用 -001 至 -004。撤回前後額度皆為 100。
4. 假設可出貨的新竹物流單兩筆物流單皆在可出貨。出貨人員開著第一筆的拋單確認框時，揀貨人員撤回確認可出貨並先成立。當出貨人員隨後送出拋單，則不受理，系統告知該物流單已因撤回確認可出貨刪除，不向物流商送出。另一張 7-11 交貨便單，出貨人員對第一筆送出拋單、正在處理中時，揀貨人員送出撤回，則撤回不受理，系統告知有物流單的出貨動作處理中。
5. 假設全家單 2 筆可出貨物流單已列印，下載中心有一筆成功的下載檔案。當揀貨人員撤回確認可出貨，則這 2 筆物流單刪除，那一筆下載檔案保留，狀態、物流單筆數與檔案不變。
