>>> ## 生產任務接收

身為生管，我要確認接收印務交付來的生產任務，以讓每一筆交出來的活都有人接手、查得到誰在什麼時候接的。

**實體關係**

1. 接收以生產任務為單位，可單筆，也可批次。每筆接收記接收人與接收時間，寫入後不清除。

**驗證規則**

1. 生產任務的交付狀態在已交付才可確認接收。
2. 已接收的生產任務不再重複寫入接收紀錄。

**驗收**

1. 假設 WO-2026-0815 的牛皮紙 150g 備料已交付、尚未接收，當許文傑在所有生產任務對這一筆按接收工作，則該筆的接收工作記許文傑與接收時間。

>>> ## 生產任務派工

身為生管，我要把可以一起做的生產任務合成一個工作包派給一位師傅，以讓師傅上工就知道要做哪一批。

**實體關係**

1. 一個工作包收多筆生產任務，可跨工單、跨印件。一筆生產任務同時只屬於一個工作包。
2. 一個工作包指派給一位師傅。旗下生產任務的指派師傅取自工作包，未打包時為空。
3. 派工後生產任務留在生產任務清單，帶出所屬工作包與指派師傅。工作包不設狀態，現場進度取「已完成任務數／任務總數」。
4. 派工時，尚未接收的生產任務由系統補記接收：接收人為派工者，時間為派工時間。
5. 自己負責範圍以生產任務的產線對應本人的所屬產線，工作包取旗下任一任務的產線。被指派範圍以工作包的指派師傅對應本人。兩種範圍各自判定、不疊加。

**驗證規則**

1. 交付狀態為已交付或已接收的自有工廠生產任務才可派工。
2. 已屬某個工作包的生產任務不可再併入其他工作包。
3. 建立工作包時驗證必填欄位是否填寫，未填齊則無法建立。
4. 派工不檢查前置到料，也不改變生產任務狀態。

**驗收**

1. 假設 WO-2026-0812 的證書裁切、信封裁切、內卡裁切已接收、尚未打包，信封裁切與內卡裁切的可做量皆為 0／500，當許文傑勾選三筆、指派李榮發、預計完成日填 2026-09-08 後建立，則派工照常成立：系統建立一個新工作包，三筆仍在所有生產任務並帶出新工作包與李榮發，生產任務狀態仍為待處理，新工作包的現場進度為 0 / 3。
2. 假設許文傑勾選證書裁切後開派工對話框，當不選指派師傅就送出，則無法建立。
3. 假設 WO-2026-0710 的海報四色印刷已屬 WP-2026-0710-01（指派師傅劉阿海），當許文傑開所有生產任務，則該列不可勾選併入其他工作包，並帶出 WP-2026-0710-01 與劉阿海。
4. 假設鄭宇翔的所屬產線為手工產線與壓克力產線，當鄭宇翔開所有生產任務，則只看到手工產線的任務，看不到 WO-2026-0815 四筆。

>>> ## 生產任務報工

身為師傅，我要做完一段活就回報投入多少、好的幾件、壞的幾件並附照片，以讓工單、印件、訂單的進度不必有人轉抄就跟上現場。

**實體關係**

1. 一筆生產任務有多筆報工紀錄。所屬工作包與提交管道由系統依派工與報工入口帶入。
2. 備註是報工人員報工當下的補充。印務事後加的人工註記另記一處，與備註並存。
3. 任務實際開工取首筆報工的時間。任務轉已完成時記任務實際完成日。
4. 外發任務與場內任務走同一套報工。外發任務由印務在工單或印件詳情頁報工。

**驗證規則**

1. 生產任務在已作廢或報廢時不可報工。
2. 任一前置任務的到料量為 0 時不可報工，系統指出在等哪張工單、哪一筆生產任務的貨。
3. 下列情形無法送出報工：
   * 必填欄位未填齊。
   * 良品數加不良品數換算成投入單位後超過生產數量。
   * 生產數量大於 0，良品數與不良品數同為 0。
4. 繞過介面送出越權的報工時，系統擋下。

**算式**

```
生產數量累計 ＝ 有效報工的生產數量加總
產出數量 ＝ 有效報工的良品數累計 ＋ 不良品數累計
完成判定：生產數量累計 ≧ 目標數量
```

1. 有效報工指未作廢的報工。報工修改後取改後的值。
2. 投入與產出單位不同時，依每件產出耗用的投入量換算。
3. 生產數量累計超過目標數量時照實記。

**驗收**

1. 假設 WP-2026-0710-01 的海報四色印刷目標 3,090、已報 2,000、製作中，當劉阿海在我的工作包對它報生產數量 500、良品 490、不良品 10、不良原因色差，則報工進度為 2,500 / 3,090，任務仍為製作中。
2. 假設同一筆任務，當劉阿海報生產數量 300、良品 300、不良品 10，則無法送出。
3. 假設同一筆任務，當劉阿海報生產數量 300、良品與不良品都不填，則無法送出，不寫入任何報工。
4. 假設 WP-2026-0710-02 的裁切成型，前置海報四色印刷的 TT-20260830-002 已送達未點收、TT-20260830-003 搬運中，當李榮發在我的工作包展開這個工作包，則裁切成型的可做量為 0／3,000，不可報工。
5. 假設接第 1 條，當劉阿海再對海報四色印刷報生產數量 590、良品 590，則報工進度為 3,090 / 3,090，任務轉已完成。

>>> ## 報工修改

身為師傅，我要把報錯的生產數量、良品數或不良品數直接改成正確的數，以讓折損率、良率與實際成本取到現場真正的數字。

**實體關係**

1. 修改只動有效的報工，直接改報工上的生產數量、良品數與不良品數。
2. 每次修改留一筆修改紀錄，記修改前後值、修改人、修改時間與原因。一筆報工可有多筆修改紀錄。

**驗證規則**

1. 修改時驗證修改原因是否填寫，未填則無法修改。
2. 修改後生產數量大於 0 時，良品數與不良品數不得同時為 0，否則無法修改。
3. 調降的數量會讓已流到下游的量對不上時，擋下修改，數字不改。擋下條件與系統列出的內容如下表，調升不擋：

| 情形 | 擋下條件 | 系統列出 |
| -- | -- | -- |
| 需轉交的任務 | 改後良品數低於在途明細搬運數量合計加已點收明細點收數量合計 | 佔用的轉交單；待搬運或搬運中提示先作廢，已送達提示先照實點收 |
| 不需轉交的任務 | 下游任務已有報工 | 已報工的下游任務 |
| 所屬印件 | 改後待驗量變成負數 | 該印件已驗量 |

4. 第 3 條以寫入當下的數字檢核。兩筆修改或作廢同時寫入時，先寫入者成立，後到者以新數字重新檢核。

**驗收**

1. 假設 WP-2026-0812-01 的證書四色印刷有一筆報工 wr-0018（生產 515、良品 500、不良 15），TT-20260827-001 已點收 480，當周建宏把良品改為 480、不填修改原因就送出，則無法修改。

>>> ## 轉交單建立

身為生管，我要在待轉交任務勾選各任務累積出來的可搬量建單，以讓負責廠務接到通知就知道送哪批貨、送去哪、送多少。

**實體關係**

1. 一張轉交單是一趟搬運，有多條明細。每條明細是一筆來源生產任務與搬運數量，同一筆任務在一張單只出現一次。一張單可含跨工單、跨印件的貨。
2. 系統依來源生產任務建單當下的目的站點分組成單，同一目的地併成一張，建單時不可改目的地。外發生產任務回台點收後為來源時，目的地為品檢站。
3. 生管建單時指定這趟的負責廠務，系統記建單人並只通知負責廠務。負責廠務的候選限持有管理轉交單（負責）權限的人員。
4. 自己負責範圍：待轉交任務以來源生產任務的產線對應本人的所屬產線；轉交單以來源產線或目的產線對應。被指派範圍以轉交單的負責廠務對應本人。

**驗證規則**

1. 建立轉交單時驗證必填欄位是否填寫，未填齊則無法建立。
2. 每條明細的搬運數量大於 0，且不超過來源任務的轉交可申請上限。額度以按下建立那一刻的最新值計。
3. 任一條超額時該張單整張擋下，系統顯示當下可搬量。其他目的地的單照常建立。
4. 來源生產任務沒有報工良品，或轉交可申請上限不大於 0 時，不列在待轉交任務，不可建單。

**算式**

```
轉交量 ＝ 來源任務未作廢轉交明細的搬運數量合計
轉交可申請上限 ＝ 良品數 − 轉交量
搬運數量預設值 ＝ 來源任務當下的轉交可申請上限
```

1. 待搬運、搬運中、已送達、已點收的明細都計入轉交量。
2. 報工修改讓良品數低於轉交量時，轉交可申請上限為負，建單一樣被擋下。

**驗收**

1. 假設 WO-2026-0820 的精裝裝訂良品 500、目的站點品檢站、尚未建單，當許文傑在待轉交任務勾選它，則可搬量顯示 500，搬運數量預設 500。
2. 假設接上一條，當許文傑不選負責廠務就建單，則無法建立；負責廠務的候選只有簡俊男與邱志明。
3. 假設接上一條，當許文傑選邱志明後建單，則建立一張目的地為品檢站、待搬運的轉交單，負責廠務邱志明、建單人許文傑；只有邱志明收到通知，簡俊男沒有；精裝裝訂不再列在待轉交任務。
4. 假設海報四色印刷良品 1,990，TT-20260830-002 已送達 1,190、TT-20260830-003 搬運中 800，當許文傑開待轉交任務，則海報四色印刷不列出，轉交可申請上限為 0。
5. 假設 WO-2026-0815 四筆任務都還沒有報工良品，當許文傑開待轉交任務，則這四筆都不列出，無法建單。
