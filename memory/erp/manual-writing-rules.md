## 二、頁面單位

- 一頁＝一個操作者在一個時點要完成的一件工作。
- 同一決定的兩個方向算一件工作（送審與收回、核可與退回、合格與不合格）。
- 系統外討論後由同一人在系統上推進的流程不拆頁（例：送印務評估與評估完成）。

## 三、資料結構（JSON，鍵名不可增減；新增頁面時複製同單元既有頁的鍵）

### howto 頁

| 鍵 | 內容 |
|---|---|
| title | 一個業務目標 |
| actor | 角色名，多角色用「、」 |
| intro | 第一句含人事時地物。兩到三句 |
| goals | 段名渲染為「看完這頁你能」。情境頁通常一條業務成果句，動詞用完成、把…推進到…。有必要才加 |
| story | 情境。只用角色與身份（客戶、客戶窗口、你是接單業務），不用人名與公司名。保留數量、金額、日期當例子 |
| before | 開始前的條件：狀態、身分、資料前提 |
| entries | 每列 [入口, 怎麼到達, 適用時機] |
| steps | 每步 ["步驟文字", "說明"]。規則見 § 四 |
| fields | 照表單實況完整列齊，不精簡。每列 [欄位, 填什麼, 必填／選填／唯讀]。沒有表單填 null |
| check | 段名「預期結果」。只寫正常路徑的單一終點，三點左右 |
| notes | 段名「常見問題」。每條 ["問句", "答句"]。規則見 § 五 |

不再使用的鍵值：actorUser（人名欄）。改寫時刪除。

### overview 頁

- goals：段名同為「看完這頁你能」。列整體運作與概念，動詞用理解、分辨、判斷、找到，可多條。
- how.stages：每列 [狀態, 負責角色, 這個狀態在等什麼, 什麼事發生後往下走, 下一個狀態]。第三欄一句話講處境，不寫操作。第四欄寫業務事件，不寫按鈕名。例外狀態（流失、已取消、不合格、待改稿、已作廢）也列進去。
- 預設 SVG 流程圖箭頭上的字是業務事件，不是按鈕名。
- 「完成後什麼會帶到下一段」表只有需求單概覽有（成交轉訂單帶入資料）。其他單元的階段是資料建立，沒有帶入概念，handoff 設 null。
- 生產管理概覽除任務狀態圖外，另有一張「一道工序做完到下一站開工」流程圖，講報工、轉交、點收、下一站開工的循環；how.flows 的每張圖可用 caption 欄自訂說明。
- 其餘段（為什麼需要、是什麼、誰在這裡做什麼、接著做）結構不動，內容依 § 一對齊。

## 四、步驟規則

1. 一步＝一個操作者動作。系統自動行為不獨立成步驟，併入前一步的結果。
2. 結果只寫操作者看得到的兩樣：狀態與活動紀錄。狀態一律寫全名：「需求單狀態轉「待評估成本」」，實體名不省。
3. 系統外的等待不成步驟，寫進下一步開頭：「客戶簽回後，回訂單詳情頁點…」。
4. 同一步有兩種操作方式時並列在同一步：「點「確認回簽」或在附件頁籤上傳「回簽檔案」」。
5. 分支結果寫成該步的說明欄。
6. 不寫畫面元件變化：按鈕換了、統計卡加一、進度條亮了、右上出現某鈕。
7. 每句依 STE100：扣掉「」內介面字串後，操作指示 25 字內、說明句 30 字內。禁散文。
8. 說明欄只給需特別提醒的步驟，一頁不超過兩處。
9. 步驟少抄欄位名，欄位細節放 fields 表。
10. 不寫介面元件實作詞（TextArea、Modal、Dialog、Drawer、placeholder、上限 N 字）。字數上限只留 fields 表。
11. 不寫測試或 prototype 專用內容（模擬回寫、本 prototype、mock、假資料、Dev、模擬角色、種子資料）。

## 五、常見問題規則

- 目的：操作者做這個情境時可能遇到的問題。讓他確認不是自己操作錯，並知道怎麼解。
- 問句＝操作者看到的現象，用問號結尾。答句＝一句原因＋下一步，兩到三個短句。
- 每頁上限四題。
- 不放：與本頁操作無關的規則說明、系統內部機制描述（「已回簽是瞬間狀態」）。
- 不用人稱代名詞指稱角色（他、她），改寫角色名。

## 六、內容通則

- 全文不用具體單號（Q-、ORD-、PI-、WO-、BI-、SSP-、DO-、AU- 等格式一律不寫）。改寫成「這張需求單」「該印件」。
- 禁跨單元指涉，用階段名：需求單階段、訂單階段、款項與發票階段、審稿階段、工單階段、生產階段。
- 不註記資料來源。禁比喻、禁「順手」「刻意」。
- 頁面標頭與情境框的角色只寫角色名。
- 發票用語一律「開立發票」。審稿清單一律用畫面標籤「待審訂單」「待分派審稿」。

## 七、改寫作業方式

- 只在指定單元的 JSON 範圍內改，不動其他單元與渲染程式。寫回同一個檔。
- 改寫前先讀該單元對應的 prototype 程式碼取介面字串；有疑問對照 wiki 狀態機卡。
- 手冊與 prototype、wiki 三方矛盾時停下呈報，不自行調和。
