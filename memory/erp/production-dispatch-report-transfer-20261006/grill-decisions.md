## 範圍

| 項目 | 決定 |
|---|---|
| 外發（外包廠、中國廠商） | 本輪不處理，延到派單與貨運單模組迭代 |
| 加工廠 | 算場內；ERP 流程與自有工廠同一套，狀態變化不因場內或加工而不同。實務上由印務報工、不打包給師傅，所以沒有指派師傅，但一樣可以報工 |
| 補做 | 不納入本輪正流程（短少時上游通常要重走） |
| 逆流程 | 不納入本輪；報工作廢保留給逆流程使用（例：印件取消），觸發條件與連動待逆流程規劃時定，屆時一併釐清與「印件棄用時已報工任務轉報廢、報工留作成本」的關係 |
| 設計稽核 | 本輪不跑 plan-audit；改為落卡時把情境卡一併寫完整，缺步驟或分支當場補齊 |

## 派工

| # | 決定 |
|---|---|
| D1 | 所有生產任務只列已交付的自有工廠與加工廠任務；待轉交任務列全部（含外發） |
| D2 | 工作包只是把生產任務分給師傅的群組，跟報工無直接關係。取消工作包即刪除工作包；報工紀錄拿掉「所屬工作包」欄，報工都記在生產任務上 |
| D3 | 交付狀態顯示「－」的範圍縮小為外包廠與中國廠商；加工廠與自有工廠同樣推導未交付、已交付、已接收 |

## 報工

| # | 決定 |
|---|---|
| R1 | 報工前提：任務已交付，且前置到料量大於 0（需轉交的前置取點收量，不需轉交的前置取報工累計良品）；不要求接收或打包 |
| R2 | 管理原則：工廠用印件、工單、工作包、生產任務四個維度看產線狀況；同一個操作在各維度都做得到，權限只切可視範圍與可做操作 |
| R3 | 報工入口：工單詳情；所有工作包、我的工作包；所有生產任務、我的生產任務。印件詳情不報工 |
| R4 | 提交管道三值：師傅自助、生產管理頁面代報、印務於工單詳情頁 |
| R5 | 每個入口只能報清單列得出來的任務，系統層照同一範圍檢查：工單詳情看負責或編輯（代理）分享；所有〇〇看所屬產線；我的〇〇看指派給自己 |
| R6 | 我的生產任務的操作從「檢視」改為可報工、修改與作廢自己的報工（主要給師傅） |
| R7 | 已完成的任務不能新增報工；輸入錯誤用修改原本的報工更正，不另做修正功能；修改使生產數量累計跌破目標時退回製作中，即可再報 |
| R8 | 檢核：生產數量大於 0 時，良品與不良品不得同時為 0；良品＋不良品不可大於生產數量。每筆報工與每次修改都檢核 |
| R9 | 報工照片必填，可多張 |
| R10 | 越權報工只擋下，不寫稽核日誌 |

## 報工與點收共用的修正規則

| 欄位 | 報工 | 點收 |
|---|---|---|
| 備註 | 回報時選填，修改時可改 | 新增欄位；規則同報工 |
| 修改原因 | 文字；新增時不填，修改時必填 | 同報工 |
| 人工註記 | 拿掉 | 拿掉（轉交單上的人工註記也拿掉） |
| 歷程 | 每次回報、每次修改各記一筆（前後值、修改人、時間、修改原因、備註） | 同報工 |

「搬運遺失」等區分寫在修改原因或備註，不另設欄位。

## 轉交與點收

| # | 決定 |
|---|---|
| T1 | 點收只有一個動作：每次填寫都新增一筆點收紀錄（不分首次或再次）；修改就改那一筆的內容。第一筆點收時單頭轉「已點收」，之後再點收只新增紀錄、狀態不變 |
| T2 | 點收佇列與所有轉交單都能點收、能修改，兩個單元功能相同，只差可視範圍（點收佇列看目的產線；所有轉交單看來源或目的產線）。給誰依需求開權限 |
| T3 | 不區分代點收：拿掉代點收標記與「站上沒人才代點收」條件，看點收人與歷程操作人 |
| T4 | 一張轉交單＝同一條目的產線，不必同一個站點 |
| T5 | 一次勾多筆建單時，任一張超額就全部擋下並提示，生管重新勾選後再送出，不另做對話框功能 |
| T6 | 修改待搬運的單時，先把本單原本的搬運數量還回額度再檢核（算式補漏，寫在生產任務「轉交可申請上限」欄） |
| T7 | 預計轉交日必填；預設帶今天屬介面，歸 Prototype |
| T8 | 轉交單作廢原因為文字（不用下拉） |
| T9 | 刪除「前置受影響」整條規則；每筆任務只標示自己的狀況（例：印刷任務逾期就由印刷任務顯示逾期） |
| T10 | 「待接收清單」不使用，一律稱「點收佇列」 |

## 產線與站點（結構性變更）

| # | 決定 |
|---|---|
| L1 | 產線與站點有主從關係：產線底下有站點，一個站點只屬一條產線（例：壓克力產線的數位站） |
| L2 | 大家的工作以產線為單位（例：師傅負責壓克力產線），權限可視範圍一律看產線 |
| L3 | 轉交以站點為目的地（例：移動到壓克力產線的數位站），但一張轉交單以產線為單位 |
| L4 | 產線沿用現有六條，另加「品檢線」（對應現況設備主檔「QC線」）；品檢人員的所屬產線改為品檢線 |
| L5 | 站點清單待 Miles 提供，先用假資料（例：壓克力產線／數位站、品檢線／品檢站） |
| L6 | 生產任務與轉交單明細記「目的站點」（明細由來源任務帶出）；轉交單單頭記「目的產線」 |

|---|---|
| U1 | 工單的生產任務一律當數值計算，單位只用來顯示；生產數量、良品、不良品都用該任務自己的單位（印務自行計算），與印件數量無關。導入拼版計算之前不處理換算 |

## 第二輪（落卡過程中追加的拍板）

| # | 決定 |
|---|---|
| Q18 | 工單或訂單已結束後，報工仍可修改，只受現有擋下條件限制，不另設終態凍結 |
| Q19 | 生產任務不設單位欄位；單位依所引用 BOM 項目的計價方法帶出、只用來顯示（Prototype 現行對照：重量計／令價計／單張計＝張，數量計＝個，單獨面積／總面積／工序面積＝才，上機印數／原紙令數／成品數量／工序總價／時間計價＝張，本數計價＝本，頁數計價＝頁，台數計價＝台）；對照表補進 [[BOM結構]] 計價方法段 |
| Q19 前置 | 生產任務的「產線」與「目的」是兩件事：產線＝這道工序在哪條線做（六條製作產線，不含品檢線）；目的＝先選目的產線、再選該線站點（含品檢線／品檢站）。品檢線是一條產線、品檢站是它的站點，只排除在生產任務產線欄之外 |
| Q20 | 所有工作包照現行規則列出（旗下任一任務在自己產線範圍內），但包裡只有產線在自己範圍內的任務能報工、修改、作廢，其他任務只能看 |
| Q21 | 不採「只改備註」；改採方案一 |
| 方案一 | 數量錯誤由下往上逐層更正：下游報工 → 點收 → 搬運數量 → 上游報工。每層照擋下條件檢查，被擋下時系統指出卡在哪一筆，不自動改別人的資料；每層修改原因必填、歷程各記一筆。已進品檢時由品檢人員先更正品檢紀錄。符合自働化（異常即停、看得見）、現地現物（每層確認實際數量）、不事後補救 |
| Q22 | 搬運數量也可用修改更正（開始搬運後只能經修改，修改原因必填、留修改紀錄）：調降不擋，調升受轉交可申請上限管制（先還回本單原佔用）。理由：只改報工與點收時，上游任務還在做會永遠卡在待點收 |
| 情境 | 新開情境卡 [[生產數量錯誤的逐層更正]] 承載方案一的例子（五色印刷 500 → 480，任務已完成與還在做兩種推演、已進品檢、結案後發現、跨產線工作包） |
| 規則歸屬 | 報工修改的擋下條件屬跨單據判定，正本從情境卡移到 [[報工規則]]（依 W2） |
| Q23 | 單位由 BOM 主檔項目設定，生產任務顯示所引用 BOM 項目的單位；不設計價方法對照表，全面拿掉單位換算邏輯（含拼版換算句、BOM 單位用量換算）。wiki 三張主檔卡（工序、裝訂、材料）補「單位」欄，維護時設、只用來顯示（後端 sens-print-core 工序計價軸與材料面積區間已有單位欄）。mock 單位錯誤一律修正（例：裝袋為「個」） |
| Q24 | 報工修改被未點收的轉交單擋下時：待搬運直接改搬運數量；搬運中用修改更正搬運數量；已送達先由收貨人照實點收，再更正搬運數量，再改報工。數量錯就修改數量，作廢只留給建錯任務或目的地 |
| 主對話判斷 | 搬運數量修改由生管主責、印務與印務主管可代行；來源任務已報廢或已作廢時搬運數量修改擋下（比照點收修改）；Q18 的「已結束」只含已完成，不含已取消；貨在路上遺失時搬運數量也照實更正、修改原因填「搬運遺失」 |
| 數量輸入 | 搬運數量、報工生產數量、點收量一律大於 0（輸入 0 沒意義），建單、回報、修改都適用。取代「點收量可填 0」「搬運數量修改後可為 0」「整筆報錯改成 0」 |
| Q25 | 轉交單只有點收前能作廢（待搬運、搬運中、已送達），原因不限；已點收不能作廢，避免影響下游已在做的生產任務。作廢後搬運數量退回來源任務。取代 Q24 的「作廢只用在建錯任務或目的地」。貨在路上全部遺失：點收前作廢整張單，來源報工照實更正（修改原因「搬運遺失」）。已送達數量不對：可作廢重建，或照實點收後逐層更正 |
| Q26 | 報工與點收紀錄：數字錯用修改，整筆不該存在用作廢（正流程與逆流程都可用，取代 Q12「作廢只給逆流程」的定位）。作廢與修改共用同一組擋下條件，作廢後數量退回。拿掉「任務已完成時不能作廢報工」的特例 |
| Q28 | 不為「搬運遺失」設特別情境。操作人員只判斷一件事：這一筆要不要取消——根本不該存在就作廢；存在但有一部分要算損耗，就修改（良品改少、不良品改多，生產數量不變）。損耗怎麼來的由修改原因自由填寫，系統不區分、不設固定字樣。轉交單同理：點收前不送或搬丟就作廢，點收後數量不對就修改 |
| 設計原則 | 先設計 MES 的工具與流程，再把商業情境套進去，驗證能否覆蓋大多數場景；不為單一情境增設規則或流程 |
| Q27 | 一張轉交單的點收紀錄全部作廢後，單頭退回「已送達」，可重新點收或作廢 |
| 稽核後主對話判斷 | 報工前提以「交付時間有值」判定（不看交付狀態，避免外發任務被「－」卡死）；沒有前置的任務不檢查到料；搬運數量一律大於 0（見「數量輸入」列）；BOM結構書冊上機張數算式保留並註明只用於計價；PT-067 只留站點清單與暫存區歸屬，站點承載方式（標籤或主檔）屬實作不進議題；點收修改擋下條件正本歸 [[工序相依性規則]]；Q24 作廢限制正本寫在 [[轉交單狀態]] 作廢轉換 |
