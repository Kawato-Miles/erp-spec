第一段

claude.dev 建議的重點

來源只限 claude.dev 網域 16 篇，抽查 7 篇逐句相符。raw 卡：2026-10-29-claude-research-claude.dev對Claude5世代的使用建議

CLAUDE.md少於 200 行。寫 repo 用途與陷阱，驗證指示拆成 skill 引用。文章 1、9
skill 說明檔description 寫觸發時機不寫摘要。只寫目標與限制。陷阱段隨真實失敗累積。文章 2
sub-agent 派工回報先查證據。小模型只做查找。團隊小、任務自成一體。文章 7、9
模型分工小模型查找、Opus 5.5 主力、Fable 5.1 最難的工作。effort 從 medium 起，量到增益才升。文章 8、9

對專案的影響

  • 專案 CLAUDE.md 現在 375 行，大半是流程規則與路由表，和建議方向相反。
  • 九個 skill 多為逐步指令與禁令清單；plan-audit 的稽核循環沒有輪數上限。
  • 評分準則多數條目已有證據要求，但判定值與可檢查程度還差一段。

對專案的影響

  • 拍板前不動任何 skill。拍板後每個檔案完整重寫，不用局部修補。
  • Miles 的日常會變三處：pre-check 後多一題「要不要調研」；稽核到上限就交你裁決；偏離業界做法時票上多一段取捨。
  • 先建評測集再重寫，每批都能回答「有沒有退步」。
